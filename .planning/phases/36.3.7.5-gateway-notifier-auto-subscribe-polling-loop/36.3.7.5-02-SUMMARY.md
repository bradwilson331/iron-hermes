**BUG-36.3.7.5-07** (receiver-end tests) by adding a NEW `notifier.rs` module to

spawn time. **Locked architectural fence held**: `ironhermes-kanban` has NO
compile-time dependency on `ironhermes-gateway` — the trait-object closure IS the
boundary.

## Notifier Module Architecture (4-step tick)

`run_notifier_tick` executes:

1. **Load terminal events past the watermark.** `store.list_terminal_events_after(watermark)`
   runs `SELECT id, task_id, run_id, kind, payload, created_at FROM task_events
   WHERE id > ?1 AND kind IN ('completed','blocked','gave_up','crashed','timed_out')
   ORDER BY id ASC`. Reclaimed is **NOT** in this set; it is silently skipped.
2. **For each event:**
   a. List subscriptions via `store.list_subscriptions_for_task(&ev.task_id)`.
      Skip via `continue` if the vec is empty (counted in `events_processed`).
   b. Fetch the task via `store.get_task(&ev.task_id)` for the `assignee` field.
   c. Format the per-kind plain-text message via `format_terminal_message(task, ev)`:
      - `completed` → `"✓ <task_id> completed by <assignee>\n<summary-first-line>"`
        (summary-first-line omitted if payload.summary is absent/empty).
      - `blocked` → `"⚠ <task_id> blocked: <reason>"` (reason from payload.reason).
      - `gave_up` → `"⚠ <task_id> gave up: <reason>"`.
      - `crashed` → `"✗ <task_id> crashed (pid=<pid>)"` (pid from payload.pid as u64).
      - `timed_out` → `"⏱ <task_id> timed out"`.
   d. Call `(ctx.send_fn)(platform, chat_id, thread_id_opt, message)` for each subscription.
      `thread_id_opt` is `None` when `sub.thread_id` is empty (the empty-string
      convention from Plan 01's schema); otherwise `Some(thread_id)`. On `Err`,
      emit one `tracing::warn!(event = "notification_failed", ...)` line and
      continue — **no retry per locked policy D-log-and-drop-on-fail**.
   e. **Auto-remove ALL subscriptions for the task** via
      `store.remove_all_subscriptions_for_task(&ev.task_id)` — auto-remove on
      FIRST attempt regardless of success/failure (locked policy
      D-auto-remove-after-attempt).
3. **Advance the watermark** via `ctx.last_event_id.fetch_max(highest_id, SeqCst)`.
   Monotonic — never goes backwards even under concurrent ticks (T-36.3.7.5-02-01
   mitigation).

`run_notifier_loop` is the standard outer shell: `init_watermark` once at
startup (seeds the `AtomicI64` from `store.max_event_id()`), then
`tokio::select!` between `cancel.cancelled()` and `interval.tick()` (interval =
`ctx.poll_interval_seconds.max(1)` with `MissedTickBehavior::Skip`). Tick errors
are logged via `tracing::warn!` and the loop continues — same isolation pattern
as `dispatcher::run_dispatch_loop`.

a Cargo dep entry.

The `SendFn` trait-object closure IS the kanban→gateway boundary:

```rust
pub type SendFn = Arc<
    dyn Fn(&str, &str, Option<&str>, &str) -> BoxFuture<'static, AnyResult<()>>
        + Send + Sync,
>;
```

- The kanban crate publishes the type alias + invokes the closure inside
  `run_notifier_tick`.
- The gateway crate (Plan 03) will construct the closure at spawn time,
  capturing its `Arc<dyn PlatformAdapter>` set and routing on the `platform: &str`
  argument.
- Returns `anyhow::Result<()>` (`AnyResult`) so the gateway can surface
  platform-specific error variants without forcing the kanban crate to know
  about them.

Receiver-test confirmation: `tests/notifier_logic.rs` constructs the mock
`SendFn` from **zero gateway types** — every test imports only from
`ironhermes_kanban`, `tempfile`, `tokio`, `serde_json`, `anyhow`, and `std`.
This proves the boundary is clean by construction.

## Threat-Model Audit

The Plan 02 threat model (3 mitigate + 2 accept rows in PLAN.md `<threat_model>`)
is honored at the code+test level:

- **T-36.3.7.5-02-01 (Tampering / watermark drift):** `AtomicI64::fetch_max` ensures
  the watermark is monotonic; the `id > ?1` SQL filter excludes already-processed
  events. Locked by `watermark_advances_past_processed_event`.
- **T-36.3.7.5-02-02 (DoS / terminal-event flood):** `accept` — bounded by upstream
  task-count gating in the dispatcher (`failure_limit`, `max_in_progress`).
- **T-36.3.7.5-02-03 (Info disclosure / payload summary relayed to chat):** `accept`
  — this IS the feature. Operator gate via `notification_sources` (Plan 03)
  controls which subscriptions can be created in the first place.
- **T-36.3.7.5-02-04 (Tampering / forged Reclaimed):** SQL kind filter excludes
  Reclaimed; locked by `reclaimed_event_is_ignored`.
- **T-36.3.7.5-02-SC (Crate boundary / kanban→gateway dep):** Gate 11 asserts the
  dep is absent at compile time; mock `SendFn` in tests proves the API works
  without any gateway type.
