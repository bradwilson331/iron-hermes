# Phase 36.3.7.5 Plan 03: Gateway Notifier Spawn + Gating Helper + Receiver Tests — Summary

Closed **BUG-36.3.7.5-04** (gateway runner spawns the kanban notifier loop, gated on
`notification_sources` + enabled-platform overlap) and the gateway-spawn-gating portion
of **BUG-36.3.7.5-07** (receiver-end tests) by wiring the notifier loop (Plan 02
producer) into the gateway runner's existing `join_set`. The spawn block mirrors the
dispatcher spawn shape (canonical at `runner.rs:1242-1294`) and shares the dispatcher's
`Arc<TokioMutex<KanbanStore>>` via a semantics-preserving store-arc lift refactor.

The kanban→gateway boundary stays a trait-object closure (`SendFn`), preserving the
locked architectural fence: `ironhermes-kanban` has zero compile-time knowledge of
`ironhermes-gateway`'s adapter types. Plan 04 will land the auto-subscribe hook +
3 CLI verbs that write the subscription rows this Plan-03 loop reads from.

## Spawn-block diff (verbatim inserted, Task 2 Change B)

Inserted in `crates/ironhermes-gateway/src/runner.rs` immediately after the dispatcher
spawn, INSIDE the new shared-store Ok-arm:

```rust
// -----------------------------------------------------------------------
// Phase 36.3.7.5 BUG-36.3.7.5-04: Gateway notifier spawn (gated on config).
//
// Mirrors the dispatcher spawn shape above (canonical).
// - Gate: notification_sources = Some(non_empty) AND at least one
//   platform in that list intersects with the enabled gateway
//   platforms set (case-insensitive). Default-off preserved.
// - On gate-fail: log ONE info line + skip; gateway continues
//   without the notifier loop.
// - On gate-pass: spawn run_notifier_loop into join_set with a
//   send_fn closure wrapping the enabled adapters by platform.
//
// The send_fn is the kanban->gateway boundary closure — keeps the
// ironhermes-kanban crate free of any compile-time dep on
// ironhermes-gateway. See Plan 02 SUMMARY crate-isolation audit.
// -----------------------------------------------------------------------
let enabled_platforms: Vec<String> =
    collect_enabled_platform_names(&self.config, &adapter);
let gate = crate::notifier_gating::compute_notifier_gate(
    kanban_config.notification_sources.as_deref(),
    &enabled_platforms,
);
match gate {
    crate::notifier_gating::NotifierGate::DisabledNoSources => {
        info!("kanban notifier disabled (notification_sources not configured)");
    }
    crate::notifier_gating::NotifierGate::DisabledNoOverlap { wanted, enabled } => {
        info!(
            wanted = ?wanted,
            enabled = ?enabled,
            "kanban notifier disabled (no enabled platform overlap)"
        );
    }
    crate::notifier_gating::NotifierGate::Enabled { sources } => {
        let adapter_snapshot: Vec<(
            String,
            std::sync::Arc<dyn crate::adapter::PlatformAdapter>,
        )> = build_adapter_snapshot(&adapter);
        let send_fn = build_notifier_send_fn(adapter_snapshot);
        let poll_seconds = kanban_config.notifier_poll_seconds;
        let notifier_ctx = std::sync::Arc::new(
            ironhermes_kanban::NotifierContext::new(
                kanban_store_arc.clone(),
                poll_seconds,
                send_fn,
            ),
        );
        let notifier_cancel = self.cancel.clone();
        join_set.spawn(async move {
            ironhermes_kanban::run_notifier_loop(notifier_ctx, notifier_cancel).await;
        });
        info!(
            sources = ?sources,
            poll_seconds = poll_seconds,
            "kanban notifier loop started"
        );
    }
}
```

The 3 supporting helpers (`collect_enabled_platform_names`, `build_adapter_snapshot`,
`build_notifier_send_fn`) live as private module-level fns near the existing
`resolve_token` helpers; signatures + bodies in the Task 2 commit (`16a208ed`).

## Threat-Model Audit

The Plan 03 threat model (3 mitigate + 1 accept rows in PLAN.md `<threat_model>`) is
honored at the code+test level:

- **T-36.3.7.5-03-01 (Spoofing / subscription names disabled platform):** Mitigated by
  the send_fn closure's `find().map()` lookup — unknown platform returns
  `Err(anyhow::anyhow!("platform {} not enabled in gateway", platform))`. The notifier's
  log+drop policy (Plan 02 producer) handles the rest. Receiver-tested indirectly:
  `gate_returns_disabled_no_overlap_when_no_intersection` confirms the gate-check
  catches obvious operator misconfigurations BEFORE the spawn happens.
- **T-36.3.7.5-03-02 (EoP / operator misconfigures notification_sources):** `accept` per
  the threat model. The intersection check at spawn time logs `wanted`/`enabled` to the
  operator. Asserted by `gate_returns_disabled_no_overlap_when_no_intersection`.
- **T-36.3.7.5-03-03 (DoS / spawn blocks startup):** `accept`. `join_set.spawn(async move
  { ... })` is non-blocking. The store-arc lift adds one extra `open_default()` at
  startup which is bounded by SQLite's open-with-WAL latency (~1ms typical). On open
  failure, BOTH dispatcher and notifier skip and the gateway proceeds.
- **T-36.3.7.5-03-SC (Tampering / store-arc lift changes dispatcher behavior):**
  Mitigated. Audited at 3 levels above — code-level structural verification, INV-test
  verification, and kanban-suite baseline match (120/120).
