<objective>
Land the decomposer kernel: the `DecomposeFn` injection-point typedef, the request/output/child-spec data shapes, the atomic store-level `specify_triage_task` and `decompose_triage_task` functions, the canonical Markdown body schema for `tasks.body` rewrites, the lib.rs re-exports, and 6 receiver-end tests proving the lifecycle (success path × 2, double-decompose race, no-op on non-triage, LLM failure with event-append, per-tick cap stub).

Purpose: This is the kernel that Plans 03 (LLM tools), 04 (dispatcher Step 0), and 05 (CLI verbs) all consume. The kernel is deliberately provider-agnostic — the `DecomposeFn` injection mirrors `SpawnFn` and `SendFn` (the two pre-existing precedents in dispatcher.rs and notifier.rs) to keep `ironhermes-kanban` free of `ironhermes-agent` / provider-client dependencies. Plans 03-05 supply the concrete `DecomposeFn` implementation at the appropriate seam (CLI builds it from the operator's configured provider; the LLM tools build it from the runtime env; the dispatcher receives it via `DispatcherContext.decompose_fn`).

Output: 1 new module (~250 LOC), 1 new test file (~250 LOC with 6 tests), additive edits to `store.rs` (helper for the atomic decompose transaction) and `lib.rs` (4 re-exports). Plan 04 will additionally extend `DispatcherContext` with a `decompose_fn: Option<DecomposeFn>` field; that change is sequenced to Wave 3 because it depends on the typedef defined here.

Failure-mode policy (per RESEARCH §Q5 — locked):
- LLM error / network / 500 / rate-limit → retain in triage, append `KanbanEventKind::DecomposeFailed` with payload `{reason: "llm_error", message: <e.to_string()>}`, return Err to caller (so dispatcher Step 0 can log without halting the rest of the tick).
- LLM returns unparseable JSON → DecomposeFn caller (CLI / tool / dispatcher) returns Err with reason="parse_error"; same retain-and-event policy.
- LLM picks unknown assignee → child task assignee falls back to `config.default_assignee`; if that is also empty, falls back to parent task's `assignee`. The decomposer.rs implementation enforces this; never lands a child with assignee="".
- Race where task is no longer in triage → `WHERE status='triage'` UPDATE returns 0 rows; decomposer returns `Ok(DecomposedIds { root_promoted: false, child_ids: vec![] })` without error.
