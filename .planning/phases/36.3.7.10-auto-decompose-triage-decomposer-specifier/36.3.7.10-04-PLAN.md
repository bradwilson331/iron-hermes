<objective>
Wire the decomposer into the dispatcher's tick loop as a new Step 0 that runs BEFORE crash detection. The step is gated on `ctx.config.auto_decompose` (default false) AND `ctx.decompose_fn.is_some()` (default None — gateway runner does not wire a production fn in v1 per RESEARCH §Q1 Open Question recommendation b). When both gates pass, the step queries triage tasks up to the configured per-tick cap and calls `decompose_triage_task` sequentially on each. Per-task failures append `decompose_failed` events and continue to the next task without halting the tick.

Purpose: Manual CLI invocation (Plan 05) handles operator-driven decomposition. This plan handles the AUTO mode — the "drop a one-liner in triage, walk away" flow from reference.md §431. Auto mode is opt-in (`kanban.auto_decompose: true`) and Production-wiring-deferred (gateway runner ships with `decompose_fn=None` in v1) — operators who set `auto_decompose=true` without wiring a DecomposeFn get a graceful no-op tick (zero work + zero noise). The Step 0 architecture is in place; future phases can wire a production DecomposeFn into the gateway runner without touching the dispatcher.

Output: 1 modified file (dispatcher.rs). ~60 LOC additive: 1 new struct field, 2 constructor updates, 1 new Step 0 block in `run_dispatch_tick_for_board`, 1 per-board context-literal update in `run_dispatch_tick`, 1 new private `decompose_triage_tasks` async fn. The existing 8 dispatcher steps are byte-stable. Default-off behavior preserved for every existing user.
</objective>

```
if ctx.config.auto_decompose {
    if let Some(ref decompose_fn) = ctx.decompose_fn {
        async {
            if let Err(e) = decompose_triage_tasks(ctx, decompose_fn).await {
                tracing::warn!(error = %e, board = board_slug, "auto-decompose step error");
            }
        }
        .instrument(tracing::info_span!("kanban.dispatch.step", step = "auto_decompose", board = board_slug))
        .await;
    }
}
```

`decompose_triage_tasks` body contract (per PATTERNS.md):
1. Read `cap = ctx.config.auto_decompose_per_tick as usize`.
2. Acquire `store.lock().await`, call `list_tasks(ListFilters { status: Some("triage".to_string()), ..Default::default() })`, drop the lock (do NOT hold across LLM calls).
3. `.take(cap)` on the resulting vec → bounded triage_tasks.
4. For each task in bounded set (sequential, NOT `join_all` — burst-billing prevention per RESEARCH):
   - Call `crate::decomposer::decompose_triage_task(ctx.store.clone(), &task.id, decompose_fn, &ctx.config).await`.
   - On Ok(_): tracing::info!(task_id=%task.id, "auto-decomposed").
   - On Err(e): tracing::warn!(error=%e, task_id=%task.id, "decomposer failed; retaining task in triage"). The Err path in decompose_triage_task ALREADY appends the DecomposeFailed event (per Plan 02); the dispatcher does NOT need to append a SECOND event here. Just log and continue.
5. Return Ok(()).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `auto_decompose=true` config → background LLM calls | Operator opts in via config; absent opt-in, zero LLM activity |
| `decompose_fn=Some(...)` injection → process privilege | Whoever wires the DecomposeFn into DispatcherContext controls what provider/credentials/skills are exposed to the auto-mode |
| Step 0 failures → tick cascade | Per-task and per-step errors must NOT halt subsequent steps |
| LLM burst billing → auto_decompose_per_tick | Configurable cap prevents runaway costs from a flood of triage tasks |
