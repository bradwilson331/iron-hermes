### Pattern: Injectable Async Fn (SpawnFn / SendFn / DecomposeFn)

**Source:** `crates/ironhermes-kanban/src/dispatcher.rs` lines 62–66 (`SpawnFn`) and `crates/ironhermes-kanban/src/notifier.rs` lines 52–66 (`SendFn`)
**Apply to:** `decomposer.rs` (`DecomposeFn` typedef), `dispatcher.rs` (`DispatcherContext.decompose_fn` field)

```rust
// dispatcher.rs:62-66 — SpawnFn canonical typedef:
type BoxFuture<T> = std::pin::Pin<Box<dyn std::future::Future<Output = T> + Send>>;
type SpawnFn = Arc<dyn Fn(Task, TaskRun, String, String) -> BoxFuture<Result<u32>> + Send + Sync>;

// notifier.rs:53-66 — SendFn canonical typedef (lifetime annotated variant):
type BoxFuture<'a, T> = std::pin::Pin<Box<dyn std::future::Future<Output = T> + Send + 'a>>;
pub type SendFn = Arc<
    dyn Fn(&str, &str, Option<&str>, &str) -> BoxFuture<'static, AnyResult<()>> + Send + Sync,
>;
```

All three injection points use `Arc<dyn Fn(...) -> BoxFuture<Result<...>> + Send + Sync>` — no `Box<dyn Trait>`, no `async_trait`, no struct vtable. DecomposeFn follows SpawnFn exactly (owned args, no borrowed lifetime).
