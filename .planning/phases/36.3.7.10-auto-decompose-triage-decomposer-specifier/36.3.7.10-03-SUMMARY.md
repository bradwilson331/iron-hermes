## v1 `no_aux_client` Envelope — Deliberate Design

The two new tools' `execute()` methods return the `no_aux_client` rejection envelope **unconditionally in v1**. This is not a bug — it is documented behavior.

**Rationale:** The `ironhermes-kanban` crate has a crate-isolation fence: no `reqwest` or `ironhermes-agent` dependency is permitted. Wiring a production DecomposeFn that calls an HTTP provider API would require one of those dependencies. The runtime-context injection mechanism (e.g. a `OnceCell<Option<DecomposeFn>>` populated at startup, or a 3rd arg to `register_kanban_tools`) is out of scope for Phase 36.3.7.10 and is **queued for a follow-up phase**.

**Value of v1 registration:** Orchestrators can see `kanban_decompose` and `kanban_specify` in the tool schema and receive a useful, actionable response: `"use hermes kanban decompose <id> CLI verb instead"`. This is preferable to the tools being absent entirely — the LLM has a path forward.

**Future wiring:** Plans 04 (dispatcher auto-mode) and 05 (CLI manual mode) wire the DecomposeFn directly via a CLI-only closure. The LLM tool surface wiring will land in a dedicated follow-up phase that introduces the runtime injection mechanism without touching the crate-isolation fence.
