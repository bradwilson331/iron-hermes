# Phase 36.3.7.6 — Kanban LLM-tool surface completion: heartbeat / link / unblock

## Phase Goal

Close the 3 LLM tools (`kanban_heartbeat`, `kanban_link`, `kanban_unblock`) that v1's `docs/kanban/reference.md` §14 + §204-208 promised but deferred. After this phase, the full 9-tool LLM surface in the reference doc is honored (the existing 6 — `kanban_show`, `kanban_list`, `kanban_complete`, `kanban_block`, `kanban_comment`, `kanban_create` — were shipped across Phases 36.3.7 + 36.3.7.0..5).

Each new tool follows the existing pattern at `crates/ironhermes-kanban/src/tools/{show,list,complete,block,comment,create}.rs`: `pub struct {Name}Tool` carrying `Arc<TokioMutex<KanbanStore>>` + `explicit_enable: bool`; `async_trait Tool` impl with `name() / toolset() / description() / schema() / is_available() / execute()`; gated on `HERMES_KANBAN_TASK` env (workers) OR `explicit_enable=true` (orchestrators); registered in `crates/ironhermes-kanban/src/tools/mod.rs:45-62`.

The phase also reconciles the 4 v1-NOTE markers in `docs/kanban/reference.md` (currently `grep -c 'deferred to Phase 36.3.7.1' docs/kanban/reference.md` = 4 — verified at develop tip) and ships the CLI parity verb `hermes kanban heartbeat <id> [--note "..."]` that reference.md:583 already claims exists but does not.

This phase is **bilateral-tracing-by-construction**: every BUG ships its producer (the tool registration + handler + any new store helper) AND its consumer (the named receiver test in `tests/tools_smoke.rs`) in the SAME commit set. Per LEARNINGS 2026-05-30.

## Architectural decisions surfaced (cite CONTEXT.md)

- **D-heartbeat-impl**: append `KanbanEventKind::Heartbeat` event row (NOT a `tasks.last_heartbeat_at` column). Variant ALREADY EXISTS at `crates/ironhermes-kanban/src/events.rs:47` (snake_case `"heartbeat"` at events.rs:93). Trade-off: ~1 row/hour/active-worker growth vs. single source of truth alignment with the dispatcher staleness reader at reference.md:869. Picked schema stability.
- **D-link-cycle-detection**: `WITH RECURSIVE` CTE walking descendants of the proposed `child`, comparing against the proposed `parent`. Wrapped in `BEGIN IMMEDIATE` together with the tenant check + `INSERT OR IGNORE` to prevent TOCTOU under WAL-mode concurrent writers. Pattern matches `block_task` at store.rs:817-821.
- **D-link-fk-enforcement**: existing `task_links` FK constraints (schema.rs:60-67) + `PRAGMA foreign_keys=ON` (schema.rs:21) automatically reject phantom ids. Tool surface wraps as `KanbanError::TaskNotFound` rejection.
- **D-unblock-status-precondition**: precondition gate lives in the LLM tool handler (NOT in the store). `store.unblock_task` at store.rs:881 remains UNCHANGED (operator CLI parity preserved). Tool handler calls `store.get_task`, checks `task.status == "blocked"`, fails closed with `{"status":"rejected","reason":"invalid_status","current":"...","expected":"blocked"}` otherwise.
- **D-cli-heartbeat-parity**: ship `KanbanCommands::Heartbeat { id, note }` + `cmd_heartbeat` to close the doc-vs-impl gap at reference.md:583. `link` + `unblock` CLI verbs already exist at commands.rs:238, 367.
- **D-tool-surface-mounts-store-directly**: new tools own `Arc<TokioMutex<KanbanStore>>` directly, matching the existing 6-tool pattern. NOT routed through `CommandContext` / `KanbanStoreWriter`. The 36.3.7.5 writer trait is NOT extended.
- **D-docs-reconciliation**: 4 v1-NOTE line replacements; verifier gate `grep -c 'deferred to Phase 36.3.7.1' docs/kanban/reference.md == 0`.
- **D-no-deferred-subverbs-change**: `DEFERRED_KANBAN_SUBVERBS` at handlers.rs:1143-1148 UNTOUCHED. Gateway slash arms for `/kanban link|unblock|heartbeat` remain deferred. This phase ships ONLY the LLM-tool surface + CLI parity for heartbeat.

Full rationale + rejected alternatives in `36.3.7.6-CONTEXT.md::<locked_decisions>`.

## Worktree / parallelization strategy

**Decision: develop-direct, inline orchestrator. NO worktrees. Single plan.**

Inherits the Phase 36.3.7.5 scope-fence (`36.3.7.5-PLAN.md::Worktree / parallelization strategy` — "develop-direct, inline orchestrator … per cwd-drift lesson from Phase 36.3.7.1").
