## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Rust module nesting — #[cfg(test)] mod inside impl block is not supported**
- **Found during:** Task 2 first compile attempt
- **Issue:** Placed `#[cfg(test)] mod open_tasks_count_tests { ... }` inside the `impl KanbanStore { }` block in store.rs. Rust does not allow module declarations inside `trait`s or `impl`s.
- **Fix:** Moved the test module to be a sibling of the `impl KanbanStore` block (still inside `store.rs` at module level). Required splitting the closing `}` of the impl block.
- **Files modified:** `crates/ironhermes-kanban/src/store.rs`
- **Commit:** `b9884c56`

**2. [Rule 2 - Missing critical functionality] board.toml written with manual format!() (T-36.3.7.9-03-SC disposition)**
- **Found during:** Task 2 implementation review
- **Issue:** Plan references `toml = "0.8"` serializer but Plan 05 (which adds the toml dep) has not landed in wave 3.
- **Fix:** Used manual `format!()` toml emission as specified in the plan's T-36.3.7.9-03-SC supply-chain accept disposition. Includes quote-escaping for `\` and `"` in names/descriptions.
- **Files modified:** `crates/ironhermes-cli/src/kanban/boards.rs`
- **Commit:** `b9884c56`

**3. [Rule 3 - Blocking] `with_home!` macro defined but unused in lifecycle tests**
- **Found during:** Task 2 test compilation
- **Issue:** The macro was defined for convenience but all tests directly construct `ScopedHome`. Clippy emits `unused_macros` warning.
- **Fix:** Left macro defined (no compile error) — the warning is benign and the macro may be useful for future tests. Documented here. The `#[warn(unused_macros)]` is at the warning level only.
- **Files modified:** None (no fix needed; not a compile error)
