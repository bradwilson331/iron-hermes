<objective>
Make every kanban LLM tool board-aware. Add `board: Option<String>` to all 11 tool schemas, resolve the `BoardContext` at the top of each `execute()` body, open the per-board store, and inject `board` + `board_source` fields into every success AND rejection envelope (D-08 invariant + T-5 mitigation). The shared envelope helpers go in a new `tools/common.rs` to avoid duplicating the same JSON-shape code 11 times.

Purpose: Without this plumbing, the LLM agent has no surface to target a specific board; orchestrator-driven multi-board deployments would silently mutate the wrong board (T-5). The `board_source` field is the debugger's friend: when a tool says `"board_source": "env"`, the operator knows the dispatcher set the env var (Plan 06); when it says `"file"`, the cursor file is the source; when `"default"`, no scoping was applied.

Output: One new file (`tools/common.rs`); 11 extended tool files (schema + execute amendments); one module declaration in `tools/mod.rs`. Tool count unchanged at 11. Existing tools_smoke.rs tests continue to pass (envelope additions are additive — existing fields preserved). New ≥11 tests assert the envelope shape on success AND rejection for every tool.
</objective>
