## Inert Explicit Codepath Proof (D-03)

Test: `subscribe_explicit_filters_out_unlisted_boards` in `tests/notifier_multi_board.rs`

Assertion: When `subscribe_boards = Explicit(["alpha"])`, the tick sweeps only "alpha" even though "default" has a seeded Completed event + subscription. The default board's subscription (`chat_id="99"`) is NOT delivered; only alpha's (`chat_id="77"`) is. The `per_board` slice contains "alpha" and NOT "default".

This proves the Explicit codepath ships, compiles, and filters correctly — even though no default user config activates it in v1.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `log::warn!` → `tracing::warn!` in notifier_config.rs**
- **Found during:** Task 1 compilation
- **Issue:** Used `log::warn!` but the crate uses the `tracing` facade (no `log` dep in Cargo.toml)
- **Fix:** Replaced all `log::warn!` calls with `tracing::warn!`
- **Files modified:** `crates/ironhermes-kanban/src/notifier_config.rs`
- **Commit:** `06b1a503`

**2. [Rule 1 - Bug] `std::io::Error` → `KanbanError` conversion for `?` in `run_notifier_tick`**
- **Found during:** Task 2 compilation
- **Issue:** `resolve_subscribe_boards` returns `std::io::Result`; `run_notifier_tick` returns `crate::error::Result<NotifierTickReport>` — `?` couldn't convert
- **Fix:** Added `.map_err(|e| KanbanError::Other(anyhow::anyhow!("{}", e)))?`
- **Files modified:** `crates/ironhermes-kanban/src/notifier.rs`
- **Commit:** `1c3844eb`

**3. [Rule 1 - Bug] First-tick-skip logic conflicted with existing tests**
- **Found during:** Task 2 test run (4/5 existing notifier_logic tests failed)
- **Issue:** The plan description said "first tick watermark==0 → initialize and skip." The existing Phase 36.3.7.5 tests call `run_notifier_tick` directly with watermark=0 and expect events to be delivered immediately. The `run_notifier_loop` already handles the skip via `init_watermark()` before starting ticks. Adding a skip inside `sweep_board_with_store_ref` broke direct tick calls.
- **Fix:** Removed the watermark==0 skip from `sweep_board_with_store_ref`. The loop-level `init_watermark` (called by `run_notifier_loop`) correctly sets watermarks to MAX(id) before any ticks, achieving the same skip-history semantics.
- **Files modified:** `crates/ironhermes-kanban/src/notifier.rs`
- **Commit:** `1c3844eb`
