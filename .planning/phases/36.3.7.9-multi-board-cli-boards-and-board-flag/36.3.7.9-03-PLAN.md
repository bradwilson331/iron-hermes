<objective>
Ship the user-facing `hermes kanban boards` subcommand surface (list/create/switch/show/rename/rm + `--delete`). All six leaf verbs land in a new `boards.rs` file with a `BoardsCommands` clap enum and per-verb `cmd_boards_*` async functions. CLI-layer concerns: slug validation at the CLI boundary (defense-in-depth even though resolver also validates), atomic current-board file writes via tmp+rename, symlink refusal on rm (T-6), advisory file lock around hard-delete (T-7), and refusal to rm the literal `default` slug.

Purpose: This is the primary user surface for the multi-board feature. Plan 04 will plumb the parent `--board` flag through every existing verb; this plan delivers the noun-verb pair that creates the underlying boards. Without Plan 03, named boards cannot exist on disk and `--board <slug>` would point at non-existent paths.

Output: One new file (`boards.rs`), two extended files (`mod.rs`, `commands.rs`). At least one tempdir-based integration test per leaf verb plus the T-3 atomicity and T-6 symlink-refusal locks.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv → slug | `boards create/switch/rm <slug>` accepts user input; validator runs at CLI layer (defense in depth) |
| `boards rm` → filesystem | `remove_dir_all` is unrecoverable; archive path is recoverable |
| `boards rm` → kanban DB | Pre-flight COUNT(*) gates the rm; concurrent task insertion is a TOCTOU window |

Crash before step 4 leaves the board accessible but not current — harmless (Pitfall 8). Locked by `create_with_switch_writes_current_only_after_db_init` test. |
