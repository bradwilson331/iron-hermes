# Phase 36.3.7.9 Plan 04: --board Flag Threading Summary

Parent-level `--board <slug>` flag threaded through all 29 existing `hermes kanban` verbs via `open_store_for_board(board)`, making every verb board-aware without breaking single-board users.

## What Was Built

### Task 1: Thread `board: Option<&str>` through every `cmd_*` function

Every `pub async fn cmd_<verb>` in `commands.rs` was extended with a `board: Option<&str>` parameter. All `open_store()` and `KanbanStore::open_default()` callsites were replaced with `open_store_for_board(board)`. `handle_kanban_command` signature extended to `(cmd: KanbanCommands, board: Option<String>)` and every non-Boards dispatch arm passes `board.as_deref()`.

### Task 2: Wire `--board <slug>` clap flag + integration tests

Added `#[arg(long, global = false)] board: Option<String>` to the `Commands::Kanban` variant in `main.rs`. Updated dispatch to `handle_kanban_command(command, board)`.

Created `crates/ironhermes-cli/tests/board_flag_threading.rs` with 4 integration tests:

| Test | Description | Exit code |
|---|---|---|
| `board_flag_parses_at_kanban_parent_level` | `kanban --board alpha list` parses correctly | pass |
| `board_flag_absent_yields_none` | `kanban list` without --board yields `None` | pass |
| `board_flag_passes_to_handler_signature_test` | Compile-time signature lock on `handle_kanban_command(KanbanCommands, Option<String>)` | pass |
| `board_flag_routes_open_store_to_named_board` | e2e: create alpha board, open via `open_store_for_board(Some("alpha"))`, assert `kanban/boards/alpha/kanban.db` used | pass |

All 4 tests pass. Full `cargo test -p ironhermes-cli` suite: 0 failures. `cargo build --workspace`: 0 errors.
