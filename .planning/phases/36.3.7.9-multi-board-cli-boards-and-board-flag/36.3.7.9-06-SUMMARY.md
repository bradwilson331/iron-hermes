# Phase 36.3.7.9 Plan 06: Dispatcher Multi-Board Sweep + Worker Env Slug Propagation Summary

Per-tick board enumeration in the dispatcher and per-task HERMES_KANBAN_BOARD/HERMES_KANBAN_DB routing through the full spawn pipeline using board_db_path_for_slug(board_slug) replacing the hardcoded "default" literal.

## What Was Built

### Task 1: build_kanban_worker_env signature extension

`pub fn build_kanban_worker_env(task: &Task, run: &TaskRun, workspace: &str, board_slug: &str)` is the new signature.

Two env var changes inside the function body:
- `HERMES_KANBAN_DB`: now uses `crate::paths::board_db_path_for_slug(board_slug)` — for `"default"` this resolves to the legacy `kanban.db` path (D-01 back-compat); for named boards it uses `boards/<slug>/kanban.db`
- `HERMES_KANBAN_BOARD`: now `board_slug.to_string()` replacing the literal `"default".into()`

`spawn_worker` is retained as a thin wrapper calling `spawn_worker_for_board(task, run, workspace, "default")` to preserve back-compat for any caller that does not carry a resolved slug.

`spawn_worker_for_board` is the new multi-board entry point used by the dispatcher's per-board spawn_fn wrapper.

**Call site inventory:** Two non-dispatcher callers existed:
- `spawn_worker` (internal to worker_spawn.rs) — now delegates to `spawn_worker_for_board`
- External test files in `argv_receiver_36_3_7_0.rs` — all 3 call sites updated to pass `"default"`

### Task 2: Dispatcher tick multi-board sweep

`run_dispatch_tick` now:
1. Builds `all_boards = ["default"] + list_boards()` (Pitfall 2 — "default" synthesized first, not from disk)
2. For `"default"`: reuses `ctx.store` Arc (back-compat invariant; existing tests construct ctx.store with custom paths)
3. For each named board: calls `KanbanStore::open_for_board(&slug)` — on `Err` logs `[kanban] dispatcher skipping board '<slug>': <e>` and `continue`s (INV-36.3.7-08-05 extension)
4. Wraps the per-board store in a `DispatcherContext` that captures the board slug in its `spawn_fn` closure
5. Delegates to `run_dispatch_tick_for_board` (private) which runs all 8 existing steps unchanged

**SpawnFn change:** Extended from `Fn(Task, TaskRun, String) -> BoxFuture<Result<u32>>` to `Fn(Task, TaskRun, String, String) -> BoxFuture<Result<u32>>` where the 4th parameter is `board_slug: String`. The `with_spawn_fn` signature now uses the `SpawnFn` type alias directly (fixes a `type_complexity` clippy lint).

**Gateway runner.rs:** Zero LOC changed. The existing `KanbanStore::open_default()` Arc hoist at lines 1281-1298 is preserved. The dispatcher's per-tick multi-board iteration is entirely internal — no runner.rs edit required (RESEARCH §7 Option A confirmed correct).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Existing dispatcher tests failed after initial multi-board refactor**
- **Found during:** Task 2, first test run
- **Issue:** Initial implementation opened `KanbanStore::open_for_board("default")` from disk via `get_hermes_home()` for all boards including "default". Existing `dispatcher_logic.rs` tests construct their store at `dir.path().join("kanban.db")` (custom temp path, not `IRONHERMES_HOME`). The per-tick open resolved to a different path, so the tests saw an empty DB.
- **Fix:** For "default" board, reuse `ctx.store` Arc from the outer `DispatcherContext` (back-compat). Only named boards open fresh stores from disk. This preserves the test contract while still implementing multi-board for named boards.
- **Files modified:** `crates/ironhermes-kanban/src/dispatcher.rs`
- **Commit:** 72bd0699

**2. [Rule 1 - Bug] Multi-board tests failed due to parallel test execution contaminating shared IRONHERMES_HOME**
- **Found during:** Task 2, second test run
- **Issue:** All 4 new tests in `dispatcher_multi_board.rs` ran in parallel, mutating the process-global `IRONHERMES_HOME` env var concurrently. Tests saw each other's board directories and tasks.
- **Fix:** Added `static SERIAL_MUTEX: std::sync::Mutex<()>` and `let _guard = SERIAL_MUTEX.lock().unwrap()` at the top of each test. Documented strategy in file header.
- **Files modified:** `crates/ironhermes-kanban/tests/dispatcher_multi_board.rs`
- **Commit:** 72bd0699

**3. [Rule 2 - Clippy] Fixed type_complexity lint introduced by SpawnFn parameter change**
- **Found during:** Task 2 clippy check
- **Issue:** `with_spawn_fn` parameter used the full expanded type instead of the `SpawnFn` alias, triggering `type_complexity` lint.
- **Fix:** Changed parameter type to use `SpawnFn` alias.
- **Files modified:** `crates/ironhermes-kanban/src/dispatcher.rs`
- **Commit:** 72bd0699
