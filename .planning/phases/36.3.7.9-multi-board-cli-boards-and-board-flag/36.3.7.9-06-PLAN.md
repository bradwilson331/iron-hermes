<objective>
Generalize the dispatcher tick to sweep every board (prepending "default" to `list_boards()` results) and propagate the resolved board slug into the worker spawn env. The literal `"default"` at `worker_spawn.rs:117` becomes a `board_slug: &str` parameter. The gateway runner.rs change is intentionally minimal: keep the default-board Arc hoist (notifier still uses it after Plan 05), and let the dispatcher internally handle multi-board iteration per RESEARCH §7 Option A.

Purpose: Without per-tick board sweep, named boards' `triage→ready→running→done` state machine never advances even though the boards exist on disk. Without `HERMES_KANBAN_BOARD = <slug>` in the worker env, the worker would open the wrong DB and write its heartbeat/completion to the default board. This plan closes both gaps.

Output: One extended signature in worker_spawn.rs; one new iteration loop in dispatcher.rs; ≤5 LOC change in runner.rs (or zero if the existing call site can remain unchanged because the dispatcher now multi-board-iterates internally). Existing single-board tests pass after passing `"default"` as the new arg.
</objective>
