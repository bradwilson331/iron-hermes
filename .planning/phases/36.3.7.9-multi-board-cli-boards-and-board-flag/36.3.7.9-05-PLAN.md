<objective>
Add the `notifier.toml` parser with `subscribe_boards = ["*"]` as the single default-shipped value; extend `NotifierContext` and `run_notifier_tick` to iterate over the resolved board set per tick instead of a single store. Both the `All` glob path AND the `Explicit` literal-list path ship — but only `All` is exercised by the default config (D-03 inert-explicit invariant). Per-board open failures log + skip (INV-36.3.7-08-05 extension), and per-board watermarks ensure each board's task_events stream is replayed independently.

Purpose: Phase 36.3.7.5 shipped the notifier polling loop for a single (default) board. Multi-board would silently miss task_events emitted on any non-default board if the loop is not generalized. Without `notifier.toml`, the user has no surface to scope notifications when the explicit-list activation lands in a future phase — the codepath ships day-one so retroactive migration is avoided (D-03 rationale).

Output: Two `Cargo.toml` edits (add `toml = "0.8"`); one new file (`notifier_config.rs`); one extended file (`notifier.rs`); one re-export amendment (`lib.rs`). All gateway-side notifier-spawn code (`runner.rs:1281-1298`) remains UNCHANGED — Plan 06 owns dispatcher/runner extensions.
</objective>
