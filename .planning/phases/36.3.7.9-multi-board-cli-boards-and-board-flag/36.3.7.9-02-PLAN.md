<objective>
Generalize `KanbanStore` to open any DB path with an optional slug label, add `open_for_board(slug)` as the canonical multi-board entry point, and inject the D-06 migration banner (stderr) into `init_schema`. The migration runs inside the existing single `init_schema` path; both default and named boards go through the same code (D-06 invariant). T-4 mitigation: the banner is emitted between `run_migrations()` success and the `UPDATE schema_version` statement, but BOTH are wrapped in a transaction so a write failure rolls back rather than leaving a partial banner+stale-version state.

Purpose: Plans 03-09 all need a way to open a board's DB by slug. Without `open_for_board`, the CLI cannot honor `--board <slug>`, the LLM tools cannot route to a per-board store, and the dispatcher/notifier cannot sweep boards. The D-06 banner is the user-facing "what just happened" signal — without it, a future v2 migration is silent and confusing.

Output: Two extended files (`store.rs`, `schema.rs`); one new integration test file (Wave 0 scaffold). `KanbanStore::open_default()` byte-stable surface; existing callers untouched. `cargo build --workspace` exit 0.
</objective>
