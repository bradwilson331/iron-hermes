# Phase 36.3.7.9 Plan 01: Multi-board foundations (paths + board module) Summary

### Task 2: board/ module (commit `782db6d9`)

Three new files:

**`board/slug.rs`** — `validate_board_slug(input: &str) -> Result<String, BoardSlugError>`:
- Security ordering: trim-mismatch (PathTraversal) → `/`/`\\`/`..` (PathTraversal) → downcase → empty → too-long → reserved → bad-start → invalid-chars
- `RESERVED_BOARD_SLUGS = ["_archived"]`
- 22 inline tests covering every positive and negative case from the plan

**`board/resolver.rs`** — `resolve_board_context(cli_flag: Option<&str>) -> Result<BoardContext, BoardSlugError>`:
- 4-tier if-let chain: flag → env → file → default
- `"default"` skips validation (Pitfall 3) and maps to `kanban_db_path()` (Pitfall 1)
- 8 inline tests with `ENV_LOCK: Mutex<()>` serialisation + tempdir `IRONHERMES_HOME` isolation

**`board/mod.rs`** — Defines `BoardContext`, `BoardSource`, `default_board_context()`, re-exports all public symbols.

`lib.rs` amended: `pub mod board` added + `pub use board::{BoardContext, BoardSource, resolve_board_context}`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Reserved slug check ordering**
- **Found during:** Task 2 test run
- **Issue:** `validate_board_slug("_archived")` returned `Err(BadStart)` instead of `Err(Reserved(_))` because the `BadStart` check (step 6) fired before the reserved check (original step 8). `_archived` starts with `_` which is not ASCII alphanumeric.
- **Fix:** Moved the reserved slug check to run before `BadStart` and `InvalidChars` checks (after empty/length checks). Doc comment updated to reflect new ordering.
- **Files modified:** `crates/ironhermes-kanban/src/board/slug.rs`
- **Commit:** `782db6d9`

**2. [Rule 1 - Bug] Rust 2024 edition unsafe env mutation**
- **Found during:** Task 1 first compile
- **Issue:** `std::env::set_var` and `remove_var` require `unsafe` blocks in the Rust 2024 edition used by this workspace.
- **Fix:** Wrapped all `set_var`/`remove_var` calls in `unsafe { ... }` with SAFETY comment. Applied to both `paths.rs` and `resolver.rs` test helpers.
- **Files modified:** `crates/ironhermes-kanban/src/paths.rs`, `crates/ironhermes-kanban/src/board/resolver.rs`
- **Commit:** `c7ea4e3b`, `782db6d9`

**3. [Rule 2 - Missing critical functionality] Empty HERMES_KANBAN_BOARD handling**
- **Found during:** Task 2 implementation review
- **Issue:** The plan's if-let chain resolves `HERMES_KANBAN_BOARD` on `Ok(v)` — but an empty string would satisfy that and pass an empty slug to the validator (returning `Empty` error). A misconfigured env var with `HERMES_KANBAN_BOARD=""` should fall through to the file/default tier.
- **Fix:** Added an `if v.is_empty()` guard inside the env tier that falls through to file/default rather than treating an empty string as a valid slug.
- **Files modified:** `crates/ironhermes-kanban/src/board/resolver.rs`
- **Commit:** `782db6d9`
