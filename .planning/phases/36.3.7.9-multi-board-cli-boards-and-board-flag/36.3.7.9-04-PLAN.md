<objective>
Thread the parent-level `--board <slug>` flag through every existing `hermes kanban` verb. Replace every `open_store()` callsite (≥20 per RESEARCH.md §2) with `open_store_for_board(board: Option<&str>)`. Add `board: Option<String>` to `handle_kanban_command` and to every `cmd_*` signature. Wire the flag into the clap parent at `main.rs` so it's accepted before the verb (`hermes kanban --board <slug> <verb> ...`).

Purpose: Without this plumbing, named boards exist on disk but no existing verb can read or write them. Plan 03 ships `boards` (the noun-verb pair to manage boards); this plan ships the `--board` flag that makes the existing 20+ verbs board-aware. The two plans are file-disjoint (this plan does NOT touch `boards.rs`), making them parallel-eligible within Wave 3.

Output: One signature change on `handle_kanban_command`; ≥20 signature changes on `cmd_*` fns; one new clap arg on the Kanban parent struct in main.rs. Existing tests continue to pass (the new parameter is opt-in; absence == legacy behavior).
</objective>
