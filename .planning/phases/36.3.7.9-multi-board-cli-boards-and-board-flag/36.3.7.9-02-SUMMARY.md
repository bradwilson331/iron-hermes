## What Was Built

### Task 1: KanbanStore generalization + D-06 banner (commit `130c202e`)

Extended `crates/ironhermes-kanban/src/store.rs` with the multi-board open surface:

| Method | Signature | Purpose |
|--------|-----------|---------|
| `open` | `pub fn open(path: impl AsRef<Path>) -> Result<Self>` | Unlabeled open; banner uses "default" if ever fires |
| `open_labeled` | `pub fn open_labeled(path: impl AsRef<Path>, slug: &str) -> Result<Self>` | Open with D-06 banner slug label |
| `open_default` | `pub fn open_default() -> Result<Self>` | Back-compat wrapper → legacy `kanban.db` (D-01) |
| `open_for_board` | `pub fn open_for_board(slug: &str) -> Result<Self>` | Canonical multi-board entry: `"default"` → legacy path, else `boards/<slug>/kanban.db` |

`init_schema` extended with three new match arms:

| arm | Action |
|-----|--------|
| `None` | Fresh DB: `INSERT INTO schema_version` — no banner |
| `Some(v) if v < SCHEMA_VERSION` | `BEGIN` → `run_migrations` → `eprintln!(banner)` → `UPDATE schema_version` → `COMMIT` (T-4) |
| `Some(v) if v > SCHEMA_VERSION` | Return `Err(KanbanError::Other(anyhow!("...newer than binary supports...")))` |
| `Some(_)` | Happy path: no-op (Pitfall 6) |

`crates/ironhermes-kanban/src/schema.rs`: Added T-4 atomicity doc comment on `run_migrations` clarifying callers must wrap it with the `UPDATE schema_version` inside a single transaction.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] KanbanError::Other variant takes anyhow::Error, not String**
- **Found during:** Task 1 implementation
- **Issue:** The plan says "add `KanbanError::Other(String)` with `#[error("{0}")]` if missing." The existing variant is `Other(#[from] anyhow::Error)` — adding a second `Other` would break the enum.
- **Fix:** Used `KanbanError::Other(anyhow::anyhow!("..."))` to construct the error with the required message. No error.rs change needed.
- **Files modified:** `crates/ironhermes-kanban/src/store.rs` only (the `Err(...)` return site)
- **Commit:** `130c202e`

**2. [Rule 1 - Bug] BEGIN/COMMIT via explicit execute() calls instead of rusqlite Transaction**
- **Found during:** Task 1 implementation review
- **Issue:** The plan suggests `conn.transaction()` but `Transaction` only implements `Deref<Target=Connection>` (not `DerefMut`), and `run_migrations` requires `&mut Connection`. The `Transaction::execute` surface does not allow passing the transaction to `run_migrations`.
- **Fix:** Used explicit `self.conn.execute("BEGIN", [])` / `COMMIT` / `ROLLBACK` guards around the `v < SCHEMA_VERSION` arm with a closure-based error capture. This preserves T-4 atomicity while avoiding the DerefMut constraint.
- **Files modified:** `crates/ironhermes-kanban/src/store.rs`
- **Commit:** `130c202e`

**3. [Rule 1 - Bug] Parallel test ENV_LOCK needed for IRONHERMES_HOME tests**
- **Found during:** Task 1 test run (2 tests failed)
- **Issue:** `open_default_still_uses_legacy_path` and `open_for_board_default_uses_legacy_path` set `IRONHERMES_HOME` in parallel test threads; `open_default()` then called `kanban_db_path()` which read the env before the store file was written, resulting in a stale path that didn't exist yet.
- **Fix:** Added `static ENV_LOCK: Mutex<()>` to serialise env-mutating tests. Tests acquire the lock before setting `IRONHERMES_HOME` and release it (via drop) after the open call. `open_for_board_named` was rewritten to use explicit `open_labeled` with a tempdir path to avoid env dependency entirely.
- **Files modified:** `crates/ironhermes-kanban/tests/multi_board_open.rs`
- **Commit:** `130c202e`
