### CR-03: Lock File Not Cleaned Up After `remove_dir_all` Failure

**Files modified:** `crates/ironhermes-cli/src/kanban/boards.rs`, `crates/ironhermes-cli/tests/boards_lifecycle.rs`
**Commit:** `31aa33c9` (included in CR-02 commit — both findings modified `boards.rs`)
**Applied fix:** Introduced a `LockGuard { path: std::path::PathBuf }` struct with `impl Drop` calling `let _ = std::fs::remove_file(&self.path)`. The guard is created immediately after `OpenOptions::create_new(true).open(&lock_path)` succeeds. The explicit `drop(_lock_file); remove_file(&lock_path)` in the `count > 0` branch was removed — cleanup is now handled unconditionally by `_lock_guard` on all exit paths.

Regression test `rm_lock_file_cleaned_up_on_count_gt_zero_exit` seeds an open task, calls `cmd_boards_rm --delete`, confirms exit code 1 (refused) and asserts `kanban.db.rm-lock` is absent afterward. Note: the `chmod 555` approach to simulate `remove_dir_all` failure was rejected because `remove_file` inside a 555 directory also fails — the `count > 0` path provides a reliable, cross-platform regression.

### CR-04: `init_schema` Uses Raw SQL Strings for Transaction Control Instead of rusqlite RAII Transactions

**Files modified:** `crates/ironhermes-kanban/src/store.rs`, `Cargo.lock`
**Commit:** `700a93a7`
**Applied fix:** Replaced `self.conn.execute("BEGIN", [])` / `execute("COMMIT", [])` / `execute("ROLLBACK", [])` with rusqlite's `Connection::transaction()` RAII pattern.

**Constraint discovered:** rusqlite 0.32 `Transaction<'_>` stores `&'conn Connection` (immutable) and implements only `Deref<Target=Connection>`, NOT `DerefMut`. Therefore `run_migrations(&mut tx, v)` does not compile. The fix restructures the migration path: `run_migrations(&mut self.conn, v)` runs first (it is a no-op stub — `let _ = conn; let _ = current; Ok(())`), then `let tx = self.conn.transaction()?` wraps the version UPDATE and commit. This preserves RAII rollback protection for the critical `schema_version` bump. When real migrations are added they should be structured to run inside a transaction scope. Existing `multi_board_open.rs` tests (9 tests) pass without modification.
