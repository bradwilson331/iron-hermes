# Phase 36.1 Plan 02: Running-agent guard parity — web UI Summary

Wired Phase 36.1 running-agent guard parity into the `iron_hermes_ui` web surface: added a per-session `Arc<AtomicBool>` map on `AppState`, intercepted slash commands in `ws.rs` before `run_web_turn`, enforced D-02 rejection for non-bypass slash commands and plain-text messages while a turn is in flight, and bound `RunningAgentGuard` RAII at `run_web_turn` entry. Behaviors verified by 6 integration tests mirroring the Phase 36 gateway suite; zero regression on the existing 11 gateway tests.

## What Was Built

**Task 1 — `AppState.running_agents` field + helper + `RunningAgentGuard` bind (state.rs):**

- Added `pub running_agents: Arc<std::sync::Mutex<HashMap<String, Arc<AtomicBool>>>>` to `AppState` directly after the existing `nudge_turns` field — same `std::sync::Mutex` flavor and `Arc<Mutex<HashMap>>` shape (D-03; Mutex choice locked per RESEARCH §Pitfall-5 rationale).
- Initialized the field in `AppState::init()` `Ok(Self { ... })` block.
- Added `pub fn get_or_create_running_flag(&self, session_id: &str) -> Arc<AtomicBool>` — mirrors `SessionStore::get_running_flag` (gateway session.rs:256). Get-OR-create semantics: repeat calls for same session return handles to the SAME `AtomicBool`.
- Bound `let _agent_guard = RunningAgentGuard::new(self.get_or_create_running_flag(session_id));` at the TOP of `run_web_turn`'s async body — INSIDE the `async fn`, not in the sync caller. Drop fires on `Ok`, `Err`-via-`?`, panic, and future cancellation (Pitfall 1 mitigated).
- Added 4 inline unit tests covering: fresh flag is false, get-OR-create returns same Arc across lookups, session isolation (T-36.1-06), and `RunningAgentGuard` RAII set/clear.

**Task 2 — `ws.rs` slash interception + plain-text guard (ws.rs):**

- Added cfg-gated imports for `ResolveResult`, `is_bypass`, `AGENT_RUNNING_REJECT_MSG`.
- Inserted slash-interception block in the WebSocket select! loop arm AFTER `let message = req.message;` and BEFORE the existing `tokio::spawn` for `run_web_turn` (D-04).
- Resolution via `app_state.command_router.resolve(&message, &Platform::Web)`; bypass check uses `is_bypass(&def.name)` on canonical post-resolution name (Pitfall 4 — `/reset → "new"` correctly bypasses).
- Non-bypass slash while running → `tx.send(ChatStreamEvent::Delta { text: AGENT_RUNNING_REJECT_MSG.to_string() })` + `Finished { total_tokens: 0 }`, then drain `rx` to the WebSocket sink and `continue` (D-05; no new protocol variant).
- Bypass-listed slash (`stop`/`new`/`status`/`queue`) dispatches via `ironhermes_core::commands::handlers::dispatch` with a minimal `CommandContext`; output sent as Delta + Finished (D-07).
- Plain-text guard check inserted directly after the slash arm, BEFORE `tokio::spawn`: same Delta+Finished delivery (D-06).
- Slash dispatch does NOT set `in_flight_turn = Some(...)` — Pitfall 7 mitigation. Pre-edit baseline grep count: 1; post-edit count: 1 (unchanged).

**Task 3 — Integration test suite (tests/running_agent_guard_web_tests.rs):**

Created a new integration test file with 6 behavior tests + 1 cross-check + 2 source-text anchor tests = 9 tests total. All pass.

Behaviors covered (mirrors Phase 36 gateway suite naming):

2. `test_model_rejected_when_running` (GW-05-WEB-2)
3. `test_stop_bypasses_guard` (GW-05-WEB-3)
4. `test_guard_clears_on_error` (GW-05-WEB-4)

Plus the d02 drift-detection cross-check (`helpers::d02_error_message()` byte-identical to `ironhermes_core::commands::running_agent::AGENT_RUNNING_REJECT_MSG`) and two source-text anchor tests pinning production code in ws.rs and state.rs to the constants the behavior tests model.

## Deviations from Plan

### Deviation 1 — [Rule 3 / Blocking issue] `cargo test --lib` does not work for iron_hermes_ui

**Found during:** Task 1 verification.
**Issue:** The plan's automated verify command was `cargo test -p iron_hermes_ui --lib server::state` but `iron_hermes_ui` is a binary crate with no `[lib]` target — `--lib` errors with "no library targets found".
**Fix:** Ran inline unit tests via `cargo test -p iron_hermes_ui --features server --bin iron_hermes_ui -- phase_36_1_02_state_tests`. The `server` feature is required because the state.rs module is behind `#[cfg(not(target_arch = "wasm32"))]` plus depends on server-side machinery.
**Impact:** Verification path differs from plan wording, but exercises the same tests with the same pass/fail semantics.
**Commit:** de2f38ba (no source change — verification harness only).

### Deviation 2 — [Rule 3 / Blocking issue] Integration test cannot `use iron_hermes_ui::ChatStreamEvent`

**Found during:** Task 3 implementation.
**Issue:** Integration tests in `tests/` cannot import types from a binary crate. The plan's Task 3 action suggested using `iron_hermes_ui` types or an end-to-end harness via `axum::Server`. The existing test patterns in `iron_hermes_ui/tests/` are all source-text assertions (e.g., `websocket_lifecycle_parity.rs`, `session_store_shared_with_gateway.rs`) — none import binary-crate types.
**Fix:** Defined a local `TestStreamEvent` enum mirroring the shape of `ChatStreamEvent` (Delta + Finished variants — the only ones ws.rs emits on the guard path). Behavior tests use the shared library types (`CommandRouter`, `is_bypass`, `RunningAgentGuard`, `AGENT_RUNNING_REJECT_MSG`) which are all importable from `ironhermes-core`. Source-text anchor tests pin production code in ws.rs and state.rs to the same constants the behavior tests model — so drift in production code breaks the anchor tests even though the behavior tests are not calling production code directly.
**Impact:** Test approach differs from plan suggestion but is the established pattern in this crate (verified via `websocket_lifecycle_parity.rs` and `session_store_shared_with_gateway.rs`). All 6 GW-05-WEB behaviors are covered.
**Files modified:** `crates/iron_hermes_ui/tests/running_agent_guard_web_tests.rs`.
**Commit:** 5ffc4127.

## Threat Flags

No new security-relevant surface introduced. The threat register items for this plan were all mitigated:

- **T-36.1-05** (concurrent slash/plain race): mitigated by `RunningAgentGuard` with SeqCst stores + ws.rs plain-text guard rejecting before `run_web_turn`.
- **T-36.1-06** (cross-session flag bleed): mitigated by per-session `HashMap<String, Arc<AtomicBool>>` keyed by `session_id`; covered by `test_session_isolation`.
- **T-36.1-07** (bypass-check on raw input): mitigated by `is_bypass(&def.name)` on the post-resolution canonical name; covered by `test_alias_bypasses_guard`.
- **T-36.1-08** (guard outside async): mitigated by binding `RunningAgentGuard::new(...)` at top of `run_web_turn` async body; covered by `test_guard_clears_on_error`.
- **T-36.1-09** (D-02 reflection): mitigated by using the canonical `AGENT_RUNNING_REJECT_MSG` constant — grep gate enforces zero inline literal in ws.rs.
- **T-36.1-10** (map growth): accepted tradeoff matching `nudge_turns` precedent.
- **T-36.1-SC** (slopsquatting): no new dependencies in this plan; zero risk.
