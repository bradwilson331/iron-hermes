**Notes:** User asked how extraction choice affects multiple simultaneous Telegram/web/TUI clients. ## Web UI interception point

| Option | Description | Selected |
|--------|-------------|----------|
| In ws.rs before run_web_turn | Detect '/' prefix in WebSocket handler, dispatch via CommandRouter. run_web_turn stays pure. | ✓ |
| At top of run_web_turn in state.rs | run_web_turn detects '/' prefix and routes internally. Makes run_web_turn dual-purpose. | |

**User's choice:** In ws.rs before run_web_turn — mirrors gateway's structural split.

**Notes:** Delivery of slash command result: `ChatStreamEvent::Delta + Finished` (no new protocol variant). Per-session running flag storage: `HashMap<String, Arc<AtomicBool>>` on `AppState`, looked up by `session_id`. This mirrors the gateway's `SessionStore.get_running_flag()` pattern.

## Web UI guard scope

| Option | Description | Selected |
|--------|-------------|----------|
| Guard both slash + plain messages | Reject any incoming message (slash or plain) with D-02 when agent_running is true. | ✓ |
| Guard slash commands only | Only check flag for slash commands; plain messages always reach run_web_turn. | |

**User's choice:** Guard both — prevents two concurrent `run_web_turn` calls racing on the same session.

**Notes:** Bypass list = full gateway parity: `stop`, `new`, `status`, `queue`. `/new` is still a stub (`reset_web_session` no-ops) but bypasses the guard so when real reset logic lands, no guard change is needed — same rationale as Phase 36 D-01 for `/queue`.

## TUI persistent flag

| Option | Description | Selected |
|--------|-------------|----------|
| New field on App struct | Add agent_running: Arc<AtomicBool> to App in tui_rata/app.rs. build_command_context reads app.agent_running.clone(). | ✓ |
| Held in event loop, passed down | Flag lives in event_loop.rs, threaded through function signatures. | |

**User's choice:** New field on App struct.

**Notes on pending_rx decoupling:** `pending_rx.is_some()` currently serves double duty (streaming receiver + running signal). Decision: replace entirely with `app.agent_running` in `build_command_context` — `pending_rx` keeps its streaming role only. No cross-check belt-and-suspenders.

**Notes on bypass check location:** Guard check lives in `tui_rata/commands.rs` after `build_command_context` and after command resolution — same position as gateway's `handle_slash_command`. RAII `RunningAgentGuard` wraps the TUI turn entry in the event loop.
