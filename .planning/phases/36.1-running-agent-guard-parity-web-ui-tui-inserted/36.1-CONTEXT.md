## Phase Boundary

Extend the per-session running-agent guard (D-01–D-06 from Phase 36) to two surfaces that Phase 36 left unguarded:

**(A) Web UI** (`iron_hermes_ui/src/server/`): Add per-WebSocket-session `Arc<AtomicBool>` running state to `AppState`, intercept slash commands in `ws.rs` before `run_web_turn`, enforce the D-02 rejection guard for both slash and plain messages while a turn is active, and wire `RunningAgentGuard` at `run_web_turn` entry.

**(B) TUI** (`ironhermes-cli/src/tui_rata/`): Replace the `pending_rx.is_some()` snapshot pattern in `build_command_context` (commands.rs:537) with a persistent `Arc<AtomicBool>` on `App`, wire `RunningAgentGuard` around the TUI turn entry, and add the bypass-list check in `commands.rs` after command resolution.

**(C) Extraction**: Move `RunningAgentGuard` + `is_bypass` from `ironhermes-gateway/src/handler.rs` to `ironhermes-core` so all three surfaces (gateway, web UI, TUI) share one canonical implementation.

**Requirements**: GW-05-WEB (web UI guard parity), GW-05-TUI (TUI guard parity) — phase-local requirements.

**In scope:**

<decisions>
## Implementation Decisions

### Extraction (shared machinery)

- **D-01:** Move `RunningAgentGuard` and `is_bypass` from `ironhermes-gateway/src/handler.rs` (currently private to that module) to `ironhermes-core` — a new module such as `ironhermes-core::running_agent` or added to `ironhermes-core::commands`. Update `ironhermes-gateway` to import from core. Web UI and TUI also import from core. This closes the three-way maintenance hazard (BACKLOG item 3) for gateway + web + TUI; CLI remains the one outlier.

- **D-02:** The shared `is_bypass` function preserves the D-01 bypass list from Phase 36: `stop | new | status | queue`. The TODO comment (`add "approve" | "deny" when approval queue lands`) migrates with the function.

### Web UI — per-session state model

- **D-03:** Add `running_agents: Mutex<HashMap<String, Arc<AtomicBool>>>` to `AppState` in `crates/iron_hermes_ui/src/server/state.rs`. Each session ID maps to its own `Arc<AtomicBool>`. Pattern mirrors `GatewaySession.running` keyed by `SessionKey` in `SessionStore`. `ws.rs` looks up the flag by `session_id` to read the running state; `run_web_turn` receives the same `Arc` to construct the `RunningAgentGuard`.

### Web UI — slash-command interception

- **D-04:** Slash-command interception lives in `ws.rs` **before** the `run_web_turn` call — not inside `run_web_turn`. Detect `/` prefix, build `CommandContext`, resolve and dispatch via `CommandRouter`. `run_web_turn` stays a pure "run an agent turn given user input" function. Mirrors the gateway's structural split (`handle_slash_command` vs `run_agent` are separate paths).

- **D-05:** Slash command dispatch result is delivered back through the WebSocket as `ChatStreamEvent::Delta { text }` followed by `ChatStreamEvent::Finished`. No new protocol variant needed — the web client already handles this sequence.

### Web UI — guard scope

- **D-06:** The running-agent guard applies to **both** slash commands and plain-message submissions. If `agent_running.load()` is true:
  - Slash command + `is_bypass(name)` → dispatch (bypass)
  - Slash command + not bypass → reject with D-02 message: `"Agent is running. Use /stop to interrupt or /queue to send after this turn."`
  - Plain message → reject with same D-02 message
  
  This prevents concurrent `run_web_turn` calls racing on the same session if the user submits a second message before the first turn completes.

- **D-07:** Web UI bypass list = full gateway parity: `stop`, `new`, `status`, `queue`. `/new` is still a stub (`reset_web_session` logs and no-ops) but bypasses the guard so when real reset logic lands, no guard change is needed — consistent with D-01 rationale for `/queue` in Phase 36.

### TUI — persistent flag

- **D-08:** Add `agent_running: Arc<AtomicBool>` as a new field on the `App` struct in `crates/ironhermes-cli/src/tui_rata/app.rs`. `build_command_context` in `commands.rs` reads `app.agent_running.clone()` instead of creating a fresh `Arc::new(AtomicBool::new(app.pending_rx.is_some()))`. The `pending_rx.is_some()` check is **removed entirely** from command context construction — `pending_rx` keeps its streaming role only. Clean separation of concerns.

- **D-09:** Wire `RunningAgentGuard::new(app.agent_running.clone())` at the TUI agent turn entry (the call site in the event loop that initiates `run_agent_turn`). RAII drop clears the flag on turn exit (success, error, or panic path).

- **D-10:** The bypass-list check lives in `tui_rata/commands.rs` **after** `build_command_context` and after command resolution via `CommandRouter`. If `app.agent_running.load()` is true and the resolved command is not on the bypass list, return the D-02 rejection message to the TUI output channel before calling `dispatch()`. Mirrors the gateway's `handle_slash_command` structure.

### Claude's Discretion

- Exact module name for the extracted guard in `ironhermes-core` (`running_agent`, `commands::running_agent`, or added to an existing `commands` module). Planner picks based on what's cleanest given the existing module layout.
- Whether `running_agents` on `AppState` uses `tokio::sync::Mutex` or `std::sync::Mutex` — depends on whether the map is accessed from async contexts only. Planner picks.
- Whether the RAII guard in TUI is created at the event loop level or inside the function that calls `run_agent_turn`. Planner picks cleanest call site.

</decisions>

## Existing Code Insights

### Reusable Assets

- `RunningAgentGuard` (`crates/ironhermes-gateway/src/handler.rs:79–92`): moves to `ironhermes-core` verbatim. No changes to the struct or Drop impl — just a module relocation and import update.
- `is_bypass` (`crates/ironhermes-gateway/src/handler.rs:101–103`): moves to `ironhermes-core` verbatim. The TODO comment for `approve`/`deny` migrates with it.
- `GatewaySession.running` field pattern: the web UI `running_agents` map uses the same `Arc<AtomicBool>` storage and lookup idiom.
- `ChatStreamEvent::Delta + Finished` (web UI WebSocket protocol): already used for agent turn output; slash command results reuse the same event sequence without a new variant.

### Established Patterns

- **RAII guard discipline (D-06 from Phase 36):** `RunningAgentGuard::new(flag)` at function entry, dropped at function exit. Covers `?` early-return paths. Do not use manual `store(true/false)` pairs — the CLI's `main.rs:1707/2024` pattern is the anti-pattern this phase avoids for new surfaces.
- **Guard check after command resolution:** check happens post-`router.resolve()` on the canonical `def.name`, never on raw user input. `/reset` resolves to `"new"` and correctly bypasses. Already enforced in gateway; web UI and TUI must follow the same ordering.
- **`SeqCst` ordering on both store sites:** `RunningAgentGuard::new` and `Drop` both use `Ordering::SeqCst` (Pitfall 3 mitigation from Phase 36 research). Do not downgrade to `Relaxed` or `Acquire/Release`.

### Integration Points

- `ironhermes-core` gains a new public type (`RunningAgentGuard`) and function (`is_bypass`). All three consuming crates (`ironhermes-gateway`, `iron_hermes_ui`, `ironhermes-cli`) add a `use ironhermes_core::...` import.
- `AppState` in `iron_hermes_ui` gains a new field; `ws.rs` gains a flag lookup + slash interception block.
- `App` in `tui_rata` gains a new field; `commands.rs` `build_command_context` is updated; event loop gains a `RunningAgentGuard` binding at turn start.

## Specific Ideas

- The `RunningAgentGuard` sketch from Phase 36 CONTEXT.md `<specifics>` is the exact implementation to move to `ironhermes-core`:
  ```rust
  pub struct RunningAgentGuard(Arc<AtomicBool>);
  impl RunningAgentGuard {
      pub fn new(flag: Arc<AtomicBool>) -> Self {
          flag.store(true, Ordering::SeqCst);
          Self(flag)
      }
  }
  impl Drop for RunningAgentGuard {
      fn drop(&mut self) {
          self.0.store(false, Ordering::SeqCst);
      }
  }
  ```
  Already implemented in gateway at lines 79–92 — move, don't rewrite.

- In `ws.rs`, the slash interception block sits between the `message` variable being populated and the existing `run_web_turn` call at line ~264. Structure:
  ```
  let running_flag = app_state.get_running_flag(&session_id);
  if message.starts_with('/') {
      // resolve + dispatch via CommandRouter
      // deliver result as Delta+Finished

  if running_flag.load(Ordering::SeqCst) {
      // send D-02 rejection as Delta+Finished
  ```

## Deferred Ideas

- **CLI unification**: `main.rs:1707/2024` still uses manual `store(true/false)` around `run_agent_turn`. After this phase, gateway + web UI + TUI all use `RunningAgentGuard`; CLI is the one remaining outlier. Full unification (BACKLOG item 3) is a follow-on cleanup phase.

- **Per-turn LLM cancellation**: `/stop` on all surfaces still only kills subagent processes; it does not cancel an in-flight LLM call on the parent turn. Requires runtime cancellation token plumbing — separate phase.

- **Queue-and-replay UX**: hermes-agent queues messages during an active turn and replays them after. Phase 36.1 (like Phase 36) rejects with D-02. Defer until UX feedback warrants the richer model.

- **`/approve` / `/deny` bypass list additions**: tracked by TODO comment inside `is_bypass` — add when the approval queue lands.

- **`enum AgentState { Idle, Running, Cancelling, Queued }`**: richer state model deferred until per-turn cancel mechanism provides an observer for `Cancelling`.
