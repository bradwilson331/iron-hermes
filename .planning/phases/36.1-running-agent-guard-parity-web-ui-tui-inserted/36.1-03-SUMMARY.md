# Phase 36.1 Plan 03: TUI Running-Agent Guard Parity Summary

One-liner: Persistent `Arc<AtomicBool>` on `App` + RAII `RunningAgentGuard` inside `spawn_turn`'s async block + post-resolution bypass check in `dispatch_slash` — replaces the `pending_rx.is_some()` snapshot anti-pattern and brings the TUI to feature parity with the gateway's guard discipline.

## What Was Built

### Task 1: App.agent_running field + build_command_context replacement + bypass check

**app.rs:** Added `pub agent_running: Arc<AtomicBool>` to the `App` struct in the same field cluster as `yolo_enabled`/`verbose_enabled`/etc. (lines 202-209). Initialized to `Arc::new(AtomicBool::new(false))` in `App::new`. The `pending_rx` field is preserved — only its `.is_some()` proxy use in `build_command_context` is gone.

**commands.rs:** Two changes:
1. Replaced `Arc::new(AtomicBool::new(app.pending_rx.is_some()))` at line ~537 with `app.agent_running.clone()` — live handle, not a disconnected snapshot (D-08, Pitfall 4 removed).
2. Inserted bypass-list guard check in `dispatch_slash` after `CommandRouter::resolve()` returns `ResolveResult::Exact|PrefixMatch(def)` and after `build_command_context(app)`, before `invoke_handler`. Uses `is_bypass(def.name)` on the canonical post-resolution name (D-10, Pitfall 4 mitigation). Returns `SlashOutcome::Handled(AGENT_RUNNING_REJECT_MSG.to_string())` — explicit form (no `From<String>` impl exists).

### Task 2: RunningAgentGuard inside tokio::spawn async block

**event_loop.rs:** Modified `spawn_turn`:
- `let agent_running = app.agent_running.clone();` added in the SYNC body (before `tokio::spawn`) so the Arc can be moved into the async closure.
- `let _agent_guard = RunningAgentGuard::new(agent_running);` is the FIRST statement INSIDE the `tokio::spawn(async move { ... })` block — before `tx.send(StreamEvent::Started)`.
- Guard covers `runtime.run_turn(request).await` and drops on all exit paths (Ok/Err/cancel/panic).
- Pitfall 1 mitigation: binding outside the async block would drop the guard when `spawn_turn` returns synchronously (immediately after `tokio::spawn`), before the turn runs.

### Task 3: Integration test suite

**tests/running_agent_guard_tui_tests.rs** (237 lines, created new):
- `d02_constant_matches_helper`: `helpers::d02_error_message()` byte-matches `AGENT_RUNNING_REJECT_MSG`
- `test_agent_running_is_live_arc` (GW-05-TUI-1): proves all Arc clones share storage — a store via any clone is visible via all others
- `test_guard_clears_on_turn_end` (GW-05-TUI-2): spawns a tokio task that binds `RunningAgentGuard`, awaits completion, asserts flag is false after join
- `test_model_rejected_when_running` (GW-05-TUI-3): `CommandRouter::resolve("/model gpt-4")` + `is_bypass("model") == false` — the rejection path is taken
- `test_stop_bypasses_guard` (GW-05-TUI-4): `is_bypass("stop") == true` — bypass path taken, not rejected
- `test_alias_reset_bypasses_guard` (GW-05-TUI-5): `/reset` → `def.name == "new"` via alias resolution; `is_bypass("new") == true` — Pitfall 4 end-to-end proof

## Deviations from Plan

None — plan executed exactly as written.

The only noteworthy implementation choice: `use ironhermes_core::commands::running_agent::RunningAgentGuard;` was placed inside the `fn spawn_turn` body (as a `use` statement at the top of the function) rather than at the top of the file, keeping it co-located with the only call site. This is stylistically consistent with the existing guard-check imports in `dispatch_slash` which use a top-of-file `use` for the same module. Both approaches are valid; the per-function `use` is slightly more self-documenting for the Pitfall 1 constraint.
