<objective>
Close BUG-36.3.7.1-02 by wiring `apply_circuit_breaker` into the `enforce_max_runtime` path
in `crates/ironhermes-kanban/src/dispatcher.rs`. The path currently bumps `consecutive_failures`
(lines 557-564) and appends a `TimedOut` event (lines 566-581) but never invokes the breaker —
same structural shape as the BUG-36.3.7-03 gap that 36.3.7.0-03 closed on
`detect_crashed_workers`. Plus partially land BUG-36.3.7.1-03 by adding the two receiver-end
tests covering both sides of the `failure_limit` bound on this path.

Purpose: make the `failure_limit` config knob behave per operator intuition on the
max-runtime-exceeded path. A task whose worker ran past its `max_runtime_seconds` budget
(and was SIGTERM'd / SIGKILL'd by the dispatcher) should be blocked on the SAME tick that
bumps `consecutive_failures` to the limit, not one tick later via the spawn-failure breaker.

Output: a single ~6 LOC insertion in `enforce_max_runtime` + a 4-line inline comment marker
+ 2 new `#[tokio::test]` functions in `tests/dispatcher_logic.rs`.

Note on slow tests: `enforce_max_runtime` calls `tokio::time::sleep(Duration::from_secs(5)).await`
at line 530 as a SIGTERM grace period. The new tests inherit this 5-second wait per tick.
This is acceptable (the crashed-path tests run sub-second; these will run ~6 seconds each)
and matches the production behavior. Do NOT short-circuit the sleep — the production code
path is the test surface.
</objective>
