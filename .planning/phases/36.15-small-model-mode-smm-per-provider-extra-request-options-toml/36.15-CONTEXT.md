# Phase 36.15: Small Model Mode (SMM) — per-provider extra_request_options TOML knob - Context

**Gathered:** 2026-05-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a per-provider (with optional per-model override) TOML configuration knob — `extra_request_options` — whose values flow through `AgentRuntime` into `ChatRequest.extra` on every LLM call, so that provider-specific request body fields (Ollama `num_ctx`, vLLM `top_k`, OpenRouter `provider.order`) can be tuned at runtime without code changes. This also closes the Ollama `exceed_context_size_error` fallback path by making `num_ctx` operator-configurable; the existing PROV-07 fallback chain handles the error case from there.

**Scope is the knob and its wiring** — TOML schema, config struct, AgentRuntime resolution, plumbing through `LlmClient::chat_completion` / `chat_completion_stream`. The full Small Model Mode architecture port (governor, router, escalation, plan tracker, etc.) is Phase 36.16; this phase delivers one input that 36.16 will consume.

</domain>

<decisions>
## Implementation Decisions

### TOML Schema Shape (D-01..D-04)
- **D-01:** Strongly-typed per-provider extras structs. Define `OllamaExtraOptions { num_ctx, num_predict, top_k, ... }`, `OpenRouterExtraOptions { provider: ProviderRouting { order, ignore, ... } }`, `VllmExtraOptions { top_k, top_p, ... }`. Each struct lives next to or inside `ProviderConfig` in `crates/ironhermes-core/src/config.rs`. Adding a new tunable field requires code (a struct field addition); changing the *value* of a known field is pure TOML.
- **D-02:** Schema location: extend `ProviderConfig` (in `crates/ironhermes-core/src/config.rs:196`) with `extra_request_options: Option<ProviderExtraOptions>` where `ProviderExtraOptions` is an enum or untagged variant keyed by provider type. Models live under a sibling `models: HashMap<String, ProviderModelConfig>` map where `ProviderModelConfig` holds its own optional `extra_request_options`.
- **D-03:** Per-provider + per-model with per-key merge — per-model overrides win per-key, missing per-model keys fall back to the per-provider default, no per-model section means provider-wide default applies as-is. Example shape locked:

  ```toml
  [providers.ollama.extra_request_options]
  num_ctx = 8192      # default for all ollama models

  [providers.ollama.models."llama3.1:8b".extra_request_options]
  num_ctx = 32768     # override just this model

  [providers.ollama.models."llama3.1:70b".extra_request_options]
  num_ctx = 4096
  ```
- **D-04:** Serialization: typed structs serialize to `HashMap<String, serde_json::Value>` (the existing `ChatRequest.extra` shape) at the AgentRuntime layer, immediately before the call into `LlmClient`. Nested values (e.g., OpenRouter's `provider: { order: [...] }`) survive the round-trip via `serde_json::to_value`.

### Request Paths Wired (D-05..D-07)
- **D-05:** **In scope** — OpenAI-compatible path only: thread merged extras into `LlmClient::chat_completion(extra)` (`crates/ironhermes-agent/src/client.rs:151`) and `LlmClient::chat_completion_stream(extra)` (`crates/ironhermes-agent/src/client.rs:215`) via the two `AgentRuntime` call sites `call_llm` (`agent_loop.rs:1757`) and `call_llm_streaming` (`agent_loop.rs:1790`), which currently pass `None`.
- **D-06:** **Out of scope (deferred)** — OpenRouter Claude cache path (`build_openrouter_chat_request_full` in `crates/ironhermes-agent/src/any_client.rs:546`, which has its own `extra` parameter) and the native AnthropicClient (`crates/ironhermes-agent/src/anthropic_client.rs:877`, where `_extra` is currently ignored). These paths can be wired in 36.16 or a follow-up; today's phase does not modify them.
- **D-07:** Coverage of provider types in scope: Ollama, vLLM, OpenRouter (non-Claude routes), and any other OpenAI-compatible provider. OpenRouter Claude (which routes through the cache_control builder when `prompt_caching.enabled = true`) is intentionally NOT covered by this phase even though OpenRouter is — `provider.order` set in TOML will apply to OpenRouter non-Claude routes and to Claude routes whenever `prompt_caching.enabled = false`. Acceptable per-D-06.

### Ollama `exceed_context_size_error` Closure (D-08)
- **D-08:** Static knob only — no dynamic retry, no automatic `num_ctx` doubling. The operator sets `num_ctx` to a value adequate for their workload; if Ollama still errors with `exceed_context_size_error`, the existing PROV-07 fallback chain (extended in Phases 27.1.4.1, 27.1.4.1.1, and 36.14) takes over and routes to the next configured provider. "Closes the fallback path" in this phase means: it is now *possible* to configure `num_ctx` at all, which it was not before — not that the agent dynamically adapts on the error.

### Merge Precedence (D-09)
- **D-09:** Caller wins per-key (`caller » config`). When `AgentRuntime` calls `chat_completion(extra)` / `chat_completion_stream(extra)` with a `Some(map)`, any key the caller has set takes precedence; config-supplied keys fill only the keys the caller did not set. This matches the existing `or_insert_with` pattern in `chat_completion_stream` at `client.rs:236` for `stream_options.include_usage`. Specifically, this means: (a) tests that override `extra` are not silently overwritten by operator config, (b) the auto-injected `stream_options.include_usage: true` remains the floor when neither side specifies it. Shallow merge only — no recursive deep merge of nested objects (deferred as future work if needed).

### Resolution Site (D-10)
- **D-10:** Per-call in `AgentRuntime`. On every turn `AgentRuntime` resolves `(provider, current_model) → merged_extra` and passes the resulting `HashMap<String, serde_json::Value>` into `call_llm` / `call_llm_streaming` (which forward to `chat_completion{,_stream}(extra)`). This means a mid-session `/model` slash-command switch picks up the new model's per-model override on the very next turn, no client rebuild required. Plumbing change: `call_llm` and `call_llm_streaming` signatures gain a way to receive (or look up) merged extras — researcher/planner picks the exact shape (extra threaded as a parameter vs read off `self.runtime_config`).

### Claude's Discretion
- Researcher chooses how `ProviderExtraOptions` is enum'd or trait-objected (untagged enum vs `Option<serde_json::Value>` + provider-type dispatch). The acceptance criterion is: typed at the config layer, `HashMap<String, serde_json::Value>` at the wire boundary.
- Researcher chooses exact merge implementation (build the caller map first, then `.entry().or_insert()` each config key — or the inverse). Functional contract is "caller wins per key".
- Researcher chooses how `AgentRuntime` reaches the resolved `ProviderConfig` (it already does for `provider_name`; the same accessor likely works). No new global state.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `ChatRequest.extra: HashMap<String, serde_json::Value>` with `#[serde(flatten)]` already exists in `crates/ironhermes-core/src/types.rs:135` — the target sink; zero changes needed to that struct.
- `LlmClient::chat_completion` and `chat_completion_stream` already accept `extra: Option<HashMap<...>>` (`crates/ironhermes-agent/src/client.rs:144`, `:208`). The phase work is to *populate* this parameter at the AgentRuntime layer; the receiving signature is ready.
- `ProviderConfig` (`crates/ironhermes-core/src/config.rs:196`) is the home of per-provider configuration with `default_model`, `enabled`, `fallback_providers`, etc. Adding `extra_request_options` + `models` here keeps configuration discoverability consistent.
- `chat_completion_stream` already auto-injects `stream_options.include_usage: true` via `.entry(...).or_insert_with(...)` at `crates/ironhermes-agent/src/client.rs:236`. This is the precedent for caller-wins merge semantics (D-09).

### Established Patterns
- **Provider-name + model lookup pattern** — `AgentRuntime` already knows `provider_name` (used in `is_openrouter_claude` checks at `client.rs:249`) and routes per-model logic. New extras resolution follows the same shape.
- **Config validation at resolver build** — `ProviderResolver::build()` validates env var names and other invariants; extras validation (if any) hooks the same path.
- **Typed config + `serde_json::Value` at wire boundary** — the project already mixes strict typing inside config with permissive JSON at the LLM wire (see `PromptCachingConfig` flowing into `cache_control` markers). 36.15 follows the same boundary placement.

### Integration Points
- `AgentRuntime::run_turn` (the per-turn entry point) is where merged extras get resolved each turn — the current_model and provider_name are already in scope there.
- `LlmClient::from_config` is where provider+model context is bound to the client; extras do NOT live on the client per D-10, only on the per-call argument.
- `OpenRouterChatRequest` (`any_client.rs:479`) has a parallel `extra: HashMap<String, serde_json::Value>` with `#[serde(flatten)]` and accepts it via `build_openrouter_chat_request_full(..., extra: HashMap)`. Per D-06 this path is NOT wired in 36.15, but the symmetry is there for a future follow-up.

<specifics>
## Specific Ideas

- The canonical examples named in the roadmap are the locked acceptance set: Ollama `num_ctx`, vLLM `top_k`, OpenRouter `provider.order = ["anthropic", "openai", ...]`. The phase is "done" when all three can be set via TOML and observed on the wire (request body assertion in tests) without code changes.
- Per-model override example is the canonical Ollama case: same provider, different model, different `num_ctx`. The `llama3.1:8b → 32k`, `llama3.1:70b → 4k` shape from the schema preview is the lived motivation — keep that as a test case.
- The streaming auto-inject of `stream_options.include_usage: true` (`client.rs:236`) is a load-bearing invariant from 36.2 Plan 07 — preserve its semantics under the merge rule (D-09: caller's `false`, if set, wins; otherwise floor remains `true`).

</specifics>

<deferred>
## Deferred Ideas

- **OpenRouter Claude cache path wiring** — `build_openrouter_chat_request_full` already accepts an `extra` HashMap; threading TOML extras through this path so `provider.order` works under `prompt_caching.enabled = true` is a natural follow-up. Out of scope per D-06.
- **Native AnthropicClient wiring** — `anthropic_client.rs:877` has `_extra: Option<HashMap<...>>` (underscore = currently ignored). Wiring this would require translating OpenAI-shaped keys to Anthropic's native body fields (e.g., `top_k` is top-level on the Messages API). Defer to 36.16 or later.
- **Dynamic `num_ctx` retry on `exceed_context_size_error`** — automatically doubling `num_ctx` and retrying the same provider before falling back. Considered and deferred per D-08; could live in 36.16's escalation logic.
- **Deep merge of nested objects** — recursive merge of nested values like `provider: {...}` from both config and caller. Considered and deferred per D-09; shallow caller-wins is sufficient for the in-scope cases.
- **Allowlist validation / soft-warn on unknown keys** — considered and rejected in favor of strongly-typed structs (D-01). Typed structs make unknown keys a compile error or `serde` deserialization error, which is stricter than a warn.
- **Full Small Model Mode architecture port** — governor, model router, escalation engine, plan tracker, compiled MarrowScript adapters, plugin loader. That is Phase 36.16's entire scope; 36.15 only delivers the per-provider extras knob that 36.16 will consume as one input.

</deferred>
