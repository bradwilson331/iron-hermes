Lock the four behavioral invariants that distinguish "PROV-11 wired" from "PROV-11 wired correctly" — all in `crates/ironhermes-agent/tests/extra_request_options.rs` (the same file as Plan 04 Task 3; this plan APPENDS, no other file is touched).

The invariants:
1. **D-09 caller-wins per-key.** When both caller and config supply the same key, the caller's value lands on the wire. Asserted by passing `extra` directly to `chat_completion` with a key that would also be supplied by config — the direct caller pass IS the "caller" half of D-09.
2. **D-09 stream_options floor preserved.** With NO `stream_options` in `extra` (and no config extras), the wire body for `chat_completion_stream` still contains `stream_options.include_usage: true` (the `or_insert_with` floor at `client.rs:236`). This guards against accidental removal of the floor when Plan 04 changed the surrounding code.
3. **Reserved-key collision: named fields win.** When `extra` contains the key `model` (a reserved ChatRequest field), the wire body's top-level `model` is the ChatRequest's actual model string, not the extras-provided value. RESEARCH §Security Domain notes this as ASSUMED serde behavior; this test verifies it.
4. **D-10 mid-session model switch.** Two sequential calls to `config_extras::resolve_extras` with different `model_name` arguments against the same `providers` HashMap return per-model overrides correctly — simulates `/model` switch picking up new per-model extras on the next turn. This is a unit-level assertion (no wiremock needed); it specifically exercises the resolution helper from Plan 02, NOT AgentRuntime as a whole.
