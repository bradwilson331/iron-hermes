## AgentLoop Wiring Approach

The builder-field pattern was chosen per RESEARCH Open Question 2:

- `resolved_extras: Option<HashMap<String, serde_json::Value>>` added to `AgentLoop` struct immediately after `provider_name` (Phase 36.2 field cluster)
- Initialized to `None` in `AgentLoop::new()` — backward-compatible with all existing call sites
- `pub fn with_resolved_extras(mut self, extras: Option<HashMap<...>>) -> Self` builder mirrors `with_provider_name` shape exactly (three lines + brace)
- `call_llm` (line ~1764): `None` → `self.resolved_extras.clone()`
- `call_llm_streaming` (line ~1797): `None` → `self.resolved_extras.clone()`

This avoids touching the 4+ internal `call_llm`/`call_llm_streaming` call sites inside `run()` (Pitfall 6 mitigation from PATTERNS.md).

## Per-Turn Resolution (D-10)

In `run_turn`, immediately after `context_length` resolution:

```rust
let resolved_extras_for_turn = {
    let provider_name = self.resolver.main_provider();
    let model_name = self.resolver.resolve_for_main().default_model.clone();
    let merged = ironhermes_core::config_extras::resolve_extras(
        &self.config.providers, provider_name, &model_name,
    );
    if merged.is_empty() { None } else { Some(merged) }
};
```

Then in the AgentLoop builder chain (after `with_provider_name`):
```rust
agent = agent.with_resolved_extras(resolved_extras_for_turn);
```

No caching across turns — each call to `run_turn` re-resolves so a mid-session `/model` switch picks up the new per-model override on the very next turn.
