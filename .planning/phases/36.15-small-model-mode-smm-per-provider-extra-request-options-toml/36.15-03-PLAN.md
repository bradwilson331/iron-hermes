<objective>
Make the new extras keys discoverable via the `hermes config` CLI surface by appending `ConfigField` entries to the static `schema()` Vec in `crates/ironhermes-core/src/config_schema.rs`. This is the only file modified in this plan, runs in parallel with Plan 02 (Wave 1), and depends only on Plan 01 (for the REQUIREMENTS.md PROV-13 row).

Purpose: `hermes config set providers.ollama.extra_request_options.num_ctx 32768` must validate against the schema, and `hermes config show` must list these keys with descriptions. Per RESEARCH §Pattern 7, these will be the FIRST `providers.*` entries in the schema — there's no existing pattern to follow inside the file for this prefix, just the generic `ConfigField` shape.

Output: Appended `ConfigField` entries for the six canonical extras keys, plus a schema-contains test asserting they are present.

Per-model variants (e.g. `providers.ollama.models.<model>.extra_request_options.num_ctx`) are NOT enumerated in the schema — they would explode the static Vec into a wildcard pattern unsupported by today's exact-match validator. Operators set per-model overrides directly in YAML; the schema covers only the provider-level keys per RESEARCH §Open Question 3.
</objective>
