## TOML Schema Shape

| Option | Description | Selected |
|--------|-------------|----------|
| Pure passthrough, nested TOML → nested JSON | `[providers.openrouter.extra_request_options]` with arbitrary keys. No allowlist. Simple, future-proof, but typos are silent. | |
| Passthrough + soft warn on unknown keys | Same shape, with a per-provider-type allowlist that emits `tracing::warn` for unknown keys. No hard fail. | |
| Strongly-typed per provider | Dedicated structs: `OllamaExtraOptions`, `OpenRouterExtraOptions`, `VllmExtraOptions`. Type-safe; new fields require code change. | ✓ |

**User's choice:** Strongly-typed per provider.
**Notes:** "No code changes" in the roadmap line refers to tuning *values* of known fields. Adding a brand-new tunable is a code change (struct field), accepted in exchange for type safety on the locked acceptance set (`num_ctx`, `top_k`, `provider.order`).

## Per-Model Overrides

| Option | Description | Selected |
|--------|-------------|----------|
| Per-provider only | `[providers.ollama.extra_request_options]` only. Operator picks a conservative provider-wide default. Simplest. | |
| Per-provider + per-model with merge | Per-model wins per-key over per-provider; missing keys fall back. Matches Ollama 8B-vs-70B `num_ctx` tuning reality. | ✓ |
| Per-model only | Force every model to be named. Verbose. | |

**User's choice:** Per-provider + per-model with merge.
**Notes:** Preview shape locked: `[providers.ollama.models."llama3.1:8b".extra_request_options]` etc. The 8B/70B/4096-vs-32768 example is the canonical test case.

## Ollama `exceed_context_size_error` Closure Mechanic

| Option | Description | Selected |
|--------|-------------|----------|
| Static knob only — operator sets num_ctx, error stops happening | No dynamic retry. Existing PROV-07 fallback chain handles residual errors. | ✓ |
| Static knob + classify the error so fallback fires reliably | Above, plus extending `classify_400_subcases` to recognize Ollama's specific error shape. | |
| Static knob + dynamic num_ctx retry on the error | Auto-bump num_ctx and retry the same provider. | |

**User's choice:** Static knob only.
**Notes:** "Closes the fallback path" in 36.15 means: configuring `num_ctx` is now possible at all, which it was not before. Anything dynamic belongs to 36.16's escalation logic, not here.

## Merge Precedence

| Option | Description | Selected |
|--------|-------------|----------|
| Caller wins (caller » config) | Caller's `extra` takes precedence per-key; config fills gaps. Matches existing `or_insert` behavior in `chat_completion_stream`. | ✓ |
| Config wins (config » caller) | Config silently overrides callers. Anti-pattern for tests. | |
| Deep merge for nested objects, caller wins on scalars | Recursive merge for `stream_options`/`provider` objects; caller wins on scalars. More forgiving, more code. | |

**User's choice:** Caller wins (caller » config).
**Notes:** Specifically protects the auto-injected `stream_options.include_usage: true` floor and any test-supplied overrides from being silently clobbered by operator config. Shallow merge only.

## Resolution Site

| Option | Description | Selected |
|--------|-------------|----------|
| Per-call in AgentRuntime | Resolve `(provider, current_model) → merged_extra` every turn. `/model` switch picks up new overrides immediately. | ✓ |
| Per-client at LlmClient build time | `from_config` resolves once. Less plumbing, but model-switch lag until rebuild. | |
| Hybrid: client holds provider-default, AgentRuntime layers per-model on top | Splits work between client and runtime. | |

**User's choice:** Per-call in AgentRuntime.
**Notes:** Slash-command `/model` mid-session is a real use case for ironhermes; per-call resolution is the only semantic that respects it without a client rebuild.

- Dynamic `num_ctx` retry on `exceed_context_size_error`.
- Deep merge of nested objects (currently shallow caller-wins).
- Allowlist validation / soft-warn on unknown keys (rejected in favor of strongly-typed structs).
- Full Small Model Mode architecture port (entire Phase 36.16 scope).
