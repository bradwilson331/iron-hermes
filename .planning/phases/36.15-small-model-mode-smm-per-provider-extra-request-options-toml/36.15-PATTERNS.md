**Merge helper — `serde_json::to_value` + `as_object` conversion pattern** (research Pattern 4):
```rust
pub fn resolve_extras(
    providers: &HashMap<String, crate::config::ProviderConfig>,
    provider_name: &str,
    model_name: &str,
) -> HashMap<String, serde_json::Value> {
    let provider_cfg = providers.get(provider_name);

    let provider_extras: HashMap<String, serde_json::Value> = provider_cfg
        .and_then(|p| p.extra_request_options.as_ref())
        .and_then(|e| serde_json::to_value(e).ok())
        .and_then(|v| v.as_object().cloned())
        .map(|m| m.into_iter().collect())
        .unwrap_or_default();

    let model_extras: HashMap<String, serde_json::Value> = provider_cfg
        .and_then(|p| p.models.get(model_name))
        .and_then(|m| m.extra_request_options.as_ref())
        .and_then(|e| serde_json::to_value(e).ok())
        .and_then(|v| v.as_object().cloned())
        .map(|m| m.into_iter().collect())
        .unwrap_or_default();

    // D-03: per-model wins per-key (insert overwrites)
    let mut merged = provider_extras;
    for (k, v) in model_extras {
        merged.insert(k, v);
    }
    merged
}
```

**Note on untagged enum + serde_yaml (Pitfall 1):** The RESEARCH flags a real risk that `#[serde(untagged)]` with all-optional fields may match the wrong variant when deserialized via `serde_yaml`. The safer fallback is `Option<HashMap<String, serde_json::Value>>` directly on `ProviderConfig` (deviating from D-01). Planner must decide which approach to use and document the wave-0 roundtrip test that validates the decision before any other tasks.
