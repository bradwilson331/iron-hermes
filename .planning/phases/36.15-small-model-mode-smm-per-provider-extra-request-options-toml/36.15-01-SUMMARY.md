### Rust Doc Comment Placement (Diagnostic)

- **Found during:** Task 3 (initial module attempt)
- **Issue:** Placing a `//!` inner doc comment at file scope (between two top-level items, after `mod tests { }`) causes the Rust compiler to silently skip the module that follows when compiled via `lib.rs`. The `#[cfg(test)] mod extras_canary` module was present in the file but never compiled.
- **Fix:** Moved the `//!` comment INSIDE the module block (as the first item inside `mod extras_canary { ... }`), which is the correct Rust syntax for inner doc comments on a module.
