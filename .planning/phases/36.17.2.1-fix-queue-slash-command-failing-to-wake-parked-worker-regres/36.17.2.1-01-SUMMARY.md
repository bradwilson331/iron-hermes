# Phase 36.17.2.1 Plan 01: Wire UQM into Handler's /queue Path Summary

## One-liner

Fix the /queue regression by routing handler's `CoreCommandResult::Queued` arm through `UQM::dispatch` (which calls `notify_one()` at user_queue.rs:154) instead of the wake-less direct `session_queue.try_push` — closes UAT-observed 128/129 stranded-message bug from parent phase 36.17.2.

## What Was Built

### Task 1 — handler.rs changes (commit `1b4c8976`)

**Imports** (handler.rs:35):
```rust
use crate::user_queue::{DispatchOutcome, UserQueueManager};
```

**New field** on `GatewayMessageHandler` (handler.rs:169):
```rust
user_queue_manager: Option<Arc<UserQueueManager>>,
```
Default-initialized to `None` in `::new()` — handlers built outside `GatewayRunner::run_gateway` fall through to the D-20 legacy direct-try_push path (preserved for `session_queue_integration.rs` harness + Phase 36 GW-05 tests).

**New setter** (handler.rs:356):
```rust
pub fn set_user_queue_manager(&mut self, uqm: Arc<UserQueueManager>) {
    self.user_queue_manager = Some(uqm);
}
```

**Rewritten `CoreCommandResult::Queued` arm body** (handler.rs:850–977):
Three-branch dispatch:
1. **UQM wired (production path)** — call `uqm.dispatch(queued_event, None, None).await`.
   - `Ok(outcome)`: compute `depth = session_queue.len(&session_key)` (unwrap_or(1) — unreachable in production), send byte-identical depth-aware reply ("Queued for the next turn." or "Queued for the next turn. (N queued)"), emit debug log. If outcome is `WorkerSpawned`, emit `tracing::warn` documenting the D-06 fresh-chat scope boundary.
   - `Err(QueueError::CapacityReached)`: UQM::dispatch already fired the ❌ reaction + "⏳ Queue is full" reply (D-11 inherited). Handler emits warn-log only — NO `adapter.send_message` (T-36.17.2.1-01 double-reply mitigation).
2. **SessionQueue wired but no UQM (D-20 legacy fallback)** — original direct-try_push path preserved verbatim. Used by `session_queue_integration.rs` harness which constructs handlers via `::new()` + `set_session_queue` without ever wiring UQM.
3. **Neither wired (degraded-degraded)** — best-effort depth-1 reply.

### Task 2 — runner.rs changes (commit `ab4b19be`)

**Reordered** `GatewayRunner::run_gateway` lines 692-712 so:
- `UserQueueManager::new(...)` is constructed FIRST (line 703).
- `let mut handler = self.build_gateway_handler();` (line 707) — owned, mutable.
- `handler.set_user_queue_manager(user_queue.clone())` (line 711) — installs the same Arc the dispatch loop uses.
- `let handler = Arc::new(handler);` (line 712) — Arc-wrap LAST.

The downstream `let user_queue_dispatch = user_queue.clone();` at line 871 is unchanged — both Arc clones reference the same UQM (same workers map, same pending_multimodal sidecar, same SessionQueue handle).

## How It Fixes The Bug

**Pre-fix flow (broken)**: `/queue text` → fast-path in runner.rs:935 → `handler.handle_with_multimodal` → `CoreCommandResult::Queued` arm → `self.session_queue.try_push(...)` → push succeeds, **no notify_one()**, worker stays parked at `notify_task.notified()` (runner.rs:1045).

**Post-fix flow**: `/queue text` → fast-path → handler → `Queued` arm → `uqm.dispatch(queued_event, None, None).await` → UQM internal flow:
1. `session_queue.try_push` (same Arc — D-20 invariant — D-14 SessionKey triple).
2. `push_multimodal((None, None))` (sidecar lockstep — text-only, observably identical to None per RESEARCH Pitfall 4).
3. Acquire `workers` mutex, look up `Notify` for this `SessionKey`, drop lock, call `notify.notify_one()` (user_queue.rs:154 — **the wake primitive**).
4. Return `Ok(DispatchOutcome::Accepted)`.

Worker unparks → pops the synthesized event → emits 👀 → processes as the next free-text turn.
