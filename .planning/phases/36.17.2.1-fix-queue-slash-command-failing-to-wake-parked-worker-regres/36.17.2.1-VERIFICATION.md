# Phase 36.17.2.1: Fix `/queue` Slash-Command Failing to Wake Parked Worker — Verification Report

**Phase Goal:** Close the production regression introduced by Phase 36.17.2's mpsc→Notify worker rewrite where `/queue <text>` typed during a busy turn pushed onto `SessionQueue` but the per-chat worker stayed parked on `notify.notified().await`, because `handler.rs`'s `CoreCommandResult::Queued` arm called `session_queue.try_push` directly without `notify_one()`. After fix: a `/queue` typed against a parked worker pushes via `UQM::dispatch` → `notify_one()` wakes the worker → worker pops, emits 👀, and processes the synthesized event as the next turn.
