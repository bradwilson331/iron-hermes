4. Dispatch 1 free-text event (`free_1` / `"initial free-text body"` / `u_qw`) via `uqm.dispatch(..., None, None).await` — must return `WorkerSpawned`.
5. `spawn_test_worker(...)` — worker pops `free_1`, emits 👀, calls `handle_with_multimodal` which fast-exits at the placeholder `send_message`, then loops back to `notify.notified().await` (parks).
6. Poll `send_log.len() >= 1` with 5s timeout — proves worker drained `free_1` and parked.
7. Assert `session_queue.len(&session_key) == 0`. Capture `send_log_baseline`.
8. Loop `i in 1..=5`: dispatch `make_event_full("chat_qw", "q_{i}", "/queue body_{i}", "u_qw")` via **`handler.handle_with_multimodal(...)` directly** — the EXACT runner.rs fast-path code path that was broken.
9. Poll 👀-count on `(chat_id == "chat_qw" AND message_id starts_with "q_" AND emoji == "👀")` until `>= 5`, 5s timeout. On timeout: panic with **REGRESSION SIGNAL** diagnostic including current 👀 count, `session_queue.len`, `send_log.len`, full send_log, full reactions, and explicit pointer to `handler.rs` `CoreCommandResult::Queued` arm + the expected `uqm.dispatch(queued_event, None, None).await` call.
10. `cancel.cancel(); let _ = worker.await;`
11. **Assertion (A):** each `q_1..q_5` got exactly one 👀 reaction on `chat_qw`.
12. **Assertion (B):** FIFO ordering of the 5 new 👀 reactions on synthesized message_ids (uses the same pattern as the parent `test_5_same_chat_messages_emit_5_eye_reactions_and_fifo_order_through_handler` at line 444-454).
13. **Assertion (C):** `session_queue.len(&session_key) == 0`.
14. **Assertion (D):** `send_log_final >= send_log_baseline + 5`.

## Deviations from Plan

### Rule 1 — Bug auto-fix: ProcessedAttachments::clone

**Found during:** First compile of the new test (Task 1, Step 4).

**Issue:** Initial implementation hoisted `let processed = ProcessedAttachments { ... };` outside the `for i in 1..=5` loop and called `processed.clone()` inside the loop. This failed compilation with `error[E0599]: no method named 'clone' found for struct 'ProcessedAttachments'`.

**Root cause:** `ironhermes_gateway::multimodal::ProcessedAttachments` does not derive `Clone`.

**Fix:** Moved the `ProcessedAttachments` construction inside the loop body. Each iteration builds a fresh `ProcessedAttachments { text_prefix: None, image_data_uri: None }`. Behavior is observably identical to a clone because both fields are always `None` for the text-only `/queue` path.

**Files modified:** `crates/ironhermes-gateway/tests/uqm_session_queue_unification.rs` (in the same commit `c0e088a9`).

**Why this is Rule 1 (auto-fix) and not Rule 4 (architectural):** Local test-file correctness only. Did not modify the upstream `ProcessedAttachments` struct or its derive macros — the parent phase 36.17.2 Plan 01 explicitly designed it as non-Clone, and the test does not need that to change.
