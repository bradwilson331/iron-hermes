## What this phase fixed

The pre-existing static-grep test
`crates/ironhermes-cli/tests/invariants_26_4_1_cfg_03.rs::phase_amendment_doc_comment_present`
was failing because Phase 36.3.7.0 commit `c453411f` legitimately added an 11-line
BUG-36.3.7-04 comment block between the original `Phase 26.4.1 (CFG-03) AMENDMENT:`
doc-comment at `main.rs:384` and the `let run_preflight = matches!(` binding at line 415.
That comment block pushed the original CFG-03 marker ~200 chars OUTSIDE the test's
1500-char scan window — the marker still existed in the file, the runtime behavior was
correct, but the static-grep regression-lock no longer found the marker.

This was a unilateral-verification miss: Phase 36.3.7.0 Plan 05 changed the producer
(file layout near the gate) without auditing the consumer (the static-grep test).
The verifier-after-the-fact for Phase 36.3.7.2 caught it as a forward-flag note.

   existing 384-399 doc-comment block (which would re-order chronological
   documentation) or deleting Phase 36.3.7.0's BUG-36.3.7-04 block (operator-facing,
   correct).

   class of "marker pushed out of window" regressions.

   playbook as Phase 36.3.7.0 Plan 05. Avoids the cwd-drift class of bug that
   Phase 36.3.7.1 hit with parallel worktree executors.

## Forward notes

1. **Hardened CFG-03 invariant family.** Future phases that rewrite comments near
   the `run_preflight` gate in `main.rs` no longer need to audit the static-grep
   tests — INV-03 anchors on function scope, not byte position. The locked-in
   semantic ("CFG-03 amendment is documented inside the function that contains
   the gate") is now codified instead of approximated.

2. **Generalization opportunity (out of scope here).** The same scope-anchor pattern
   could be backported to sibling Phase 22.4 / Phase 23 / Phase 24 static-grep
   tests (`tests/invariants_22_4.rs`, etc.) if they exhibit the same byte-window
   brittleness. Not folded into this phase — separate hardening initiative if
   value emerges.

3. **Meta-lesson reinforced.** The bilateral-tracing rule (LEARNINGS 2026-05-29)
   applies to STATIC-GREP TESTS as much as it does to runtime wire-up. A producer
   change that's runtime-correct can still break a consumer that's grep-based.
   Future "I changed a comment block" PRs in this codebase should explicitly
   `cargo test --workspace` before considering the change ready, as a cheap
   bilateral check.
