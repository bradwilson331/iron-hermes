## Deviation Legitimacy (Plan 02 Auto-Fixes)

### Deviation 1: Existing `scroll_tests` calls updated from `wrapped_line_count` to `word_wrapped_line_count`

**Verdict: LEGITIMATE BUG FIX.** When Task 2 deleted `wrapped_line_count`, 4 pre-existing tests in `scroll_tests` that called the old function would have caused a compile failure. The fix updated those calls to `word_wrapped_line_count`. The test inputs (single-word strings and empty string) produce identical results from both functions — the semantics are compatible for that class of input, so no test assertions were relaxed.

### Deviation 2: `flush_word` closure patched for oversized-word double-count bug

**Verdict: LEGITIMATE BUG FIX.** The Plan 01 implementation of `flush_word` double-counted an extra row when a single oversized word began at the start of a row (`current_row_width == 0, pending_ws_width == 0`). The fix adds a guard: `if *current_row_width > 0 || *pending_ws_width > 0` before emitting the wrap row. This was confirmed by the `wrapped_overflows_one_row` test (`word_wrapped_line_count("helloworld!", 10)` returning 3 instead of the correct 2). The corrected algorithm is verified correct by D-02 tests which compare against ratatui's actual TestBackend render.

Current implementation at app.rs:998–1003:
```
if *current_row_width > 0 || *pending_ws_width > 0 {
    *rows += 1;
    *current_row_width = 0;
    *pending_ws_width = 0;
}
```

### Deviation 3: 5 insta snapshots re-baselined

**Verdict: LEGITIMATE CORRECT BEHAVIOR.** The `word_wrapped_line_count` fix correctly computes `max_scroll > 0` for content that the old formula underestimated as zero. This causes the scrollbar (▲, █, ▼) to appear in snapshot frames that previously had no scrollbar. The new snapshots are the correct representation of what the UI renders with the fixed formula. All 5 snapshot files contain scrollbar characters in column 78, confirming the scrollbar now appears when content genuinely overflows the viewport — which is the expected behavior after the bug fix.

### Deviation 4: Visual assertion row index corrected (y=17 not y=22)

**Verdict: LEGITIMATE BUG FIX.** RESEARCH §6 Pitfall 4 stated "rows 1..22 for a 24-row terminal" but this was wrong — the transcript chunk is only 19 rows tall (24 - 1 knight-rider - 1 status - 3 input = 19). The last content row inside the transcript block is y=17 (19 rows total, minus 2 borders, last content row = index 17). The Plan 02 executor dynamically computed this as `(transcript_area.height - 2) as u16`, which is robust to future layout changes.
