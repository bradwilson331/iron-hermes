<objective>
Fix the line-count formula that drives `transcript_max_scroll` so the computed total row count matches what ratatui actually renders. The auto-scroll undershoot (AI responses partially or fully hidden below viewport — bug screenshots 1 & 2) is caused by `wrapped_line_count` using character-ceiling-divide instead of word-wrap, and by both call sites in `transcript_line_count` using `chars().count()` instead of unicode display width.

Purpose: When `total` is correct, `transcript_max_scroll = total - visible` is correct, and the existing (already-correct) `reconcile_scroll` clamp lands `transcript_scroll` at the true visual bottom on every `Finished` event. No scroll-control-flow changes; only the input arithmetic.

Output: A new `word_wrapped_line_count` function in `app.rs`, both call sites in `transcript_line_count` rewired, `unicode-width` promoted to a direct dependency, and 5 unit tests proving the formula matches ratatui's actual render row count.
</objective>
