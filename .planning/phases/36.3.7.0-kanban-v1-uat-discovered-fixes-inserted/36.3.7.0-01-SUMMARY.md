# Phase 36.3.7.0 Plan 01: Drop `--skills` argv + env carrier Summary

**One-liner:** Closed BUG-36.3.7-01 by removing the `--skills kanban-worker` argv emission from `worker_spawn.rs` and replacing it with a `HERMES_KANBAN_TASK_SKILLS` env var carrier, unblocking UAT-09-A worker startup.

## What Was Built

### Lines Deleted (worker_spawn.rs)

Removed the `skill_args` construction block at lines 181–191:
```rust
// deleted:
let mut skill_args: Vec<String> = vec!["--skills".into(), "kanban-worker".into()];
if let Some(ref skills_json) = task.skills {
    if let Ok(extras) = serde_json::from_str::<Vec<String>>(skills_json) {
        for s in extras { skill_args.push("--skills".into()); skill_args.push(s); }
    }
}
```

Removed `.args(&skill_args)` from the `Command::new("ironhermes")` builder chain.

### Lines Added (worker_spawn.rs)

Added `HERMES_KANBAN_TASK_SKILLS` conditional env emission in `build_kanban_worker_env` after the `HERMES_TENANT` block:
```rust
if let Some(ref skills_json) = task.skills {
    if let Ok(extras) = serde_json::from_str::<Vec<String>>(skills_json) {
        if !extras.is_empty() {
            env.push(("HERMES_KANBAN_TASK_SKILLS".into(), skills_json.clone()));
        }
    }
}
```

### Doc Comments Updated

- Line 37 (module-level spawn shape): removed `--skills kanban-worker [--skills <extra>...]`; shape now `ironhermes --profile <assignee>`
- Line 142 (`spawn_worker` doc): updated to reference env-only path and cross-reference BUG-36.3.7-01

## Audit Findings

Task 1 audit (see `36.3.7.0-01-SKILLS-EXTRAS-AUDIT.md`) found **Outcome A — receiver is dead**:

- `worker_spawn.rs:184` — the only consumer of `task.skills` for routing (the broken emitter, now removed)
- `format.rs:102` — JSON display serializer only (not a routing consumer)
- `store.rs:237` — CREATE-time serializer that writes skills into the DB row (not a routing consumer)

No code path reads `task.skills` to do anything at the receiver side. The extras were only ever emitted by the broken argv builder and never consumed.

## Meta-finding: Receiver-End Gap Pattern

This is the same "emitter exists, receiver never wired" pattern as BUG-36.3.7-02 (`cmd_kanban` handler) and BUG-36.3.7-03 (circuit-breaker off-by-one). All three were missed by automated verification because the tests only checked the emitter side. The `worker_argv_omits_skills_flag` static-grep test and the `ironhermes_binary_accepts_constructed_argv` integration test are the concrete examples of "receiver-end verification" that would have caught Bug #1 pre-merge. This pattern is a candidate for the LEARNINGS.md entry to be written in Plan 04 SUMMARY: "Trace emitter + receiver + dispatch for every wire-up claim; do not stop at the emitter."
