## Section 1: D-12 Locked Decision (verbatim from `36.3.7-CONTEXT.md`)

> **D-12:** Failure circuit breaker via `kanban.failure_limit` (default 2). After N consecutive
> non-successful attempts (spawn_failed / crashed / timed_out / protocol_violation), emit `gave_up`
> event with `{failures, effective_limit, limit_source, error}` and auto-block the task with the
> last error as reason. Per-task `max_retries` overrides global; both fall through to built-in
> default.

**Determination:** The comparison operator (`>=`) is correct per D-12 intent. The UAT-09-A
off-by-one is purely structural: `apply_circuit_breaker` is only invoked from the spawn-failure
branch of `claim_and_spawn`. The `detect_crashed_workers` path bumps `consecutive_failures` but
never calls the breaker, so the UAT-09-A scenario (worker spawns OK then crashes immediately)
required an additional spawn-failure tick before the breaker fired — one tick too late per operator
expectation.

**In-scope fix (36.3.7.0, Plan 03):** Wire `apply_circuit_breaker` into `detect_crashed_workers`
AFTER the `consecutive_failures += 1` bump (around line 283) and AFTER the `crashed` event append
(around line 298), mirroring the spawn-failure path's order (event THEN breaker).

**Out-of-scope (deferred to 36.3.7.1):** The same structural gap exists in `reclaim_stale_claims`
(line ~458) and `enforce_max_runtime` (line ~553). These paths are explicitly excluded by
CONTEXT.md scope_fences ("No feature work beyond the three named bugs"). A follow-up sub-phase
should mirror the same breaker call into those two sites if a future UAT surfaces them.

## Section 3: D-12 Clarification (operator semantic)

The intended operator semantic for `failure_limit = N` is:

> "`failure_limit = N` means stop AT N failures (regardless of failure source:
> spawn_failed / crashed / timed_out / reclaimed), on the same tick the limit is reached."

Task 2 will add a one-line code comment immediately above `dispatcher.rs:988` recording this
clarification so the intent is co-located with the implementation:

```rust

// failures, on the same tick the limit is reached (regardless of failure

// invoked from each bump site; do NOT change `>=` to `>`.
```
