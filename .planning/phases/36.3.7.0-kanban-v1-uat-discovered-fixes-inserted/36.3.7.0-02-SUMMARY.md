# Phase 36.3.7.0 Plan 02: Kanban Slash Command Handler Summary

**One-liner:** JWT-style cycle-break wires `/kanban` slash dispatch through KanbanStoreReader trait-object to KanbanStore — closing BUG-36.3.7-02 where the `todo_stub` catch-all intercepted all `/kanban` invocations.

## What Was Built

### Task 1 — KanbanStoreReader trait + CommandContext field + builder

File: `crates/ironhermes-core/src/commands/context.rs` (+38 lines)

Added after `CronJobReader` (the precedent trait):

```rust
pub trait KanbanStoreReader: Send + Sync {
    fn list_text(&self) -> String;
    fn show_text(&self, id: &str) -> Option<String>;
    fn tip_text(&self) -> String;
    fn deferred_subverb_message(&self, name: &str) -> String;
}
```

Added to `CommandContext`:
- Field: `pub kanban_store: Option<Arc<dyn KanbanStoreReader>>`
- Init: `kanban_store: None` in `::new`
- Builder: `pub fn with_kanban_store(mut self, store: Arc<dyn KanbanStoreReader>) -> Self`

All adjacent to their `Cron*` analogs. Compilation gate: `cargo check -p ironhermes-core` + 531 lib tests pass.

### Task 2 — cmd_kanban handler + dispatch arm

File: `crates/ironhermes-core/src/commands/handlers.rs` (+54 lines)

**Dispatch arm** at line 72 (right after `"cron"` arm):
```rust
"kanban" => cmd_kanban(args, ctx),
```

**`fn cmd_kanban`** mirrors `cmd_cron` structure exactly:

| Subverb | Routing |
|---------|---------|
| `(none)` or `list` | `store.list_text()` → `Output` |
| `show <id>` | `store.show_text(id)` → `Output` or `Error("No kanban task found: {id}")` |
| `show` (no id) | `Error("/kanban show <id>: missing id")` |
| `tip` | `store.tip_text()` → `Output` |
| Known deferred (24 verbs) | `store.deferred_subverb_message(name)` → `Output` |
| Unknown verb | typo-suggest against `["list", "show", "tip"]` → `Error` |
| No store | `Output("/kanban: kanban store not configured.")` |

**`DEFERRED_KANBAN_SUBVERBS` const** (exactly 24 entries):
`claim, complete, block, unblock, comment, archive, reclaim, reassign, assign, link, unlink, create, init, tail, watch, runs, assignees, dispatch, stats, log, context, gc, daemon, diagnostics`

**Key design choice:** Deferred subverbs route to `store.deferred_subverb_message(name)` — NOT to `todo_stub`. This creates a GREPPABLE arc that future grep-based verifiers can find. The catch-all `todo_stub` hid BUG-36.3.7-02 from automated verification — this explicit routing closes that gap.

### Task 3 — KanbanStoreReaderImpl + build_cmd_ctx wiring

**New file:** `crates/ironhermes-cli/src/kanban/store_reader_impl.rs` (+95 lines)

```rust
pub struct KanbanStoreReaderImpl { store: Arc<Mutex<KanbanStore>> }
```

- `open_default() -> ironhermes_kanban::Result<Self>` — one-shot at session start
- `new(store: Arc<Mutex<KanbanStore>>) -> Self` — inject constructor
- `list_text()` → lock → `list_tasks(ListFilters::default())` → `format_task_table`
- `show_text(id)` → lock → `get_task(id)` → `get_runs` + `get_events` → `format_task_detail(&task, &runs, &events, &[])` (empty comments — no public `get_comments` API)
- `tip_text()` → static scratch-workspace hint (3 lines)
- `deferred_subverb_message(name)` → `format!("/kanban {}: use 'ironhermes kanban {}' from the CLI for v1.", name, name)`

**`crates/ironhermes-cli/src/kanban/mod.rs`** gains:
```rust
pub mod store_reader_impl;
pub use store_reader_impl::KanbanStoreReaderImpl;
```

**`crates/ironhermes-cli/src/main.rs`:**
- `build_cmd_ctx` gains trailing parameter: `kanban_store: Option<Arc<dyn ironhermes_core::commands::context::KanbanStoreReader>>`
- Final block in `build_cmd_ctx` body: `if let Some(handle) = kanban_store { ctx.with_kanban_store(handle) } else { ctx }`
- `kanban_store_handle` constructed ONCE in `run_chat` after `command_router` (line ~1466):
  ```rust
  let kanban_store_handle = match KanbanStoreReaderImpl::open_default() {
      Ok(imp) => Some(Arc::new(imp) as Arc<dyn KanbanStoreReader>),
      Err(e) => { tracing::warn!(...); None }
  };
  ```
- Both `build_cmd_ctx` call sites (prompt-time + mid-turn) pass `kanban_store_handle.clone()`
- `run_single` does NOT call `build_cmd_ctx` — no change needed (per CONTEXT.md scope fence)
