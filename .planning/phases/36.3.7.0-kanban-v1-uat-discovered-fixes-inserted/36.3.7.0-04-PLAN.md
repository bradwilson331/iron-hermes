## UAT-09-A — Live worker subprocess spawn (re-run from 36.3.7-09 SUMMARY Addendum)

**Preconditions:**
- (a) `cargo build --workspace` exits 0 against the merged Plans 01+02+03 branch.
- (b) At least one configured profile in `~/.ironhermes/profiles/`.
- (c) Ability to make real LLM calls (network + valid API key for the profile's provider).
- (d) The operator has reviewed and accepts the cost of an LLM round-trip (typically 1–5K tokens).

**Procedure (run in operator terminal):**

1. `cargo build --workspace` — confirm success.
2. Isolated home: `IRONHERMES_HOME=$(mktemp -d) && export IRONHERMES_HOME && echo "Using IRONHERMES_HOME=$IRONHERMES_HOME"`.
3. Init kanban: `./target/debug/ironhermes kanban init` — verify both files exist:
   `ls $IRONHERMES_HOME/kanban.db && ls $IRONHERMES_HOME/skills/kanban-worker/SKILL.md`
4. Create a task (substitute `YOUR_PROFILE`):
   ```bash
   ./target/debug/ironhermes kanban create \
     "smoke-test task — say hello and call kanban_complete with a one-line summary" \
     --assignee YOUR_PROFILE --json
   ```
   Capture the returned `task_id`.
5. Confirm ready: `./target/debug/ironhermes kanban list` — task must appear with `status=ready`.
6. **Env-scrub probe (D-18):** stash the real key, then set sentinel:
   ```bash
   export REAL_OPENAI_API_KEY="$OPENAI_API_KEY"
   export OPENAI_API_KEY="marker_${RANDOM}_${RANDOM}"
   echo "Sentinel: $OPENAI_API_KEY"
   ```
   (You'll restore the real key in step 11.)
7. One-shot dispatch: `RUST_LOG=ironhermes_kanban=info ./target/debug/ironhermes kanban dispatch --max 1`
   Watch for: `claimed` event, `spawned` event with non-zero PID.
8. (Optional) `ps -p <PID>` should show `ironhermes --profile YOUR_PROFILE chat -q "work kanban task <id>"` (NOTE: no `--skills` flag — that's the Plan 01 fix).
9. Wait for the worker to exit (or `kill -TERM <PID>` if hung).
10. Verify outcome:
    - `./target/debug/ironhermes kanban show <task_id>` → expect `status: done` (GOLDEN) or `status: blocked` (PARTIAL).
    - `./target/debug/ironhermes kanban runs <task_id>` → expect ≥1 row with `outcome: completed` (GOLDEN) or `outcome: blocked` (PARTIAL).
    - `cat $IRONHERMES_HOME/logs/kanban/<task_id>.stdout.log` — confirm non-empty.
    - `grep "marker_" $IRONHERMES_HOME/logs/kanban/<task_id>.stdout.log` — MUST return ZERO matches.
11. Restore real key: `export OPENAI_API_KEY="$REAL_OPENAI_API_KEY"`.

**PASS criteria for UAT-09-A (all must hold):**
1. `kanban dispatch --max 1` emits a `claimed` event followed by a `spawned` event with non-zero PID.
2. After the worker exits, `kanban show <task_id>` returns `status: done` (GOLDEN) or `status: blocked` (PARTIAL).
3. `kanban runs <task_id>` returns ≥1 row with `outcome: completed` or `outcome: blocked`.
4. `$IRONHERMES_HOME/logs/kanban/<task_id>.stdout.log` exists and is non-empty.
5. No stranded claim_lock — `kanban list` after worker exit does not show the task as `running`.
6. Sentinel `marker_*` does NOT appear in worker's stdout log (D-18 env scrub).
7. **NEW (Plan 01 verification):** `kanban runs <task_id>` does NOT show `outcome: crashed` from an argparse failure. Worker stderr log (`<task_id>.stderr.log`) does NOT contain `unexpected argument '--skills' found`.

## UAT-09-B — Live `/kanban list` slash command (re-run from 36.3.7-09 SUMMARY Addendum)

**Preconditions:**
- (a) UAT-09-A PASSED.
- (b) Gateway can start (or interactive `ironhermes chat` REPL is available — the locked decision in CONTEXT.md notes only the interactive REPL path is in scope, NOT `chat -q "/kanban list"` which is intentionally non-bypass per main.rs:875).

**Procedure (run in operator terminal):**

1. Fresh home: `IRONHERMES_HOME=$(mktemp -d) && export IRONHERMES_HOME && ./target/debug/ironhermes kanban init`.
2. Seed a task: `./target/debug/ironhermes kanban create "bypass-smoke task" --assignee YOUR_PROFILE --json` → capture `task_id`.
3. (Optional Terminal A — for the gateway-embed PASS criterion) start the gateway:
   ```bash
   RUST_LOG=ironhermes_gateway=info,ironhermes_kanban=info \
     ./target/debug/ironhermes gateway start
   ```
   Wait for the `kanban.dispatch.tick` span in the gateway log.
4. Terminal B: `./target/debug/ironhermes chat`.
5. After the prompt appears, type `/kanban list` and Enter.
6. (Optional) `/kanban show <task_id>` to verify show subverb.
7. (Optional) `/kanban tip` to verify tip subverb.
8. (Optional) `/kanban claim t_fake` — should print "use `ironhermes kanban claim` from the CLI for v1." (Plan 02 deferred-subverb routing).
9. (Negative control) Type `/kanban garbage-verb` — should print "Unknown /kanban subcommand: garbage-verb" (typo-suggest) — NOT "not yet available".
10. Send a regular non-slash message ("what's the weather"); let the LLM respond.
11. Exit chat (Ctrl-D or Ctrl-C).
12. Inspect transcript: `find $IRONHERMES_HOME -name '*.jsonl' -newer $IRONHERMES_HOME/kanban.db -print` then `grep '/kanban' <transcript>` — MUST return ZERO matches (D-36 bypass means the command never enters agent context).
13. If gateway running in Terminal A, Ctrl-C it. Verify no orphans: `ps -A | grep -E 'ironhermes (gateway|chat|--profile)' | grep -v grep` — MUST be empty.

**PASS criteria for UAT-09-B (all must hold):**
1. `/kanban list` prints the CLI task table directly (column headers `ID`, `STATUS`, `ASSIGNEE` visible) — NOT routed through the LLM.
2. Latency is sub-second.
3. Token usage for the `/kanban list` line is zero (verify via the chat session's `/usage` or token counter).
4. The session transcript JSONL contains the regular non-slash message but NOT `/kanban list`.
5. `/kanban claim ...` returns the "use `ironhermes kanban claim` from the CLI for v1." message (Plan 02 deferred-subverb routing) — NOT "is not yet available."
6. `/kanban garbage-verb` returns the typo-suggest error — NOT `todo_stub`.
7. If gateway was running: dispatcher tick spans continued through the slash command (no pause).
8. After gateway shutdown (if started): no orphan `ironhermes` processes remain.
