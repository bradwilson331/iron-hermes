## Bug summary

**BUG-36.3.7-04:** `ironhermes --profile P chat -q "PROMPT"` is functionally equivalent to `-e/--execute` (both short-circuit through `run_single`), but the `run_preflight` gate at `crates/ironhermes-cli/src/main.rs:402` only excluded `cli.execute.is_some()`. It matched any `Commands::Chat { .. }` invocation and tried to launch the FirstRun/FixMode wizard, which then failed to read from stdin in a non-interactive context.

Phase 36.3.7 Plan 01 added the `-q/--query` flag + the `run_single` short-circuit but never updated the preflight gate. The bug was masked in the original UAT round by Bug #1 (`--skills` argparse error killed the worker before it ever reached the preflight gate). Plan 01 of 36.3.7.0 dropped the `--skills` argv, exposing this gate as the next receiver-end gap.

## What this plan changed

**`crates/ironhermes-cli/src/main.rs` (line 411 → line 438):**

Added `chat_has_query` predicate:
```rust
let chat_has_query = matches!(
    &cli.command,
    Some(Commands::Chat { query: Some(_), .. })
);
```

Patched both sibling gates with `&& !chat_has_query`:
- `run_preflight` at line 419 — so the FirstRun/FixMode wizard does NOT fire on `chat -q`
- `is_interactive_repl` at line 436 — so the log filter does NOT switch to interactive mode on `chat -q`

Inline comments cite BUG-36.3.7-04 + the receiver-end-gap pattern.

**`crates/ironhermes-cli/tests/preflight_chat_query_gate.rs` (NEW, 3 tests):**

Static-grep regression tests using the same pattern as `tests/kanban_worker_session.rs`:
1. `preflight_gate_excludes_chat_with_query` — asserts MAIN_RS contains `!chat_has_query`
2. `chat_has_query_destructures_query_some` — asserts the predicate uses `Commands::Chat { query: Some(_), .. }` (not a broader pattern that would break interactive `chat`)
3. `interactive_repl_gate_also_excludes_chat_with_query` — asserts `!chat_has_query` appears at least twice (proves BOTH sibling gates were patched)

Each test's failure message cites BUG-36.3.7-04 so future regressions are greppable.
