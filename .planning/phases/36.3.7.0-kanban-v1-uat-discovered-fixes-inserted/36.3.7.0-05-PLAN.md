# Plan 36.3.7.0-05 — Suppress preflight wizard for `chat -q` non-interactive path (BUG-36.3.7-04)

<objective>
Close BUG-36.3.7-04 discovered during UAT-09-A re-run on Phase 36.3.7.0's post-fix binary: `ironhermes --profile P chat -q "PROMPT"` exits immediately with `Error: EOF on stdin` because the `run_preflight` gate at `crates/ironhermes-cli/src/main.rs:402` matches `Commands::Chat { .. }` and tries to launch the FirstRun/FixMode wizard, which then fails to read from stdin in a non-interactive context.

The `chat -q "..."` path is functionally equivalent to `-e/--execute` (both short-circuit through `run_single`), but the preflight gate only excludes `cli.execute.is_some()` — it doesn't know about `Commands::Chat { query: Some(_), .. }`. Phase 36.3.7 Plan 01 added `-q/--query` and the `run_single` short-circuit but did not update the preflight gate. The bug was masked in original UAT-09-A by Bug #1 (`--skills` argparse error killed the worker before it ever reached the preflight gate).

Same receiver-end-gap pattern as Bugs #1, #2, #3: emitter wired, receiver gate missed.
</objective>

<tasks>

<task id="1" type="execute">
<action>
Patch the `run_preflight` gate in `crates/ironhermes-cli/src/main.rs` (around line 402) to ALSO exclude the `Chat { query: Some(_), .. }` case, mirroring the existing `cli.execute.is_none()` exclusion for the `-e` non-interactive path.

The current gate:
```rust
let run_preflight = matches!(
    cli.command,
    Some(Commands::Chat { .. }) | Some(Commands::Gateway { .. }) | None
) && cli.execute.is_none();
```

Becomes:
```rust
let chat_has_query = matches!(
    &cli.command,
    Some(Commands::Chat { query: Some(_), .. })
);
let run_preflight = matches!(
    cli.command,
    Some(Commands::Chat { .. }) | Some(Commands::Gateway { .. }) | None
) && cli.execute.is_none()
  && !chat_has_query;
```

Add an inline comment citing BUG-36.3.7-04: "Phase 36.3.7.0 BUG-36.3.7-04: `chat -q "..."` is functionally equivalent to `-e` (both short-circuit through run_single — see line ~430 below); exclude it here so the FirstRun/FixMode wizard does not try to read from stdin in this non-interactive path."

Also update the sibling `is_interactive_repl` check at line ~412 in the same way — `chat -q` is NOT interactive even though it nominally matches `Commands::Chat { .. }`:

```rust
let is_interactive_repl =
    matches!(cli.command, Some(Commands::Chat { .. }) | None)
    && cli.execute.is_none()
    && !chat_has_query;
```

DO NOT change the order in which match arms evaluate after this; only the early-return gating.
</action>
