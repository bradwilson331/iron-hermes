## Conclusion

**Outcome A — extras path is dead at the receiver.**

Dropping `--skills` from argv does NOT regress any working receiver; it only removes a broken emitter. The extras data on the Task row becomes dormant until a future phase wires a consumer.

## Decision for this plan

Add `HERMES_KANBAN_TASK_SKILLS` env var (JSON-encoded array of skill slugs) to `build_kanban_worker_env` output ONLY when `task.skills` is `Some` AND the decoded array is non-empty. Emit the original JSON string verbatim (do not re-serialize). This is a forward-compatible carrier: receiver-side consumption of that env var is OUT OF SCOPE for 36.3.7.0 per scope_fences (no behavior change since the prior argv path was also unconsumed at the receiver).
