# Phase 36.3.7.0 Plan 03: Circuit Breaker Structural Fix (BUG-36.3.7-03) Summary

Closed BUG-36.3.7-03 by wiring `apply_circuit_breaker` into the `detect_crashed_workers` path — the structural gap that caused UAT-09-A's spawned-then-crashed workers to require an extra tick before the breaker fired.

## D-12 Determination Outcome

**D-12 determination doc:** `.planning/phases/36.3.7.0-kanban-v1-uat-discovered-fixes-inserted/36.3.7.0-03-D12-DETERMINATION.md`

**Finding 1 — Semantic comparison:** The literal line at `dispatcher.rs:988` is `if consecutive_failures >= effective_limit {`. The `>=` operator is correct per D-12 intent. No character-level change was needed.

**Finding 2 — Structural gap (UAT off-by-one source):**

| Line | Function | Bumps `consecutive_failures`? | Calls `apply_circuit_breaker`? | Status |
|------|----------|-------------------------------|-------------------------------|--------|
| ~280 | `detect_crashed_workers` | YES | **NO → now YES** | Fixed in this plan |
| ~458 | `reclaim_stale_claims` | YES | NO | Deferred to 36.3.7.1 |
| ~553 | `enforce_max_runtime` | YES | NO | Deferred to 36.3.7.1 |
| ~849 | `claim_and_spawn` (spawn-failure) | YES | YES (line 891) | Already wired |

The breaker was only invoked from the spawn-failure branch. UAT-09-A workers spawned OK (exec succeeded) then crashed immediately (argparse error from BUG-01). The crashed-detection path bumped `consecutive_failures` 0→1→2→3 without ever calling the breaker, so the operator had to manually archive the task.

**Finding 3 — Operator semantic clarification:** `failure_limit = N` means stop AT N failures on the same tick the limit is reached, regardless of failure source.

## Dispatcher Change

**`crates/ironhermes-kanban/src/dispatcher.rs`:**

1. In `detect_crashed_workers` (after the `crashed` event append block, ~line 299): added `apply_circuit_breaker` call mirroring the spawn-failure path's event-then-breaker ordering:
   ```rust
   // Phase 36.3.7.0 BUG-36.3.7-03: circuit breaker on crashed-detection path.
   let error_msg = format!("worker process crashed (pid={pid})");
   apply_circuit_breaker(ctx, &task, &run.id, &error_msg, now).await?;
   ```
   Binding names: `task` (Task), `run.id` (String run_id), `pid` (i64 from `run.claim_pid`), `now` (f64). No binding renaming was needed — the local shape matched `apply_circuit_breaker`'s signature directly.

2. Above the `if consecutive_failures >= effective_limit` check (~line 996): added 4-line D-12 clarifying comment naming `36.3.7.0-03` as the source of the clarification and forbidding `>=` → `>` changes.

**Grep verification:** `apply_circuit_breaker(` appears 3 times in `dispatcher.rs`: definition (line 972) + spawn-failure call site (line 899) + crashed-detection call site (line 305).

## Two New Receiver-End Tests

**`crates/ironhermes-kanban/tests/dispatcher_logic.rs`:**

1. **`circuit_breaker_trips_on_crashed_detection_path`** — seeds a running task with `consecutive_failures = 1` (failure_limit - 1) and dead PID `999_999_999`. After `run_dispatch_tick`: asserts `task.status == "blocked"`, `crashed` event present, `gave_up` event present. PASSES.

2. **`circuit_breaker_does_not_trip_below_limit_on_crashed_path`** — seeds a running task with `consecutive_failures = 0` and dead PID `999_999_998`. Sets `scheduled_at` to `now + 3600` to prevent same-tick re-claim (which would trigger the spawn-failure bumper and trip the breaker at 2). After `run_dispatch_tick`: asserts `task.status == "ready"`, `consecutive_failures == 1`, `crashed` event present, `gave_up` event absent. PASSES.

**Test deviation from plan spec:** The plan specified using `make_ctx_failing_spawn` for the no-trip test. During execution, `make_ctx_failing_spawn` caused the test to fail because the released-ready task was immediately re-claimed and the spawn failure bumped `consecutive_failures` to 2, tripping the breaker. Fix: set `scheduled_at` to a future timestamp so the dispatcher skips re-claiming in the same tick. This is a Rule 1 auto-fix (the naive approach didn't work; a mechanical adjustment to isolate only the crashed-detection path was needed). Documented in SUMMARY per deviation protocol.

## UAT-09-A Symptom Closure

The operator-visible symptom from UAT-09-A ("breaker fired one late — `consecutive_failures` reached 3 before `failure_limit = 2` blocked further spawns") is closed by this structural fix. With `apply_circuit_breaker` now wired into `detect_crashed_workers`, a worker that spawns OK then crashes will be blocked on the same tick that bumps `consecutive_failures` to `failure_limit`. The literal `>` vs `>=` framing in CONTEXT.md BUG-36.3.7-03 was not the actual fix path — the comparison was already `>=`; the gap was that the check was never reached from the crashed path.

Note: with Plan 01 in place (dropping the `--skills kanban-worker` argv that caused the argparse crash), UAT-09-A workers should not crash at all on re-run, so the circuit breaker should not fire on the happy path.
