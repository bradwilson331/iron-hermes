<objective>
Fix a pre-existing latent bug where the in-flight transport reaction emitted by the per-chat
worker (`'👁'`, U+1F441 EYE) is not on Telegram's `setMessageReaction` allow-list, causing a
`REACTION_INVALID 400` error on every popped message. Replace with `'👀'` (U+1F440 EYES),
which IS on the allow-list and carries the same "I see you / agent is working" intent.

Purpose: Unblock Scenarios 1, 5, 6, and 7 of the live Telegram UAT runbook, which all assert
that the in-flight reaction renders successfully. The D-09 warn-and-continue fallback meant the
agent itself kept functioning, but every turn emitted a WARN log and the user never saw the
reaction.

This is NOT a 36.17.2 regression. The same `👁` literal existed in earlier phases; 36.17.2's
UAT simply made the silent failure observable. The fix is a single glyph replacement in the
emission site plus consistency updates to comments, tests, and docs.

Output:
- runner.rs: `'👁'` → `'👀'` at line 1066; doc comments updated at lines 1060-1074 and line 1007
- user_queue.rs: doc comment references `👁` → `👀` at lines 33 and 99
- tests/uqm_session_queue_unification.rs: all `"👁"` string literals in `.filter` comparisons,
  assert messages, and docstrings replaced with `"👀"`; the inline `add_reaction` call at line 267
  updated to `"👀"`
- tests/session_queue_telegram_uat.md: all `👁` glyphs in Scenarios 1, 5, 6, 7 and the
  sign-off checklist replaced with `👀`; Document History entry added
- 36.17.2-CONTEXT.md: D-28 appended below D-27 recording the emoji-choice rationale
