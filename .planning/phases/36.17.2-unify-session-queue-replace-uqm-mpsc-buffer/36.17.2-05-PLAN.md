**Locked decisions for this plan (D-23..D-27, no executor discretion):**
1. **Command detection:** `event.content.starts_with('/')` — strict prefix, no `.trim_start()`, no length check (D-24). Matches the existing handler.rs:411 command parser behavior. Empty content or non-string content cannot pass this check (Telegram MessageEvent.content is `String`, not `Option<String>` per ironhermes-core).
2. **Fast-path target:** `handler.handle_with_multimodal(event, adapter, cancel.child_token(), ProcessedAttachments { text_prefix: None, image_data_uri: None }).await` (D-27). `handle_with_multimodal` already routes slash commands internally to `handle_slash_command` (handler.rs:964) — no new routing logic needed in runner.rs. The fast-path's job is purely to break the per-chat worker serialization.
3. **Concurrency bound:** `sem_dispatch.acquire().await` MUST be acquired before the handler call (T-36.17.2-06 mitigation). The existing `Arc<Semaphore>` at runner.rs:854 (already cloned as `semaphore_dispatch` at line 860) is the same semaphore used by the worker spawn. Acquiring it in the fast-path preserves the TG-06 per-chat concurrency bound established in Phase 22.4.2.1.
4. **Detached spawn:** the spawned task is NOT added to `worker_join_set` (D-27). Commands are short-lived; graceful-shutdown drain at runner.rs:1159-1170 sets `is_draining=true` and cancels the cancel_token, which the in-flight command's handler observes via `cancel.is_cancelled()` and exits cleanly. Note: `tokio::spawn` returns a `JoinHandle` — we let it drop immediately (`tokio::spawn(async move { ... });` with no `let _ = ` is sufficient).
5. **Multimodal skipped:** commands do NOT go through `multimodal::process_attachments` (D-27). Commands are text-only by contract — the parser at handler.rs:411 splits on whitespace and dispatches by `def.name`. Any photo/document attachment that arrives WITH a leading-slash caption (rare edge case — Telegram allows captions on photo messages) is treated as a command-with-empty-attachments; the caption text reaches the command parser normally. If a future phase wants photo+slash multimodal commands, that's a separate scope.
6. **`/queue` synthesized event still hits SessionQueue:** `/queue arbitrary text` enters the fast-path (slash prefix) → `handle_with_multimodal` → `handle_slash_command` → `cmd_queue` returns `CommandResult::Queued { message }` → handler's intercept (handler.rs from 36.17.1-03) synthesizes a `MessageEvent` and calls `session_queue.try_push(&session_key, queued_event)`. The fast-path itself doesn't enter UQM, but the `/queue`-synthesized event DOES land on SessionQueue via the existing intercept. The integration test (Task 2) asserts this end-to-end.

After this plan ships, commands respond in sub-second wall-clock time regardless of free-text queue depth.

        session_queue.len(&session_key),
        2,
        "/queue intercept must push synthesized event onto SessionQueue (was 1, expected 2). Actual len: {}",
        session_queue.len(&session_key)
    );

    // Assertion (c) — RecordingFailingAdapter recorded the /queue chat reply.
    // The handler's intercept emits "Queued for the next turn." (singular at depth 1) OR
    // "Queued for the next turn. (N queued)" (plural at depth > 1). Either form is acceptable.
    let send_log = adapter.send_log.lock().unwrap();
    let queued_reply = send_log
        .iter()
        .filter(|(c, content, _)| c == "chat_fp" && content.starts_with("Queued for the next turn"))
        .count();
    assert!(
        queued_reply >= 1,
        "/queue intercept must send 'Queued for the next turn...' reply. send_log: {:?}",
        *send_log
    );
    drop(send_log);

    // Assertion (d) — free-text event (free_1) is still in queue (fast-path did NOT pop or process it).
    // We can verify by popping it: it must still be `free_1`, not the synthesized /queue event.
    // Note: SessionQueue is FIFO, so the first pop is free_1 (pushed first), the second pop is
    // the /queue synthesized event (pushed by the intercept after).
    let first = session_queue.pop(&session_key).expect("first pop must yield free_1");
    assert_eq!(
        first.message_id, "free_1",
        "FIFO order broken: first pop should be free_1, got {}",
        first.message_id
    );
    let second = session_queue.pop(&session_key).expect("second pop must yield /queue synthesized event");
    assert_eq!(
        second.content, "interrupt this",
        "/queue intercept must synthesize event with content == args (got: {})",
        second.content
    );
}
