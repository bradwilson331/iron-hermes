# Phase 36.17.2 Plan 02: Notify-Based Per-Chat Worker Pop-Loop Summary

Transitional worker body replaced with full Notify-based idle-wait pop-loop; dispatch loop now matches all three Result<DispatchOutcome, QueueError> arms; 👁 reaction moved from fire-and-forget tokio::spawn into inline await at pop time; post-turn drain_pending call removed.

## What Was Built

**Import addition:**
- Added `DispatchOutcome` to the `use crate::user_queue::` import at runner.rs:29, replacing the inline `crate::user_queue::DispatchOutcome::WorkerSpawned` path qualification used in the transitional worker.

**Dispatch loop match (D-15):**
- Replaced the `if let Ok(DispatchOutcome::WorkerSpawned) = dispatch_result` guard with a full `match dispatch_result` block covering all three arms:
  - `Ok(DispatchOutcome::Accepted)` — logs debug, no action needed (existing worker will wake)
  - `Ok(DispatchOutcome::WorkerSpawned)` — spawns the full Notify-based pop-loop worker
  - `Err(QueueError::CapacityReached { .. })` — logs warn; UX already fired by UQM::dispatch (D-11)

**SessionKey construction:**
- Moved from inside the `WorkerSpawned` arm to immediately after `dispatch()` returns, using the pre-captured `(event_platform, event_chat_id, event_sender_id)` fields. SessionKey is then cloned as `session_key_for_worker` before the `async move` spawn.

**Full Notify-based worker spawn closure (D-04, D-05, D-06, D-08, D-09, D-16):**
- Acquires `Arc<Notify>` via `queue_task.notify_for(&session_key_for_worker).await.expect(...)` immediately after seeing `WorkerSpawned` (D-19, M4 locked — `notify_for` is `pub async fn`)
- Captures per-worker: `handler_task`, `adapter_task`, `sem_task`, `cancel_task`, `queue_task`, `session_queue_task` (via `runner_dispatch.session_queue.clone()`), `session_key_for_worker`, `notify_task`
- `runner_task` (Arc<Self>) capture **removed** — no longer needed (drain_pending call removed, D-07)

**Worker loop body:**
1. `session_queue_task.pop(&session_key_for_worker)` — sync, returns immediately
2. On `None` (queue empty): `tokio::select!` on `cancel_task.cancelled()` (break) or `notify_task.notified()` (continue / re-poll)
3. Cancellation check after pop (T-36.17.2-03 window acknowledged)
4. `sem_task.acquire().await` — bounded concurrency (TG-06)
5. `adapter_task.add_reaction(&next_event.chat_id, &next_event.message_id, "👁").await` — inline await, warn-and-ignore on failure (D-06 step 3, D-08, D-09)
6. `queue_task.take_multimodal(&session_key_for_worker).await.unwrap_or((None, None))` — FIFO lockstep with pop
7. `handler_task.handle_with_multimodal(...)` — full turn
8. Error logging on Err result
9. D-07 note in comment: post-turn drain_pending REMOVED; next iteration is the natural drain
10. `drop(permit)`; cancellation check between iterations
11. On loop exit: `queue_task.remove(&session_key_for_worker).await` (D-16)

## Deviations from Plan

None — plan executed exactly as written.
