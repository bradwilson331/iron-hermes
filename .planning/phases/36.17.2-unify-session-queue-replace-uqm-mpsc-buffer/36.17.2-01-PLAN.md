<objective>
Rewrite `UserQueueManager`'s internals to back its per-chat queue with `SessionQueue` (via an owned `Arc<SessionQueue>`) and replace the `mpsc::Sender`/`Receiver` map with a `SessionKey`-keyed worker-presence + `tokio::sync::Notify` map. The 👁 transport reaction emission is **removed from `dispatch`** — Plan 02 moves it to the per-chat worker. The cap-hit UX (❌ + "⏳ Queue is full…" chat reply) is **migrated into `dispatch`** (currently in `handler.rs:980-1020`, which becomes defensive fallback only). The `try_send` worker-replacement branch (current `user_queue.rs:77-95`) is deleted — cap-hit now bubbles `QueueError` to the caller instead.

Purpose: closes 36.17.1 unreachability gap (busy-branch + drain_pending dead code on Telegram path) by giving the `SessionQueue` a direct production write path through `UQM::dispatch`. After this plan ships, the `SessionQueue` already wired into `GatewayRunner` (36.17.1-02) starts receiving messages from real Telegram traffic — but the worker still consumes via `mpsc` until Plan 02 lands. **Plan 01 alone does not ship working code at the dispatch loop level; Plan 02 rewires that consumer.** Plan 01 is a precondition.
