### Key fixture: `RecordingFailingAdapter`

A new adapter struct (unique to this file) that records every `add_reaction`, `send_message`, and `edit_message` call, AND returns `Err` on `send_message`. This causes `run_agent` inside `handle_with_multimodal` to fail fast at its first `█` placeholder send without entering PromptBuilder / StreamConsumer / runtime setup — keeping all 5 tests under 100ms total.

### Key fixture: `spawn_test_worker`

Mirrors Plan 02's `runner.rs:991-1061` pop-loop shape exactly: pop → 👁 reaction → `take_multimodal` → `handle_with_multimodal` → loop. The handler call IS inside the loop body, satisfying M5 (handler ordering observable through real call path, not in-driver recorder).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Rate limit silently dropped messages 4-5 in headline test**

- **Found during:** Task 1 — test ran 5s timeout, only 3 `send_log` entries recorded
- **Issue:** `Config::default()` sets `burst_size: 3`, `messages_per_minute: 10`. The inbound `PerUserRateLimiter::check_and_consume` in `handle_with_multimodal` (handler.rs:930) silently returns `Ok(())` when the token bucket is exhausted (D-21 design: silent drop). With 5 rapid dispatches for the same `sender_id`, messages 4 and 5 hit the rate limit and were silently dropped by the handler — the worker popped them but `handle_with_multimodal` returned before recording any `send_log` entry.
- **Fix:** `build_test_handler_with_queue` overrides `config.rate_limit.burst_size = 128` and `config.rate_limit.messages_per_minute = 600` so the rate limiter is never the binding constraint in integration tests.
- **Files modified:** `crates/ironhermes-gateway/tests/uqm_session_queue_unification.rs`
- **Commit:** bca8abdc (same commit — fix applied before initial commit)
