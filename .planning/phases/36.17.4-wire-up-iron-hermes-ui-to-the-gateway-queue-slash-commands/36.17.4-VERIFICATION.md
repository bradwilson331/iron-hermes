### Human Verification Required

These three behavioral items were declared as Manual-Only Verifications in VALIDATION.md (table at lines 81-86) and are surfaced here per the verifier's Step 8 protocol. They are NOT verification gaps — they document UX behaviors that headless tests cannot exercise but the codebase has been shown to structurally support.

#### 1. Pill renders QUEUE N then disappears when N=0

**Test:** Run `dx serve --platform web`. Open the iron_hermes_ui browser surface. Send `/queue foo` mid-turn three times (or while a long-running turn is active). Observe the AppFooter `QUEUE N` pill increment from absent → `QUEUE 1` → `QUEUE 2` → `QUEUE 3`.
**Expected:** Pill appears at depth>0 and updates on every push. As the turn drains (auto-pops), pill decrements back through `QUEUE 2` → `QUEUE 1` → absent (hide-when-zero). When pause is active, suffix `(paused)` appears in the value span.
**Why human:** Visual / wasm runtime; no headless wasm test in iron_hermes_ui. Direct unit tests verify the signal-update behavior and the source-text tests lock the conditional render, but the actual DOM-rendered pill behavior across paint cycles is wasm-bound.

#### 2. Multi-tab queue sharing (same session_id)

**Test:** Open two browser tabs on the same `session_id`. In tab A, send `/queue foo` mid-turn. Verify either tab's recv-loop can drain the queued item. Confirm tab A's pill updates immediately while tab B's pill drifts (does not receive `QueueUpdated`).
**Expected:** Per CONTEXT.md D-01 / D-02a, queue is shared across tabs but `QueueUpdated` reaches only the WS that performed the action. Tab B's pill becoming stale is an accepted divergence — not a bug.
**Why human:** Visual + multi-WS state — requires two real browser tabs with a live server. The drift is intentional and documented; manual UAT is the only way to confirm UX acceptability.

#### 3. `/stop` clears queue without aborting in-flight turn

**Test:** While a long-running turn is actively streaming Deltas, send `/stop`. Confirm the current Delta stream continues to complete, the queue is cleared (any future drain finds nothing), and the user sees the Delta `"Queue cleared. Current turn finishing.\n"`.
**Expected:** Per D-05 documented divergence — Web `/stop` is clear-queue-only. The in-flight turn completes naturally. No abrupt termination.
**Why human:** Timing / visual; requires actually running a multi-second turn and observing the stream behavior. Source-text tests assert the absence of `handle.abort` and `cancel_token.cancel` but cannot exercise the live behavior.
