# Phase 36.17.4 Plan 05: Wasm queue pill wire-up Summary

Land the wasm-side queue UI: a `Signal<(u32, bool)>` on `HermesApp` is
updated from `ChatStreamEvent::QueueUpdated` events (shipped by Plan 02),
exposed via `use_context_provider`, and rendered by `AppFooter` as a
`QUEUE N` / `QUEUE N (paused)` pill that hides when depth is zero.

## What shipped

| File | Change |
| --- | --- |
| `crates/iron_hermes_ui/src/components/hermes_app/mod.rs` | `let mut queue_state = use_signal(|| (0u32, false));` declared alongside `subagent_events`; Plan 02's NO-OP `QueueUpdated { .. }` placeholder match arm REPLACED with `QueueUpdated { depth, paused } => { queue_state.set((depth, paused)); }`; `use_context_provider(|| queue_state);` added alongside the existing `subagent_events` / `is_ws_connected` providers. |
| `crates/iron_hermes_ui/src/components/hermes_app/app_footer.rs` | `let queue_state = use_context::<Signal<(u32, bool)>>();` added beside the existing `active_screen` context; `let (queue_depth, queue_paused) = *queue_state.read();` reads the tuple into Copy locals before rsx! (clippy.toml safety); conditional pill `if queue_depth > 0 { span.sep + span "QUEUE " + value span with paused/not-paused two-arm rsx! }` inserted between the AGENT span and the `div.app-footer-right` group. |

## Deviations from Plan

**None.** Plan executed exactly as written. The plan's two-arm-rsx! fallback path (described in Task 2 Step B as the safer alternative for Dioxus 0.7 conditional rendering inside a value span) was the chosen branch — wrapped in the outer `if queue_depth > 0 { ... }` so the hide-when-zero discipline applies to the separator, the QUEUE label, and the value span together.

## Known Stubs

None. The pill is fully data-driven: it reads the live `queue_state` signal,
which is updated by the WS recv loop on every `QueueUpdated` event from the
server (gateway). When the queue is empty, the pill is absent from the DOM
(no placeholder text, no zero-state span).
