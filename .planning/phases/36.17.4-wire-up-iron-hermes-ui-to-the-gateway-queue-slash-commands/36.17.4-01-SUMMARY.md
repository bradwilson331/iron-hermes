# Phase 36.17.4 Plan 01: Extend `is_bypass` for pause/unpause Summary

One-line: Added `"pause" | "unpause"` to the `matches!` literal in `ironhermes_core::commands::running_agent::is_bypass`, restoring the D-08 locked-list invariant assumed by CONTEXT.md and unblocking Plan 04's `/pause` and `/unpause` arms (RESEARCH Finding 4 closure).

## What Shipped

A single-source-of-truth fix at the core crate level. The `is_bypass(name: &str) -> bool` function in `crates/ironhermes-core/src/commands/running_agent.rs` now returns `true` for both `"pause"` and `"unpause"`, so every consumer — `crates/iron_hermes_ui/src/server/ws.rs:242` (web), `crates/ironhermes-gateway/src/handler.rs` (gateway), and `crates/ironhermes-cli/src/tui_rata/commands.rs:370` (TUI) — automatically routes those slash commands around the running-agent guard via the existing `is_bypass(&def.name)` call.

The `is_bypass_locked_list` unit test was extended in lock-step:
- Two new positive assertions (`pause`, `unpause` must bypass).
- One new negative assertion (`PAUSE` must not bypass — case-sensitivity preserved for the new members, matching the D-01 discipline already locked for `STOP`).

## Why This Was Necessary

RESEARCH Finding 4 surfaced a critical mismatch: CONTEXT D-08 stated `is_bypass("pause") == true && is_bypass("unpause") == true` as a locked invariant, but the shipped `is_bypass` only matched `"stop" | "new" | "status" | "queue"`. Without this fix, Plan 04's planned `/pause` and `/unpause` arms in `ws.rs` would have been rejected by the running-agent guard whenever a turn was in flight — exactly when the user most needs to pause the drain. RESEARCH recommended Option B (extend `is_bypass` at the core level) over Option A (ws.rs interception) because the core-level fix benefits every surface from one diff with one test.

## Behavior Locked

After this plan, every consumer of `is_bypass` honors the following invariants:

- `is_bypass("stop")` → `true`
- `is_bypass("new")` → `true`
- `is_bypass("status")` → `true`
- `is_bypass("queue")` → `true`
- `is_bypass("pause")` → `true` *(new)*
- `is_bypass("unpause")` → `true` *(new)*
- `is_bypass("model")`, `is_bypass("retry")`, `is_bypass("approve")`, `is_bypass("deny")`, `is_bypass("")` → `false`
- `is_bypass("STOP")`, `is_bypass("PAUSE")` → `false` (case-sensitive — explicit assertion)

Observable TUI behavior is unchanged because `pause` / `unpause` are dispatched via `handle_session_control` (independent of the running-agent guard) — the test gate at `ironhermes-cli` confirms zero regression.
