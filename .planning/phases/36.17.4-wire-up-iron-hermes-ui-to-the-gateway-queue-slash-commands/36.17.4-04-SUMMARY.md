# Phase 36.17.4 Plan 04: wire-up-iron-hermes-ui-to-the-gateway-queue-slash-commands Summary

## One-liner

Wired the iron_hermes_ui WebSocket recv-loop to enqueue free-text via `queue.try_push` instead of rejecting, dispatched `CommandResult::{Queued, PauseQueue, UnpauseQueue}` arms with the depth-aware `Delta` + typed `QueueUpdated` pattern, enforced D-04 ordering on `NewSession`, intercepted `/stop` early with the D-04a sequence (zero abort calls), and extended the arm-2 `None =>` branch with the D-02 self-drain (paused-aware `queue.pop` + `QueueUpdated` socket frame + respawn mirroring the primary spawn block).

## What Was Built

### Task 1: Wire queue push + slash command arms (commit `96fdaac3`)

Six discrete edits to `crates/iron_hermes_ui/src/server/ws.rs` (single-file change, +442 lines net):

**Edit A — `web_key(session_id)` local helper** at the top of the `ws_chat` `async move` block. Returns a canonical `SessionKey` with `platform: Platform::Web`, `chat_id: session_id`, `user_id: Some("web")`. Used at 6+ call sites below to eliminate construction repetition.

**Edit B — Replaced the in-flight HARD REJECT** (lines 204-214 in pre-edit ws.rs):
- Old: `ChatStreamEvent::Error { message: "Another request is already in progress" }` socket emit + `continue`.
- New: Guard `if in_flight_turn.is_some() && !message.starts_with('/')` (slash commands fall through to the existing slash interception block so the Plan 01 bypass list applies). Inside the guard: snapshot the paused flag, build a fresh `(tx_q, rx_q)` pair, `match app_state.queue.try_push(&key, message.clone())`:
  - `Ok(())` → push `Delta { text: "Queued: \"{msg}\" ({depth} in queue)\n" }` + `QueueUpdated { depth, paused: paused_snapshot }`.
  - `Err(QueueError::CapacityReached { max, .. })` → push `Delta { text: "Queue is full ({max}/{max}). /stop or /flush to drain.\n" }` only (no QueueUpdated — depth did not change).
- Both paths push `Finished { total_tokens: 0 }`, drop tx_q, drain rx_q to the socket, then `continue`. Initially placed BEFORE the `let session_id = req.session_id;` bindings (compile error E0425), corrected on second pass to land AFTER the bindings.

**Edit C — Three new `CommandResult` arms** inserted BEFORE the existing `CommandResult::Output(t)` arm in the slash dispatch `match result` block. Each arm performs its own complete `tx.send(...)` sequence + `drop(tx)` + drain rx to socket + `continue`, bypassing the shared Delta/Finished delivery so `QueueUpdated` can be interleaved between Delta and Finished per the must_have invariant.
- `CommandResult::Queued { message: queued_msg }` — same `try_push` + cap-hit fork as Edit B (but reuses the primary `tx`/`rx` pair already in scope).
- `CommandResult::PauseQueue` — `paused_flag.fetch_xor(true, SeqCst)` toggle, emit `QueueUpdated { depth, paused: new_paused }` then `Delta { text: "Queue paused. ({depth} queued)\n" }` (if newly paused) or `Queue resumed. ({depth} queued)\n` (toggle returned was_paused=true) then `Finished`.
- `CommandResult::UnpauseQueue` — `paused_flag.swap(false, SeqCst)` explicit-set, emit `QueueUpdated { depth, paused: false }` then `Delta { text: "Queue resumed.\n" }` (if was paused) or `"Queue was not paused.\n"` then `Finished`.

**Edit D — Extended `CommandResult::NewSession`** with the D-04 ordering invariant. Before the existing `app_state.reset_web_session(&session_id);` call: `queue.clear(&key)` → `paused.store(false, SeqCst)` → push `QueueUpdated { depth: 0, paused: false }` into the primary `tx` (mpsc is FIFO, so this Delta-shaped event reaches the client BEFORE the `Delta { text: m }` emitted by the shared delivery below).

**Edit E — `/stop` early-intercept** added BEFORE the `let result = ironhermes_core::commands::handlers::dispatch(...)` call. Check on the canonical `def.name == "stop"` (Pitfall 4 — post-resolution name, not raw input). Sequence: `queue.clear(&key)` → `paused.store(false, SeqCst)` → `QueueUpdated { depth: 0, paused: false }` → `Delta { text: "Queue cleared. Current turn finishing.\n" }` → `Finished { total_tokens: 0 }` → drop(tx) → drain rx to socket → `continue`. NO `JoinHandle::abort()` (D-05 documented divergence). NO `cancel_token.cancel()` (no CancellationToken exists on AppState yet).

**Edit F — Extended the `None =>` branch in arm 2** with the D-02 self-drain. After capturing `session_id_done = turn.session_id.clone()` BEFORE the `turn.handle.await` (so the value survives the consumption), and after the existing `if let Err(err) = turn.handle.await { warn!(...) }`:
- Read `paused_flag.load(SeqCst)` into `paused_now`.
- If `!paused_now AND queue.pop(&key) returns Some(next_text)`:
  - Compute `depth_after = queue.len(&key) as u32`.
  - Emit `QueueUpdated { depth: depth_after, paused: false }` directly to the socket via `send_raw(Message::Text(serde_json::to_string(&qu_event).unwrap_or_default()))` BEFORE spawning the next turn (D-03 ordering: pill update before next Delta stream).
  - Build a fresh `(tx_drain, rx_drain) = mpsc::unbounded_channel()`, then `tokio::spawn` a future that mirrors the primary spawn block (lines 421-499 in the original ws.rs): construct a `StreamingContextScrubber` Arc, install `stream_callback` / `tool_progress_callback` / `tool_result_callback` + `subagent_callback_slot` (via `SubagentCallbackSlotGuard`), call `app_state_drain.run_web_turn(&session_id_spawn, &next_text_owned, ...)`, flush scrubber tail, emit `Finished { total_tokens }` on Ok or `Error { message }` on Err.
  - Assign `in_flight_turn = Some(InFlightTurn { session_id: session_id_done, rx: rx_drain, handle: drain_handle })` so the recv-loop continues servicing the drained turn.
- If `paused_now OR pop() == None`, leave `in_flight_turn = None` and fall through — the recv-loop naturally idles until the next inbound frame.

## Decisions Made

1. **Edit B placement bug found + fixed inline (Rule 1 / Rule 3)** — initial placement of the new in-flight push block was BEFORE the `let session_id = req.session_id; let message = req.message;` bindings derived from `req`. Compile gave 5 × E0425 ("cannot find value `message` / `session_id` in this scope"). Moved the entire push block to AFTER the bindings without re-introducing the legacy reject. No content change, position change only.

2. **D-05 documented divergence ratified at the code site** — `/stop` does NOT abort the in-flight `JoinHandle` on the web surface. AppState has no `CancellationToken` (and no `cancel_token` is threaded through `run_web_turn`). The user-facing acknowledgement is the Delta `"Queue cleared. Current turn finishing.\n"`. The in-flight turn completes naturally; when its `None =>` arm fires it sees an empty queue (we just cleared it) and does not re-drain. Mirrors CONTEXT.md's D-05.

3. **Test evolution (Rule 1)** — `busy_gate_opportunistically_clears_finished_turn` in `websocket_lifecycle_parity.rs` was pinned to the literal `"if in_flight_turn.is_some() {"` form. Plan 36.17.4 explicitly evolves that guard to `"if in_flight_turn.is_some() && !message.starts_with('/') {"`. Updated the test to search for the new form first with a fallback to the legacy form, so the WR-02 ordering invariant (finished-check BEFORE busy-gate) is still pinned but the body string is allowed to evolve.
