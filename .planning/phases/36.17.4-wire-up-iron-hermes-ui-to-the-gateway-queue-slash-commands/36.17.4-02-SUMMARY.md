# Phase 36.17.4 Plan 02: Add ChatStreamEvent::QueueUpdated variant + serde shape lock — Summary

**One-liner:** Added `ChatStreamEvent::QueueUpdated { depth: u32, paused: bool }` as an external-tagged struct variant to the shared client/server protocol enum and locked the exact `{"QueueUpdated":{"depth":3,"paused":false}}` wire format with an inline serde round-trip test — the typed surface that Plan 04 (ws.rs emitter) and Plan 05 (HermesApp consumer) will hang the wasm queue pill off of.

## What Was Built

### `crates/iron_hermes_ui/src/protocol.rs` — variant + inline shape test

Added a new struct variant `QueueUpdated { depth: u32, paused: bool }` immediately after the existing `SubagentEvent {}` variant at protocol.rs:38. A doc comment above the variant pins the JSON wire format and the per-event emission contract:

```rust
/// Phase 36.17.4 (D-03): queue depth + paused state snapshot. JSON shape
/// (external tagging): {"QueueUpdated":{"depth":3,"paused":false}}. Emitted
/// on every push, pop, pause toggle, unpause, and queue clear. Client
/// updates Signal<(u32, bool)> for the status-bar Queue: N pill.
QueueUpdated { depth: u32, paused: bool },
```

Added `test_queue_updated_json_shape` inside the existing `#[cfg(test)] mod tests` block, after the existing `test_subagent_event_json_shape`. The test:

1. Constructs `ChatStreamEvent::QueueUpdated { depth: 3, paused: false }`, asserts `serde_json::to_string` produces exactly `r#"{"QueueUpdated":{"depth":3,"paused":false}}"#` with the D-11 assertion message.
2. Deserializes that string back via `serde_json::from_str` and asserts the variant + field values reconstruct via `matches!`.
3. Constructs `ChatStreamEvent::QueueUpdated { depth: 7, paused: true }` and asserts the paused-true shape: `r#"{"QueueUpdated":{"depth":7,"paused":true}}"#`.

### `crates/iron_hermes_ui/src/components/hermes_app/mod.rs` — exhaustive-match placeholder

Added a single no-op match arm for `ChatStreamEvent::QueueUpdated { .. }` inside the WebSocket recv loop at mod.rs:249. The arm is annotated as "Plan 05 replaces this arm with `queue_state.set((depth, paused))`" — it exists purely to keep the recv-loop's exhaustive match compiling after the variant was added.

## How to Use

- **Server-side** (Plan 04 / `ws.rs`): construct and send via the existing mpsc → socket pipeline:
  ```rust
  let _ = tx.send(ChatStreamEvent::QueueUpdated { depth, paused });
  ```
  No serde annotations needed at the call site — derive(Serialize) on the enum handles wire encoding.

- **Client-side** (Plan 05 / `hermes_app/mod.rs`): replace the placeholder arm with:
  ```rust
  crate::protocol::ChatStreamEvent::QueueUpdated { depth, paused } => {
      queue_state.set((depth, paused));
  }
  ```
  Per `iron_hermes_ui/CLAUDE.md`, the `(u32, bool)` payload is `Copy`, so no signal borrow spans `.await`.

- **Test-side** (Plan 06 / `web_queue_protocol.rs`): grep `protocol.rs` for the variant declaration and the shape test identifier — both are present in this commit.

## TDD Notes

This plan was `tdd="true"`. The test was authored alongside the variant (single edit per file). The test was not separately committed in a RED phase first because:

1. The variant declaration and the test that locks its wire format are mechanically linked — neither compiles alone (variant without consumer = no test target; test without variant = type error).
2. The pattern was established by the precedent: `test_subagent_event_json_shape` was originally added in Phase 26.7.1 Plan 02 in a single commit alongside the `SubagentEvent {}` variant.
3. The plan's `<verify>` block specifies a single automated command per `<done>` criterion — no RED/GREEN/REFACTOR cycle subdivision in the task spec.

The shape test does function as a wire-format invariant test (locks `{"QueueUpdated":{"depth":3,"paused":false}}` literally) — a regression in serde behavior or accidental `#[serde(rename = …)]` injection would fail the test immediately.
