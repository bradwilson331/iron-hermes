## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] `make_queue` typed as `Arc<SessionQueue>` failed to compile against the `String`-typed trait API**
- **Found during:** Task 1 first verification run (`cargo test --test web_queue_drain`)
- **Issue:** `SessionQueue` exposes inherent methods on `MessageEvent` (concrete type) and a separate `impl MessageQueue<SessionKey>` whose `try_push`/`pop` take/return `String`. The plan's helper `fn make_queue() -> Arc<SessionQueue>` therefore resolved to the `MessageEvent`-typed inherent methods, producing `E0308: expected MessageEvent, found String` at every `try_push` / `pop` call.
- **Fix:** Re-typed the helper as `fn make_queue() -> Arc<dyn MessageQueue<SessionKey>>` — exactly mirrors `AppState::queue`'s declared shape in `state.rs`. Resolves dispatch to the `String`-typed trait impl, which is the surface `ws.rs` actually uses.
- **Files modified:** `crates/iron_hermes_ui/tests/web_queue_drain.rs`
- **Commit:** `13f68324`

**2. [Rule 1 — Bug] `fetch_xor(true` / `swap(false` substrings absent due to multi-line rustfmt wrapping**
- **Found during:** Task 2 first verification run (`cargo test --test web_queue_controls`)
- **Issue:** The plan's acceptance criterion required `WS_SOURCE.contains("fetch_xor(true")` and `WS_SOURCE.contains("swap(false")`. Production source formats these as `paused_flag.fetch_xor(\n  true,\n  std::sync::atomic::Ordering::SeqCst,\n)` (and same for `swap`), so the literal substring search fails even though the call is correctly present.
- **Fix:** Replaced the brittle literal-substring asserts with a method-site anchor (`find("fetch_xor(")`) plus a short 80-byte post-context slice that verifies the `true` (resp. `false`) argument appears. Same approach for `paused_flag.swap(...)`. Resilient to future rustfmt wrapping changes.
- **Files modified:** `crates/iron_hermes_ui/tests/web_queue_controls.rs`
- **Commit:** `845e4896`

**3. [Rule 3 — Scope] `include_str!` token count mis-prediction in plan acceptance**
- **Found during:** Task 1 and Task 3 acceptance-criterion verification
- **Issue:** Plan acceptance demanded an exact `grep -c 'include_str!'` count of 2 (Task 1) and 3 (Task 3). The first drafts each carried one additional occurrence inside a doc-comment that referenced the pattern by name (e.g. `Source-text anchors via \`include_str!\``). The `grep -c` includes doc-comment matches, so the count was over by 1 in each file.
- **Fix:** Reworded the doc-comments to `Source-text anchors mirror ...` / `All anchors are source-text grep — ...` so only the actual macro calls are counted. No functional change.
- **Files modified:** `crates/iron_hermes_ui/tests/web_queue_drain.rs`, `crates/iron_hermes_ui/tests/web_queue_protocol.rs`
- **Commit:** rolled into `13f68324` / `293aa06d` respectively.

### D-04a ordering anchor adjustment

The plan asked for `.store(false` as one of the /stop window ordering tokens. Source uses multi-line `.store(\n  false,\n  std::sync::atomic::Ordering::SeqCst,\n)`. I anchored on `.store(` instead and asserted the `false`-then-`Ordering` order via the cascading position checks (`queue.clear` < `.store(` < `QueueUpdated` < Delta text < `Finished {`). All five anchors still appear in the documented order; the substantive D-04a invariant is unchanged.
