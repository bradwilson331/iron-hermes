## Critical Pitfalls for Planner

**Pitfall 1 — `is_bypass` gap (RESEARCH Finding 4):** `"pause"` and `"unpause"` are NOT currently in `is_bypass`. File 9 (`running_agent.rs`) must add them. `web_queue_controls.rs` (file 7) must include a test that FAILS against the pre-fix binary. This is the highest-risk integration point.

**Pitfall 2 — Dioxus signal borrows:** In `mod.rs` and `app_footer.rs`, all signal `.read()` borrows must be dropped before any `.await` or RSX tree (clippy.toml enforces this). The `*queue_state.read()` deref-copy pattern satisfies the constraint for `(u32, bool)` which is `Copy`.

**Pitfall 3 — QueueUpdated emit ordering:** Emit `QueueUpdated` BEFORE `Finished` in slash arms, and BEFORE `tokio::spawn` in the drain arm. Reversed ordering produces a confusing client experience (pill updates after turn already started).

**Pitfall 4 — D-04 ordering in `/new`/`/reset`:** `queue.clear` → `paused.store(false)` → `QueueUpdated` → `reset_web_session`. Violating this order can leave stale queue items visible post-session-reset.

**Pitfall 5 — `/stop` is not a `CommandResult` variant:** `/stop` dispatches as `CommandResult::Handled` (no dedicated variant). Must intercept via `def.name == "stop"` check, not `CommandResult::Stop`. See RESEARCH Finding 5 pattern.

**Pitfall 6 — D-05 documented divergence:** Web `/stop` does NOT abort the in-flight `JoinHandle` (no `CancellationToken` on `AppState` yet). The Delta message `"Queue cleared. Current turn finishing.\n"` is the user-facing acknowledgement. Planner records this divergence in PLAN.md decisions + ROADMAP.md.
