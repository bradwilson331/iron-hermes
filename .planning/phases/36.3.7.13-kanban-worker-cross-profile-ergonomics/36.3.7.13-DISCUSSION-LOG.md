## Pre-discussion clarification — Gateway dispatch + config

User asked mid-flow: "Does the dispatch live in the gateway mode? What is the configs for the gateway look like?"

**Answer captured:** Dispatcher runs in TWO host contexts —
(1) CLI one-shot `ironhermes kanban dispatch` → `main.rs:935`, and
(2) Gateway background loop spawned at `runner.rs:1281` (Phase 36.3.7.5
Plan 03). Plus the dashboard plugin's REST `#[server]` fns + WS tailer at
`iron_hermes_ui/src/server/kanban_api.rs` (8 sites) + `kanban_ws.rs:239`.
SCOPE.md D-01 originally only named the CLI dispatcher — gateway runner +
dashboard were gaps. Gateway YAML stanza shape:

```yaml
kanban:
  dispatcher_enabled: true        # default false
  notification_sources: ["telegram"]
  notifier_poll_seconds: 3
  decomposer_model: "anthropic:claude-sonnet-4-6"
  judge_model: ""                 # falls back to auxiliary.kanban_judge
```

No `kanban_db_path` field — DB path resolution is HERMES_HOME-relative
via `paths::kanban_db_path()`. This answer reframed Area 1 (HERMES_KANBAN_DB
consumer scope) to include gateway + dashboard explicitly.
