# Phase 36.3.7.13 Plan 02: Worker Bin Override (F-02) Summary

**One-liner:** `resolve_worker_bin()` reads `IRONHERMES_WORKER_BIN` env first (falls back to `"ironhermes"` PATH lookup); added as 8th `SAFE_SYSTEM_VARS` entry + `Command::new` swap — closes F-02 symlink-dance foot-gun.

## What Was Built

Three edits to `crates/ironhermes-kanban/src/worker_spawn.rs`:

### Edit 1: SAFE_SYSTEM_VARS extended to 8 entries

```rust
pub const SAFE_SYSTEM_VARS: &[&str] = &[
    "PATH", "HOME", "USER", "LANG", "TERM", "RUST_LOG", "IRONHERMES_HOME",
    "IRONHERMES_WORKER_BIN",  // Phase 36.3.7.13 D-02: forward-compat for recursive worker spawn
];
```

This single append enables forward-carry: `build_kanban_worker_env` iterates `SAFE_SYSTEM_VARS` and includes any set vars in the child env — no other wiring needed.

### Edit 2: resolve_worker_bin() helper added

```rust
pub fn resolve_worker_bin() -> String {
    std::env::var("IRONHERMES_WORKER_BIN").unwrap_or_else(|_| "ironhermes".to_string())
}
```

Placed immediately after `SAFE_SYSTEM_VARS` declaration. Re-exported from `lib.rs` as `pub use worker_spawn::resolve_worker_bin`.

### Edit 3: Command::new swap at spawn site

```rust
// Before:
let child = Command::new("ironhermes")
// After (Phase 36.3.7.13 D-02):
let child = Command::new(resolve_worker_bin())
```

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] resolve_worker_bin visibility changed from pub(crate) to pub**
- **Found during:** Task 2 compile
- **Issue:** PATTERNS.md specified `pub(crate)` for `resolve_worker_bin`, but `pub(crate)` items cannot be re-exported via `pub use` in `lib.rs` (Rust E0364). Integration tests require the function via the crate's public API.
- **Fix:** Changed to `pub fn resolve_worker_bin()`. Function surface is appropriate to expose (it reads a non-secret env var; no security concern).
- **Files modified:** `crates/ironhermes-kanban/src/worker_spawn.rs`
- **Commit:** `ba764462`

**2. [Rule 1 - Bug] Rust 2024 edition requires unsafe blocks for set_var/remove_var**
- **Found during:** Task 1 first compile attempt
- **Issue:** `std::env::set_var` and `remove_var` are unsafe in Rust 2024 edition. Test file needed `unsafe { ... }` blocks wrapping each call.
- **Fix:** Wrapped all `set_var`/`remove_var` calls in `unsafe {}` blocks, matching the pattern used by `tests/tools_smoke.rs`.
- **Files modified:** `crates/ironhermes-kanban/tests/worker_bin_resolution.rs`
- **Commit:** `69dd064f`
