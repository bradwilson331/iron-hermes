# Phase 36.3.7.13 Plan 01: Cross-profile DB resolution (F-01 closure) Summary

Two new public constructors on `KanbanStore` — `open_from_env()` and
`open_from_env_or_board(Option<&str>)` — wired into all 25 dispatcher-bridged
open sites so workers spawned across profile boundaries now consume the
`HERMES_KANBAN_DB` env var the dispatcher has been setting since Phase
36.3.7.0. Closes F-01 (silent cross-profile DB mismatch surfaced in Phase
36.3.7.12 live UAT).

## Tasks Completed

### Task 1 — Add open_from_env() + open_from_env_or_board() + 6 bilateral tests (Wave 0 scaffold)

**Commit:** `f801a8d6`

- `crates/ironhermes-kanban/src/store.rs`: added two new public constructors
  immediately after `open_for_board` (around line 235). Both fns emit
  `tracing::info!(target: "kanban.db", path = %path, ...)` on every env
  override (D-H1 — locked target invariant).
- `crates/ironhermes-kanban/tests/cross_profile_db_resolution.rs`: new test
  file with **6 tests** (5 consumer + 1 producer-side per WARNING 6):
  1. `open_from_env_reads_hermes_kanban_db` — D-A1 env override wins

  4. `open_from_env_or_board_env_wins_over_slug` — D-A2 env beats slug
  5. `open_from_env_or_board_fallback_when_env_unset_and_no_slug` — D-A2 default fallback
  6. `build_kanban_worker_env_emits_hermes_kanban_db` — **producer-side**:
     `build_kanban_worker_env` emits `HERMES_KANBAN_DB=boards/my-board/kanban.db`
     for a named board slug. Forms bilateral pair with the consumer tests
     (LEARNINGS 2026-05-30: producer + consumer in same commit set).

  process-global env serialization (per STATE.md side-quest 4208bc28).
