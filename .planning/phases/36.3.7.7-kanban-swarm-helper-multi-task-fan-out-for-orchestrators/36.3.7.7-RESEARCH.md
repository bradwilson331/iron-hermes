## Summary

Phase 36.3.7.7 ships a single cohesive slice: `kanban_swarm` LLM tool + `hermes kanban swarm` CLI verb + `store.create_swarm(SwarmGraphSpec)` sibling method — the 10th LLM tool, closing the §664 v1-NOTE marker in `docs/kanban/reference.md`. The implementation follows the sibling-method pattern established by `insert_link_checked` (Phase 36.3.7.6) and the `block_task` (original 36.3.7) precedent: all inserts run inside a single `BEGIN IMMEDIATE` transaction that rolls back atomically on any failure.

All 8 open assumptions from CONTEXT.md have been resolved by direct source inspection. The most significant finding: **`task_comments.author` is a free-text column** — `add_comment` (store.rs:351) performs NO profile validation on the `author` argument, so the `"swarm"` sentinel string is unconditionally valid. The contingency fallback in D-blackboard-init is NOT needed.

`parse_max_runtime` is currently a `pub fn` at `tools/create.rs:45` (exported from the crate via `pub use create::parse_max_runtime` — confirmed by `tools_smoke.rs:430` importing it directly). The cleanest shared-module path is to keep it `pub` in `create.rs` and import it from `swarm.rs` as `use crate::tools::create::parse_max_runtime`. No new `shared.rs` file is required.

The `DEFERRED_KANBAN_SUBVERBS` array currently contains 24 entries; `"swarm"` is absent. A single `"swarm",` entry is the complete gateway-side change. The `tools_smoke.rs` receiver-test layout convention is fully verified: `// kanban_X tests` banner, `make_store()` helper (tempfile-backed, leaks tempdir), `ENV_LOCK` static mutex, `#[tokio::test]`, structured `v["status"] == "rejected"` / `v["reason"]` assertion shape. The `heartbeat_cli.rs` file establishes the exact CLI parity test convention: local `TestCli` + `TestSub` wrapper around `KanbanCommands`, `try_parse_from`, match-arm destructure.

**Primary recommendation:** Implement as a single `36.3.7.7-01-PLAN.md` (all deliverables fit within ~50 plannable tasks; no context-budget split needed).

### Pattern 1: Sibling-Method Transactional Primitive

**What:** A new `pub fn create_swarm(&mut self, spec: SwarmGraphSpec) -> Result<SwarmGraphIds>` alongside (not inside) `create_task`. Inlines INSERT statements inside a `tx` handle from `Connection::transaction_with_behavior(TransactionBehavior::Immediate)`.

**When to use:** Any time multiple rows must be written atomically and the caller already holds `&mut self` on `KanbanStore`.

**Example (sibling precedent from store.rs:440-481):**
```rust
// Source: crates/ironhermes-kanban/src/store.rs:440 (insert_link_checked)
pub fn insert_link_checked(&mut self, parent_id: &str, child_id: &str) -> Result<()> {
    use rusqlite::TransactionBehavior;
    let tx = self.conn.transaction_with_behavior(TransactionBehavior::Immediate)?;
    // ... all reads and writes via tx.execute() / tx.query_row() ...
    tx.commit()?;
    Ok(())
}
```

**create_swarm mirrors this exactly.** The `tx` handle is passed to `append_event_internal` (which accepts `&Connection`, not `&mut KanbanStore` — confirmed at store.rs:181: `fn append_event_internal(conn: &Connection, ...)`) so it works against the tx handle without borrow conflict.

### Anti-Patterns to Avoid

- **Calling `create_task` inside `create_swarm`:** `create_task` takes `&mut self` and runs its own autocommit per statement — a re-entrant call inside `create_swarm`'s outer `BEGIN IMMEDIATE` would either deadlock (SQLite rejects nested writes on the same connection in Immediate mode) or break atomicity. Locked in D-no-create-task-reuse. [VERIFIED: source — store.rs:243 shows `self.conn.execute(...)` without tx handle]
- **Using `insert_link_checked` inside the swarm tx:** `insert_link_checked` opens its own `BEGIN IMMEDIATE` on `self.conn`. Nesting is not possible. Use plain `INSERT OR IGNORE INTO task_links` inside the swarm tx (cycles are impossible by construction — all nodes are freshly minted with new IDs in this same tx). [VERIFIED: reasoning — locked in CONTEXT.md]
- **Top-level boolean schema combinators (`oneOf` at tool root):** Banned per Phase 36.3.7.2 Anthropic compat rule. Only nested `oneOf` inside a property value is safe. [ASSUMED — from CONTEXT.md, not re-verified here]
- **Missing `unsafe` on `std::env::set_var` / `remove_var` in tests:** Rust 1.80+ requires `unsafe` blocks. All existing `tools_smoke.rs` tests already use `unsafe { std::env::set_var(...) }` consistently (verified at tests:212, 561, 599). New swarm tests must follow suit.
- **Not leaking tempdir in `make_store()`:** The existing `make_store()` calls `std::mem::forget(dir)` deliberately (tools_smoke.rs:45). Tests that create their own stores must do the same or the DB file will be deleted before the test finishes.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Atomic multi-write | Manual autocommit loop | `connection.transaction_with_behavior(TransactionBehavior::Immediate)` | Proven pattern at store.rs:440, 773 |
| Duration string parsing | Custom regex/match | `parse_max_runtime` from `crate::tools::create` | Already pub, tested, handles `s/m/h/d` + integer |
| Profile name validation | Custom alphanumeric check | `ironhermes_core::profile::validate_profile_name` | Same validation used by all 9 existing tools |
| Workspace path validation | Manual path::is_absolute check | `validate_dir_workspace` from `crate::paths` | Already handles `dir:` prefix and relative-path rejection |
| Unique task ID generation | UUID or timestamp | `KanbanStore::new_id("t")` / `new_id("c")` | Consistent `t_<hex8>` format; already used by all task types |
| Cycle detection on new links | Custom DFS | Plain `INSERT OR IGNORE` (no check needed) | Cycles impossible by construction — all swarm nodes are freshly minted in the same tx with new IDs; no pre-existing edges connect to them |

**Key insight:** `create_swarm` is deliberately thin. It inlines proven SQL patterns from `create_task` and reuses existing store helpers (`append_event_internal`, `find_by_idempotency_key`). The only new logic is: (a) computing per-card idempotency suffixes, (b) setting root's `status='done'` + `ended_at=now`, (c) normalizing the `workers` union type to `Vec<KanbanWorkerSpec>`, and (d) wiring the optional verifier/synthesizer topology.

## Common Pitfalls

### Pitfall 1: `ended_at` column missing from root INSERT
**What goes wrong:** Root card has `ended_at = NULL` instead of `now()`, breaking the `status='done'` + `ended_at` invariant (mirrored from `complete_task` behavior).
**Why it happens:** The `create_task` INSERT does NOT include `ended_at` (it defaults NULL); developers copy it verbatim for root without adding the column.
**How to avoid:** Explicitly add `ended_at` to the root card's INSERT column list with `?16 = now`.
**Warning signs:** `ended_at IS NULL` for a root card with `status='done'` — violates D-root-ended-at.

### Pitfall 2: Borrow conflict when passing `tx` to `append_event_internal`
**What goes wrong:** Calling `append_event_internal(&self.conn, ...)` while `tx` is alive causes a borrow conflict (`self.conn` is borrowed exclusively by the tx).
**Why it happens:** `append_event_internal` signature is `fn(conn: &Connection, ...)`. Inside `create_swarm`, the tx handle IS the connection — pass `&tx` (which derefs to `&Connection`), not `&self.conn`.
**How to avoid:** All calls inside `create_swarm`'s tx block: `Self::append_event_internal(&tx, ...)`.
**Warning signs:** Rustc error "cannot borrow `self.conn` because it is already borrowed" or "cannot borrow `*__tx` as immutable because it is also borrowed as mutable".

### Pitfall 3: Idempotency replay returns wrong type
**What goes wrong:** When the root already exists (idempotency replay path), the function returns `Ok(existing_task)` as a `Task` instead of a `SwarmGraphIds`.
**Why it happens:** The `find_by_idempotency_key` helper returns `Option<Task>` (same as `create_task` uses). `create_swarm` needs to walk `task_links` from root to reconstruct `SwarmGraphIds` on the replay path.
**How to avoid:** Replay path: look up root by `k:root` → query `SELECT child_id FROM task_links WHERE parent_id = <root_id>` → re-derive `worker_ids`, `verifier_id`, `synthesizer_id` from task statuses or link cardinality.
**Warning signs:** Replay returns `{root_id: "...", worker_ids: []}` (empty workers) instead of the full graph.

### Pitfall 4: ENV_LOCK not held during env-var manipulation in tests
**What goes wrong:** Parallel test runs clobber `HERMES_KANBAN_TASK` / `HERMES_PROFILE` across test instances, producing `task not found: t_<other-test's-id>` flakiness.
**Why it happens:** Cargo runs `#[tokio::test]` functions concurrently within a test binary.
**How to avoid:** `let _env_guard = ENV_LOCK.lock().unwrap_or_else(|e| e.into_inner());` as the FIRST line of every test that calls `set_var`/`remove_var`. (Confirmed pattern at tools_smoke.rs:35, used at 109, 205, 554, etc.)
**Warning signs:** Intermittent `task not found` or `invalid assignee` errors in swarm tests when run with `cargo test` (they pass when run with `cargo test -- --test-threads=1`).

### Pitfall 5: CLI `--workers` comma parsing vs clap tokenization
**What goes wrong:** `--workers a,b,c` is not automatically split into `Vec<String>` by clap — it arrives as a single `String` `"a,b,c"` that `cmd_swarm` must split on `,`.
**Why it happens:** Clap's `Vec<String>` with a long argument parses space-separated items or repeated flags, not comma-separated strings.
**How to avoid:** Declare `workers: Option<String>` in the `Swarm` variant (not `Vec<String>`), split on `,` in `cmd_swarm`'s body.
**Warning signs:** `--workers a,b,c` arriving as `workers = Some("a,b,c")` with only 1 element if treated as Vec.

### Pitfall 6: `blackboard-file` not resolved before `SwarmGraphSpec` construction
**What goes wrong:** `SwarmGraphSpec.blackboard` receives a file path string instead of the parsed JSON value.
**Why it happens:** `cmd_swarm` receives `--blackboard-file <path>` as `Option<PathBuf>` — the file must be read and JSON-parsed before building `SwarmGraphSpec`.
**How to avoid:** `cmd_swarm` resolves `blackboard_file` → `serde_json::from_reader(File::open(path)?)` before constructing `SwarmGraphSpec`. The store layer only ever sees `Option<serde_json::Value>`.
**Warning signs:** `serde_json::from_str` error on what should be a JSON object but gets a file path string.

## Risk Inventory

### Risk 1: `ended_at` column omission on root card
**Probability:** Medium (easy to overlook since `create_task` doesn't set it)
**Impact:** High — root card is `status='done'` with `ended_at=NULL`, which violates the D-root-ended-at invariant and may confuse dashboard queries expecting `ended_at IS NOT NULL` for done cards
**Mitigation:** Include an explicit test `swarm_root_card_has_ended_at_set` that asserts `store.get_task(root_id).ended_at.is_some()`
**Pattern anchor:** bilateral-tracing-by-construction — the test ships in the same commit as the store method

### Risk 2: Idempotency replay reconstructs `worker_ids` incorrectly
**Probability:** Medium (non-trivial query to reconstruct full SwarmGraphIds from task_links)
**Impact:** High — replay returns wrong IDs, breaking the "re-invocation is safe" guarantee
**Mitigation:** Test `swarm_idempotency_key_replays_return_same_graph` must assert that replayed `worker_ids` matches the original slice (by value, not just by count)
**Pattern anchor:** The atomic transaction guarantee means "fully present or fully absent" — only one query needed: `SELECT child_id FROM task_links WHERE parent_id = <root_id>`

### Risk 3: `KanbanCommands` `Debug` derive absent — TestSub in swarm_cli.rs fails to compile
**Probability:** High (trip-wire for anyone who tries to derive Debug on TestSub)
**Impact:** Low (compile error, not a runtime bug)
**Mitigation:** heartbeat_cli.rs comment (line 14) documents this explicitly; swarm_cli.rs should copy the same comment verbatim
**Pattern anchor:** develop-direct — the test file is in-tree and the compile error surfaces immediately on `cargo build`

### Risk 4: `"swarm"` placement in `DEFERRED_KANBAN_SUBVERBS` vs. future `"heartbeat"` addition
**Probability:** Low (heartbeat is already absent from the array; the CONTEXT.md note confirms this was intentional per 36.3.7.6 D-no-deferred-subverbs-change)
**Impact:** Low — `"heartbeat"` was deliberately NOT added because `hermes kanban heartbeat` was shipped as a real CLI verb. Similarly, `"swarm"` is being added to the deferred list precisely because slash surface is deferred. No conflict.
**Mitigation:** None needed; the invariant is already correctly recorded in the 36.3.7.6 SUMMARY.

### Risk 5: Blackboard JSON round-trip loses type information
**Probability:** Low
**Impact:** Low (blackboard is opaque; workers parse it themselves)
**Mitigation:** Test `swarm_blackboard_arg_seeds_initial_comment_on_root` asserts `serde_json::from_str::<Value>(comment.body)` succeeds and the parsed value equals the input value. The test seeds a structured JSON with multiple types (`{nested: {a: 1, b: [1, 2, 3]}, flag: true}`) to catch partial serialization.
