## Graph topology

| Option | Description | Selected |
|--------|-------------|----------|
| Both tiers optional | Required: root + N workers. --verifier and --synthesizer each independently optional. 4 allowed shapes covering P1, P3, full 4-tier, and fan-out+verify. | ✓ |
| Verifier required, synth optional | Required: root + N workers + verifier. Synthesizer optional. Forces a quality gate on every swarm. | |
| Full 4-tier always required | Matches reference.md §664 example verbatim. Every swarm has root + N workers + verifier + synthesizer. | |

**User's choice:** Both tiers optional.
**Notes:** User explicitly grounded the decision in the patterns table at `docs/kanban/reference.md` §740-744 — "Fan-out only (Root → Workers) matches P1 Fan-out ('research 5 angles in parallel'). Fan-out + Synthesizer (Root → Workers → Synthesizer) matches P3 Voting / quorum ('3 researchers → 1 reviewer picks'). Full 4-tier (Root → Workers → Verifier → Synthesizer) covers the complex pipeline scenario shown in the example. Therefore, allowing all four shapes provides the flexibility needed to handle different multi-agent workflows without requiring a strict 4-tier topology every time." Locked as D-topology-shapes with explicit shape↔pattern mapping table in CONTEXT.md.

## Tool input shape

| Option | Description | Selected |
|--------|-------------|----------|
| Both (flat + structured via nested oneOf) | workers accepts array-of-string OR array-of-object via nested oneOf. CLI: --workers a,b,c AND --workers-json '[...]'. Matches P1 fan-out and P8 fleet farming. | ✓ |
| Flat only (assignees) | workers: [string] always. Each card gets the same body + auto-suffixed title. Fleet farming becomes N separate kanban_create calls. | |
| Structured only | workers: [{assignee, title?, body?}]. Even simple cases must pass objects. Slightly more verbose for the common case. | |

**User's choice:** Both.
**Notes:** Anthropic tool-API compatibility preserved by using nested `oneOf` inside the `workers` property (not top-level) — same pattern as `kanban_create::max_runtime` at tools/create.rs:138-144. CLI flags `--workers` (flat, comma-separated) and `--workers-json` (rich, JSON-parsed) are mutually exclusive at parse time. Locked as D-worker-shape + D-cli-worker-flags.

## Blackboard semantics — initial payload

| Option | Description | Selected |
|--------|-------------|----------|
| Yes, optional --blackboard arg | swarm accepts optional `blackboard: <json>` (LLM) / `--blackboard <json>` or `--blackboard-file <path>` (CLI). When present, appends one TaskComment to root with body = JSON, author='swarm'. | ✓ |

**User's choice:** Yes, optional --blackboard arg.

Fallback documented in CONTEXT.md if research surfaces validator constraint. Blackboard JSON is opaque — swarm does NOT parse, validate, or impose a schema (D-no-blackboard-validation). Locked as D-blackboard-init.

## Blackboard semantics — root discovery

| Option | Description | Selected |
|--------|-------------|----------|
| Walk parents via kanban_show | Workers call kanban_show on $HERMES_KANBAN_TASK → sees parents = [<root>]. Walks to root. Zero spawn-contract change. | ✓ |
| Mark root with sentinel + helper tool | Root gets a sentinel (assignee='__swarm_root__' or tenant='swarm:<id>'). Ship a kanban_blackboard tool that auto-walks to root. Bumps tool count to 11. | |
| Stamp HERMES_KANBAN_SWARM_ROOT on spawn | Extend worker_spawn.rs env contract with a 10th var. Touches the locked 9-env spawn invariant (INV-36.3.7). | |

**User's choice:** Walk parents via kanban_show.
**Notes:** The 9-env-var worker spawn contract from `crates/ironhermes-kanban/src/worker_spawn.rs::build_kanban_worker_env` is locked by INV-36.3.7 invariants. Workers' single parent IS the root by topology construction (worker `parents = [root]`); verifier/synth are 1-2 hops away. SQLite point lookups on `tasks.id` PK are sub-millisecond — no performance concern. Planner may optionally append a brief paragraph to `kanban_guidance.rs` documenting the swarm-root-walk pattern. Locked as D-root-discovery.

## Slash surface deferral

| Option | Description | Selected |
|--------|-------------|----------|
| Defer slash | Pattern-match 36.3.7.6. Ship LLM tool + CLI verb. Add 'swarm' to DEFERRED_KANBAN_SUBVERBS so /kanban swarm returns CLI-redirect message. | ✓ |
| Ship slash (flat form only) + auto-subscribe root | Add cmd_kanban arm in handlers.rs for 'swarm' subverb. Parse flat form only. Auto-subscribe chat to root so verifier/synth completion notifications fire via 36.3.7.5 notifier. Adds ~150 LOC + 4-6 receiver tests. | |

**User's choice:** Defer slash.
**Notes:** Mirrors the 36.3.7.6 disposition for `link`/`unblock`/`heartbeat`. Rich worker form (`--workers-json '[{...}]'`) is chat-hostile. Auto-subscribe-the-chat-to-root would need a KanbanStoreWriter trait extension (current writer's `append_subscription` only covers the single-card create path). Forward phase can ship gateway wiring if chat demand materializes — non-blocking for the 10-tool surface milestone. 1-line addition to `DEFERRED_KANBAN_SUBVERBS` is the entire gateway-side surface change. Locked as D-slash-deferred.
