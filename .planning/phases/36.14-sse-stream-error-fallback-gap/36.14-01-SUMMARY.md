# Phase 36.14 Plan 01: SSE Stream Error Fallback Gap Summary

## One-liner

Added `StreamEvent::ProviderError(String)` with tolerant numeric+string code extraction and log-hygiene capping so HTTP-200 SSE error envelopes from OpenRouter/Qwen activate the PROV-07 fallback chain via `classify_llm_error_typed`.

## Objective

Closed the SSE stream error silent-drop gap: when an LLM provider returns HTTP 200 but embeds an error payload inside an SSE data line (`data: {"error":{"message":"...","code":400}}`), the stream consumer previously silently dropped it at `debug!` level and `call_llm_streaming` returned `Ok((empty_message, None))` — the fallback chain never activated.

## What Changed

### `crates/ironhermes-agent/src/client.rs`

- Added `ProviderError(String)` variant to `StreamEvent` enum (with doc comment linking to phase 36.14).
- Added `fn extract_sse_error_code(val: &serde_json::Value) -> Option<u16>` — tolerant extractor that accepts both numeric (`as_u64`) and string (`as_str().parse::<u16>()`) code shapes (Codex MEDIUM #2).
- Added `fn sse_error_to_bail_string(raw: &str, val: &serde_json::Value) -> String` — formats the propagated error string with `(NNN Reason)` token, extracts `error.message` field, caps raw JSON tail at 512 chars with `... [truncated]` marker (Codex MEDIUM #3 log hygiene).
- Replaced `Err(e)` arm in SSE consumer loop with second-pass `serde_json::Value` parse: if the chunk is a JSON object with a top-level `"error"` key, sends `StreamEvent::ProviderError(msg)` and returns. Otherwise preserves the existing `debug!("Failed to parse stream chunk...")` log (D-05).

### `crates/ironhermes-agent/src/agent_loop.rs`

- Added `StreamEvent::ProviderError(body) => return Err(anyhow::anyhow!(body))` arm in the exhaustive `match event { ... }` block inside `call_llm_streaming`, placed before `StreamEvent::Done(_) => break`.
- Added 7 unit tests in the `fallback_tests` cfg(test) mod covering 400 (numeric + string code), 429, 500, 502, 503, and unknown-code SSE error fixtures.

### `crates/ironhermes-agent/tests/sse_provider_error_stream.rs` (new)

7 `#[tokio::test]` integration tests using wiremock: mount an HTTP 200 SSE response with an error envelope body, drain events, assert `StreamEvent::ProviderError` is emitted with the correct `(NNN Reason)` status token. Covers 400 (numeric), 400 (string code), 429, 500, 502, 503, and unknown-code fixtures.

### `crates/ironhermes-agent/tests/invariants_36_14.rs` (new)

4 static-grep tests:
1. `client_has_sse_provider_error_variant_prov07` — `ProviderError(String)` in client.rs

3. `agent_loop_handles_sse_provider_error_prov07` — `StreamEvent::ProviderError` in agent_loop.rs
4. `agent_loop_provider_error_returns_err_anyhow_prov07` — co-occurrence: `return Err(anyhow` within 400 bytes of `StreamEvent::ProviderError(body)` (Codex LOW #5 strengthened invariant)

## Deferred Items

Per plan `<deferred>` section:
- **Partial content before SSE error envelope** — if a provider streams `ContentDelta` events before the error envelope, those tokens have already been observed by the UI. `call_llm_streaming` returns `Err` and discards in-function accumulated text. Trade-off accepted for phase 36.14; locked by co-occurrence invariant + deferred entry.
- **`(NNN Reason)` string-bridge is a compatibility hack** — long-term fix is a structured `ProviderErrorSource::SseBody` classifier API. Tracked for a future provider-polish phase.
- **AnthropicClient SSE-body error path** — D-04 scope exclusion; monitor if third-party providers via AnthropicMessages arm exhibit this behaviour.
- **Emit SSE error body as `usage_events.error_kind` row** — requires schema extension, deferred.
