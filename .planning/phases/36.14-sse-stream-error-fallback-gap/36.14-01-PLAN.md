<objective>
Close the SSE stream error silent-drop gap in the PROV-07 fallback chain.

**Current behaviour (broken):** When a streaming LLM provider (e.g. OpenRouter) returns HTTP 200 but embeds an error payload as a plain SSE data line (`data: {"error":{"message":"...","code":400}}`), the stream consumer in `client.rs` tries to deserialise the line as `ChatStreamChunk`, fails, emits `debug!("Failed to parse stream chunk...")`, and silently continues. `call_llm_streaming` returns `Ok((empty_message, None))`. The fallback condition in `run()` is never reached. Configured `fallback_providers` never activate.

**Target behaviour (fixed):** When the stream consumer encounters a failed `ChatStreamChunk` parse and the raw data is a JSON object with a top-level `"error"` key, it sends `StreamEvent::ProviderError(formatted_error_string)` and exits. `call_llm_streaming` returns `Err(anyhow!(formatted_error_string))`. `classify_llm_error_typed` classifies it (400 → `SchemaInvalid` → `should_fallback=true`; 429/5xx → retry+fallback; unknown → `Unknown` → safe no-fallback default). The existing `run()` fallback/retry block activates the configured fallback provider as designed.

**Replan summary (vs. the original 36.14-01-PLAN.md reviewed by Codex):**

This plan revises the original two-task structure in response to the Codex cross-AI review in `36.14-REVIEWS.md`. Changes:

1. **HIGH — Atomicity.** Task 1 now lands the new `StreamEvent::ProviderError(String)` variant AND its match arm in `call_llm_streaming` in **the same task and the same commit**. The previous structure split these across two commits, and the exhaustive `match event { ... }` block in `agent_loop.rs::call_llm_streaming` (lines 1805–1828, confirmed no wildcard) would have failed `cargo build -p ironhermes-agent` between Task 1 and Task 2.
2. **MEDIUM — Tolerant code extraction.** The plan now requires an `extract_sse_error_code` helper that handles BOTH `as_u64()` and `as_str()?.parse::<u16>()` shapes (provider variation: OpenRouter sometimes returns `"code":400`, some upstreams forward `"code":"400"`).
3. **MEDIUM — Log hygiene.** The propagated error string now extracts the `message` field and length-caps the raw JSON tail at 512 chars with a `... [truncated]` marker so request IDs / echoed user input cannot bloat `warn!`-level fallback logs.
4. **MEDIUM — Partial-content-then-error.** Explicitly acknowledged in this plan (see `<deferred>` and the on-stream callback note in Task 1 `<behavior>`). The trade-off is accepted; no mitigation implemented in phase 36.14.
5. **LOW — Strengthened invariants.** `invariants_36_14.rs` now asserts CO-OCCURRENCE of `StreamEvent::ProviderError` AND `return Err(anyhow` in `agent_loop.rs` source, not just token presence.
6. **NEW — Real stream-path integration test.** Added `crates/ironhermes-agent/tests/sse_provider_error_stream.rs` using the existing `wiremock` infrastructure (already a dev-dependency; pattern mirrors `tests/streaming_usage_capture.rs`). Covers 400, 429, 500, 502, 503, AND the string-code shape.

Decision traceability:
- D-01: error detection only in the existing parse-failure branch; serde_json::Value second-pass; top-level "error" key check.
- D-02: StreamEvent::ProviderError(String) variant; stream task sends and returns; call_llm_streaming converts to Err.
- D-03: extract SSE error "code" field (NUMERIC or STRING) → "NNN Reason" format → extract_http_status recognises it.
- D-04: AnthropicClient excluded (its own SSE loop emits `StreamEvent::Done(None)` on unrecognized chunks per anthropic_client.rs line 1135; no error-envelope path observed for the Anthropic-native wire format).
- D-05: existing debug! log for non-error parse failures is preserved.
- D-06: invariants_36_14.rs static-grep locks variant, match arm, AND the new co-occurrence assertion.

**Scope:** Four files (one new test crate-level file added), two atomic commits. No changes to `run()`, `classify_llm_error_typed`, `classify_400_subcases`, or `AnthropicClient`.
</objective>

## Carry-overs and intentional non-mitigations

- **Partial content before SSE error envelope** (Codex MEDIUM #4). If a provider streams `ContentDelta` events BEFORE emitting the error envelope, those deltas have already been forwarded to the on-stream callback by the time `StreamEvent::ProviderError` arrives. `call_llm_streaming` returns `Err` on receiving the event, which discards the in-function accumulated assistant text — but downstream consumers (TUI, web UI) may have already painted partial tokens. **Trade-off accepted for phase 36.14**: in practice, OpenRouter's documented failure mode (invalid model ID → error in first SSE data line) emits the error before any content. Providers that interleave content + error are rare. Mitigation deferred — if needed, add a "discard buffered output on ProviderError" hook to the on-stream callback in a future phase. The trade-off is locked by an inline comment on the new match arm and by this `<deferred>` entry.
- **`(NNN Reason)` string-bridge is a compatibility hack** (Codex LOW #6). The propagated error string format `"Streaming chat completion failed (400 Bad Request): ..."` exists so the existing `extract_http_status` regex picks up the status code and routes through `classify_400_subcases`. A long-term fix is a structured classifier API (e.g. `ProviderErrorSource::SseBody { code: u16, message: String }` carried alongside `anyhow::Error` via `.context()`), which would eliminate the string round-trip. Out of scope for 36.14; tracked here for the next provider-polish phase.
- **AnthropicClient SSE-body error path** (D-04 scope exclusion). The native Anthropic Messages API uses proper HTTP status codes for errors; no SSE-body error envelope has been observed. If a third-party provider exposed through the `AnthropicMessages` `AnyClient` arm ever surfaces this behaviour, the fix would mirror this one in `anthropic_client.rs`. Out of scope.
- **Emit the SSE error body as a `usage_events.error_kind` row** (carried over from the original plan). Richer SSE-origin forensics (actual error message) would require extending the `usage_events` schema. Not in scope for this phase.
- **Structured `SseErrorEnvelope` deserialize type** (carried over from the original plan). A `#[derive(Deserialize)] struct SseErrorEnvelope { error: SseErrorBody }` would give compile-time confidence about the shape. Deferred in favour of the simpler `serde_json::Value`-based approach (more resilient to provider variations like the string-code shape this plan now handles via the tolerant extractor).
