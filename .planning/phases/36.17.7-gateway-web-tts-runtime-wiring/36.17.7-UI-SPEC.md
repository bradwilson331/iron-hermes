# Phase 36.17.7 — UI Design Contract

> Visual and interaction contract for the web audio control surface introduced
> by Phase 36.17.7. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase is primarily backend (Rust/Dioxus server + runtime
> wiring). The only visible UI surface is the inline `<audio controls>` element
> that appears in the iron_hermes_ui chat transcript per each `send_audio` emit
> (D-02-a through D-02-f). All other decisions in D-01 through D-06 are runtime
> contracts and are out of scope for this spec.

**Accent reserved for:** Focus ring on the native `<audio controls>` element only.
Do NOT apply `--accent-primary` to the audio control chrome itself — the
browser's native control chrome is intentionally unstyled to avoid the
`appearance: none` complexity and browser inconsistency.

**Block stripe:** The block that contains the audio control uses the existing
`is-ai` block type with `--w-stripe-ai` (magenta `var(--accent-secondary)`)
per the existing block stripe rotation. Audio does not get a new stripe color.

**Source:** `warp-ih.css` lines 14-48, `design-tokens.css` lines 40-86.

## Component Inventory

### New: `AudioBlock` (or inline `Block::Audio` variant)

**Decision (from D-02-f):** One inline audio control per `send_audio` call,
dropped into the chat transcript at the exact stream position of the emit.
Multiple emits in a single turn produce multiple inline controls in order.

**Recommended block variant:** Add `Block::Audio { uuid: String, mime: String }`
to `crates/iron_hermes_ui/src/state.rs`. This gives the audio control the same
stable `key: "{entry.id}"` identity as other block entries and follows the
existing `BlockEntry` / `Block` dispatch model in `block_stream.rs`.

**CSS class:** `wh-block is-ai` — audio blocks are semantically Hermes output
and inherit the magenta left-stripe and author color of AI blocks. No new
class required.

**Dioxus RSX shape:**

```rust
// Inside Block match arm for Block::Audio { uuid, mime }:
div { class: "wh-block is-ai",
    div { class: "wh-block-head",
        span { class: "wh-author", "Hermes" }
        span { class: "wh-block-time", "{time_or_empty}" }
    }
    div { class: "wh-block-body wh-audio-body",
        audio {
            controls: true,
            preload: "none",
            "aria-label": "Synthesized audio",
            title: "{uuid}",
            src: "/audio/{uuid}",
        }
    }
}
```

The `src` attribute uses the HTTP replay route (`GET /audio/:uuid` per D-02-c).
For first-play from the binary WS frame, the executor builds a Blob URL via
`URL.createObjectURL` and sets `src` to that URL; the element falls back to
`/audio/{uuid}` when the Blob URL is no longer valid (page reload path).

## Interaction Contract

### Audio control states

| State | Visual | Notes |
|-------|--------|-------|
| Idle (unplayed) | Native `<audio controls>` at rest | Browser renders play button, duration (unknown until loaded), scrubber. No custom chrome. |
| Playing | Native `<audio controls>` playing state | Browser pause button, scrubber advancing. |
| Paused | Native `<audio controls>` paused state | Browser play button, scrubber frozen. |
| Error (src 404) | Native `<audio controls>` error state | Browser renders error indicator. No custom error overlay for v1. |
| Keyboard focused | 2px `outline` using `var(--accent-primary)` color | Applied via CSS rule below. |

### Focus ring (accessibility)

```css
/* In warp-ih.css or a new audio-specific rule block in main.css */
audio:focus-visible {
  outline: 2px solid var(--accent-primary);
  outline-offset: 2px;
}
```

This follows the identical pattern used for `.wh-tab:focus-visible` in
`warp-ih.css` line 126. Source: default + existing pattern.

### Autoplay policy (MANDATORY — D-02-b)

`autoplay` attribute MUST NOT be set on the `<audio>` element. No
`audio.play()` call on the client side. No "click anywhere to unlock" page-level
gesture handler. The user initiates playback via the native browser play button.
This is a hard constraint from D-02-b.

### Width

`width: 100%` on the `audio` element so it fills the `.wh-block-body` content
column. Do not set `max-width` — the block body already constrains the width
through `.wh-stream-scroll` padding.

### CSS additions for the audio body cell

```css
/* In main.css (additive, does not modify warp-ih.css) */
.wh-audio-body {
  padding-top: var(--space-2);   /* 8px gap above control */
}

.wh-audio-body audio {
  width: 100%;
  display: block;
}

audio:focus-visible {
  outline: 2px solid var(--accent-primary);
  outline-offset: 2px;
}
```

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| `aria-label` | `"Synthesized audio"` — descriptive; does not expose uuid to screen readers |
| `title` attribute | `{uuid}` — developer-visible hover tooltip for debugging; not surfaced to AT by default |
| Keyboard operability | Native `<audio controls>` is natively keyboard-operable (Space to play/pause, arrow keys to scrub) — no custom JS required |
| Focus visible | `audio:focus-visible` rule above provides visible 2px cyan outline |
| Color contrast | Native browser audio control chrome is unaffected by the IronHermes color system; the block background (`--w-bg-2`) and body text (`--fg`) meet WCAG AA (5.4:1 per `design-tokens.css` comment on `--fg-dim`) |
| Reduced motion | Audio scrubber animation is browser-native; no custom animations introduced |
| Coarse pointer | Native `<audio controls>` sizing is sufficient for touch; no custom hit-target override needed. If the touch override in `warp-ih.css` line 621-626 is applied to `.wh-icon-btn`, it does not affect `<audio>` — acceptable for v1. |

## Out-of-Scope UI (explicitly deferred per CONTEXT)

The following items were handed to executor discretion or deferred; do NOT
add to this phase's implementation scope:

- **TUI "🔊 played" indicator** — executor discretion per CONTEXT "Claude's
  Discretion" section. The ratatui TUI plays audio via rodio on the host; no
  new TUI widget is required unless the executor chooses to add it.
- **Toolset-list "registered" indicator column shape and labels** — D-06 locks
  the principle; concrete UX is planner territory, not UI-SPEC territory.
- **Custom audio player chrome** (replacing the native control) — rejected; the
  native `<audio controls>` is the v1 implementation. Custom chrome would
  require `appearance: none` hacks with significant cross-browser risk and is
  not necessary for the phase's success criteria.
- **Coalesced end-of-turn playlist** — rejected per D-02-f.
- **Volume slider, speed control** — native browser control provides these; no
  custom UI needed.
