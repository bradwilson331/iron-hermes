## MEDIUM 8 Behavioral Test Resolution

**Test name:** `tts_wiring_registers_tools_in_run_turn` (`crates/ironhermes-agent/tests/tts_per_turn_wiring.rs`)

**Path chosen:** **Direct ToolRegistry call** (the fallback path explicitly allowed in Plan 01 Task 1 `<behavior>` block).

**Rationale:** `AgentRuntime::for_tests()` is gated `#[cfg(any(test, feature = "test-support"))]`. From an integration-test crate (`tests/*.rs`), the `test` cfg does NOT activate for the `ironhermes-agent` dep — integration tests link against the regular library build, so `for_tests` is invisible unless the `test-support` feature is enabled on the dev-dep. Adding `ironhermes-agent` as a self-dep with `features = ["test-support"]` would force every workspace consumer's test build to compile that code path; isolating the behavioral assertion to a direct ToolRegistry exercise is cleaner.

The test asserts the exact mutation contract that Task 2's per-turn block commits to (`register_tts_tools(session_key, dispatcher, config)` results in `text_to_speech` + `send_audio` in the registry). The production wiring is verified by source-grep Test 5 (`agent_runtime_source_calls_register_tts_tools_in_run_turn`). End-to-end audible coverage is delivered by Plan 02 UAT-T.

**Result:** GREEN. Both `text_to_speech` and `send_audio` appear in the registry after `register_tts_tools` is called with the wiring's contents.

## ToolRegistry::register — Upsert vs Append Verdict

**Verdict: UPSERT** (verified at `crates/ironhermes-tools/src/registry.rs:137`):

```rust
pub fn register(&mut self, tool: Box<dyn Tool>) {
    let name = tool.name().to_string();
    assert!(
        !self.intercepts.contains_key(&name),
        "register: name '{}' already registered as an intercepted tool — schema duplication blocked at registry build (D-15)",
        name,
    );
    self.tools.insert(name, Arc::from(tool));   // ← HashMap::insert overwrites by key
}
```

`HashMap::insert` returns the previous value if the key existed; it does not duplicate. Therefore the per-turn `register_tts_tools` call in `run_turn` is idempotent — repeated turns replace the previous `SendAudioTool` instance (with the previous SessionKey + dispatcher) with the current turn's instance.

**No `unregister` call needed.** Pitfall 1 mitigation is structurally satisfied by `HashMap::insert` semantics.
