## Pattern Overview

**Overall:** Agentic LLM loop with layered safety nets

**Key Characteristics:**
- Single-process Node.js with a central `while` loop driving the agent
- Compiled MarrowScript (`.marrow` → `.js`) provides zero-latency deterministic components (tool routing, compression, repair)
- Defense-in-depth: clarification → plan → tool routing → execution → validation → improvement → decompose → escalation
- Plugin system extends tools, commands, and hooks without modifying core
- Two separate "compiled" artifact sets: `src/compiled/` (MarrowScript output) and `marrow/src/` (MarrowScript source)

## Layers

**Entry / CLI Layer:**
- Purpose: Parse arguments, load config, boot TUI, start MCP server mode
- Location: `bin/smallcode.js`, `bin/init.js`
- Contains: Arg parser, `.env` loader, `main()` boot sequence, top-level MCP/ACP mode switches
- Depends on: All other layers
- Used by: End users (CLI), CI pipelines

**Agent Loop Layer:**
- Purpose: Orchestrate per-turn LLM calls, tool dispatch, and all safety guardrails
- Location: `bin/smallcode.js:482` (`runAgentLoop`)
- Contains: Clarification check, tool routing, `chatCompletion`, tool-call dispatch loop, improvement loop, escalation triggers
- Depends on: Governor, Router, Tools, Session, Compiled features
- Used by: TUI `onSubmit` handler, non-interactive prompt mode, programmatic API

**Tool Layer:**
- Purpose: Define and execute tools the model can call
- Location: `bin/tools.js` (schemas), `bin/executor.js` (dispatch), `src/tools/builtin/` (implementations)
- Contains: 18+ tool definitions (read_file, write_file, patch, bash, search, find_files, memory_*, web_*, bone_compile, MCP tools, plugin tools)
- Depends on: Security sanitize, snapshot manager, shell session, MCP bridge
- Used by: Agent loop via `executeTool()`

**Governor Layer:**
- Purpose: Safety, quality, and loop-control enforcement
- Location: `bin/governor.js`, `src/governor/early_stop.js`
- Contains: `ToolScorer` (Bayesian tool confidence), `EarlyStopDetector` (patch spiral + read-loop detection), `checkAndEnforceHardFail`, `pickDecomposeStrategy`
- Depends on: Nothing (standalone safety checks)
- Used by: Agent loop at every tool call result

**Session Layer:**
- Purpose: Manage per-session and cross-session state
- Location: `src/session/`
- Contains: Plan tracking, snapshot/undo, token tracking, reference resolution, dependency graph, git context injection, image detection, action classification
- Depends on: Nothing (pure logic modules)
- Used by: Agent loop throughout `runAgentLoop()`

**Model Layer:**
- Purpose: LLM provider abstraction and multi-model routing
- Location: `src/model/`, `bin/model_client.js`
- Contains: `routeModel()` complexity estimator, model profiles, thinking-budget truncation, reviewer agent, multi-model chain, adaptive temperature
- Depends on: Config, compiled providers
- Used by: Agent loop for `chatCompletion` and escalation

**Compiled Layer:**
- Purpose: MarrowScript-compiled deterministic components (zero LLM overhead)
- Location: `src/compiled/`
- Contains: `tool_router.js` (intent classifier), `cognition/` (compress, repair, validate, classify), `features/` (checkpoints, context retrieval, multi-file coordination, policy)
- Depends on: Nothing (self-contained compiled output)
- Used by: Agent loop via adapters (`cognition_adapter.js`, `features_adapter.js`)

**Plugin Layer:**
- Purpose: Extensibility — add tools, prompts, commands, hooks
- Location: `src/plugins/`, `.smallcode/plugins/` (project), `~/.config/smallcode/plugins/` (user)
- Contains: `PluginLoader`, `SkillManager`, hook runner
- Depends on: Nothing (isolated sandbox)
- Used by: Agent loop tool dispatch and command handler

**TUI Layer:**
- Purpose: User interface (fullscreen default, classic readline fallback)
- Location: `src/tui/fullscreen.js`, `bin/tui.js`
- Contains: Alternate-buffer terminal UI, virtual framebuffer diff renderer, tool panel, chat panel, markdown renderer
- Depends on: chalk
- Used by: `runTUI()` in entry point

## Data Flow

### Primary Request Path (TUI interactive)

1. User types message → `FullScreenTUI.onSubmit()` (`src/tui/fullscreen.js`)
2. `runAgentLoop(userMessage, config)` called (`bin/smallcode.js:482`)
3. Clarification check — `checkNeedsClarification()` via `features_adapter` (`bin/features_adapter.js`)
4. `@file` reference resolution — `resolveReferences()` (`src/session/references.js`)
5. Git context auto-injection — `shouldInjectGitContext()` (`src/session/git_context.js`)
6. Plan-mode activation — `shouldPlan()` / `PlanTracker.activate()` (`src/session/plan_tracker.js`)
7. Deterministic tool routing — `classifyToolCategory()` from compiled router (`src/compiled/tool_router.js`)
8. Context compaction if over token budget — semantic compress or oldest-message drop
9. `chatCompletion(config, conversationHistory)` → LLM API call (`bin/model_client.js`)
10. Model responds with `tool_calls` → `executeTool(name, args)` → `bin/executor.js`
11. Tool result appended to `conversationHistory`; governor records success/failure
12. Improvement loop fires on write errors: retry → decompose → escalate
13. Model responds with text (no tool calls) → rendered in TUI, history updated
14. Reviewer agent fires async if files were edited (`src/model/reviewer.js`)
15. Trace saved (`bin/trace_recorder.js`)

### MCP Server Path

1. `smallcode --mcp` → JSON-RPC over stdio
2. `bin/smallcode.js` routes to MCP handler
3. Incoming tool calls dispatched directly to `executeTool()`
4. Results returned as JSON-RPC responses

### Non-Interactive Path

1. `smallcode --non-interactive -P "prompt"` or stdin pipe
2. Skips TUI boot, calls `runAgentLoop()` directly
3. Output printed to stdout

**State Management:**
- `conversationHistory` array in module scope of `bin/smallcode.js` — single source of truth for conversation
- `improvementAttempts` map tracks per-file retry counts within a turn
- `_planTracker`, `_bootstrapDetector`, `_testRunnerDetector` re-instantiated per `runAgentLoop()` call (per-turn state)
- Session persistence via `SessionStore` (`src/session/persistence.js`) — saved on exit

## Key Abstractions

**Tool Schema (OpenAI function-calling format):**
- Purpose: Defines the tool interface the LLM sees
- Examples: `bin/tools.js` TOOLS and COMPOUND_TOOLS arrays
- Pattern: `{ type: 'function', function: { name, description, parameters } }`

**Compiled MarrowScript Components:**
- Purpose: Deterministic logic compiled from `.marrow` source — replaces LLM calls for classification, repair, and compression
- Examples: `src/compiled/tool_router.js`, `src/compiled/cognition/`
- Pattern: Source in `marrow/src/**/*.ms`, compiled output in `src/compiled/**/*.js`

**Governor Safety Chain:**
- Purpose: Multi-layer loop termination — patch spiral, read loop, hard fail, greeting detection
- Examples: `src/governor/early_stop.js`, `bin/governor.js`
- Pattern: Each check returns a `signal` object `{ message, injection }` that gets pushed into `conversationHistory`

**Improvement Loop:**
- Purpose: Auto-fix validation errors (lint, compile) before giving up
- Examples: `bin/smallcode.js:1142-1330`
- Pattern: retry (×2) → decompose → escalate to cloud LLM → auto-rollback snapshot

**Plugin Manifest:**
- Purpose: Declarative plugin definition
- Examples: `.smallcode/plugins/hello-plugin/plugin.json`
- Pattern: JSON manifest with `tools[]`, `prompts[]`, `commands[]`, `hooks[]` arrays pointing to JS handler files

**MCP Server:**
- Location: `bin/smallcode.js` (`--mcp` flag)
- Triggers: `smallcode --mcp` or `npm run mcp`
- Responsibilities: JSON-RPC over stdio, exposes SmallCode tools to MCP-compatible hosts

**Init:**
- Location: `bin/init.js`
- Triggers: `smallcode-init` command or `smallcode init`
- Responsibilities: Project scaffold (creates `.smallcode/` directory, config template)

## Architectural Constraints

- **Threading:** Single-threaded Node.js event loop. MCP bridge runs as a separate child process communicating over stdio (JSON-RPC). No worker threads.
- **Global state:** `conversationHistory`, `config`, `toolScorer`, `earlyStop`, `tokenMonitor`, `traceRecorder`, `memoryStore`, `pluginLoader`, `skillManager`, `sessionStore`, `tokenTracker`, `_fullscreenRef` are all module-level singletons in `bin/smallcode.js`. The programmatic `src/api/index.js` uses instance properties instead.
- **Circular imports:** `bin/smallcode.js` requires from `bin/` and `src/` freely; `src/` modules must NOT require from `bin/` (one-way dependency).
- **Context budget:** Token estimation is char-count/4 heuristic, not exact. `SMALLCODE_CONTEXT_WINDOW` env var overrides auto-detection. Budget enforcement is advisory for local use.
- **Tool result cap:** Tool results are hard-capped at 4000 chars before being added to history (`bin/smallcode.js:1131`).

## Anti-Patterns

### Bypassing the executor

**What happens:** Calling `fs.readFileSync` / `execSync` directly inside `bin/smallcode.js` instead of going through `executeTool()`
**Why it's wrong:** Skips security sanitization in `src/security/sanitize.js`, snapshot recording, and RTK rewriting
**Do this instead:** Route all file and shell operations through `executeTool()` → `bin/executor.js`

### Adding state to `src/` modules

**What happens:** Storing mutable session state (counters, histories) in `src/session/*.js` module scope
**Why it's wrong:** `src/` modules are loaded fresh per-instance in the programmatic API but shared as singletons in CLI mode, causing cross-turn leakage
**Do this instead:** Pass state explicitly as arguments or keep it in `bin/smallcode.js` module scope (CLI) or `SmallCode` instance properties (API)

### Reading from `marrow/src/` at runtime

**What happens:** Importing `.ms` files directly at runtime instead of their compiled `.js` counterparts
**Why it's wrong:** MarrowScript source files are not valid Node.js; they require the MarrowScript compiler
**Do this instead:** Import from `src/compiled/` for runtime use; `marrow/src/` is source-only

## Error Handling

**Strategy:** Optimistic with layered recovery — never crash the agent loop on a single tool failure

**Patterns:**
- All tool calls wrapped in try/catch; errors returned as `{ error: string }` not thrown
- `checkAndEnforceHardFail()` in governor enforces absolute stop conditions (e.g., infinite loop detected)
- Improvement loop: validation failure → retry (×2) → decompose strategy → cloud escalation → snapshot rollback
- `EarlyStopDetector` injects corrective messages into history rather than throwing
- All plugin hooks wrapped in try/catch — plugin failures never propagate to agent loop

## Cross-Cutting Concerns

**Logging:** `console.log` redirected in fullscreen TUI mode to push output to the tool panel. Classic mode prints directly to stdout. `bin/tui.js` provides all formatting helpers (`toolStart`, `toolError`, `toolSuccess`, `renderMarkdown`).

**Validation:** Post-write validation via `runValidation(filePath)` in `bin/governor.js` — runs language-appropriate lint/compile check (node --check, python -m py_compile, tsc, etc.) and feeds errors back to the model.

**Authentication:** No in-app auth. API keys read from environment variables (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`) or `.env` file. See `bin/escalation.js` for provider config.
