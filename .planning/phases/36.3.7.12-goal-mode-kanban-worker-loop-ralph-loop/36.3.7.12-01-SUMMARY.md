# Phase 36.3.7.12 Plan 01: Schema-and-types foundation Summary

Land the v2 SQLite migration (3 new `tasks` columns), the matching producer-side fields on `Task` + `CreateTaskOptions` + `KanbanConfig`, the `JudgeFn` typedef in a new `judge.rs` sibling of `decomposer.rs`, and the `kanban_judge` entry in the `ironhermes-core` reserved-role list — unblocking Wave 2 (Plans 02–04) of the Goal Mode phase.

## What Was Built

### Schema (Task 1)

- `crates/ironhermes-kanban/src/schema.rs`:
  - `SCHEMA_VERSION` constant bumped from 1 → 2.
  - DDL `CREATE TABLE IF NOT EXISTS tasks (...)` block extended with three new columns: `goal_mode INTEGER NOT NULL DEFAULT 0`, `goal_max_turns INTEGER NOT NULL DEFAULT 20`, `goal_turns_used INTEGER NOT NULL DEFAULT 0`. Fresh-DB path.
  - `run_migrations(conn, current)` gains an `if current < 2 { ... }` branch that issues three idempotent `ALTER TABLE tasks ADD COLUMN ...` statements (each wrapped in `let _ =` to swallow rusqlite's duplicate-column error on partial re-run) followed by a load-bearing `UPDATE schema_version SET version = 2` that propagates failures with `?`. Existing-DB path.
- `crates/ironhermes-kanban/tests/goal_mode_migration.rs` (new): bilateral migration regression test with three `#[test]` functions — `fresh_db_has_v2_columns`, `v1_db_upgrades_to_v2` (hand-crafted v1 schema seed → re-open via `KanbanStore::new`), `migration_is_idempotent`. All three pass.

### Producer surface (Task 2)

- `types.rs::Task` gains `goal_mode: bool`, `goal_max_turns: u32`, `goal_turns_used: u32` (all `#[serde(default)]`).
- `store.rs::CreateTaskOptions` gains `goal_mode: bool`, `goal_max_turns: u32`.
- `store.rs::KanbanStore::create_task` binds the two new columns on INSERT, with producer-level coercion: `let goal_max_turns = if opts.goal_max_turns == 0 { 20 } else { opts.goal_max_turns };` per D-03. `goal_turns_used` is left to the DDL DEFAULT 0.
- `store.rs::row_to_task` + all six `SELECT id, title, ...` callsites updated to fetch the three new columns and hydrate them via `i64 → u32 / bool` casts (treating `goal_mode INTEGER` as `0/1` → `bool`).
- `dispatcher.rs::claim_and_spawn` inline `SELECT` + Row→Task mapper updated parallel to `row_to_task` so dispatched workers see the goal-mode fields on the `Task` passed to `SpawnFn`.
- `config.rs::KanbanConfig.judge_model: String` added (D-05) with `#[serde(default)]`, sibling of `decomposer_model`. `Default` impl + `default_matches_context_md` test updated.
- `tools/create.rs::KanbanCreateTool`: passes the LLM's optional `goal_mode` / `goal_max_turns` JSON args through to `CreateTaskOptions` (full schema entries land in Plan 02).
- CLI helper `cmd_create` and the two `fake_task` test helpers (`worker_spawn.rs`, `argv_receiver_36_3_7_0.rs`) extended with default values for the three new required `Task` / `CreateTaskOptions` fields.
- `crates/ironhermes-kanban/tests/goal_mode_persistence.rs` (new): three `#[test]` functions — `goal_mode_round_trips`, `goal_max_turns_zero_coerces_to_twenty`, `default_options_have_goal_mode_false_and_default_budget`. All pass.

## Decisions Made

- **Producer-level coercion over silent DDL DEFAULT**: the `create_task` site explicitly maps `goal_max_turns = 0 → 20` rather than relying on the column DEFAULT, so a caller binding `0` cannot accidentally land a 0-budget row even though the column DEFAULT also says 20. Encodes D-03's intent twice — once at the producer, once at the column — so a future caller that hand-rolls an INSERT still gets the budget floor.
- **`JudgeFn` uses the kanban-crate `Result` alias (not `anyhow::Result`)** — mirrors `DecomposeFn` exactly. The plan text suggested `anyhow::Result` but mirroring `decomposer.rs:141-142` one-for-one was a stronger anchor for the closure-injection contract; the kanban `Result` is itself a `KanbanError`-typed alias that `Other(#[from] anyhow::Error)` accepts, so production code in Plan 03 can still bubble provider errors via `anyhow::anyhow!(...)`.
- **`worker_turn_output: String` field on `JudgeRequest`** instead of streaming the trajectory — the Plan 04 wrapper will pass a flattened textual rendering of the last turn. Trajectory richness is a deferred observability concern.
- **`#[serde(default)]` on the three new `Task` fields** — keeps deserialization of any pre-migration JSON-serialized rows (none expected in this codebase, but a defense-in-depth choice for the gateway/UI consumer crates that may cache `Task` envelopes).
