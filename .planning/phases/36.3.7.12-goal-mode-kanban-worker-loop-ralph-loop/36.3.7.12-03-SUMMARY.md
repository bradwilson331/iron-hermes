# Phase 36.3.7.12 Plan 03: Goal Mode CLI surface + JudgeFn factory

CLI flag wiring (`--goal` + `--goal-max-turns N`) lands on `hermes kanban create`, `kanban show` reports goal-mode state, and `build_runtime_judge_fn` joins `build_runtime_decompose_fn` in `commands.rs` so Plan 04's Wave 3 loop wrapper has a real `JudgeFn` to inject — three threads on the production-CLI side of the crate-isolation fence.

### Task 2 — `build_runtime_judge_fn` (D-05)

- **`crates/ironhermes-cli/src/kanban/commands.rs`** — new pair of `pub fn` symbols directly below `build_runtime_decompose_fn`:
  - `resolve_judge_model_and_endpoint(kanban, main) -> anyhow::Result<(ResolvedEndpoint, String)>` — testable hoist of the cascade:
    - Tier 1: `kanban_config.judge_model` (non-empty) wins → main provider endpoint + that model.
    - Tier 2: `registry.resolve_role("kanban_judge")` returns Some → role endpoint + role's model.
    - Tier 3: main provider's default model.
    - Failure (no API key resolvable) → `Err` with actionable message naming BOTH `kanban.judge_model` AND `auxiliary.kanban_judge` (and `model.default`), mirroring decomposer CR-03 at commands.rs:1442-1454.
  - `build_runtime_judge_fn(kanban, main) -> anyhow::Result<JudgeFn>` — calls the resolver, then constructs the `Arc<dyn Fn(JudgeRequest) -> BoxFuture<Result<JudgeOutput>>>` closure:
    - System prompt: TRUSTED static text instructing the judge to return `{"verdict":"met"|"not_met","reason":"<short explanation>"}` JSON.
    - User prompt: `Title: …\n\nAcceptance criteria (body):\n…\n\nWorker output:\n…` — untrusted content scoped to the USER role (T-T03 prompt-injection mitigation).
    - `chat_completion(..., Some(1024), Some(0.0), None)` — short structured JSON, max determinism.
    - Three fail-closed parse gates:
      1. `serde_json::from_str` failure → Err with raw snippet truncated to 200 chars via `.chars().take(200).collect::<String>()` (UTF-8-safe; mirrors decomposer CR-01).
      2. Missing `verdict` field → Err with the same truncation.
      3. `verdict` value not in case-sensitive `{"met","not_met"}` → Err (T-T02 — even "MET", "yes", "true" fall through).
- **`crates/ironhermes-cli/tests/judge_model_resolution.rs`** (new, 10 tests):
  - Cascade tests (4): `tier_1_judge_model_explicit`, `tier_2_kanban_judge_role`, `tier_3_fallback_to_main_default`, `error_message_names_both_config_keys`.
  - Reachability test (1): `build_runtime_judge_fn_symbol_exists` — compile-anchor for `pub` visibility from outside the crate.
  - Wire-level closure tests (5) using `wiremock::MockServer` to fake the `/chat/completions` endpoint:
    - `closure_parses_met_verdict` — `{"verdict":"met","reason":"..."}` → `Ok(Met, reason)`.
    - `closure_parses_not_met_verdict` — `{"verdict":"not_met","reason":"..."}` → `Ok(NotMet, reason)`.
    - `unknown_verdict_returns_error` (T-T02) — `verdict="MAYBE"` → Err with both the locked verdict pair AND "MAYBE" in the message.
    - `non_json_body_returns_error_with_snippet` (T-T01 + I01) — non-JSON body → Err with raw snippet for operator triage.
    - `missing_verdict_field_returns_error` (T-T01) — well-formed JSON missing `verdict` field → Err.

No live-LLM call in this plan — closure semantics are exercised against wiremock-backed mocks. Live-LLM smoke belongs to Plan 05 manual UAT per RESEARCH §Manual-Only Verifications.

## Decisions Made

- **Testable side-effect hoist over inline cascade**: The decomposer's `build_runtime_decompose_fn` mixes the cascade with the closure construction in a single fn body. For the judge, the cascade is hoisted into `resolve_judge_model_and_endpoint` so the three tier_* tests can assert which model wins WITHOUT constructing or executing the closure. This is purely additive — `build_runtime_judge_fn` calls the helper and proceeds; the decomposer is unchanged.
- **`pub` not `pub(crate)`**: Plan 04's loop wrapper may live in either a sibling test binary OR an integration-test crate that's outside `ironhermes-cli`. `pub` keeps imports trivial. The CLI `commands` module already exports `cmd_decompose`, `cmd_specify`, etc. publicly, so this is consistent with the existing surface.
- **wiremock for closure-execution tests**: Live-LLM smoke is explicitly Plan 05 UAT scope (RESEARCH §Manual-Only Verifications). To verify the fail-closed JSON parse gates without a live provider, the five closure tests mount a `wiremock::MockServer` and exercise the closure end-to-end against a stub `/chat/completions` endpoint. The dev-dep is already in `ironhermes-cli/Cargo.toml` (used by `provider_integration.rs`), so no Cargo.toml edit was needed.
- **Why `chat_completion(... Some(1024), Some(0.0), None)`**: Judge responses are short structured JSON; 1024 tokens leaves headroom for a long `reason` field but caps runaway prose. `temperature=0.0` maximizes determinism — the judge should not vary its verdict on identical inputs across goal-loop iterations.
- **No `JudgeFn` re-export from `ironhermes-cli`**: Plan 01 already re-exports `JudgeFn` / `JudgeRequest` / `JudgeOutput` / `JudgeVerdict` from `ironhermes-kanban`. Plan 04 will import them through `ironhermes_kanban::{JudgeFn, ...}`. Re-exporting them from `ironhermes-cli` would add a duplicate import path with no callers.
