The expected case is contention-free (the wrapper releases its guard before falling out of scope), so `try_lock` is correct in the common path. The lock-busy fallback emits a tracing warning rather than blocking — Plan 05 UAT row 2 will catch the resulting orphaned `running` task and a fresh dispatcher reclaim will release it. # Phase 36.3.7.12 Plan 04: Goal-loop wrapper + main.rs integration

The load-bearing new file in this phase — `crates/ironhermes-cli/src/kanban/goal_loop.rs` — lands with five behavioral consumer tests, BudgetSentinel RAII drop guard, synthetic-block helper mirroring the production `kanban_block` tool path, and main.rs worker-mode dispatch that routes through the wrapper when `HERMES_KANBAN_TASK` is set.

## What Was Built

### Task 1 — `goal_loop.rs` + tests (the wrapper itself)

- **`crates/ironhermes-cli/src/kanban/goal_loop.rs`** (~290 LOC):
  - `pub type GoalLoopFuture<T>` — local `BoxFuture` alias mirroring `decomposer.rs:58` (avoids pulling `futures` crate as a direct dep).
  - `pub type TurnRunner` — `Box<dyn FnMut(Vec<String>) -> BoxFuture<Result<String>>>`. The narrow closure surface composes with both production (`AgentRuntime::run_turn`) and tests (mock closures) without leaking `ChatMessage`/`AgentResult`/`AgentLoop` types into the wrapper signature.
  - `pub async fn run_goal_loop_if_enabled(turn_runner, initial_messages, task_id, run_id, claim_lock, judge_fn, store) -> Result<()>` — single entry point implementing all five behavioral paths from PLAN.md.
    - Non-goal passthrough: when `HERMES_KANBAN_GOAL_MODE` env is unset, call `turn_runner(initial_messages).await` once and return. No event emission, no counter bump, no budget tracking — byte-equivalent to a direct `runtime.run_turn`.
    - Goal-mode loop: parses `HERMES_KANBAN_GOAL_MAX_TURNS` (default 20, zero coerces to 20), fetches the task once for title+body, then iterates `for turn in 0..max_turns`:
      1. Call `turn_runner(messages.clone()).await?` for the agent invocation.
      2. CAS-gated `store.bump_goal_turn_counter(task_id, claim_lock)?` — if `Ok(false)` (stale claim), emit a `judge_error{error:"claim_expired"}` advisory and exit cleanly.
      3. Emit `Edited{subkind:goal_turn_advanced, turn}`.
      4. Refetch task; if `status ∈ {done, blocked}` → `sentinel.done = true; return Ok(())`.
      5. Build `JudgeRequest{task_id, title, body, worker_turn_output, turn}` and call `judge_fn(req).await`.
      6. On `Ok(Met)` → emit `judge_verdict{verdict:"met"}`, set `done`, return.
      7. On `Ok(NotMet)` → emit `judge_verdict{verdict:"not_met"}`, reset consecutive errors, push a synthetic continue-message into the running textual history.
      8. On `Err` → emit `judge_error{error:<200-char truncated>}`, increment consecutive errors; on `>= 2` → call `synthetic_kanban_block(reason="judge unavailable")`, set `done`, return.
    - Loop exits naturally (budget exhausted) → `sentinel` Drop fires, emitting `goal_budget_exhausted` + `kanban_block(reason="goal_max_turns exhausted; needs human review")`.
  - `struct BudgetSentinel` + `Drop for BudgetSentinel` — owned RAII guard. Drop body uses `try_lock` first; on contention degrades to a tracing warning rather than blocking (Rust's "no panic from Drop" rule). All store calls wrapped in `let _ =` to swallow any internal errors.
  - `async fn synthetic_kanban_block` — calls `store.block_task(task_id, reason, Some(run_id))`. This is the same public store API the production `kanban_block` tool calls at `tools/block.rs:140`. No new mutation pathway; the tool's existing invariants (status validation, event emission inside one BEGIN IMMEDIATE tx) ride along (T-36.3.7.12-04-T05 mitigation).
  - `fn status_is_terminal(status: &str) -> bool` — string-based self-termination check matching `Task::status: String` (D-17).

- **`crates/ironhermes-cli/src/kanban/mod.rs`** — added `pub mod goal_loop;`.

- **`crates/ironhermes-cli/tests/goal_loop_wrapper.rs`** (~470 LOC) — five behavioral consumer tests:
  - `non_goal_passthrough_calls_run_once` — env unset → exactly one turn-run, zero judge calls, zero counter movement, zero goal-subkind events.
  - `judge_met_exits_cleanly` — judge returns Met on turn 1 → 1 turn-run, 1 `judge_verdict` event, 0 `goal_budget_exhausted` events, task status STILL `running` (judge-met does NOT change status; the worker LLM owns `kanban_complete`).
  - `self_termination_exits_cleanly` — TurnRunner mutates `task.status = "done"` mid-loop via a sibling rusqlite Connection → wrapper exits before judge fires; 0 judge calls; final status `done`.
  - `budget_exhaustion_synthesizes_block` — judge always NotMet, `max_turns=3` → exactly 3 turn-runs; 3 `judge_verdict` + 3 `goal_turn_advanced` + 1 `goal_budget_exhausted`; task status `blocked`.
  - `two_consecutive_judge_errors_block` — judge Err twice → exactly 2 turn-runs (NOT a 3rd); 2 `judge_error` events; 0 `goal_budget_exhausted`; task status `blocked`. (The 2-strike block is NOT the budget path.)

  Tests use a test-local `ENV_LOCK` (`Mutex<()>`) to serialize `std::env::set_var` calls across the binary's parallel-test threads. Direct status mutation goes through an independent `rusqlite::Connection` opened on the same db path, mirroring `cas_concurrency.rs:32-37`.

### Task 2 — Wire wrapper into `run_single` worker-mode dispatch + `load_kanban_config` widening

- **`crates/ironhermes-cli/src/main.rs::run_single`** — surgical edit at the `runtime.run_turn(request)` call site (around line 929). The original single `run_turn` call is now wrapped in a worker-mode branch:
  - `let worker_mode = std::env::var("HERMES_KANBAN_TASK").is_ok();`
  - `let runtime_handle = Arc::new(runtime);` — wrap the runtime up-front so both the goal-loop closure (which clones per turn) and the post-loop `runtime.registry()` session-end-hooks consumer share ownership.
  - When `worker_mode == true`: load `kanban_config` via `crate::kanban::commands::load_kanban_config(&config)`, build the runtime `JudgeFn` via `build_runtime_judge_fn(&kanban_config, &config)?`, read `HERMES_KANBAN_TASK/RUN_ID/CLAIM_LOCK` env, open the kanban store via `KanbanStore::open_default()?`, build a `TurnRunner` closure wrapping `runtime_handle.run_turn(TurnRequest{...})`, then call `run_goal_loop_if_enabled(...)`. The wrapper itself decides goal vs passthrough internally based on `HERMES_KANBAN_GOAL_MODE`.
  - When `worker_mode == false`: untouched single `runtime_handle.run_turn(request).await?` call — preserving the existing non-worker `chat -q` semantics byte-for-byte.
  - Post-wrapper, the synthesized `AgentResult::budget_exhausted(vec![], 0)` carries downstream so the existing `result.context_warnings` rendering block stays well-typed. (The wrapper's per-turn `run_turn` invocations already streamed all assistant text to stdout via the closure's stream callback.)

- **`crates/ironhermes-cli/src/kanban/commands.rs::load_kanban_config`** — widened from `fn` to `pub fn` so main.rs can call it (Rule 3 blocking-fix). Behavior unchanged; only visibility.

## Decisions Made

- **Closure-based TurnRunner surface instead of `&mut AgentLoop`** — see frontmatter `decisions[0]`. This is the Rule 1 adaptation from the plan's signature; the plan-text signature would have required the wrapper to receive a long-lived borrow of an `AgentLoop` instance that doesn't exist as a separate object at the main.rs worker dispatch site (production goes through `AgentRuntime::run_turn(TurnRequest)`). The TurnRunner closure is the minimum-surface seam.
- **Drop guard uses `try_lock` not `blocking_lock`** — see frontmatter `decisions[1]`. Drop must not deadlock the runtime; a missed synthetic block in a contended-Drop scenario is bounded by the 4h heartbeat reclaim and surfaces as orphaned `running` (caught by Plan 05 UAT row 2).
- **`AgentResult::budget_exhausted(vec![], 0)` post-wrapper sentinel** — see frontmatter `decisions[2]`. The downstream code only reads `context_warnings` (empty) and iterates `messages` for `state_store.add_message` (also empty in the wrapper case). All assistant text was already streamed during the wrapper's iterations.
- **Up-front `Arc::new(runtime)`** — see frontmatter `decisions[3]`. Two consumers (wrapper closure + post-loop registry) need shared ownership; one shared Arc is cleaner than rebuilding the borrow story in two branches.
- **`load_kanban_config` widened to `pub`** — see frontmatter `decisions[4]`. Surgical visibility-only change; aligns with the existing `pub`-on-`build_runtime_judge_fn` from Plan 03.
- **String-based status terminal-check** — see frontmatter `decisions[5]`. Honors D-17 (`Task::status: String`).
- **Wrapper takes `Vec<String>` history, not `Vec<ChatMessage>`** — see frontmatter `decisions[6]`. Keeps the wrapper's public surface independent of `ironhermes-core` / `ironhermes-agent` ChatMessage types; the TurnRunner adapter at the production call site converts judge feedback into a `ChatMessage::user` on each iteration.
