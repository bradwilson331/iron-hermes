## Notable Observations

1. **D-06 amendment is fully realized.** The CONTEXT.md original said `/resume` as alias; the planner amended to `/unpause` to avoid colliding with the pre-existing session-resume command at `registry.rs:96`. Both commands now coexist:
   - `/pause` + alias `/unpause` → queue drain pause toggle (TUI).
   - `/resume` → session resume (unchanged).
   The dispatch layer at `commands.rs:399-411` detects the typed alias from raw input so `/unpause` reaches the correct arm even though the registry resolves it to canonical name `pause`.

2. **CommandResult variants (`PauseQueue`, `UnpauseQueue`) added.** The defensive fallback arms exist at `commands.rs:1228-1229` (TUI), `tui/commands.rs:164` (classic CLI), and `handler.rs:691` (gateway) — all map to `Silent` / no-op as designed.

3. **Cap-hit ordering matches expectation.** The `Err(QueueError::CapacityReached { max, .. })` destructures `max` and uses it twice in the format string (`{max}/{max}`), so any future change to `MAX_QUEUE_DEPTH` propagates automatically.

4. **`/stop` ordering deviates slightly from RESEARCH Pitfall 1 commentary but is correct.** The Pitfall said "clear before cancel"; the code does exactly this: line 870 clear → line 872 cancel. The Cancelled arm in `app.rs:794-803` also defensively skips drain — belt-and-suspenders as documented inline.

5. **Status bar live-reads per frame.** `ui.rs:104` calls `app.queue.len(&app.queue_key)` directly during the render pass, not from a cached field. This sidesteps Pitfall 5 (one-tick staleness) — the `StatusLineState` fields are written on each render, not on queue mutation.
