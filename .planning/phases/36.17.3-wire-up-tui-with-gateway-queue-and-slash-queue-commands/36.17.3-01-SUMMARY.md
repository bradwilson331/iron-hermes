# Phase 36.17.3 Plan 01: MessageQueue Trait Extraction + SessionKey Relocation Summary

**Shared `MessageQueue<K>` FIFO trait extracted into `ironhermes-core` (try_push/pop/len/clear, no peek) with cap=128 / warn=96 constants and `QueueError` colocated; `SessionKey` relocated into core with a back-compat re-export from gateway; `SessionQueue` now implements `MessageQueue<SessionKey>` via a `String`→`MessageEvent` adapter — gateway test suite still 100% green (T-03 mitigated).**

## Performance

- **Started:** 2026-05-28
- **Completed:** 2026-05-28
- **Tasks:** 3 (Task 3 is a test-only gate, no source diff)
- **Files modified:** 5 (2 created, 3 modified)

## Accomplishments

- `MessageQueue<K: Hash + Eq + Clone + Send + Sync + 'static>` trait shipped in `ironhermes-core::queue` with the locked surface (`try_push`/`pop`/`len`/`clear`; `peek` intentionally omitted per Resolution 3).
- `QueueError::CapacityReached` and `MAX_QUEUE_DEPTH=128` / `WARN_QUEUE_DEPTH=96` constants relocated to core; gateway re-exports both so every existing `ironhermes_gateway::session_queue::QueueError` / `MAX_QUEUE_DEPTH` import path keeps compiling.
- `SessionKey` relocated to `ironhermes-core::session` (Platform-only dep, dep-cycle-free); `ironhermes_gateway::session` re-exports it (`pub use ironhermes_core::session::SessionKey;`) so every existing call site (`session_queue.rs`, `user_queue.rs`, plus any downstream `use ironhermes_gateway::session::SessionKey;`) compiles unchanged.
- `impl ironhermes_core::queue::MessageQueue<SessionKey> for SessionQueue` added as a production-level adapter block in `session_queue.rs` (Resolution 5). Adapter wraps the `String` payload into a minimal `MessageEvent` with `content`/`platform`/`chat_id`/`sender_id` (from `key.user_id`) populated and gateway-internal metadata defaulted (`message_id=""`, `attachments=[]`, `thread_id=None`, `chat_type="queue"`, `chat_name/sender_name/replied_to_id=None`); `pop` returns `MessageEvent.content`; `len`/`clear` delegate verbatim.
- T-03 gate satisfied: `cargo test -p ironhermes-gateway` exits 0 with **10 passing `test result` summary lines and 0 FAILED occurrences**. No source file outside `session.rs` and `session_queue.rs` was touched in this plan; the inner `SessionQueue::try_push(&self, key, MessageEvent)` API is byte-for-byte identical.
