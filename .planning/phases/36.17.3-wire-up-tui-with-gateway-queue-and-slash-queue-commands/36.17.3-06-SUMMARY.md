## What Was Built

### Task 1: `tui_queue_drain.rs` — D-04 / D-05 / D-11 / D-12

- **`tui_queue_drain_fifo`** (D-04 + D-05): Push 5 items via the queue surface, simulate a turn-in-flight via the `install_pending_turn` helper (mirrors `submit()`'s mpsc channel installation), then fire six `StreamEvent::Finished` cycles. Each cycle clears `pending_tx`/`pending_rx` first so the `Finished` arm's `maybe_drain_queue` guard 2 (T-04: `pending_tx.is_some()`) lets the drain pop. The first five cycles each drop depth by 1; the sixth confirms `pending_tx.is_none()` (no fresh channel for an empty drain). FIFO order is asserted by inspecting `user_history_texts(&app)` — the alpha → echo sequence matches push order.
- **`tui_queue_regression_d11`** (CONTEXT D-11 7-step headline): Synthesizes the full headline regression — turn-1 free-text + 5 `/queue` pushes during in-flight + 6 `Finished` drains + 2 more pushes with `queue_paused = true` + Finished cycle confirms paused-drain skipped + `queue_paused.store(false)` + next Finished drains foxtrot + next Finished drains golf + `/new` simulation (clear + store false). Each step's observable state is asserted (`queue.len`, `pending_tx`, `queue_paused.load`, user-history order).
- **`tui_queue_regression_negative_control`** (D-12 hook): The doc-commented function asserts `queue.len(&key) == 5` after 5 trait-level `try_push` calls. Against the pre-fix textarea-prepopulate handler the queue is never touched and the assertion fails at depth 0 — this is the manual rebase-verification surface documented in `tests/README.md` (Plan 03).

**Commit:** `cf409608`

### Task 2: `tui_queue_controls.rs` — D-06 / D-07 / D-08 / D-10

- **`tui_queue_pause_unpause`** (D-06 amended): Pause + Finished cycle confirms drain skipped (depth unchanged); unpause + Finished cycle pops one item; second `swap(false, SeqCst)` returns `false`, witnessing the "Queue was not paused" informational path that the `/unpause` arm emits.
- **`tui_queue_new_clears_atomic`** (D-07; T-02 mitigation witness): Push 3 items, set paused=true, then run the Plan 05 `/new` arm order (clear → reset paused). Assert depth == 0 AND paused == false.
- **`tui_stop_clears_queue`** (D-08; Pitfall 1 ordering witness): Install a `cancel_child` token mirroring `submit()`, then run the Plan 05 `/stop` order — `queue.clear` → `queue_paused.store(false)` → `cancel_child.take().cancel()`. The cloned child token observes `is_cancelled() == true` after the take.
- **`tui_queue_cap_hit`** (D-10; T-01 mitigation witness): Loop `0..MAX_QUEUE_DEPTH` (=128) and `try_push` via the trait, assert depth == 128. Push one more, assert `Err(QueueError::CapacityReached { max: 128, .. })`. Depth still == 128 (drop-newest preserved).

**Commit:** `7e5ce27f`

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Repaired pre-existing test that asserted the obsolete pre-36.17.1 /queue contract**
- **Found during:** Task 3 (phase-gate `cargo test -p ironhermes-cli --features test-support` run).
- **Issue:** `queue_no_agent_loop_returns_informational` in `crates/ironhermes-cli/tests/tui_rata_session_control.rs:323-339` asserted that `/queue` returned `CommandResult::Output(..)` containing "Agent loop" / "not configured". This was the contract before Phase 36.17.1 D-01.c removed the `agent_loop.is_none()` gate from `cmd_queue` (rationale: `agent_loop` is never set in the gateway `CommandContext`, so the gate was always true and the command was effectively a no-op). The handler now returns `CommandResult::Queued { message }` — and the gateway / tui_rata layer intercepts the variant to perform the actual push. Plan 05's wiring depends on this. The pre-existing test still expected the old behavior and broke once the full suite ran.
- **Fix:** Renamed the test to `queue_with_args_returns_queued_variant` and updated the assertion to match the canonical `CommandResult::Queued { message: "later task" }` contract (also re-anchored the doc-comment to the Phase 36.17.1 D-01.c / D-08 amendment).
- **Files modified:** `crates/ironhermes-cli/tests/tui_rata_session_control.rs`
- **Commit:** `999b2d14`

### Test-body fixes during Task 1

- **Empty-drain assertion** (`tui_queue_drain_fifo`): The initial body asserted `pending_tx.is_none()` immediately after the last drain cycle, but the last drain *had* installed a fresh pending channel (the echo turn). Added one trailing Finished cycle (with `pending_tx` cleared first) — that cycle finds an empty queue and DOES NOT install a fresh channel, witnessing the maybe_drain_queue short-circuit on empty.
- **Trait-method dispatch** (`tui_queue_regression_negative_control`): The raw `Arc<SessionQueue>` resolved to the inherent `try_push(&self, key, MessageEvent)` rather than the trait `try_push(&self, key, String)`. Cast to `Arc<dyn MessageQueue<SessionKey>>` to force trait dispatch.
