**Key technical decisions:**

1. **Active key vs commented key:** The drift test uses `map.contains_key()` on the parsed YAML mapping. A commented-out section (e.g., `# kanban:`) does not appear in the parsed map — the key must be syntactically active in the YAML.

2. **Null-safe nested fields:** Sections with all nested fields commented parse as `null` in YAML. Rust serde with `#[serde(default)]` treats a YAML null value for a mapping key identically to the key being absent — the struct field gets its `Default::default()` value. This is safe for all 10 struct-valued sections.

3. **Exception — TtsConfig sub-keys:** `edge:` and `elevenlabs:` inside `tts:` were initially added as active sub-keys (parsing as null). serde may fail to deserialize `null` into a non-Option struct if the struct lacks `#[serde(default)]` at the field level. Fix: comment out `edge:` and `elevenlabs:` lines entirely so `tts:` parses as a null scalar (not a mapping with null values), which Default handles cleanly.

4. **Exception — Vec/HashMap:** `custom_providers: []` and `mcp_servers: {}` cannot use the null strategy because serde cannot coerce null to Vec/HashMap without an explicit `#[serde(default)]` + Option wrapper. Empty collection literals are used instead.

5. **Plan stated 9 missing sections; actual count was 12:** Python parse of the original file revealed that `tools`, `auxiliary`, and `custom_providers` were also present only as comments (not active YAML keys), not just the 9 listed in the plan. All 12 were added.
