## Decisions Made

- **Default block constants as `{}`/`[]`:** Comment-only YAML strings parse as Null via
  `serde_yaml::from_str`, which would insert `null` as the section value. Using `"{}"` (empty
  mapping) or `"[]"` (empty sequence) ensures parse-safe non-null defaults while still satisfying
  the "key present" contract for D-11 idempotency.
- **Kanban handled outside the sections loop:** `apply_kanban_section_answer` already produces
  a typed `serde_yaml::Mapping`; we insert it directly as `Value::Mapping` rather than
  round-tripping through a YAML string parse in `write_defaults_if_absent`.
- **`write_defaults_if_absent` promotes Null to Mapping:** Fresh config.yaml from `Config::save_to`
  may produce an empty file; the helper promotes a Null root value to an empty Mapping so
  the first-install case always works.
- **Default-block mechanism:** `pub fn default_block_for(section: &str) -> Option<&'static str>`
  (dispatch function) rather than a large match expression inline in setup.rs — testable and
  extensible without touching setup.rs.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed explicit `ref mut` borrow syntax error**
- **Found during:** Task 1 (first compile attempt)
- **Issue:** `if let serde_yaml::Value::Mapping(ref mut map) = yaml_value` fails with
  "cannot explicitly borrow within an implicitly-borrowing pattern" on Rust edition 2021.
  When matching on `&mut T`, the pattern implicitly borrows; `ref mut` is redundant and rejected.
- **Fix:** Changed to `if let serde_yaml::Value::Mapping(map) = yaml_value` (implicit borrow).
- **Files modified:** `crates/ironhermes-core/src/wizard.rs`
- **Verification:** `cargo nextest run -p ironhermes-core --test wizard_coverage` → 3/3 PASS
- **Committed in:** `8238e153` (part of Task 1 commit)

**2. [Rule 1 - Bug] Fixed comment-only YAML constants parsing to Null**
- **Found during:** Task 1 (design review)
- **Issue:** Initial default block constants used comment-only YAML strings (e.g., `"# max_turns: 50\n"`).
  `serde_yaml::from_str` on a comment-only document returns `Null`, so `write_defaults_if_absent`
  would insert `null` as the section value — semantically incorrect (should be empty mapping).
- **Fix:** Changed all 13+2 block constants to `"{}"` (empty mapping) or `"[]"` for
  `custom_providers`. The `gateway` constant stays `"platforms: {}"` (has a real default value).
- **Files modified:** `crates/ironhermes-core/src/wizard.rs`
- **Verification:** `serde_yaml::from_str("{}")` → `Value::Mapping({})` (confirmed via Python yaml.safe_load).
- **Committed in:** `8238e153` (part of Task 1 commit)

**3. [Rule 1 - Bug] Fixed double-borrow in setup.rs kanban insertion block**
- **Found during:** Task 2 (code review before compile)
- **Issue:** Original kanban block used nested `if let serde_yaml::Value::Mapping(ref map) = yaml`
  followed immediately by `if let serde_yaml::Value::Mapping(ref mut m) = yaml` — two borrows
  of the same binding in overlapping scope.
- **Fix:** Used split-borrow pattern: immutable `.as_mapping().map(|m| !m.contains_key(&key))`
  produces the `bool` and ends the borrow, then `if let Mapping(m) = &mut yaml` begins
  the mutable borrow. Used inner scope block for `kanban_key` lifetime management.
- **Files modified:** `crates/ironhermes-cli/src/setup.rs`
- **Verification:** Code review confirms no overlapping borrows.
- **Committed in:** `612db0d0` (part of Task 2 commit)
