# Phase 36.3.7.8 Plan 02: @mention Delegation Store Primitive Summary

**One-liner:** Atomic `create_mention_children` store primitive with `BEGIN IMMEDIATE` tx, `WITH RECURSIVE` ancestor-chain cycle check (REQ-10 layer 2), per-child rollback on any failure (REQ-11), and idempotency replay via `k:mention:{mention_index}` suffix scheme (REQ-12).

## What Was Built

Added 389 lines to `crates/ironhermes-kanban/src/store.rs` (zero deletions):

### Task 1 — Types + replay finder (`c82b3485`)

Four `pub` structs with `Debug + Clone` added to the public option/filter types section:

- `MentionPlan` — input plan carrying `parent_id`, resolved `children: Vec<MentionChildSpec>`, `idempotency_key`, workspace/skills/tenant/created_by.
- `MentionChildSpec` — single resolved child: `handle` (original-cased), `assignee` (normalized), `mention_index` (0-indexed in original parse order for REQ-12 key stability), `title`, `body`.
- `MentionResult` — output wrapper: `children: Vec<MentionChildIds>`.
- `MentionChildIds` — materialized child IDs: `child_id`, `assignee`, `handle`, `mention_index`.

`find_mentions_by_idempotency_key(&self, base_key) -> Result<Option<MentionResult>>`:
- Scans `tasks WHERE idempotency_key LIKE '{base_key}:mention:%'`
- Parses `mention_index` from key suffix (numeric sort, not lexicographic — avoids `:mention:10` < `:mention:2` bug)
- Returns `Ok(None)` on miss; `Ok(Some(MentionResult))` with children sorted by `mention_index` ascending

### Task 2 — `create_mention_children` primitive (`51eb27fb`)

`pub fn create_mention_children(&mut self, plan: MentionPlan) -> Result<MentionResult>`:

1. **Empty-plan short-circuit:** `plan.children.is_empty()` → `Ok(MentionResult { children: vec![] })` without opening a tx (valid no-op, not an error).
2. **Pre-flight:** all `MentionChildSpec.assignee` validated via `validate_profile_name` before tx opens.
3. **BEGIN IMMEDIATE** via `self.conn.transaction_with_behavior(TransactionBehavior::Immediate)`.
4. **Idempotency replay inside tx (WR-01):** checks for `{base}:mention:0` key inside the tx; if found, commits the read-only tx then calls `find_mentions_by_idempotency_key` via `&self`.
5. **Per-child loop** (in `mention_insert_loop` free fn):
   - `WITH RECURSIVE ancestors` CTE bounded to `MAX_MENTION_CHAIN_DEPTH=4` hops checks assignee identity in parent chain (REQ-10 layer 2); cycle → `Err` → tx RAII rollback → zero rows (REQ-11).
   - 15-column `INSERT INTO tasks` (mirrors `create_task` column list per INV-36.3.7).
   - Inline `INSERT OR IGNORE INTO task_links` (no `insert_link_checked` — avoids deadlock).
   - `append_event_internal` with `{source:"mention", handle, mention_index, parent_id}` payload.
6. `tx.commit()` → `Ok(MentionResult { children })`.

Per-child idempotency key: `"{base}:mention:{mention_index}"` (Landmine 2 — NOT `k:worker:{i}`).
