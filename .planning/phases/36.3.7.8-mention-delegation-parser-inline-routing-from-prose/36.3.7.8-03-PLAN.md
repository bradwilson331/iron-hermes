REJECTION REASON SLUGS this tool emits:
  invalid_task_id   — no task_id arg AND no $HERMES_KANBAN_TASK env
  task_not_found    — store lookup returned NotFound
  invalid_policy    — fallback_policy not in {skip,pending,error}
  unknown_handle    — policy=error AND a mention failed UnknownHandle
  invalid_assignee  — store.create_mention_children rejected an assignee (defense-in-depth)
  mention_cycle     — store layer-2 ancestor walk rejected a child
  store_error       — any other KanbanError propagated from store

EXECUTE FLOW (per RESEARCH §Code Examples kanban_mention.execute):

  1. Resolve task_id from args or $HERMES_KANBAN_TASK env; reject(invalid_task_id) if neither.
  2. Parse fallback_policy from string ("skip" default); reject(invalid_policy) on parse failure.
  3. Read optional idempotency_key.
  4. Acquire `let mut store = self.store.lock().await;`. Fetch parent via store.get_task(&task_id); reject(task_not_found) on Err.
  5. body = args["body_override"].as_str() OR parent.body.clone().unwrap_or_default().
  6. spans = parse_mentions(&body).
  7. Build known assignees HashSet from store (call list_known_assignees if it exists; else inline SELECT DISTINCT — see <interfaces> note below).
  8. For each (i, span) in spans.iter().enumerate(): call resolve_mention(&span.handle, &ctx). Match Resolution::{Resolved, Fallback, Skipped} into `children` and `skipped` vecs. If policy=Error AND Skipped(UnknownHandle), break and reject(unknown_handle).
  9. Build MentionPlan { parent_id=task_id, children, idempotency_key, workspace/skills/tenant from parent, created_by=$HERMES_PROFILE }.
 10. result = store.create_mention_children(plan); map error keywords to slugs ("invalid assignee" → invalid_assignee; "mention_cycle" → mention_cycle; else store_error).
 11. Format success JSON: { task_id, mentions_parsed: spans.len(), children_created: [...], skipped: [...] }.
