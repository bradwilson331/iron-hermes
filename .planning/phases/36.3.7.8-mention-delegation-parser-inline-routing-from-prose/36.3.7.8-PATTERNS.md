### `crates/ironhermes-kanban/src/mention/parser.rs` (utility, transform)

**Analog:** No codebase analog exists. Use the RESEARCH.md §"Pattern 1" proposal directly.

**Key conventions to carry forward:**
- The `once_cell::sync::Lazy<Regex>` static for the `@handle` pattern. Verify `once_cell` is in the workspace dep tree before use; alternatively use `std::sync::OnceLock` (stable since Rust 1.70, zero new deps).
- The "redact-then-scan" strategy: `redact_non_prose(body) -> String` produces a same-length string where fence/inline-code/comment regions are blanked, then `HANDLE_RE.captures_iter(&redacted)` extracts handles. This keeps byte offsets consistent.
- `MentionSpan { handle: String, byte_offset: usize }` — `handle` is raw-cased (NOT lowercased here; resolver does that per REQ-04).
- No IO, no async, no `&mut self` — this is a free function. Tests live in `#[cfg(test)]` at the bottom of the same file.

**Concrete regex pattern from RESEARCH.md §Pattern 1:**
```rust
// Handle regex: @ followed by word-chars (first char must be alnum)
Regex::new(r"@([A-Za-z0-9][A-Za-z0-9-]*)").unwrap()
```

**Fence-state machine rules (from REQ-01/02):**
- Skip between matching ``` ``` ``` or `~~~` fences (CommonMark §6.6).
- Skip between single-backtick `` ` `` pairs (CommonMark §6.5 inline code).
- Skip between `<!--` and `-->` (HTML comments).
- Indented 4-space code blocks: DEFER — documented v1 limitation, do NOT attempt in this phase.

**validate_profile_name signature** (`crates/ironhermes-core/src/profile.rs` lines 63–88):
```rust
pub fn validate_profile_name(name: &str) -> Result<String, ProfileNameError> {
    if name.is_empty() {
        return Err(ProfileNameError::Empty);
    }
    if name.len() > PROFILE_NAME_MAX_LEN {
        return Err(ProfileNameError::TooLong);
    }
    if name.starts_with('_') {
        return Err(ProfileNameError::LeadingUnderscore);
    }
    if RESERVED_NAMES.contains(&name) {
        return Err(ProfileNameError::Reserved(name.to_string()));
    }
    let valid_chars = name
        .chars()
        .all(|c| c.is_ascii_lowercase() || c.is_ascii_digit() || c == '-');
    let starts_ok = name
        .chars()
        .next()
        .map(|c| c.is_ascii_lowercase() || c.is_ascii_digit())
        .unwrap_or(false);
    if !valid_chars || !starts_ok {
        return Err(ProfileNameError::InvalidChars);
    }
    Ok(name.to_string())
}
```

**Resolver conventions:**
- `resolve_mention(handle: &str, ctx: &ResolverCtx) -> Resolution`
- Lowercase the handle BEFORE calling `validate_profile_name`: `let normalized = handle.to_lowercase();` (REQ-04 — `@Reviewer` → `reviewer`).
- If `validate_profile_name` fails → `Resolution::Skipped(SkipReason::Malformed)`.
- If normalized == parent task's assignee → `Resolution::Skipped(SkipReason::SelfReference)` (REQ-09, constant-time).
- Ancestor-chain walk (REQ-10): reuse the WITH RECURSIVE SQL from `insert_link_checked` at `store.rs:499–516` but inverted to walk PARENTS (replace `child_id` walk with `parent_id` walk), limited to `MAX_MENTION_CHAIN_DEPTH` hops.
- `pub const MAX_MENTION_CHAIN_DEPTH: usize = 4;` exported from this module (REQ-10).

    UNION

## Landmines — Do NOT Copy Blindly

### Landmine 1: `parents` arg in `create_task` vs. `create_mention_children`
**Source of confusion:** `cmd_create` in `commands.rs` line 85+ accepts `parents: Vec<String>` from the user. `create_mention_children` auto-derives the parent from `MentionPlan.parent_id`.
**Wrong:** Copying `cmd_create`'s `parents` handling into `cmd_mention`.
**Correct:** `cmd_mention` has NO `--parent` flag. The parent is always the `task_id` argument. `MentionPlan.parent_id` is set from `task_id` directly.

### Landmine 2: Idempotency key suffix scheme difference
**Source of confusion:** `create_swarm` uses `k:root`, `k:worker:{i}`, `k:verifier`, `k:synthesizer`. `create_mention_children` uses `k:mention:{i}`.
**Wrong:** Reusing `k:worker:{i}` suffixes.
**Correct:** `"{base}:mention:{mention_index}"` where `mention_index` is the 0-based position in the ORIGINAL parsed list (not the created-children list — skipped mentions do NOT consume an index slot in the per-child keys, but the `mention_index` on each `MentionChildSpec` is its original parse position, so the key is still deterministic on re-parse).

### Landmine 3: Resolver vs. store cycle detection responsibility
**Source of confusion:** `insert_link_checked` at `store.rs:443+` does cycle detection at the DAG level. Mention cycle detection is at the ASSIGNEE identity level (same worker appearing in ancestor chain), NOT the task-link DAG level.
**Wrong:** Relying on `insert_link_checked`'s WITH RECURSIVE to catch mention loops.
**Correct:** Two-layer check: (1) self-reference at resolver layer (constant-time string compare); (2) ancestor-chain assignee walk in `create_mention_children` before inserting links.

### Landmine 4: `"heartbeat"` may or may not be in `DEFERRED_KANBAN_SUBVERBS` already
**Source of confusion:** Phase 36.3.7.6 added `"heartbeat"` to the CLI but the grep output shows the constant ends at `"swarm"` with no `"heartbeat"`. Adding `"heartbeat"` is NOT this phase's job.
**Correct:** Only add `"mention"`. The current array (confirmed at `handlers.rs` lines 1143–1149) ends at `"swarm"`.

### Landmine 5: `validate_profile_name` only accepts lowercase
**Source of confusion:** Natural-language prose may contain `@Reviewer` (capital R). `validate_profile_name` will return `ProfileNameError::InvalidChars` for `"Reviewer"`.
**Wrong:** Calling `validate_profile_name(handle)` where `handle` is the raw-cased string from `MentionSpan`.
**Correct:** Always lowercase first: `validate_profile_name(&handle.to_lowercase())`.

### Landmine 6: tools/mod.rs docstring says "10 kanban tools" — must be updated
**Source:** `tools/mod.rs` line 45 `/// Register all 10 kanban tools onto \`registry\`.`
**Correct:** Update to `/// Register all 11 kanban tools onto \`registry\`.`

### Landmine 7: `KanbanCommands` does NOT derive `Debug`
**Source:** `swarm_cli.rs` lines 14–18 comment.
**Correct:** CLI parity tests in `mention_cli.rs` must NOT use `{:?}` on `KanbanCommands` variants. Use plain `panic!("expected Kanban::Mention variant")` for the mismatch arm.
