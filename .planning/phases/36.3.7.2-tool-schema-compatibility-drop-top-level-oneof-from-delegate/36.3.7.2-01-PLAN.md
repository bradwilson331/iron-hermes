<objective>
Eliminate the Anthropic-rejected top-level `oneOf` from `delegate_task`'s `input_schema` and prove (via audit) that it is the only offender in `crates/ironhermes-tools/src/`. The runtime mutual-exclusion check at `execute()` line 745 stays untouched as the load-bearing correctness layer; the LLM continues to see the mutex constraint through prose in the `task` and `tasks` property descriptions.

Purpose: Phase 36.3.7.0 UAT-09-A re-run #5 surfaced `400: input_schema does not support oneOf, allOf, or anyOf at the top level` from every Anthropic-via-OpenRouter worker call. That error blocks ALL kanban workers routed through Anthropic. Removing the schema-level `oneOf` unblocks the worker path without weakening runtime correctness.

Output: A flat `input_schema` for `delegate_task` (no top-level boolean combinator), an inverted unit test that asserts the new shape, and an audit doc that proves the fix surface is complete.
</objective>
