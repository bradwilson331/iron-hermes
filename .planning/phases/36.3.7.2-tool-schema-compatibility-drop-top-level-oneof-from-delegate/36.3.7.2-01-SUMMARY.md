## Before/After Regions in delegate_task.rs

**Region A (schema producer, was lines 731-738):**

Before:
```rust
                // oneOf enforces that exactly one of `task` (single mode) or `tasks`
                // (batch mode) is present. ...
                "oneOf": [
                    { "required": ["task"] },
                    { "required": ["tasks"] }
                ]
```

After: `oneOf` block deleted; closing `}` of `"properties"` now closes the JSON object directly. Comment placed after the `json!` macro call explaining the runtime-validation fallback.

**Region B (property descriptions):**

`task` description: appended ` Mutually exclusive with \`tasks\` — provide exactly one of \`task\` (single mode) or \`tasks\` (batch mode).`

`tasks` description: replaced trailing `Mutually exclusive with 'task'.` with `` Mutually exclusive with `task` — provide exactly one of `tasks` (batch mode) or `task` (single mode). ``

**Region C (test, was lines 1219-1251):**

Renamed: `test_delegate_task_schema_task_and_tasks_are_mutually_exclusive_optional` → `test_delegate_task_schema_has_no_top_level_boolean_combinator`

Inverted: removed all `oneOf` array assertions; added three `is_none()` assertions for `oneOf`/`allOf`/`anyOf`; kept property-existence assertions; added two description-content assertions checking for `"Mutually exclusive"` substring.
