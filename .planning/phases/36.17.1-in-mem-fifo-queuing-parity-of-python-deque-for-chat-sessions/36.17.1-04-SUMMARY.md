# Phase 36.17.1 Plan 04: Drain-mode flag on GatewayRunner Summary

`is_draining: Arc<AtomicBool>` on `GatewayRunner` paired with a
`drain_for_restart()` helper that flips the flag to `true` **before**
`cancel.cancel()` — locking the T-36.17.1-03 mitigation (lost-update during
drain-mode transition) at the type level rather than relying on every caller
to remember the ordering.

## Objective

Close T-36.17.1-03 by adding a drain-mode signal to `GatewayRunner`:

1. Field: `is_draining: Arc<AtomicBool>` initialized to `false`.
2. Accessor: `pub fn is_draining(&self) -> bool` (SeqCst load).
3. Helper: `pub fn drain_for_restart(&self)` that executes
   `is_draining.store(true, SeqCst)` **before** `self.cancel.cancel()` in
   source order.
4. Shutdown injection: replace the bare `self.cancel.cancel()` in the
   graceful-shutdown path (~`runner.rs:1105`) with `self.drain_for_restart()`.
5. Contract: `SessionQueue::try_push` has **no** `is_draining` gate. Drain
   mode is preserve-AND-accept per D-03 — a push observing `is_draining=true`
   must still succeed so messages arriving in the brief in-process window
   between drain entry and process exit are not lost.

Python parity reference: `_queue_during_drain_enabled`
(`gateway/run.py:2298-2302`).
