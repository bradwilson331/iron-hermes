### `crates/ironhermes-gateway/src/session_queue.rs` (new — data structure, sync CRUD)

**Primary analog:** `crates/ironhermes-gateway/src/rate_limiter.rs`
**Secondary analog:** `crates/ironhermes-gateway/src/user_queue.rs` (structure shape for `HashMap<K, V>` keyed queue, though it uses `tokio::sync::Mutex` — NOT to be copied for `SessionQueue`)

**Why `rate_limiter.rs` is the best match:**
- Uses `Arc<Mutex<HashMap<String, …>>>` with `std::sync::Mutex` (NOT tokio) — exact mutex flavor required by D-16/D-17
- All methods are synchronous: `.lock().unwrap()` → operate → drop guard
- Uses `entry(key).or_insert_with(…)` pattern for lazy per-key initialization
- `#[cfg(test)] mod tests` inlined at the bottom of the same file (confirmed pattern: `rate_limiter.rs:66`, `backoff.rs:66`, `user_queue.rs:119`)
- No `.await` anywhere in the implementation

pub fn try_push(&self, key: &SessionKey, event: MessageEvent) -> Result<(), QueueError> {
    let mut map = self.queues.lock().unwrap();
    let q = map.entry(key.clone()).or_default();
    if q.len() >= MAX_QUEUE_DEPTH {
        return Err(QueueError::CapacityReached {
            session_key: key.to_string_key(),
            max: MAX_QUEUE_DEPTH,

    Ok(())
}
