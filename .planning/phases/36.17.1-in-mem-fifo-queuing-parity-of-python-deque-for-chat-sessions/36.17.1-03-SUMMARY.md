# Phase 36.17.1 Plan 03: /queue slash command end-to-end + /new clear-queue ordering

## One-liner

Wires the previously-broken `cmd_queue` stub to `CommandResult::Queued`, makes
the gateway handler intercept that variant to call `session_queue.try_push`
with depth-aware confirmation (and D-13 cap-hit UX on overflow), and adds the
Pitfall-5 `clear_queue` hook on `/new` and `/reset` BEFORE `session_store.remove`.

## What changed

### `crates/ironhermes-core/src/commands/mod.rs`

- New `CommandResult::Queued { message: String }` variant inserted adjacent
  to `SkillActivated`. Doc comment cites Phase 36.17.1 D-01.c / D-08 and
  explains that non-gateway surfaces (CLI/TUI without a SessionQueue) should
  map this to `Output(format!("Queued: {message}"))` or surface-appropriate
  equivalent. Existing `#[derive(Debug, Clone, PartialEq, Eq)]` is unchanged
  — `String` satisfies all four traits.

### `crates/ironhermes-core/src/commands/handlers.rs`

- Rewrote `cmd_queue` (around line 1607). Removed the `ctx.agent_loop.is_none()`
  early-return gate (Pitfall 3 — that gate was always true in gateway context
  and always returned "Agent loop not configured."). Renamed `ctx` to `_ctx`
  to silence unused-arg warnings. Empty args still produce `Output(...)` with
  a usage string containing `"Usage: /queue"`. Non-empty args produce
  `CommandResult::Queued { message: args.join(" ") }`.
- 3 new unit tests inside `commands::handlers::tests`:
  - `test_cmd_queue_produces_queued` — non-empty args -> `Queued { message }`.
  - `test_cmd_queue_empty_args_returns_usage` — empty args -> `Output(usage)`.
  - `test_cmd_queue_agent_running_state_is_irrelevant` — Pitfall 3 evidence:
    `cmd_queue` returns `Queued` regardless of `agent_running` flag state.

  Tests are added to the main `tests` mod (around line 2623), NOT the
  `cmd_agents_tree_tests` submodule — the latter does not have `make_ctx`
  in scope.

### `crates/ironhermes-gateway/src/handler.rs`

- New `CoreCommandResult::Queued { message }` arm in `handle_slash_command`'s
  match expression. Synthesizes
  `MessageEvent { content: message.clone(), ..event.clone() }`, calls
  `session_queue.try_push(&session_key, queued_event)`:
  - On `Ok(())`: reads `queue.len(&session_key)` and replies
    `"Queued for the next turn."` (depth <= 1) or
    `"Queued for the next turn. ({depth} queued)"` (depth > 1). Mirrors
    Python parity at gateway/run.py:6814-6820.
  - On `Err(QueueError::CapacityReached { .. })`: identical D-13 UX to the
    Plan 02 busy-branch cap-hit path — best-effort `❌` reaction via
    `.ok()` so reaction-rate-limit failures don't poison the chat reply,
    then the `"⏳ Queue is full (128 messages). Wait for the agent to drain
    before sending more."` chat reply, then `tracing::warn!`.
  - If `self.session_queue` is `None` (handler built outside
    `build_gateway_handler`): degraded fallback sends the depth-1
    confirmation anyway.
- Pitfall 5 injection in the `NewSession` arm: `if let Some(ref queue) =
  self.session_queue { queue.clear(&session_key); }` lands IMMEDIATELY
  BEFORE the existing `store.remove(&session_key)` block (around line 614).
  Source-line ordering verified by acceptance-criterion `awk` script
  (clear at line offset < remove at line offset, gap < 15 lines).
- `/reset` is already aliased to `"new"` at the router level (`def.name`
  canonicalizes), so a single injection covers both commands.

### `crates/ironhermes-cli/src/tui/commands.rs` and `tui_rata/commands.rs`

- Both `map_core_to_*` functions gained a `CommandResult::Queued { message }`
  arm that maps to a `Handled(format!("Queued: {message}"))` outcome on the
  legacy/rata surfaces respectively. No per-session FIFO exists outside the
  gateway (D-02), so this is the visible-but-not-enqueueing fallback.

### `crates/ironhermes-gateway/tests/session_queue_integration.rs`

3 new integration tests (the file now totals 6 tests — 3 from Plan 02 still
passing, 3 new for Plan 03 Task 2):

| Test | Asserts |
|------|---------|
| `test_cmd_queue_enqueues_and_replies_with_depth` | `/queue hello` -> depth 1 + singular reply; `/queue world` -> depth 2 + plural "(2 queued)" reply. Popped events confirm identity inheritance (chat_id/sender_id/content == args). |
| `test_cmd_queue_cap_hit_emits_reaction` | Pre-fill 128, `/queue overflow` trips `CapacityReached` arm; one `❌` reaction targeting the slash message_id; one chat reply containing `"Queue is full (128 messages)"`; cap holds at 128. |
| `test_new_clears_queue_before_session_remove` | Pre-fill 3 events, dispatch `/new`, assert `queue_len(key) == 0` AND `session_store.get(&key) == None` post-dispatch. Pitfall 5 runtime proof. |

The integration tests use the same `RecordingPlatformAdapter` from Plan 02
and add a `make_slash_event` helper that builds `/queue <text>` and `/new`
events with deterministic `message_id`s so cap-hit reaction assertions can
target them.

## Threat-model evidence

- **T-36.17.1-01** (DoS via /queue flood): `test_cmd_queue_cap_hit_emits_reaction`
  proves the 128-cap holds on the /queue dispatch path with the same UX as
  the busy-branch cap-hit.
- **T-36.17.1-02** (identity inheritance): `test_cmd_queue_enqueues_and_replies_with_depth`
  pops queued events and asserts `chat_id == event.chat_id`, `sender_id ==
  event.sender_id`, and content == the args (not the raw "/queue ..." text).
  The synthesis pattern `MessageEvent { content: message.clone(), ..event.clone() }`
  cannot take identity fields from user input.
- **T-36.17.1-03** (clear-before-remove race): `test_new_clears_queue_before_session_remove`
  proves both ran and the post-state is consistent. Source-line ordering is
  enforced by the acceptance `awk` check.
