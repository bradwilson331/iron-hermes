## Phase Boundary

Close the four AGENT-LOOP & CORE parity gaps from iron-hermes-planning.md §2.1 against hermes-agent (Python v0.14.0). Phase 36.2 lands the missing core machinery as four interlocking sub-systems with a shared classification source, so v3.0's milestone parity claim for "Agent loop & core" can be marked PARITY rather than PARTIAL/GAP.

**The four sub-systems (all ship in this phase):**

**(A) Prompt caching — close PRMT-08 / PRMT-09.**
Anthropic-native `cache_control` breakpoints with `system_and_3` strategy (system prompt + last 3 non-system messages). Cached/ephemeral layer separation enforced at assembly time (PRMT-02). Configurable TTL (5m | 1h) defaulting to 1h. Cache_read_input_tokens / cache_creation_input_tokens (already round-tripped through the Usage struct, currently always None) populated from Anthropic responses. Cache-break warnings on the existing PRMT-10/11 channel for the 3 known triggers (model swap, memory edit, context file edit mid-session). OpenRouter `cache_control` lands as a wave-3 optional stretch plan within this phase.

**(B) Per-provider rate-limit tracker.**
New module in `ironhermes-agent` (in-memory, per-process, lost on restart). Telemetry: parse `x-ratelimit-*` response headers when available (Anthropic, OpenRouter both expose them); fall back to reactive 429 counting for providers that don't (Ollama, custom endpoints). Three-axis tracking key: `(provider, api_key_hash, model)`. Emits a structured `RateLimitEvent { provider, key_hash, model, remaining, reset_at, severity }` on a Tokio channel; AgentLoop consumes events and decides what to do (at 90% remaining → hint; post-429 → trigger existing fallback chain via `classify_llm_error`). Tracker does NOT directly trigger fallback — separation of concerns from the existing PROV-07 fallback path.

**(C) Usage & cost accounting ledger.**
Static USD pricing table mirroring Phase 21.3's ModelRegistry pattern: ship `pricing.toml` (USD per 1M input/output/cache_read/cache_creation per model), refreshable via `hermes pricing refresh` (fetches models.dev / OpenRouter API), disk-cached at `$HERMES_HOME/pricing-cache.json`. Offline by default; online on demand. Storage: extend existing `sessions` table columns (add cache_read_tokens, cache_create_tokens, cost_usd_micros) AND add a new `usage_events` per-turn table (session_id, ts, provider, model, in_tok, out_tok, cache_read, cache_create, cost_usd_micros, error_kind). Per-turn grain with SQL rollups for session, daily, and per-provider aggregation. Surfaced through THREE channels: `/usage` slash command (via CommandRouter — works on CLI, TUI, gateway, web UI), status-bar live counter (TUI + web UI), and a per-turn `tracing::info!` debug log line.

**(D) Error classification taxonomy.**
Evolve the existing `classify_llm_error` (Phase 27.1.4.1.1) from a `(should_retry: bool, should_fallback: bool)` tuple into a typed `ProviderError` enum: `RateLimited { retry_after: Option<Duration> }`, `Auth`, `ContextLength`, `Server { status: u16 }`, `Transport`, `SchemaInvalid`, `ToolError`, `Unknown`. Additive refactor: add `classify_llm_error_typed(err) -> ProviderError` as the new canonical fn; the existing `classify_llm_error(err) -> (bool, bool)` becomes a thin facade delegating via `ProviderError::into()`. The 12+ existing test cases in `agent_loop.rs` and `tests/invariants_27_1_4_1_1.rs` keep passing verbatim with zero churn. `ProviderError` is the canonical classification source consumed by sub-system (B) (extracts `RateLimited{retry_after}` for the tracker) and sub-system (C) (`error_kind: Option<ProviderError>` recorded on `usage_events` for forensics). Coverage: port hermes-agent's `error_classifier.py` test cases verbatim into Rust as the parity bar.

## Implementation Decisions

### Area A — Prompt caching scope & strategy

- **D-CACHE-01:** Provider scope = **Anthropic now; OpenRouter as a wave-3 optional stretch plan within this phase**. Anthropic-native `cache_control` ships in wave 1/2 plans. A separate optional plan adds OpenRouter `cache_control` (different request envelope on `LlmClient` chat_completions path); if that plan slips, it's cut to a follow-up phase without affecting the parity-PASS claim for the Anthropic side. This preserves the §2.1 "PARTIAL → PARITY" outcome for Anthropic and gives OpenRouter a clean cut-line.

- **D-CACHE-02:** TTL = **configurable, default 1h**. Surfaced in `config.yaml` as `prompt_caching.ttl: 5m | 1h` (validated, no free-form duration). Default 1h matches hermes-agent's cross-session strategy. A single `cache_control: { type: "ephemeral", ttl: "1h" }` marker on the breakpoint (or `"5m"` if configured). No per-layer split for now — D-CACHE-04 keeps cached layers stable; rolling 3-message breakpoint inherits the same TTL.

- **D-CACHE-03:** Cache-break warnings ride **the same channel as PRMT-10/11 context-pressure warnings**. The three known triggers each emit one warning, before the next turn would otherwise issue a cache-invalidated request:
  - **Model swap mid-session** (`/model X` while a session has any prior turns) → "Switching from {old_model} to {new_model} will invalidate the cached prefix; next turn pays full prompt tokens."
  - **Memory edit mid-session** (MEMORY.md / USER.md mutation after session start) → "Memory edit will invalidate cache; new snapshot applies at next session start (PRMT-06)."
  - **Context file edit mid-session** (SOUL.md / AGENTS.md / CLAUDE.md mutation during session) → "Context file edit will invalidate cache for this session."
  Surfaces: TUI status bar (out-of-band, same `context_warnings` channel Phase 34b shipped), gateway out-of-band reply, web UI sidebar. Slash command `/cache` for on-demand inspection is **deferred** — push-only this phase.

- **D-CACHE-04:** Cached/ephemeral layer separation = **strict assertion at assembly time**. The 10-layer assembler (Phase 15) gains a `cached_layers_must_be_stable()` check: layers 1-8 (per PRMT-02 — SOUL identity, tool-aware guidance, optional provider block, optional system message, frozen MEMORY snapshot, frozen USER snapshot, skills index, context files) are asserted free of timestamps, session IDs, or per-turn data. Hard `panic!` in debug builds; `tracing::warn!` in release. Catches the silent-cache-break class of bug at the source.

### Area B — Per-provider rate-limit tracker

- **D-RL-01:** Telemetry source = **response headers when available, 429 fallback otherwise**. Anthropic and OpenRouter both expose `x-ratelimit-remaining-requests`, `x-ratelimit-remaining-tokens`, `x-ratelimit-reset-*` style headers — parse them out of every successful + every error response. For providers that don't (Ollama, custom OpenAI-compatible endpoints), the tracker reactively counts 429s on a rolling window keyed by `(provider, api_key_hash, model)`. Both signals feed the same `RateLimitEvent` channel — consumers don't care which source filled the fields.

- **D-RL-02:** Tracking key granularity = **`(provider, api_key_hash, model)` — three-axis**. `provider` matches `ProviderResolver`'s field. `api_key_hash` is a stable hash (BLAKE3 first 16 bytes, hex) of the resolved API key — never logged in cleartext, never serialized to disk in this phase. `model` is the resolved canonical model name. Three axes cover (a) Anthropic's per-key quota model, (b) per-model class separation (Opus/Sonnet/Haiku have independent buckets), and (c) future credential-pool work (v2.2 AUTH-01 will fan out across multiple `api_key_hash` values for the same provider). Map: `HashMap<(String, [u8;16], String), TrackerState>`.

- **D-RL-03:** Action on near-limit = **log + emit structured event; AgentLoop decides**. The tracker is pure observability + event source; it never calls into `fallback_providers` directly. It emits `RateLimitEvent { provider, key_hash, model, remaining, reset_at, severity: Info | Warning | Critical }` on a Tokio broadcast channel. AgentLoop subscribes and decides:
  - `Warning` (remaining < 10% of bucket) → emit a hint via `tracing::warn!` and the existing context_warnings out-of-band channel
  - `Critical` (post-429) → no new behavior; the existing `classify_llm_error` → `fallback_providers` path already handles it (Phase 27.1.4.1)
  Clean separation: tracker measures, AgentLoop reacts. Future credential-pool work can subscribe to the same channel without touching the tracker.

- **D-RL-04:** Crate home + storage = **new module in `ironhermes-agent`, in-memory only**. Module name TBD (planner's pick from `agent::rate_limit`, `rate_limit_tracker`, or a small new file alongside `agent_loop.rs`). Storage = `Arc<tokio::sync::RwLock<HashMap<(...), TrackerState>>>` owned by AgentLoop or a sibling registry constructed at AgentLoop init. Per-process, lost on restart — acceptable because headers re-populate on next call. Does NOT live in `ironhermes-core` (would muddle the unrelated gateway user-rate-limiter `RateLimitConfig` at `core/config.rs:812`); does NOT create a new `ironhermes-providers` crate (premature; iron-hermes-planning §1 already notes the absence of one is intentional).

### Area C — Usage & cost accounting ledger

- **D-USAGE-01:** Pricing source = **static `pricing.toml` mirroring Phase 21.3's ModelRegistry pattern, refreshable via CLI**. Ship a hand-curated `crates/ironhermes-core/src/pricing.toml` (or wherever ModelRegistry sits) with rows like `[claude-opus-4-7] input_per_1m_usd_micros = 15000000 / output_per_1m_usd_micros = 75000000 / cache_read_per_1m_usd_micros = 1500000 / cache_creation_per_1m_usd_micros = 18750000`. Storage as micro-USD integers (1 USD = 1_000_000) to avoid float drift. CLI: `hermes pricing refresh` fetches from models.dev (preferred — broader catalog) with OpenRouter API as a secondary source, writes a disk cache to `$HERMES_HOME/pricing-cache.json`. Resolution chain at lookup time: disk cache > static table > best-effort fallback (`0` with a `tracing::warn!`). Offline by default; online on user demand.

- **D-USAGE-02:** Storage = **extend existing `sessions` table columns + new `usage_events` per-turn table**. Schema migration adds three columns to `sessions`: `cache_read_tokens INTEGER DEFAULT 0`, `cache_creation_tokens INTEGER DEFAULT 0`, `cost_usd_micros INTEGER DEFAULT 0`. New table:
  ```
  usage_events (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id  TEXT NOT NULL,
    ts          INTEGER NOT NULL,            -- unix epoch ms
    provider    TEXT NOT NULL,
    model       TEXT NOT NULL,
    in_tok      INTEGER NOT NULL,
    out_tok     INTEGER NOT NULL,
    cache_read  INTEGER NOT NULL DEFAULT 0,
    cache_create INTEGER NOT NULL DEFAULT 0,
    cost_usd_micros INTEGER NOT NULL DEFAULT 0,
    error_kind  TEXT                         -- NULL on success; serialized ProviderError variant name on failure
  );
  CREATE INDEX usage_events_session_idx ON usage_events(session_id);
  CREATE INDEX usage_events_ts_idx      ON usage_events(ts);
  ```
  Both views: `sessions` row stays the fast aggregate path (already wired in `crates/ironhermes-state/src/lib.rs:707-711`); `usage_events` enables per-turn forensics + flexible `/usage` queries. Per turn: AgentLoop writes one `usage_events` row AND increments the matching `sessions` row in a single transaction.

- **D-USAGE-03:** Surfacing = **all three channels** ship in this phase:
  - **`/usage` slash command** (via CommandRouter, registered in `ironhermes-core::commands::registry`): subcommands `/usage` (current session totals), `/usage --today` (all sessions today), `/usage --provider X` (filter), `/usage --since 7d` (windowed), `/usage --model X`. Multi-platform automatically: CLI, TUI, gateway (Telegram/Discord/Slack), web UI — all dispatch through the same CommandRouter.
  - **Status-bar live counter** in TUI's `tui_rata` status bar and web UI sidebar. Format: `│ $0.234 │ 12.4K tok │` (current session, updates after every turn). Subscribes to a per-session usage ticker derived from the latest `sessions` row.
  - **Per-turn `tracing::info!` debug log line**: `usage: session={id} provider={p} model={m} in={i} out={o} cache_read={cr} cache_create={cc} cost_usd_micros={u}` emitted at turn end. Visible in `tracing` logs only — power-user forensics, not UI.

- **D-USAGE-04:** Aggregation grain = **per-turn with rollups**. Each successful LLM call writes exactly one `usage_events` row; the sibling `sessions` row is incremented in the same transaction. Rollups (session totals, daily totals, per-provider totals) are SQL aggregations over `usage_events` — no maintained counter tables. Subagent calls write their own rows tagged with the subagent's session_id (matches PROV-09/10 budget model — subagent consumes from parent's budget but is its own session for usage forensics). Failed calls (any `ProviderError`) ALSO write a row, with `error_kind` populated and `cost_usd_micros = 0` — important for "I got rate-limited 47 times today" forensics.

### Area D — Error classification taxonomy depth

- **D-ERR-01:** Taxonomy shape = **typed `ProviderError` enum, with existing `(should_retry, should_fallback)` tuple kept as a facade method**. New enum (likely in `crates/ironhermes-agent/src/error_classifier.rs` or a sibling module — planner's pick):
  ```rust
  pub enum ProviderError {
      RateLimited { retry_after: Option<Duration> },
      Auth,                              // 401 / 403
      ContextLength,                     // model context exceeded
      Server { status: u16 },            // 5xx
      Transport,                         // connection refused / DNS / connect timeout
      SchemaInvalid,                     // malformed response / tool schema mismatch
      ToolError,                         // tool-side failure surfaced via the provider
      Unknown,
  }

  impl ProviderError {
      pub fn should_retry(&self) -> bool   { /* ... */ }
      pub fn should_fallback(&self) -> bool { /* ... */ }
  }
  ```
  The tuple becomes a `From<ProviderError> for (bool, bool)` so existing call sites keep working without textual changes.

- **D-ERR-02:** Cross-system integration = **yes, ProviderError is the canonical classification source for all three sub-systems shipped this phase**. RateLimitTracker (Area B) destructures `ProviderError::RateLimited { retry_after }` directly to seed the rolling-window state when headers are absent. UsageEvents (Area C) records `error_kind: Option<ProviderError>` as a string (variant name) on every per-turn row, enabling `/usage --errors` slicing. The fallback chain (PROV-07, Phase 27.1.4.1) continues to consume the `(bool, bool)` facade — zero churn there. Single source of truth means the next person extending error handling only edits one enum.

- **D-ERR-03:** Refactor scope = **additive — wrap existing helper, keep old tests verbatim**. Concretely:
  - Add `pub fn classify_llm_error_typed(err: &anyhow::Error) -> ProviderError` as the new canonical entry point. Internally reuses existing `extract_http_status` + `is_transport_failure` helpers (zero rewrite). Maps HTTP codes + transport patterns to enum variants.
  - The current `pub fn classify_llm_error(err: &anyhow::Error) -> (bool, bool)` becomes a one-liner: `classify_llm_error_typed(err).into()`. Signature byte-identical.
  - The 12+ existing test cases in `agent_loop.rs` (lines 2586-2700+) and `crates/ironhermes-agent/tests/invariants_27_1_4_1_1.rs` keep passing verbatim. ZERO test churn.
  - New tests live alongside the new fn, asserting on the enum variant.
  This is the lowest-blast-radius path that still gets us the typed taxonomy.

- **D-ERR-04:** Test coverage = **port hermes-agent's `error_classifier.py` test cases into Rust as the parity bar**. Read `/Users/twilson/code/hermes-agent/agent/error_classifier.py` + its accompanying test file; for each variant covered there (including each weird real-world error string the Python suite has accumulated), write the Rust equivalent test against `classify_llm_error_typed`. Plus the existing 12+ Rust tests for the legacy tuple-shaped path stay green. End state: every classification decision hermes-agent makes is covered, plus the existing Phase 27.1.4.1.x guarantees.

  pub enum ProviderError {
      RateLimited { retry_after: Option<Duration> },  // 429 or header-derived
      Auth,                                            // 401 / 403
      ContextLength,                                   // model context exceeded

      ToolError,                                       // tool execution failed in-provider
      Unknown,
  }

  impl From<ProviderError> for (bool /* should_retry */, bool /* should_fallback */) {
      fn from(e: ProviderError) -> Self {
          match e {
              ProviderError::RateLimited { .. } => (true, true),
              ProviderError::Auth               => (true, true),
              ProviderError::ContextLength      => (false, true),
              ProviderError::Server { .. }      => (true, true),
              ProviderError::Transport          => (true, true),
              ProviderError::SchemaInvalid      => (false, false),

  }
