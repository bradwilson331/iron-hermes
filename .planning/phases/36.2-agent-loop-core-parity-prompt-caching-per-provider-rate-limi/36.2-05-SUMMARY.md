# Phase 36.2 Plan 05: Anthropic prompt caching (cache_control + system_and_3) Summary

Attach Anthropic-native `cache_control` markers (ephemeral, configurable 5m or 1h TTL, default 1h) on the system block + the last 3 non-system messages — the **system_and_3** strategy from D-CACHE-01/02. Wire the request envelope through `AnthropicClient` and the `AnyClient::AnthropicMessages` arm ONLY (D-CACHE-01 explicitly defers OpenRouter `cache_control` to Plan 11 stretch). Add the cached-layer-stability assertion `cached_layers_must_be_stable()` to `prompt_builder.rs` per D-CACHE-04 (debug `panic!`, release `tracing::warn!`). Add `PromptCachingConfig` + `CacheTtl` enum to `Config` per D-CACHE-02 with `#[serde(default)]` so pre-36.2 config.yaml files parse cleanly. **Closes PRMT-08 + PRMT-09.**

## What Was Built

- **`PromptCachingConfig`** struct — two fields:

  - **T-36.2-05-CFG mitigation:** Closed enum + `#[serde(rename = …)]` rejects any other TTL value at deserialization with a structured serde error. No string interpolation into the request body.

- **`Config.prompt_caching`** field added after `extract: ExtractConfig` (line 339).

### 3. `crates/ironhermes-agent/src/anthropic_client.rs` (Task 2)

- **`CacheControl`** struct (D-CACHE-01/02) — `ty: String` + `ttl: String`; serializes as `{"type":"ephemeral","ttl":"1h"|"5m"}`. Constructor `CacheControl::ephemeral(ttl: &'static str)`.

- **`AnthropicSystem`** enum — replaces `Option<String>` on `AnthropicRequest.system`:
  - `Text(String)` — legacy plain-string serialization (no caching).
  - `Blocks(Vec<SystemBlock>)` — array form required when attaching `cache_control` to a content block per Anthropic API.
  - Custom `Serialize` impl flattens both to the appropriate JSON shape.

- **`SystemBlock`** struct — `{ type: "text", text, cache_control: Option<CacheControl> }`.

- **`ContentBlock` variants** (`Text`, `Image`, `ToolUse`, `ToolResult`) — each gains a `cache_control: Option<CacheControl>` field with `#[serde(default, skip_serializing_if = "Option::is_none")]`. Pre-36.2 JSON shape is byte-identical when None.

- **`AnthropicClient` struct** — gains `prompt_caching: PromptCachingConfig` field.
  - Legacy `new()` constructor unchanged signature; internally calls `new_with_prompt_caching(.., PromptCachingConfig::default())`. Zero churn at existing call sites.
  - New `new_with_prompt_caching(base_url, api_key, model, prompt_caching)` for operator-configured TTL/enable flag.

- **`build_anthropic_request()`** (lines 592-622) — `pub(crate)` single-source request builder consumed by both `chat_completion()` and `chat_completion_stream()`. Guarantees streaming and non-streaming attach markers identically.

- **`attach_cache_control_markers()`** (lines 632-655):
  - Marks the system block (converts `Text` → single-element `Blocks` so `cache_control` attaches to a content block).
  - Marks the LAST content block of the last `min(3, messages.len())` non-system messages via `saturating_sub(3)..n` iteration.

- **`attach_marker_to_last_block()`** (lines 659-681) — helper that converts a message's `AnthropicContent::Text` to `Blocks` form before attaching the marker. Handles all 4 `ContentBlock` variants symmetrically.

- **Test helpers (Task 2 acceptance)** —
  - `build_anthropic_request_for_test(messages, model, &prompt_caching) -> AnthropicRequest`
  - `serialize_request_for_test(&req) -> Result<String>`

**2. [Rule 1 - Bug] Existing test-mode patterns broke when adding `cache_control` field to `ContentBlock` variants**

- **Found during:** Task 2 build, after adding `cache_control: Option<CacheControl>` to all 4 variants.
- **Issue:** Pre-existing tests at lines 1162, 1196, 1424 in `anthropic_client.rs` (`#[cfg(test)] mod tests`) destructure `ContentBlock::Text { text }`, `ContentBlock::ToolUse { id, name, input }`, etc. Adding a new field to each variant breaks exhaustive patterns — `error[E0027]: pattern does not mention field 'cache_control'`.

**3. [Rule 2 - Critical correctness add] Streaming + non-streaming paths share a single `build_anthropic_request()` helper**

- **Found during:** Task 2 implementation
- **Issue:** The plan's behavior section says markers must attach identically on both streaming and non-streaming paths (Pitfall guard: "streaming … must attach markers identically"). The original `chat_completion` and `chat_completion_stream` had inline `AnthropicRequest { … }` literal construction in two places — two-site marker logic is fragile.
- **Fix:** Extracted `build_anthropic_request()` as a `pub(crate)` helper. Both `chat_completion` and `chat_completion_stream` now delegate to it. Marker attachment is structurally single-source.
- **Commit:** `f54a0a93` (Task 2 GREEN).

**4. [Rule 1 - Bug] Plan-specified `AnthropicSystem` shape did not exist — system was `Option<String>`**

- **Found during:** Task 2 implementation
- **Issue:** Plan's `<interfaces>` section assumed an existing `AnthropicContentBlock` struct on the system side and that attaching `cache_control` to it would Just Work. Actual code had `system: Option<String>` — a plain string, no content-block array shape. Anthropic's API requires the array form when attaching `cache_control` (markers attach to content blocks, not strings).
- **Fix:** Introduced `AnthropicSystem` enum (`Text(String)` | `Blocks(Vec<SystemBlock>)`) with custom `Serialize` impl that flattens to the right JSON shape per variant. `attach_cache_control_markers` upgrades `Text` → `Blocks` when caching is enabled. Pre-36.2 wire format (plain string) is byte-preserved when caching is disabled.
- **Justification:** The plan's success criterion is the literal serialized JSON shape (`"cache_control":{"type":"ephemeral","ttl":"1h"}`) — that shape requires the array form. The plan would not be satisfiable without this upgrade.
- **Commit:** `f54a0a93` (Task 2 GREEN).

**5. [Rule 1 - Bug] `CacheControl` needed `Deserialize` because `ContentBlock` derives Deserialize**

- **Found during:** Task 2 build
- **Issue:** Adding `cache_control: Option<CacheControl>` to `ContentBlock::Text` (which derives `Deserialize`) requires `CacheControl: Deserialize`. Plan sketch had `&'static str` fields which can't deserialize.
- **Fix:** Used `String` fields on `CacheControl` (constructor accepts `&'static str` and converts via `.to_string()`). Tiny allocation cost per request; correctness preserved.
