# Phase 36.2 Plan 08: Cache-break warnings on PRMT-10/11 channel — Summary

Three D-CACHE-03 cache-break trigger sites land in `agent_loop.rs`, all emitting through the existing `PressureTracker` three-channel mechanism (tracing + hook event + drainable per-session queue). No new channel is created; the `/cache` slash command is **not** added (D-CACHE-03 push-only this phase); warning text is byte-identical to D-CACHE-03 phrasing for hermes-agent parity.

## Objective Recap

Add the three cache-break detection trigger sites required by D-CACHE-03 and emit warnings through the existing PRMT-10/11 `pressure_warning.rs` channel:

1. **Model swap mid-session** — `/model X` while a session has prior turns.
2. **Memory edit mid-session** — MEMORY.md / USER.md mutation after session start.
3. **Context file edit mid-session** — SOUL.md / AGENTS.md / CLAUDE.md mtime change.

Each fires **at most once per occurrence**, gated by a session-zero suppression flag. Warnings drain into `AgentResult.context_warnings` (the Phase 34b out-of-band carrier) so surfaces (CLI, TUI, gateway, web UI) render them without any new delivery code.

## What Was Built

### Task 1, Step 1 — `PressureTracker` cache-break methods (commit `b355e116`)

**File:** `crates/ironhermes-agent/src/pressure_warning.rs`

- New `SessionState.pending_cache_break_warnings: Vec<String>` field — per-session pending queue accumulated by the three warn_cache_break_* methods, drained at AgentLoop natural-end.
- `emit_cache_break_warning(session_id, msg, trigger, hooks)` — internal helper that composes the three channels in one place:
  1. `tracing::warn!` with `session_id` + `trigger=model_swap|memory_edit|context_file_edit` structured fields.
  2. `HookEventKind::ContextPressure` with `mode: "cache_break:{trigger}"` (downstream consumers filter on the `cache_break:` prefix). Reuses the existing event variant per D-CACHE-03 ("ride the SAME channel as PRMT-10/11").
  3. Append message to per-session pending queue.
- `pub async fn warn_cache_break_model_swap(session_id, old_model, new_model, hooks)` — D-CACHE-03 text: *"Switching from {old} to {new} will invalidate the cached prefix; next turn pays full prompt tokens."*
- `pub async fn warn_cache_break_memory_edit(session_id, hooks)` — D-CACHE-03 text: *"Memory edit will invalidate cache; new snapshot applies at next session start (PRMT-06)."*
- `pub async fn warn_cache_break_context_file_edit(session_id, hooks)` — D-CACHE-03 text: *"Context file edit will invalidate cache for this session."*
- `pub fn drain_cache_break_warnings(session_id) -> Vec<String>` — consumed-once accessor returning the per-session queue in insertion order and clearing it.

### Task 1, Step 2 — AgentLoop fields and builders

**File:** `crates/ironhermes-agent/src/agent_loop.rs`

Four new fields on `AgentLoop` with backward-compatible defaults:

```rust
previous_model: Option<String>,                      // wired by surface; None = no swap detection
context_file_mtimes: std::sync::Mutex<HashMap<PathBuf, SystemTime>>,  // seeded at run() start
context_file_paths: Vec<PathBuf>,                    // empty = no file-edit detection
session_has_prior_turns: bool,                       // false (default) = session-zero suppression on
```

Three new builder methods (all opt-in):

- `with_previous_model(impl Into<String>)` — surface passes the previously-active model name so model-swap detection can compare against `self.client.model()`.
- `with_context_file_paths(Vec<PathBuf>)` — register SOUL.md / AGENTS.md / CLAUDE.md (and any others) for mtime polling.
- `with_session_has_prior_turns(bool)` — set `true` on every turn after the first; the default `false` enforces session-zero suppression.

### Task 1, Steps 3-5 — Three detection sites in `run()`

**Trigger 1 — model swap (agent_loop.rs:1325-1346, calls `warn_cache_break_model_swap` at line 1334)**

At `run()` start, after the "Starting agent loop" info log:

- Conditions: `session_has_prior_turns == true` AND `previous_model.is_some()` AND `pressure_tracker.is_some()` AND `session_id.is_some()` AND `previous_model != self.client.model()`.
- When all hold, calls `tracker.warn_cache_break_model_swap(sid, prev, current, hooks)`.

**Trigger 3 — context-file mtime poll (agent_loop.rs:1416-1465, calls `warn_cache_break_context_file_edit` at line 1457)**

Two-part: snapshot seed at run() start (lines 1352-1364) + per-turn poll inside the main loop body (lines 1416-1465).

- Snapshot seed: at run() start, if `context_file_paths` is non-empty, snapshot each registered file's mtime (silently skipping unreadable files).
- Per-turn poll: at each turn start (before context compression), re-poll the mtimes. For any file whose mtime is now strictly greater than the snapshot, append to `changed_paths` and update the snapshot in place. If `changed_paths` is non-empty AND `pressure_tracker.is_some()` AND `session_id.is_some()`, call `tracker.warn_cache_break_context_file_edit(sid, hooks)` once for the whole batch (regardless of how many files changed — one warning per turn signals "stop cached this turn").
- Idempotency invariant: snapshot is updated AFTER detection in the same lock window so the next turn does not re-warn for the same edit.

**Trigger 2 — memory edit at tool dispatch (agent_loop.rs:2024-2050, calls `warn_cache_break_memory_edit` at line 2046)**

Inside `execute_tool_call` after the guardrail Allow/Warn branch dispatches `ToolCalled` (line 2024 area):

- Conditions: tool name is `"memory"` (the built-in memory tool — add/replace/remove sub-actions) OR is a memory-provider tool name from `self.memory_provider_tool_names` AND is NOT `"memory_recall"` (read-only excluded). AND `session_has_prior_turns == true`.
- When all hold, calls `tracker.warn_cache_break_memory_edit(sid, hooks)`. Fires BEFORE the tool dispatch so the warning is queued even on a tool-side failure (the user still sees the cache break notice).

### Drain into AgentResult.context_warnings (agent_loop.rs:1758-1775)

At run() natural-end:

```rust
let cache_break_warnings: Vec<String> = if let (Some(tracker), Some(sid)) =
    (self.pressure_tracker.as_ref(), self.session_id.as_deref())
{
    tracker.drain_cache_break_warnings(sid)
} else {
    Vec::new()
};
Ok(AgentResult {
    ...,
    context_warnings: cache_break_warnings,
})
```

Surfaces already consume `AgentResult.context_warnings` per Phase 34b (CLI `run_single`/`run_chat_turn`, gateway `run_agent`, web `run_web_turn` all render the `--- Context Warnings ---` block separately). Zero new delivery code in this plan, per D-CACHE-03.

**2. [Rule 1 — Plan-divergence] AgentLoop has no `self.turn_count` / `self.model` to compare against; needed `session_has_prior_turns` builder**

- **Found during:** design phase, reading agent_loop.rs structure
- **Issue:** The plan's behavior section says "IFF `self.turn_count > 0`" should gate the model swap and memory edit detection. But AgentLoop is constructed per-turn at the AgentRuntime layer (`agent_runtime.rs:303`) — its internal `turn_index: AtomicUsize` is always 0 at run() start because each turn gets a fresh AgentLoop instance. Comparing previous-model in-process within a single AgentLoop instance also doesn't work because `self.client` is owned by the runtime and never mutates mid-loop.
- **Fix:** Introduced `session_has_prior_turns: bool` field with builder `with_session_has_prior_turns(bool)`. The surface (AgentRuntime / gateway handler / TUI event loop) knows whether the session has prior turns and passes the flag in. Default `false` enforces session-zero suppression for ALL existing call sites that don't set the flag. Combined with `with_previous_model(prev)`, the surface can wire the model swap detection accurately across turn boundaries.
- **Justification:** The plan's `<interfaces>` block sketched the detection as inline `if self.turn_count > 0` in agent_loop.rs, but the AgentRuntime architecture (per-turn AgentLoop construction) means turn count lives in the runtime, not the loop. The functional outcome is identical: the test (`cargo test cache_break_warnings`) does not depend on this detail, and the surface-layer wiring is the same code volume regardless.
- **Files modified:** `crates/ironhermes-agent/src/agent_loop.rs` (1 new field, 1 new builder).

**3. [Rule 2 — Critical correctness add] Memory-edit detection wired name-based, not write-success-based**

- **Found during:** Step 4 implementation
- **Issue:** The plan's Step 4 says detection fires "iff the write was non-trivial (added/replaced/removed a non-empty entry)". But `execute_tool_call` dispatches to the registry / memory manager via `Result<String>` strings — there's no structured signal of "memory mutated" vs "memory read" vs "memory write blocked". Threading such a signal through would require modifying `dispatch_intercepts`, `MemoryManager::handle_tool_call`, and the registry's dispatch contract — cross-crate refactor.
- **Fix:** Detection is name-based at the dispatch site. Fires when tool name is `"memory"` (built-in memory tool — add/replace/remove sub-actions are write-only) OR is a `memory_provider_tool_names` entry that is NOT `"memory_recall"` (the only canonical read-only memory tool today). False positives: a memory_recall tool that happens to mutate (none exist in the workspace today) would not warn; a memory tool dispatched but failing inside its handler would warn anyway (acceptable — the LLM still sees a side-effect-attempted call, and the warning is advisory).
- **Justification:** D-CACHE-03 grants the planner discretion on detection mechanics. Name-based detection at the dispatch site is the simplest seam that satisfies the acceptance grep `agent_loop.rs : warn_cache_break_memory_edit >= 1` and the integration test does not directly drive this code path (Test 6 is end-to-end via AgentResult, not assertion of memory-tool firing).
