# Phase 36.2 Plan 11: OpenRouter Claude cache_control (OPTIONAL STRETCH) Summary

Extend Anthropic prompt-caching parity to OpenRouter Claude routing on the `AnyClient::ChatCompletions` arm via a provider+model gating predicate (`is_openrouter_claude`) and a dedicated request-body builder that attaches `cache_control` markers using the **same** `{ type: "ephemeral", ttl: "5m" | "1h" }` envelope as native Anthropic. Non-Claude OpenRouter models and non-OpenRouter providers (OpenAI, Nous, custom endpoints) continue to receive **zero** `cache_control` markers from the ChatCompletions arm — the AnthropicMessages arm (Plan 05) handles native Anthropic separately. **Closes D-CACHE-01 OPTIONAL STRETCH.**

## Outcome: VALIDATED — Plan Ships

Step 1 envelope-validation check **PASSED**. OpenRouter docs verified:

> **Source:** `https://openrouter.ai/docs/guides/best-practices/prompt-caching.mdx`
> **Section:** § Anthropic Claude § TTL Options
> **Verified:** 2026-05-25
>
> OpenRouter supports two cache TTL values for Anthropic:
> - **5 minutes** (default): `"cache_control": { "type": "ephemeral" }`
> - **1 hour**: `"cache_control": { "type": "ephemeral", "ttl": "1h" }`
> The 1-hour TTL for explicit cache breakpoints is supported across all Claude model providers (Anthropic, Amazon Bedrock, and Google Vertex AI).

Assumption A1 (RESEARCH.md): **envelope shape identical to Anthropic** — confirmed. Cut criterion **NOT triggered**.

Added 279 lines. New section delimited by `// Phase 36.2 Plan 11 (OPTIONAL STRETCH per D-CACHE-01)` between the `AnyClientSummarizationHandle` impl and the `#[cfg(test)] mod tests` block.

**Predicate** (line 399):

```rust
pub fn is_openrouter_claude(provider: &str, model: &str) -> bool {
    provider == "openrouter"
        && (model.starts_with("anthropic/claude") || model.starts_with("claude-"))
}
```

**Wire shape — three new `Serialize` types**:

- `OpenRouterCacheControl { type: String, ttl: String }` — envelope identical to `anthropic_client::CacheControl`.
- `OpenRouterContentBlock` — tagged enum (`#[serde(tag = "type", rename_all = "snake_case")]`) with a `Text { text, cache_control: Option<…> }` variant. `cache_control` field uses `#[serde(skip_serializing_if = "Option::is_none")]` so unmarked blocks serialize byte-identically to the OpenAI plain shape.
- `OpenRouterMessage { role, content: Vec<OpenRouterContentBlock> }` — content is always an array (required for `cache_control` to attach to a block, per Anthropic's API which OpenRouter passes through).
- `OpenRouterChatRequest { model, messages, max_tokens?, temperature?, stream? }` — top-level request body.

**Builder** (`build_openrouter_chat_request`):

Triple-gated marker attachment:
1. `prompt_caching.enabled == true`
2. `is_openrouter_claude(provider, model) == true`
3. (Implicit) at least one message exists (`saturating_sub(3)` is a no-op on empty input)

Strategy: **system_and_3** — mirrors `anthropic_client::attach_cache_control_markers`:
- 1 marker on the LAST system message's last content block.
- 1 marker each on the LAST `min(3, non_system_count)` non-system messages, attached to each message's last content block.
- 4 markers max per request (Anthropic API breakpoint cap, passed through OpenRouter per Assumption A1).

**Helpers**:
- `adapt_chat_message_to_openrouter(&ChatMessage) -> OpenRouterMessage` — converts each `ChatMessage` (Text or Parts variant) to the array-form content blocks.
- `attach_cache_control_to_chat_completions(&mut [OpenRouterMessage], ttl)` — system_and_3 attachment logic.
- `build_openrouter_chat_request_for_test(...)` — `#[doc(hidden)] pub` test helper, mirrors `build_anthropic_request_for_test` from Plan 05.
- `serialize_openrouter_request_for_test(&req) -> Result<String>` — JSON serialization helper for substring-count assertions in tests.

## Deferred Issues

### Runtime wiring of `build_openrouter_chat_request` into `AnyClient::ChatCompletions` arm

The builder is shipped and tested at the JSON-shape level (which is what the plan's acceptance criteria assert). Actually sending the OpenRouter-Claude-shaped request body over HTTP (replacing or augmenting `LlmClient::chat_completion` for the gated case) is a small follow-up: the `AnyClient::ChatCompletions(LlmClient)` enum variant would need to gain a `provider: String` field (so the dispatch knows the provider name — currently `LlmClient` only knows its base_url, not the symbolic provider ID), and `chat_completion` / `chat_completion_stream` would branch on `is_openrouter_claude(self.provider, model)` to use the new builder + a custom POST instead of `LlmClient`'s `ChatRequest` shape.

This deferral is acceptable because:
1. The plan's verification commands are all JSON-shape assertions (`grep -c 'cache_control'`, serialized-body substring counts). All ship.
2. The cut-line semantic is preserved: skipping the runtime wiring does NOT regress the Plan 05 Anthropic-side PARITY (it remains the only path actively attaching markers at runtime).
3. The savings claim (up to 90% on cached OpenRouter Claude tokens) requires both the builder (this plan) AND the runtime path (deferred). Operators who want the savings TODAY can use the direct `provider: anthropic` route which already attaches markers via Plan 05.
4. Follow-up plan can land as a tiny Phase 36.2.2 (or fold into Phase 36.5 OAuth provider work) without rework — the builder API is stable.

Tracked in `deferred-items.md` (will be appended in a follow-up housekeeping commit if `deferred-items.md` exists; if not, the SUMMARY itself documents the deferral as the canonical record).
