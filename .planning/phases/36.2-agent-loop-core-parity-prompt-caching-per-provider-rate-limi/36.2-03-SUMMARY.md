# Phase 36.2 Plan 03: Error Classification Taxonomy — Summary

`ProviderError` enum + `classify_llm_error_typed` ship as the canonical typed taxonomy in `ironhermes-agent`, with the legacy `(bool, bool)` `classify_llm_error` refactored to a one-line facade — closing D-ERR-01..04 with zero churn to the 15 existing fallback tests.

## Objective Recap

Land the typed `ProviderError` enum as the canonical classification source consumed by Plan 06 (RateLimitTracker — destructures `RateLimited { retry_after }`) and Plan 07 (usage_events writer — records `variant_name(): &'static str` in the `error_kind` column). Port the 30 enumerated Python `error_classifier.py` test cases as the D-ERR-04 parity bar. Preserve the `invariants_27_1_4_1_1.rs` PROV-07 static-grep guarantee.

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Keep `extract_http_status` / `is_transport_failure` in `agent_loop.rs`; widen to `pub(crate)` | Moving them would break `invariants_27_1_4_1_1.rs`'s static-grep (which inspects `agent_loop.rs` source). The `pub(crate)` upgrade is the minimum mechanical change that lets `error_classifier.rs` reuse them. | PROV-07 invariant preserved byte-identically |
| 11 variants in `ProviderError` (vs CONTEXT.md sketch of 8) | The Python `FailoverReason` has 19 variants and the 30 Python test cases distinguish billing/rate-limit/payload-too-large/model-not-found/policy-block at granularities the 8-variant sketch could not represent without rolling them into Unknown. 11 is the minimum needed to cover the parity bar. | Each Python test case maps to a precise Rust variant; the failover (bool, bool) tuple is preserved at all 15 legacy call sites |
| HTTP 400 disambiguated via `classify_400_subcases` (context-overflow → image-too-large → multimodal-tool → thinking-signature → grammar → long-context-beta → SchemaInvalid fall-through) | The 30 Python items required distinguishing 7 sub-shapes of HTTP 400 by message content. A flat status-code switch could not cover the parity bar. | Six new sub-arms — all unit-tested |
| `variant_name()` returns one of 11 `&'static str` literals — never response-derived text | Plan 07 stores this in `usage_events.error_kind`. A bounded compile-time set guarantees HTTP bodies, headers, and PII cannot leak through this column. | T-36.2-03-PII mitigated structurally |
| `retry_after: Option<Duration>` extracted via a needle-search helper (`parse_retry_after`) without `regex` dep | Zero new deps mandate; the 4 needles (`retry-after:`, `retry_after:`, `retry after:`, `retry-after `) cover the case-insensitive shapes in real-world provider error bodies. | Plan 06 RateLimitTracker can read `retry_after` directly off the classification result; verified by `test_http_429_with_retry_after_header_parses_duration` |
| Collapse Python `provider_policy_blocked` → Rust `Auth` (both yield `(false, true)`) | The semantic intent ("user needs intervention, not blind retry") matches Auth; a separate `PolicyBlocked` variant is deferred until tool-error parity (Plan 36.3) lands. | One fewer variant; downstream behavior identical |
| Collapse Python `oauth_long_context_beta_forbidden` → Rust `SchemaInvalid` | Beta-availability is a server-side schema-level restriction — closer to SchemaInvalid than Auth or RateLimited. Captured in the 400-subcase disambiguation chain. | One Rust variant covers Python's `oauth_long_context_beta_forbidden`, `thinking_signature`, `llama_cpp_grammar_pattern`, and generic `format_error` — all `(false, true)` |

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Initial test strings used plain `"HTTP NNN Reason"` format which `extract_http_status` does not parse**
- **Found during:** Task 2 first test run (16 / 34 tests failed)
- **Issue:** I authored `provider_error_classification.rs` with error strings like `"HTTP 502 Bad Gateway"`. The existing parser only recognises two production formats: `"(NNN ReasonPhrase)"` (the `bail!` shape from `client.rs:170`) and `"HTTP request failed with status: NNN"` (synthetic). Plain `"HTTP NNN"` has neither marker.
- **Fix:** Rewrote each HTTP-status test to use one of the two recognised formats. Did NOT modify `extract_http_status` itself — the parser's recognised formats are part of the locked PROV-07 contract.
- **Files modified:** `crates/ironhermes-agent/tests/provider_error_classification.rs` only
- **Verification:** 34/34 tests pass on the second run.
- **Commit:** `2a5b694c` (included in Task 2)

**2. [Rule 1 — Doc lint] `clippy::doc_list_item_without_indent` warnings on the module doc block of `provider_error_classification.rs`**
- **Found during:** Task 2 clippy check

- **Fix:** Reformatted the doc block: added a blank line before the bulleted list and another after; unindented prose now stands as a separate paragraph.
