# Phase 36.2 Plan 01: Anthropic cache field population Summary

Populate `cache_read_input_tokens` and `cache_creation_input_tokens` on the outer `Usage` wrapper from Anthropic response bodies (both the non-streaming `parse_anthropic_response` site and the streaming `MessageDelta` SSE event), so downstream Phase 36.2 plans (cost accounting, cache-break detection, rate-limit tracking) stop silently receiving `None` for cache tokens on every Anthropic call.

## What Was Built

### Source change — `crates/ironhermes-agent/src/anthropic_client.rs`

- **`AnthropicUsage` struct** (lines 138-152): two new `#[serde(default)] Option<usize>` fields — `cache_read_input_tokens`, `cache_creation_input_tokens`. `Default` derived so existing test fixtures can use `..Default::default()`.
- **`SseUsage` struct** (lines 207-218): same two `#[serde(default)] Option<usize>` fields appended to the streaming delta deserializer.
- **Non-streaming parse site** (line 549, was 533): `cache_read_input_tokens: response.usage.cache_read_input_tokens` replaces the prior hardcoded `None`. Same for cache_creation.
- **Streaming parse site** (line 835, was 819): `cache_read_input_tokens: u.cache_read_input_tokens` replaces the prior hardcoded `None`. Same for cache_creation. This closes RESEARCH Open Question 1 (the streaming/non-streaming silent-divergence bug).
- **Existing test fixtures** (lines 1032-1036 and 1066-1070): `test_parse_anthropic_response_text` and `test_parse_anthropic_response_tool_use` updated to use `..Default::default()` (the only behavioral change to existing tests — original assertion bodies are byte-identical).
- **4 new inline tests** (end of `#[cfg(test)] mod tests`):
  1. `anthropic_usage_deserializes_cache_fields_when_present` — JSON with both cache fields → `Some(8200)` / `Some(4200)`.
  2. `anthropic_usage_defaults_cache_fields_to_none_when_absent` — legacy/non-cached JSON → `None` via `#[serde(default)]`.
  3. `anthropic_usage_treats_null_cache_fields_as_none` — explicit JSON `null` → `None`.
  4. `parse_anthropic_response_populates_outer_usage_cache_fields` — outer `Usage` wrapper carries the values through, not always-None.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Type mismatch: plan specified `Option<u64>`, outer Usage is `Option<usize>`**

- **Found during:** Task 1, after first `cargo build` failure
- **Issue:** The plan's `<interfaces>` block and acceptance criteria specified `cache_read_input_tokens: Option<u64>` on the new `AnthropicUsage` fields. But the outer `ironhermes-core::types::Usage` struct declares those fields as `Option<usize>`. The plan's also-required verbatim copy `cache_read_input_tokens: response.usage.cache_read_input_tokens` at the parse site only typechecks if both ends agree on the type.
- **Fix:** Used `Option<usize>` on both `AnthropicUsage` and `SseUsage` so the parse sites can use the bare assignment with no cast. Plan's literal-string acceptance criterion (`Option<u64>`) is consciously violated; the alternative — `Option<u64>` plus `.map(|v| v as usize)` at every parse site — would have broken the "verbatim copy" criterion AND required updating every downstream consumer's expected type.
- **Files modified:** `crates/ironhermes-agent/src/anthropic_client.rs` (struct field types)
- **Doc trail:** Inline comment on the AnthropicUsage struct explains the deviation; integration test asserts the `Option<usize>` shape so the deviation is locked in code, not just docs.
- **Commit:** 6d8adf91

**2. [Rule 2 - Critical correctness add] Extended `SseUsage` in lockstep with `AnthropicUsage`**

- **Found during:** Task 1, while patching the streaming parse site
- **Issue:** The plan said both parse sites must populate cache fields, but the streaming site uses a different deserialization struct (`SseUsage`, not `AnthropicUsage`). `SseUsage` originally had only `output_tokens: Option<usize>` — no cache fields. Without extending it, the streaming site would still effectively populate `None` (with no input source from the SSE message).
- **Fix:** Added the same two `#[serde(default)] Option<usize>` cache fields to `SseUsage`. The streaming site now copies `u.cache_read_input_tokens` / `u.cache_creation_input_tokens` through to the outer Usage.
- **Justification:** Plan success criterion explicitly says "the streaming path is patched alongside the non-streaming path so no caller of `AgentLoop` silently loses cache visibility based on which response path they take." This was the only way to honor that.
- **Commit:** 6d8adf91

**3. [Rule 1 - Bug] Test fixture compile error**

- **Found during:** Task 1, after first `cargo build` failure
- **Issue:** Two existing test fixtures (`test_parse_anthropic_response_text`, `test_parse_anthropic_response_tool_use`) construct `AnthropicUsage { input_tokens, output_tokens }` as struct literals. Adding new fields to the struct definition breaks these struct literals at compile time. Plan claimed `#[serde(default)]` would make existing tests pass byte-for-byte, but `#[serde(default)]` affects deserialization only — not Rust struct literal construction.
- **Fix:** Derived `Default` on `AnthropicUsage`; rewrote the two literal closures to use `..Default::default()` (3-line change per fixture, original assertions unchanged). This both:
  - Restores compilation.
  - Keeps the `no hardcoded None,` static-grep invariant clean — `..Default::default()` is the canonical way to fill in defaults without sentinel literals.
- **Commit:** 6d8adf91
