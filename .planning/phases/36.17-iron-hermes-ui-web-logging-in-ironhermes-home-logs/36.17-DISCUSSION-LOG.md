## Log filename + path layout

| Option | Description | Selected |
|--------|-------------|----------|
| `web.log` (Recommended) | `~/.ironhermes/logs/web.log.YYYY-MM-DD` — short, parallel to `tui.log`, names the surface | |
| `ui.log` | `~/.ironhermes/logs/ui.log.YYYY-MM-DD` — matches crate name but ambiguous next to `tui.log` | |
| `server.log` | `~/.ironhermes/logs/server.log.YYYY-MM-DD` — names the role, not the surface | |
| Split: `web.log` + `web-access.log` | Two streams — app/agent tracing + HTTP access. Doubles file count but cleanly separates the two log types. | ✓ |

**User's choice:** Split: `web.log` + `web-access.log`
**Notes:** User picked the split, which signals HTTP access logging is in scope and the access lines should not pollute the app log. This decision pre-shaped Area 4 — TraceLayer is mounted and access lines route to their own file via a per-layer filter.

## Default EnvFilter level

| Option | Description | Selected |
|--------|-------------|----------|
| `ironhermes=info,iron_hermes_ui=info` (Recommended) | Parity with TUI's `ironhermes=info`, extended to the iron_hermes_ui crate. | ✓ |
| `ironhermes=info,iron_hermes_ui=info,tower_http=info` | Same plus tower_http=info for the access log via global filter. | |
| `warn` (current default) | Keep iron_hermes_ui's existing `warn` default. | |
| `RUST_LOG` required (no default) | Empty subscriber unless operator sets RUST_LOG. | |

**User's choice:** `ironhermes=info,iron_hermes_ui=info` (Recommended)
**Notes:** The user picked the option without `tower_http=info` in the global default, but had picked split streams in Area 1. Resolved by routing the access stream through a per-layer filter (`tower_http::trace=info`) rather than the global EnvFilter — captured as D-05/D-06. This keeps the global app filter clean (matches TUI parity) and pins HTTP lines to `web-access.log` only.

## Console output behavior

| Option | Description | Selected |
|--------|-------------|----------|
| Keep console + add file (Recommended) | Console keeps printing (colored, ANSI); file layer writes ANSI-stripped lines in parallel. Both fed by same EnvFilter. | ✓ |
| Keep console but drop ANSI | Strip ANSI on console too. | |
| File-only (no console) | Remove the stdout fmt layer entirely. | |
| Env-gated: console for dev, file-only for prod | Install console layer conditionally on `IRONHERMES_LOG_CONSOLE=1` or isatty. | |

**User's choice:** Keep console + add file (Recommended)
**Notes:** Lowest-disruption choice. `cargo run --features server` and `dx serve` behave identically to today, plus the two log files now exist. Access lines do NOT print to console — they're filtered to `web-access.log` only via the per-layer filter from Area 2.

## HTTP request logging

| Option | Description | Selected |
|--------|-------------|----------|
| Basic (Recommended) | method + path + status + duration_ms per request via `tower_http::TraceLayer::new_for_http()` at INFO. | ✓ |
| Detailed | Basic + request_id, remote_addr, user-agent, content-length, request span timing at DEBUG. | |
| Minimal | Only failures (status ≥ 500 or connection error). | |
| Tracing events only — skip tower_http | Custom middleware emitting `tracing::info!(target = "http_access", ...)` lines. | |

**User's choice:** Basic (Recommended)
**Notes:** `TraceLayer::new_for_http()` defaults are used. Per-layer filter `tower_http::trace=info` directs lines to `web-access.log`. Detailed fields (request_id, remote_addr, etc.) deferred to a future phase if the basic format proves insufficient.

## Deferred Ideas

- Detailed access log fields (request_id, remote_addr, user-agent, content-length, request-span timing).
- Custom `http_access` target (hand-rolled middleware instead of `tower_http::trace`).
- Dev-vs-prod console gating (`IRONHERMES_LOG_CONSOLE=1` / `isatty` detection).
- Log forwarding to external collectors (Loki, OTLP, etc.).
- Structured JSON log format.
- Log retention beyond daily-rolling (gzip + N-day cleanup housekeeping).
