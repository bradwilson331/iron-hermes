## Decisions Made

- **Function-scoped `use` imports vs file-top imports.** Chose function-scoped (`use tower_http::trace::{...}; use tracing::Level;` inside `async fn main()`) to mirror the existing `use dioxus::prelude::*;` already in the same function body. The alternative — wrapping a `#[cfg(feature = "server")] use ...;` block at the file top — would have required two `#[cfg(...)]` attributes (one for each crate) and made the imports visible to readers in a context where they had no purpose. Function-scoped is tighter.
- **Pre-built `let trace_layer = ...` binding vs inline `.layer(TraceLayer::new_for_http()...)`.** Chose the `let` binding form. The two `.on_request(...)` / `.on_response(...)` calls are the Q2 risk gate — they're the only reason `web-access.log` will contain anything. Putting them on their own indented lines inside a named binding makes them impossible to miss during code review; an inline chain would have visually crowded the Router build.
- **Kept the `_info_level` placeholder in logging.rs.** Plan 02 deliberately added `let _info_level: Level = Level::INFO;` to anchor the contract that main.rs uses `Level::INFO`. Removing it now that main.rs actually uses `Level::INFO` directly would be valid — but Plan 03's task says nothing about it, and the value (a small documentation aid for future readers of logging.rs) costs nothing.
- **No `drop(_web_log_guard); drop(_access_log_guard);` at end of main().** Plan's Task 1 explicitly says this is the executor's discretion: "Both `_web_log_guard` and `_access_log_guard` will be dropped automatically when `main()` returns — no explicit `drop(...)` call is required". Skipped them. The TUI's `event_loop.rs:68` has one (`drop(_file_log_guard)`) for clarity, but in the web UI's main() the function ends two lines after `axum::serve(...).await.unwrap()` — the scope-end drop is right there visually.
