# Phase 36.17 Plan 04: Wave-3 Behavioral UAT Script Summary

Authored `scripts/uat/phase-36.17-web-logging.sh` — a self-contained bash UAT
that the human operator runs once after Wave 2 merges to prove the web-logging
wiring works end-to-end (two daily-rolling files appear, web-access.log is
non-empty AND carries the `tower_http::trace` target string, neither file
contains ANSI escapes, access events do not leak to either the app log or
stdout). The Q2 risk (TraceLayer defaults to DEBUG, the per-layer access
filter is locked at INFO) is enforced by Gate 3, whose failure message
explicitly cites `RESEARCH.md Q2` so any future operator hitting the gate has
a direct recovery affordance.

## What Got Built

**`scripts/uat/phase-36.17-web-logging.sh`** — 294-line executable bash script
with five gates plus a port precheck:

| Gate | Decisions | What It Asserts |
|------|-----------|-----------------|
| Precheck | — | TCP 8080 is free (clear abort if a previous run or another process owns it) |
| Gate 1 | D-01 / D-02 / D-15 / D-16 | Both `web.log.YYYY-MM-DD` and `web-access.log.YYYY-MM-DD` exist under `$IRONHERMES_HOME/logs/` |
| Gate 2 | D-04 | `web.log` contains at least one `INFO` line (app filter wired) |
| Gate 3 | **D-05 / D-10 (Q2 risk)** | `web-access.log` contains the `tower_http::trace` target string — failure message cites RESEARCH.md Q2 verbatim |
| Gate 4 | D-03 | Neither file contains ANSI escapes (portable bash ANSI-C quote — `grep $'\x1b\['`) |
| Gate 5 | D-09 | Access events do NOT leak into `web.log` and do NOT print on server stdout |

**Script structure:**

1. `set -euo pipefail` + `SCRIPT_DIR`/`WORKSPACE_ROOT` resolution mirroring `scripts/ci-gates.sh`.
2. `IRONHERMES_HOME="$(mktemp -d)"` with `export` so the child server inherits.
3. `trap cleanup EXIT` — SIGTERM-then-wait the server FIRST (so both WorkerGuards drop and flush), only then `rm -rf` the tmp dir. Covers normal exit, `set -e` abort, and SIGINT.
4. `lsof -iTCP:8080 -sTCP:LISTEN` precheck — aborts cleanly with operator hint if the port is busy.
5. `cargo build -p iron_hermes_ui --features server` runs FIRST so the background process step doesn't race a cold-target/ compile against the 30-iteration bind poll.
6. `cargo run` in the background; stdout → `/tmp/phase-36.17-stdout.log`, stderr → `/tmp/phase-36.17-stderr.log`. Both files preserved for post-mortem (intentional — T-36.17-10).
7. 30×1s `curl -sS http://127.0.0.1:8080/` poll for bind readiness. Drops `-f` — a 404 still proves the server is listening and TraceLayer is in the path.
8. One real `curl` to trigger TraceLayer (tolerates non-2xx via `|| true`).
9. `kill -TERM "$SERVER_PID"; wait "$SERVER_PID"` — synchronous flush via guard Drop.
10. Five gate assertions in order; each prints `--> Gate N (D-XX): …` / `    OK` on success, `    GATE FAIL (D-XX): …` + `exit 1` on failure.
11. Final `==> Phase 36.17 web-logging UAT: all green`.

## Threat Surface Notes

No new threat surface introduced. The script's threat model is captured
inline in the plan's `<threat_model>`:

- **T-36.17-08** (Denial of Service: server left alive after abnormal exit) — mitigated by `trap cleanup EXIT` which SIGTERMs `$SERVER_PID` before any other cleanup. Verified by inspection (lines 63–73).
- **T-36.17-09** (Tampering: writing outside the tmp dir) — mitigated by `mktemp -d`-rooted `IRONHERMES_HOME`; no other filesystem mutation occurs. Verified by reading the script — every write target resolves under `${IRONHERMES_HOME}` (the appenders) or `/tmp/phase-36.17-{stdout,stderr}.log` (the redirected server output, intentional per T-36.17-10).
- **T-36.17-10** (Information Disclosure: `/tmp/phase-36.17-*.log` preserved across runs) — accepted; each run uses a fresh `mktemp -d` so dirty state from a previous run is logically isolated to the synthetic test traffic.
