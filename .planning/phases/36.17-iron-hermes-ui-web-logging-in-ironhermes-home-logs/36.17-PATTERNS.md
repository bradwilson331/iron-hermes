## Pattern Assignments

### `crates/iron_hermes_ui/src/server/logging.rs` (NEW — utility, log fan-out)

**Analog:** `crates/ironhermes-cli/src/tui_rata/event_loop.rs` lines 85–117

**Imports pattern** (lines 86, implicit from context):
```rust
use tracing_subscriber::prelude::*;
```
The TUI install function uses a single `use tracing_subscriber::prelude::*;` inside the function body (not at file top). The web logging module should instead declare imports at file top per standard module convention:
```rust
use tracing::Level;
use tracing_appender::non_blocking::WorkerGuard;
use tracing_subscriber::{fmt, prelude::*, registry, EnvFilter};
```

**Core pattern — full install function** (`event_loop.rs` lines 85–117):
```rust
fn install_tui_logger_subscriber() -> Option<tracing_appender::non_blocking::WorkerGuard> {
    use tracing_subscriber::prelude::*;

    let log_dir = ironhermes_core::constants::get_hermes_home().join("logs");
    let file_layer_pair = std::fs::create_dir_all(&log_dir).ok().map(|_| {
        let file_appender = tracing_appender::rolling::daily(&log_dir, "tui.log");
        let (non_blocking, guard) = tracing_appender::non_blocking(file_appender);
        let env_filter = tracing_subscriber::EnvFilter::try_from_default_env()
            .unwrap_or_else(|_| tracing_subscriber::EnvFilter::new("ironhermes=info"));
        let layer = tracing_subscriber::fmt::layer()
            .with_writer(non_blocking)
            .with_ansi(false)
            .with_target(true)
            .with_filter(env_filter);
        (layer, guard)
    });

    let tui_layer = tui_logger::TuiTracingSubscriberLayer;
    let registry = tracing_subscriber::registry().with(tui_layer);
    let guard = match file_layer_pair {
        Some((file_layer, guard)) => {
            let _ = registry.with(file_layer).try_init();
            Some(guard)
        }
        None => {
            let _ = registry.try_init();
            None
        }
    };
    let _ = tui_logger::init_logger(tui_logger::LevelFilter::Trace);
    tui_logger::set_default_level(tui_logger::LevelFilter::Info);
    guard
}
```

**Deltas from analog for the new `logging.rs`:**

1. **Two appenders, not one.** The TUI function creates one `rolling::daily(&log_dir, "tui.log")` appender. `logging.rs` creates two: `rolling::daily(&log_dir, "web.log")` and `rolling::daily(&log_dir, "web-access.log")`.

2. **Return type changes from `Option<WorkerGuard>` to `(Option<WorkerGuard>, Option<WorkerGuard>)`.** Per D-17 (locked). Both options are always set together (both-or-none) reflecting that both appenders share the same `log_dir`.

3. **No `tui_logger` layer.** The TUI installs `tui_logger::TuiTracingSubscriberLayer` as its console-equivalent. The web UI installs a `fmt::layer().with_writer(std::io::stdout)` console layer instead (the existing stdout subscriber that is being replaced).

4. **Console layer uses explicit `with_writer(std::io::stdout)`.** The TUI omits a console fmt layer (relying on the in-TUI panel). The web UI includes one so `cargo run --features server` output is unchanged.

5. **EnvFilter default string changes.** TUI uses `"ironhermes=info"`. Web UI uses `"ironhermes=info,iron_hermes_ui=info"` per D-04.

6. **Third layer: access file layer with fixed filter.** New to web UI only:
   ```rust
   let access_file_layer = fmt::layer()
       .with_writer(access_nb)
       .with_ansi(false)
       .with_target(true)
       .with_filter(EnvFilter::new("tower_http::trace=info"));
   ```
   The per-layer filter `tower_http::trace=info` is intentionally not driven by `RUST_LOG` (D-05/D-06).

7. **`match` structure expands for two layers.** The `match file_layer_pair` block becomes a `match std::fs::create_dir_all(&log_dir)` that builds both file layers in the `Ok` arm and registers all three layers (`console`, `web_file`, `access_file`).

8. **`try_init()` placement is the same.** `let _ = registry().with(...).try_init();` — identical idiom, same no-op-on-double-install behavior.

#[tokio::main]
async fn main() {
    use dioxus::prelude::*;

    tracing_subscriber::fmt()
        .with_env_filter(

                .unwrap_or_else(|_| tracing_subscriber::EnvFilter::new("warn")),

    }

    // Initialize shared state at server startup.

**Deltas for modified `main.rs`:**

1. **Delete lines 18–23** (the `tracing_subscriber::fmt()...init()` block). Replace with:
   ```rust
   let (_web_log_guard, _access_log_guard) = server::logging::install_web_logger_subscriber();
   ```
   Placement: immediately after the `use dioxus::prelude::*;` line, before the `let env_path = ...` block. The underscore prefix on the names silences "unused variable" warnings while extending lifetime to end of `main()`.

2. **Add `TraceLayer` imports** (top of `main.rs` server block or as `use` lines inside `main()`):
   ```rust
   use tower_http::trace::{DefaultOnRequest, DefaultOnResponse, TraceLayer};
   use tracing::Level;
   ```

3. **Mount `TraceLayer` on the router** (replace lines 41–44). Build `trace_layer` first, then chain it:
   ```rust
   let trace_layer = TraceLayer::new_for_http()
       .on_request(DefaultOnRequest::new().level(Level::INFO))
       .on_response(DefaultOnResponse::new().level(Level::INFO));

   let router = axum::Router::new()
       .serve_dioxus_application(ServeConfig::new(), App)
       .layer(axum::Extension(app_state))
       .layer(trace_layer)
       .into_make_service();
   ```
   **Critical:** `.on_request(DefaultOnRequest::new().level(Level::INFO))` and `.on_response(DefaultOnResponse::new().level(Level::INFO))` are mandatory. Without them, `DefaultOnRequest` emits at `Level::DEBUG` (confirmed at docs.rs/tower-http/0.6.8), so `web-access.log` would be empty despite the file existing. See RESEARCH.md Q2.

4. **Guards must outlive `axum::serve(...).await`.** Both `_web_log_guard` and `_access_log_guard` declared before the router build are dropped at the natural end of `main()` — after `axum::serve(listener, router).await.unwrap()` returns. No explicit `drop(...)` calls required, but they mirror the TUI's `drop(_file_log_guard)` style for clarity.

## Shared Patterns

### WorkerGuard Lifetime (applies to `logging.rs` and `main.rs`)
**Source:** `crates/ironhermes-cli/src/tui_rata/event_loop.rs` lines 56–68
```rust
// The WorkerGuard must outlive the TUI session — dropping it shuts down the
// non-blocking file-appender thread and any buffered log lines are lost.
let _file_log_guard = install_tui_logger_subscriber();
// ... work happens ...
drop(_file_log_guard);
```
**Rule:** Bind to a named local with `_` prefix (not `_` alone — that drops immediately). Drop explicitly after the async work is done, or rely on scope-end drop. Applies to both `_web_log_guard` and `_access_log_guard` in `main()`.

### `try_init()` over `init()` (applies to `logging.rs`)
**Source:** `crates/ironhermes-cli/src/tui_rata/event_loop.rs` line 106:
```rust
let _ = registry.with(file_layer).try_init();
```
Use `try_init()` everywhere; never `init()`. Rationale: test-friendliness (no panic on double-install). The `let _ =` intentionally ignores the `Result` (a no-op on second install is correct behavior).

### `create_dir_all` fallback (applies to `logging.rs`)
**Source:** `crates/ironhermes-cli/src/tui_rata/event_loop.rs` lines 89–100:
```rust
let file_layer_pair = std::fs::create_dir_all(&log_dir).ok().map(|_| {
    // ... build appender + layer + guard ...
    (layer, guard)
});
// ...
let guard = match file_layer_pair {
    Some((file_layer, guard)) => {
        let _ = registry.with(file_layer).try_init();
        Some(guard)
    }
    None => {
        let _ = registry.try_init();
        None
    }
};
```
The `ok().map(|_| ...)` idiom converts `io::Error` to `None` silently. The web UI mirrors this: on failure, `(None, None)` is returned, but the console layer is still installed so the server is usable.

### `get_hermes_home()` resolution (applies to `logging.rs`)
**Source:** `crates/ironhermes-cli/src/tui_rata/event_loop.rs` line 88:
```rust
let log_dir = ironhermes_core::constants::get_hermes_home().join("logs");
```
Use `ironhermes_core::constants::get_hermes_home()` directly. `ironhermes-core` is already declared in `crates/iron_hermes_ui/Cargo.toml` under the `[target.'cfg(not(target_arch = "wasm32"))'.dependencies]` block (line 47). No new dep needed.

### `.with_ansi(false)` on file layers (applies to `logging.rs`)
**Source:** `crates/ironhermes-cli/src/tui_rata/event_loop.rs` line 96:
```rust
let layer = tracing_subscriber::fmt::layer()
    .with_writer(non_blocking)
    .with_ansi(false)
    .with_target(true)
    .with_filter(env_filter);
```
All file layers use `.with_ansi(false)`. Console layer omits it (defaults to ANSI-on). Both file layers in `logging.rs` must carry `.with_ansi(false)`.

### `EnvFilter::try_from_default_env().unwrap_or_else(...)` (applies to `logging.rs`)
**Source:** `crates/ironhermes-cli/src/tui_rata/event_loop.rs` lines 92–93:
```rust
let env_filter = tracing_subscriber::EnvFilter::try_from_default_env()
    .unwrap_or_else(|_| tracing_subscriber::EnvFilter::new("ironhermes=info"));
```
Web UI mirrors this pattern with a different default string per D-04: `"ironhermes=info,iron_hermes_ui=info"`. The access-log layer uses a fixed `EnvFilter::new("tower_http::trace=info")` directly (no `try_from_default_env` — per D-05/D-06, this filter is intentionally not driven by `RUST_LOG`).
