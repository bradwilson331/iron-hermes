# Phase 36.17 Plan 02: iron_hermes_ui web logging helper — Summary

**`crates/iron_hermes_ui/src/server/logging.rs` now exposes `install_web_logger_subscriber()`, the three-layer (stdout console + `web.log` + `web-access.log`) tracing subscriber install helper that Plan 03's `main.rs` rewrite will call. Returns `(Option<WorkerGuard>, Option<WorkerGuard>)` per D-17, falls back to console-only with `(None, None)` on `create_dir_all` failure (D-16), and uses `try_init` (D-18) — pattern parity with `crates/ironhermes-cli/src/tui_rata/event_loop.rs::install_tui_logger_subscriber`.**

## Accomplishments

- New file `crates/iron_hermes_ui/src/server/logging.rs` (95 lines pre-attribute / 102 after the doc + `#[allow(dead_code)]` addition) defining a single public function `install_web_logger_subscriber() -> (Option<WorkerGuard>, Option<WorkerGuard>)`.
- The function composes three `tracing_subscriber::Layer`s onto a single `registry()`:
  - **Console (stdout)** — default ANSI, filter via `EnvFilter::try_from_default_env().unwrap_or_else(|_| EnvFilter::new("ironhermes=info,iron_hermes_ui=info"))` (D-04 / D-06 / D-09).
  - **Web file** — `tracing_appender::rolling::daily(&log_dir, "web.log")` (D-01) wrapped in `tracing_appender::non_blocking` (D-02), `.with_ansi(false)` (D-03), same filter as console (D-04).
  - **Access file** — `tracing_appender::rolling::daily(&log_dir, "web-access.log")` (D-01) wrapped in `non_blocking` (D-02), `.with_ansi(false)` (D-03), fixed `EnvFilter::new("tower_http::trace=info")` (D-05 / D-06).
- `log_dir = ironhermes_core::constants::get_hermes_home().join("logs")` (D-15) — same path used by the TUI's `tui.log`, so `tui.log.YYYY-MM-DD` and `web.log.YYYY-MM-DD` sit side by side.
- `match std::fs::create_dir_all(&log_dir)` (D-16): `Ok` branch installs all three layers and returns `(Some(web_guard), Some(access_guard))`; `Err` branch installs only the console layer via `registry().with(console_layer).try_init()` and returns `(None, None)` — TUI fallback parity (`crates/ironhermes-cli/src/tui_rata/event_loop.rs:88-100`).
- Registry composition uses `try_init()` (D-18) — silent no-op on double-install, no panic.
- `crates/iron_hermes_ui/src/server/mod.rs` now declares `#[cfg(feature = "server")] pub mod logging;` (two appended lines), mirroring the existing `state` cfg-gate pattern. Keeps `tracing-appender` and `tower-http` out of wasm32 client builds.
- `cargo build -p iron_hermes_ui --features server` exits 0 (finished 1.95s on the incremental rebuild after the `#[allow(dead_code)]` edit; the original cold build was 44.46s).
- `cargo build -p iron_hermes_ui` (default features, wasm32 client path) exits 0 (1m 00s cold), confirming the `#[cfg(feature = "server")]` gate correctly excludes the new file from non-server builds.

## Decisions Made

- **Module placement: `crates/iron_hermes_ui/src/server/logging.rs` (NEW file), not inline in main.rs.** RESEARCH.md Q8 + CONTEXT.md `<discretion>` left this open; the helper's size (~50 LOC core body + ~30 LOC doc / type signature / fallback) and the existing `server/` subdirectory convention (`api`, `state`, `ws` already live there) tip the scale to a dedicated file.
- **Honored D-17 verbatim as `(Option<WorkerGuard>, Option<WorkerGuard>)`.** RESEARCH.md Q6 recommended `Option<(WorkerGuard, WorkerGuard)>` as more semantically accurate (both-or-none invariant), but D-17 is locked in CONTEXT.md and the ergonomic gain is small. Either tuple shape is exhaustively destructured in Plan 03's `main.rs` rewrite, so the choice is invisible at the call site.
- **`#[allow(dead_code)]` on `install_web_logger_subscriber`** — scoped only to the function, with an in-source doc comment stating "Plan 36.17-03 must remove this attribute when adding the call site". Without it, `cargo clippy -p iron_hermes_ui --features server --no-deps -- -D warnings` would error on the helper while Plan 03 is in flight, polluting CI gates in the inter-plan window. Decision is reversible: Plan 03's executor instructions need only delete the attribute + its doc paragraph as part of their main.rs rewrite.
- **Imported `tracing::Level` and bound a `_info_level` placeholder inside the function body.** The install function does not pass a `Level` to any sink itself (filters use `EnvFilter`, not `Level`), but the import makes the contract with Plan 03 (`DefaultOnRequest::new().level(Level::INFO)` + `DefaultOnResponse::new().level(Level::INFO)`, per RESEARCH.md Q2 / Pitfall 1) anchored in source. Cheaper than a comment that drifts.
- **No `#[cfg(test)]` smoke test added** (RESEARCH.md Q7 / Open Question 1). UAT in Plan 04 will cover the behavior; the TUI's `install_tui_logger_subscriber` also has no automated test.
