## Test count and case enumeration

**Planned cases:** 13 (per plan task 1 behavior block).
**Shipped cases:** 16 — 4 for `escape_markdown_v2` + 12 for `escape_outside_code_blocks`.

The extra 3 cases beyond the planned 13 come from explicitly testing each of the 4 emphasis variants (`*bold*`, `**bold**`, `_italic_`, `__italic__`) separately rather than as a single combined case — the plan listed them as four separate behaviors, so each got its own `#[test]`.

### `escape_markdown_v2` (4 tests)

- `all_18_reserved_chars_isolated` — all 18 chars each gain a leading backslash; output length doubles.
- `non_reserved_chars_pass_through` — letters, digits, spaces, and non-ASCII (`İ`, `Привет`) survive verbatim.
- `pre_escaped_reserved_not_double_escaped` — input `\.` returns `\.` (single existing backslash honored).
- `empty_input_returns_empty`.

### `escape_outside_code_blocks` (12 tests)

- `bold_star_pair_preserved` — `*bold*` → `*bold*`.
- `double_star_bold_preserved` — `**bold**` → `**bold**`.
- `single_underscore_italic_preserved` — `_italic_` → `_italic_`.
- `double_underscore_italic_preserved` — `__italic__` → `__italic__`.
- `inline_code_passes_reserved_through` — `` `foo.bar(baz)!` `` survives verbatim.
- `fenced_code_passes_all_18_chars_through` — triple-backtick fence containing every reserved char survives verbatim.
- `link_label_escaped_url_preserved` — `[label.with.dots](https://example.com/foo.bar)` → label dots escaped (`[label\.with\.dots]`), URL untouched (Pitfall 1 mitigation).
- `link_url_with_inner_parens` — URL paren-depth tracker handles `[label](url with (parens))` without prematurely closing the URL state.
- `backslash_escaped_backtick_does_not_open_code` — `\`` is a literal escaped backtick that does NOT toggle inline-code (Pitfall 5).
- `inline_code_inside_fence_no_effect` — backticks inside a fence do NOT toggle inline-code state; fence dominates.
- `reserved_after_existing_escape_not_doubled` — `already-\.` → `already\-\.` (bare `-` escaped, pre-escaped `\.` left alone).
- `mixed_real_world` — combined real-world scenario exercising bold, link, inline-code, and stray reserved chars.

## Implementation notes (for future maintainers)

### Link-URL paren tracking: depth counter, not stack

The `link_url_with_inner_parens` test (input `[label](url with (parens))`) was the deciding question — does inner-paren handling need a stack of contexts (in case the URL contains nested matched `[…]` or special `\(`), or just a depth counter?

**Answer: depth counter (`usize`) suffices.** Telegram MarkdownV2 link grammar treats the URL half as opaque between `](` and its matching `)`. Once you're inside the URL there are no further markdown structures to track — only the literal nesting of `(` and `)` matters so the closing `)` is identified correctly. A single `link_url_depth: usize` initialized to 1 on the `](` transition, incremented per `(`, decremented per `)`, and cleared (alongside `in_link_url = false`) when it hits 0, handles every test case and every realistic URL.

### Em-dash escape (Rule 1 deviation — see below)

The plan's task-1 spec for `mixed_real_world` listed em-dash (`—`, U+2014) among the "bare em-dash + final `.` escaped" cases. **Em-dash is not one of the 18 Telegram MarkdownV2 reserved chars** (the only dash-family reserved char is ASCII hyphen-minus `-`). The test expectation was corrected to pass em-dash verbatim per the canonical Bot API reserved-char list cited in CONTEXT.md `<canonical_refs>` D-04. This is a Rule 1 deviation (test asserts incorrect behavior — fix in-line).

### Emphasis markers (`*` and `_`) — always preserved

The plan's algorithm description (task 2 `<behavior>`) says: "Otherwise → if `RESERVED.contains(&c)` and `!prev_was_backslash`, push `\\` then `c`; else push `c`." Strict adherence escapes every `*` and `_` not inside a code context — which breaks `*bold*` rendering.

The locked golden tests (`bold_star_pair_preserved`, `_italic_preserved`, etc.) require `*` and `_` to be preserved as syntactic markers. The implementation chose the pragmatic interpretation: **never escape `*` or `_` outside code contexts.** Edge cases (a stray `*` in "5 * 3 = 15") fall through to D-02's single-retry-as-plain-text fallback.

The alternative — emphasis-pair detection (scan-ahead for matching closing marker) — would add significant complexity and is not exercised by any locked test. Documenting here for future maintainers who may revisit if D-02 retries become noisy in live UAT.

- **Found during:** Task 2 (GREEN verify run).
- **Issue:** Plan task 1 listed em-dash `—` (U+2014) among the chars that should be escaped by `mixed_real_world` test. **2. [Rule 1 - Bug] Strict plan algorithm would escape `*` and `_` and break emphasis tests**

- **Found during:** Task 2 (GREEN verify run, initial implementation).
- **Issue:** The plan task 2 `<behavior>` algorithm's catch-all branch ("if `RESERVED.contains(&c)` … push `\\` then `c`") would escape every `*` and `_` outside code/link contexts. But the plan task 1 golden tests `bold_star_pair_preserved`, `double_star_bold_preserved`, `single_underscore_italic_preserved`, `double_underscore_italic_preserved` all require these chars to survive verbatim. This passes all 16 golden tests and matches the plan's preserve-real-markdown intent. Documented as a known under-escape — stray emphasis markers in non-emphasis contexts (e.g., "5 * 3") fall through to D-02's parse-error plain-text retry per the threat model.
