# Phase 36.17.2.2 Plan 05: D-01 Final-Text Rendering Pipeline Complete Summary

Apply `escape_outside_code_blocks` at the stream_consumer.rs final-edit call site AND extend the overflow-chunk path to also render as MarkdownV2. After this plan, every byte of the final response (single chunk OR multi-chunk overflow) reaches Telegram with `parse_mode: MarkdownV2` and a correctly-escaped body; intermediate streaming edits stay plain text per the prior-phase D-03 invariant.

## What Shipped

### Task 1 — `send_message_markdown_v2` trait method + D-02 fallback in TelegramAdapter (commit `ae30a075`)

Added a new method to the `PlatformAdapter` trait in `crates/ironhermes-gateway/src/adapter.rs`:

```rust
async fn send_message_markdown_v2(
    &self,
    chat_id: &str,
    content: &str,
    thread_id: Option<&str>,
) -> Result<MessageResponse>;
```

Doc-comment records: (a) the caller-pre-escape contract (callers MUST escape via `crate::markdown_v2::escape_outside_code_blocks`); (b) the D-Discretion provenance (overflow-chunk path per CONTEXT.md); (c) the D-02 fallback shape (TelegramAdapter only).

**TelegramAdapter impl** (telegram.rs at the bottom of `impl PlatformAdapter for TelegramAdapter`): mirrors the existing `send_message` body but adds `"parse_mode": "MarkdownV2"` to the params JSON AND threads `thread_id` through as `message_thread_id` (the existing `send_message` actually ignores thread_id today — flagged for plan 06 if relevant; for this plan we match the trait signature). The full body wraps the `api_call::<TgMessage>("sendMessage", &params)` in `match`. On `Err`, substring-match the error description against `"can't parse"`, `"parse entities"`, `"parse_mode"` (identical keyword set to `edit_message_markdown_v2`). If matched: `warn!` + re-issue with `parse_mode` OMITTED + `message_thread_id` preserved. On retry-Ok project `TgMessage` → `MessageResponse`; on retry-Err `error!` and return the second Err. Non-parse-mode errors propagate unchanged.

### Task 2 — `escape_outside_code_blocks` at stream_consumer.rs + overflow chunks → MarkdownV2 (commit `595df71a`)

Wired the escape function into the final-edit branch of `StreamConsumer::flush(true)`:

**(a) Import:** added `use crate::markdown_v2::escape_outside_code_blocks;` to the top of `stream_consumer.rs` (plan 01 task 3 already exposed `pub mod markdown_v2` in `lib.rs`).

**(b) Single-chunk final-edit:** at the call site where `remaining.len() <= MAX_MESSAGE_LEN`, the third argument changed from `&remaining` to `&escape_outside_code_blocks(&remaining)`. Updated the inline comment block from the plan-04 INTERIM CONTRACT note to a doc explaining the smart-escape semantics; D-02 is now the rare-case safety net (model emits malformed markdown), not the common-path crutch.

**(c) Overflow chunks:** two `send_message(...)` call sites inside the final-edit branch transitioned to `send_message_markdown_v2(...)` with pre-escaped bodies:
- The `else` branch of `if first_chunk { ... }` — was `send_message(&self.chat_id, &chunk, None)`; now `send_message_markdown_v2(&self.chat_id, &escape_outside_code_blocks(&chunk), None)`.
- The post-if/else `send_message(&self.chat_id, &rest, None)` — now `send_message_markdown_v2(&self.chat_id, &escape_outside_code_blocks(&rest), None)`.

**(d) D-03 invariant preserved:** the `first_chunk` branch (`edit_message(&chunk)` — plain-text finalize of placeholder) stays untouched; the non-final branch (`flush(false)`) at lines 160-193 stays untouched (`edit_message` plain + `send_message` plain + cursor `█` append). Verified via `git diff` — zero `+`/`-` lines touched CURSOR or the `else { ... }` non-final block.

**(e) Test fixture update — single asserting test:** the existing `test_final_flush_overflow_chunks_long_content` (stream_consumer.rs:516+) was the only test asserting on overflow-chunk routing. The assertion shape changed from:

```rust
let send_count = calls.iter().filter(|c| matches!(c, AdapterCall::SendMessage { .. })).count();
assert!(send_count >= 1, "Should send at least one new message for overflow content");
```

to:

```rust
let send_md_count = calls.iter().filter(|c| matches!(c, AdapterCall::SendMessageMarkdownV2 { .. })).count();
let send_plain_count = calls.iter().filter(|c| matches!(c, AdapterCall::SendMessage { .. })).count();
assert!(send_md_count >= 1, "Should send at least one new MarkdownV2 message for overflow content (D-Discretion)");
assert_eq!(send_plain_count, 0, "Final-edit overflow path must NOT use plain SendMessage (D-Discretion: every overflow chunk is MarkdownV2)");
```

The positive `send_plain_count == 0` assertion is the regression guard against a future revert of D-Discretion (or an accidental partial revert that lets one site escape the MarkdownV2 routing).

No other test in stream_consumer.rs:343-575 needed updating:
- `test_final_edit_uses_edit_message_markdown_v2` uses a plain-ASCII body (`"**bold** text"` — `*` is not escaped by `escape_outside_code_blocks` when it forms part of bold syntax, per plan 01 golden tests). Test passes as-is.
- `test_flush_final_strips_cursor_and_uses_markdown` uses body `"hello"` (no reserved chars). Test passes as-is.
- `test_overflow_chains_new_message` uses `flush(false)` (non-final branch — D-03) so its `SendMessage` assertion is unaffected.

## Hand-off to Plan 06

- **D-01 final-text rendering pipeline is complete in production code.** Plan 06's integration test (`tests/telegram_media_delivery.rs`) can drive a synthetic LLM stream emitting literal markdown syntax + reserved chars and assert the body reaches the MockAdapter / RecordingPlatformAdapter ESCAPED + as `EditMessageMarkdownV2` (for the single-chunk path) or `SendMessageMarkdownV2` (for the overflow path).
- **D-02 fallback is doubly-active:** both `edit_message_markdown_v2` AND `send_message_markdown_v2` now substring-match parse-mode failures and retry as plain text. Plan 06's parse-mode-400 assertion scenario should exercise the edit path (since the single-chunk path is the common case); the send path is exercised when overflow chunks fail parse mode.
- **Test fixtures are forward-compatible.** Plan 06's new `RecordingMediaAdapter` (`MediaSender` + `PlatformAdapter`) extends the existing recording fixture pattern; the `send_message_markdown_v2` impl required for the trait already lives in `RecordingPlatformAdapter` (records into `sent`) so plan 06 only needs to add the `MediaSender` impl.
- **The dead_code warnings on `AdapterCall::SendMessageMarkdownV2 { chat_id, content }` are intentional** — Rust's reachability analysis does not walk `matches!()` macros for field-read detection. Plan 06's tests that assert specific overflow-chunk bodies (e.g., "the second chunk has prefix X") will read the `content` field via destructuring and the warning will go away naturally.
