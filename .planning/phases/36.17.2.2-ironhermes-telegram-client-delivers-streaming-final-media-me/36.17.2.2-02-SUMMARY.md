# Phase 36.17.2.2 Plan 02: MediaTagExtractor + supporting types Summary

Implemented the streaming `<MEDIA: ...>` extractor that future plans 03/04/06 will compose into Telegram media delivery. One-liner: **stateful streaming extractor that strips `<MEDIA: path|url>` inline tags from LLM deltas (mirroring `StreamingContextScrubber`'s partial-prefix algorithm) and dispatches to `MediaKind` per the D-06 extension table, with D-09 fenced/inline-code skip + Pitfall 5 backslash respect, and a flush_tail policy that diverges from scrubber's discard semantics by emitting unterminated tag text as visible.**

### `crates/ironhermes-gateway/src/media_tag.rs` (NEW, 631 lines)

**Public surface (locked for Plans 03/04/06):**

```rust
pub enum MediaSource { Path(PathBuf), Url(String) }
pub enum MediaKind   { Photo, Voice, Audio, Video, Document }
pub struct MediaRef  {
    pub source: MediaSource,
    pub kind: MediaKind,
    pub original_tag_text: String,  // D-19 reinsert literal
}

pub struct MediaTagExtractor { /* private 7-field state */ }
impl MediaTagExtractor {
    pub fn new() -> Self;
    pub fn reset(&mut self);
    pub fn feed(&mut self, delta: &str) -> String;
    pub fn flush_tail(&mut self) -> String;
    pub fn take_attachments(&mut self) -> Vec<MediaRef>;
}
```

**Algorithm summary:**

1. **`feed(delta)`** — prepends any held-back `self.buf`, then walks the combined string. State is one of:
   - **`in_tag`** — accumulating tag body until `>`. On close, calls `parse_tag_body` (URL detect by `http://`/`https://`, MediaKind from last path-segment extension with case-insensitive + query-string strip), pushes `MediaRef`.
   - **`in_fenced_code`** — searches for the closing triple-backtick run; emits everything verbatim (no extraction). Partial-suffix held-back at end of buffer.
   - **`in_inline_code`** — walks char-by-char honoring `prev_was_escape`; first unescaped backtick closes the span. Emits verbatim.
   - **Plain text** — chooses the earliest of {fence, inline-code, `<MEDIA:`} opener via `earliest()`, emits text before, dispatches. When no opener is found, the held-back is `max(max_partial_suffix(buf, FENCE), max_partial_suffix(buf, OPEN_TAG))` (inline-backtick is one byte, no partial possible).

2. **`flush_tail()`** — extractor policy DIVERGES from scrubber. If `in_tag`, emits `<MEDIA: ` + accumulated body as VISIBLE text. The held partial buffer is also emitted verbatim. `attachments` is NOT cleared (drained separately via `take_attachments`).

3. **`take_attachments()`** — `std::mem::take(&mut self.attachments)`.

4. **`reset()`** — clears ALL state (in_tag, in_fenced_code, in_inline_code, prev_was_escape, tag_body, buf, attachments).

**D-06 dispatch table** (in `infer_kind`):

| Extension | MediaKind |
|---|---|
| `.png .jpg .jpeg .webp .gif` | Photo |
| `.ogg .opus` | Voice |
| `.mp3 .m4a .flac .wav` | Audio |

URL query strings (`?token=x`) and fragments (`#anchor`) stripped before extension lookup. Extension comparison is case-insensitive (`FOO.PNG` → Photo).

### Defensive guard in `max_partial_suffix`

Added a `t.len() < 2` short-circuit at the top of `max_partial_suffix` so the helper is safe to call with the 3-byte FENCE (` ``` `) and 1-byte inline-backtick patterns. The scrubber's original `max_partial_suffix` only ever sees 16/17-char tags, so the guard wasn't necessary there; in this module the helper is reused for FENCE held-back too. The guard is cheap insurance against future single-byte-pattern callers. Not a deviation from spec — just a defensive addition to the verbatim port.

## flush_tail Divergence from Scrubber (recorded per plan output spec)

The plan's `<output>` section asks for *"a one-line note on how `flush_tail` handled the unterminated-tag case"*. Note:

> **Extractor `flush_tail` emits the held buffer as VISIBLE text.** Scrubber's `flush()` discards the in-span content (memory-context leakage is a security concern; truncating is safer than leaking). Extractor's policy is the opposite: tag-like text must never silently disappear, because the user's mental model is "everything the model wrote is visible somewhere." If `<MEDIA: foo` arrives unterminated, the user sees `<MEDIA: foo` in the message and can ask the model to retry. Test `tag_never_closes_flush_tail_emits_visible` enforces this.
