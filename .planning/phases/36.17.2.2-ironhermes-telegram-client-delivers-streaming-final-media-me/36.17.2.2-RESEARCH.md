## Pattern Audit: `StreamingContextScrubber` Walkthrough

`MediaTagExtractor` (D-08) must mirror this exactly. The full code is at `crates/ironhermes-agent/src/streaming_scrubber.rs:32-180`. Algorithm summary:

### State

- `in_span: bool` — true between OPEN_TAG and CLOSE_TAG. For the extractor: `in_tag: bool` — true between `<MEDIA:` and `>`.
- `buf: String` — held-back partial-tag prefix from prior `feed()` call. Same role in the extractor (partial `<`, `<M`, `<ME`, ..., `<MEDIA:`).

### `feed(text)` algorithm

```
1. Prepend self.buf to the new text (drains any held partial tag).
2. Loop:
   a. If in_span: search for CLOSE_TAG (case-insensitive ASCII byte scan).
      - Found: drop chars before close, advance past CLOSE_TAG, in_span=false, continue.
      - Not found: held-back = max suffix that COULD be a prefix of CLOSE_TAG.
        Drop everything before held-back (inside span). Save held-back to buf. Return out.
   b. If not in_span: search for OPEN_TAG (case-insensitive ASCII byte scan).
      - Found: emit chars before tag to out, advance past OPEN_TAG, in_span=true, continue.
      - Not found: held-back = max suffix that COULD be a prefix of OPEN_TAG.
        Emit chars before held-back to out. Save held-back to buf. Return out.
3. Return accumulated out.
```

### `flush()` semantics (scrubber)

- If `in_span` (unterminated open tag at end-of-stream): **discard `buf` silently**, return `""`. Safer to truncate than leak.
- Otherwise: return `buf` verbatim (it turned out not to be a real tag prefix).

### Non-obvious pitfalls (MUST port)

1. **ASCII-byte case-insensitive search, NOT `str::to_lowercase()`.** `to_lowercase()` is NOT byte-length-preserving (`U+0130` lowercases from 1 byte to 2 bytes; "İ" → "i̇"). Using it would desync offsets and slice on non-char-boundaries → panic. The scrubber uses `slice::eq_ignore_ascii_case` and asserts the needle is pure ASCII. **The MEDIA tag prefix `<MEDIA:` is pure ASCII**, so the same approach works.

2. **`max_partial_suffix` returns at most `tag.len() - 1`.** A buffer that fully contains the tag would have been matched by `find_ascii_ci`; partial-suffix is only for the "tag might continue in next delta" case.

3. **No emit while inside a span (scrubber).** The scrubber discards content between OPEN and CLOSE. `MediaTagExtractor` must instead **accumulate** the body (the URL/path) into a per-tag `tag_body: String` until `>` is seen, then push a `MediaRef` to `attachments`.

4. **Two-state-machine interaction for D-09 (fenced-code / inline-code skip).** The scrubber only tracks `in_span`. The extractor needs two MORE booleans:
   - `in_fenced_code` toggled by ``` ``` ``` runs
   - `in_inline_code` toggled by `` ` `` runs that are NOT inside a fence
   Tags inside either state pass through to visible output unchanged. This is **a significant departure** from the scrubber's simpler state machine. Planner should consider (a) extending the extractor's loop with code-fence detection (recommended — small, local), or (b) factoring out a shared "delta-buffered state machine" helper (premature; only one consumer).

5. **`reset()` for reuse.** Scrubber exposes `reset()`. Planner should do the same for `MediaTagExtractor`.

6. **Backslash-escape of backtick (Pitfall 5 below).** `` \` `` should NOT toggle `in_inline_code`. The extractor must track whether the immediately-preceding char was an unescaped `\`.

### Test cases the extractor MUST cover (mirroring scrubber's test suite)

- Full tag in one delta (`<MEDIA: foo.png>` → one MediaRef)
- Split tag across two deltas (`<MEDIA: f` then `oo.png>` → one MediaRef)
- Partial tail held then disproved (`<MEDI` then `um is the message` → no extraction, both deltas emit verbatim)
- Tag never closes (`<MEDIA: foo` then stream ends → **planner: decide policy.** Scrubber discards (safer for memory-context = leak prevention). Extractor's natural choice is FLUSH AS VISIBLE — losing tag-like text to silence breaks user trust; if user wanted a tag, they ask for retry. Recommend: extractor `flush_tail()` returns the unfinished `<MEDIA:...` text verbatim.)
- Tag inside fence: `` ```\n<MEDIA: foo.png>\n``` `` → tag passes through, no extraction
- Tag inside inline code: `` `<MEDIA: foo.png>` `` → passes through
- Escaped backtick: `` \`<MEDIA: foo.png>\` `` → extraction HAPPENS (backticks were escaped, not in code span)
- Multiple tags in one delta — emitted in stream order
- Non-ASCII before/around tag — no panic, tag still extracted
- `take_attachments()` drains and clears (next call returns `[]`)


Both the trait definition and the impl block use the `#[async_trait]` attribute macro. `MediaSender` (D-18) follows the same style verbatim.

**Crate version:** Not directly checked this session, but production usage proves it works for traits with multiple async methods returning `Result<T>`, including the dyn-compatible `Arc<dyn PlatformAdapter>` pattern used throughout `runner.rs`, `handler.rs`, `stream_consumer.rs`. **`Arc<dyn MediaSender>` will work the same way** — no dyn-compatibility (object safety) concerns.

**Caveat:** With `#[async_trait]`, trait methods desugar to `Pin<Box<dyn Future>>`-returning fns. Don't switch to `impl Future` return types for `MediaSender` — it would break `Arc<dyn MediaSender>` dyn dispatch.

## Common Pitfalls

### Pitfall 1: MarkdownV2 escape applied inside link URLs corrupts the link

**What goes wrong:** `[label](https://example.com/foo.bar)` naively escaped becomes `[label](https://example\.com/foo\.bar)` — Telegram parses as broken link.

**Why it happens:** MarkdownV2 grammar treats `(URL)` as a contained context; reserved-char escaping is forbidden inside.

**How to avoid:** D-04's `escape_outside_code_blocks` tracks link-URL state. Golden test `<canonical_refs>` line 197 covers `[label with .](url with (parens))` explicitly. **Plan as TDD — golden tests before the escape function.**

**Warning signs:** UAT "model emits a link with a dot in URL" → broken link OR 400 `can't parse entities`.

### Pitfall 2: `<MEDIA:` partial buffering and the user "sees" the prefix

**What goes wrong:** Model streams "Here's the file: `<MEDI`" then pauses. Scrubber emits "Here's the file: " and holds "<MEDI". User sees stalled text.

**Why it happens:** Partial-prefix held-back is necessary correctness behavior, but USER-VISIBLE absence.

**How to avoid:** The 300ms `EDIT_INTERVAL` throttle (`stream_consumer.rs:7`) bounds visible-but-unflushed duration. The cursor `\u{2588}` (line 9) appears at end of emitted content, so user sees "Here's the file: █" — looks normal. Verify cursor placement is correct vs. extractor output, not raw buffer.

**Warning signs:** UAT operator reports "message stops mid-sentence for 1-2 seconds before attachment arrives."

### Pitfall 3: `set_media_sender` not called when Telegram is configured → silent drop

**What goes wrong:** Production runner builds Telegram adapter but forgets `handler.set_media_sender(...)`. `<MEDIA: ...>` tags extracted, `self.media_sender` is `None`, D-19 `else` branch fires (`warn!("media tags emitted on platform without MediaSender")`). User sees text but no attachments — only signal is the warn log.

**Why it happens:** Setter-based wiring is opt-in. Missing the call is silent.

**How to avoid:** Add integration smoke test asserting `media_sender` field is `Some` for `Platform::Telegram` after `GatewayRunner` construction. Alternative: a stricter "MediaSender required for Telegram" runtime assertion.

**Warning signs:** UAT scenarios 2/3/4/5 all fail with "I see the text but never see the photo/voice/mp3."

### Pitfall 4: Multipart helper Result<()> mismatch with MediaSender Result<MessageResponse>

**What goes wrong:** D-18 says `MediaSender::send_*` return `Result<MessageResponse>`. `send_file_multipart` returns `Result<()>` and parses response as `TelegramResponse<serde_json::Value>`.

**How to avoid:** Refactor `send_file_multipart` signature to `Result<MessageResponse>`, deserialize `TelegramResponse<TgMessage>`, project to `MessageResponse`. Only 4 internal callers (telegram.rs:31,40,49,58) — they discard via `.await.map(|_| ())` already, just add the discard at the call site.

**Warning signs:** Type errors during `MediaSender for TelegramAdapter` impl; integration tests can't assert returned message IDs.

### Pitfall 5: Inline-code tracker confused by escaped backticks

**What goes wrong:** Model emits `` Use \` for inline code `` — the `` \` `` is escaped backtick, not a code-span boundary. Naive `in_inline_code = !in_inline_code` flips state incorrectly.

**Why it happens:** MarkdownV2 allows backslash escapes.

**How to avoid:** Track whether preceding char was unescaped `\`. Unit test: `` \`<MEDIA: foo.png>\` `` SHOULD extract (backticks escaped); `` `<MEDIA: foo.png>` `` SHOULD NOT.

**Warning signs:** False positives (tag swallowed when should pass) OR false negatives (tag passes when should extract). Both caught by unit test suite with escape-backtick cases.

### Pitfall 6 (NEW from architectural finding): D-19 dispatch placed at wrong handler.rs site

**What goes wrong:** Planner writes "after `stream_consumer.flush(true).await?`" per CONTEXT.md D-19. There IS no such inline call — final flush is INSIDE the `tokio::spawn(consumer_handle)` task at handler.rs:1307,1322. If the dispatch loop is placed adjacent to the scrubber tail flush at line 1430, it runs BEFORE the consumer task has processed the final delta — the placeholder may still show streaming-intermediate text.

**How to avoid:** Place the D-19 block AFTER `consumer_handle.await.ok()` at line 1439 (the synchronization barrier that guarantees `flush(true)` has run). Even better: after `typing_handle.await.ok()` at line 1443 so the typing indicator clears before attachments dispatch.

**Warning signs:** Attachments arrive while the message still shows the streaming `█` cursor; or attachments arrive BEFORE the final markdown edit.

```rust
pub trait MediaSender: Send + Sync {
    async fn send_photo(&self, chat_id: &str, source: &MediaSource, thread_id: Option<&str>) -> Result<MessageResponse>;
    async fn send_voice(&self, chat_id: &str, source: &MediaSource, thread_id: Option<&str>) -> Result<MessageResponse>;

    async fn send_document(&self, chat_id: &str, source: &MediaSource, thread_id: Option<&str>) -> Result<MessageResponse>;

    async fn send_media(&self, chat_id: &str, m: &MediaRef, thread_id: Option<&str>) -> Result<MessageResponse> {

            MediaKind::Photo    => self.send_photo(chat_id, &m.source, thread_id).await,

            MediaKind::Video    => self.send_video(chat_id, &m.source, thread_id).await,
            MediaKind::Document => self.send_document(chat_id, &m.source, thread_id).await,
        }
    }
}

pub enum MediaSource { Path(PathBuf), Url(String) }
pub enum MediaKind   { Photo, Voice, Audio, Video, Document }
pub struct MediaRef  { pub source: MediaSource, pub kind: MediaKind }
```
