# Phase 36.17.2.2 Plan 03: MediaSender trait + Telegram MEDIA-tag prompt — Summary

**One-liner:** Declared the `MediaSender` trait surface in `adapter.rs` (six async methods per D-18, type re-exports for a one-import surface, D-17 no-caption divergence doc-comment) and taught the model the `<MEDIA: path|url>` tag convention in the Telegram branch of `prompt_builder.rs::platform_hint`, so plan 04's concrete `impl MediaSender for TelegramAdapter` and plan 06's `Option<Arc<dyn MediaSender>>` field can compile against a stable interface and the model actually emits the tags the extractor will consume.

## What Shipped

### `crates/ironhermes-gateway/src/adapter.rs` (+105 lines)

Added directly after the existing `pub trait PlatformAdapter` block:

1. **Type re-export** (one statement):
   ```rust
   pub use crate::media_tag::{MediaKind, MediaRef, MediaSource};
   ```
   So consumers can write the one-import line:
   ```rust
   use ironhermes_gateway::adapter::{MediaSender, MediaRef, MediaSource, MediaKind};
   ```
   The canonical type definitions still live in `crate::media_tag` (plan 02); both paths resolve to the same types.

2. **`#[async_trait] pub trait MediaSender: Send + Sync`** with exactly six async methods (D-18):
   - `send_photo(&self, chat_id, &MediaSource, Option<&str>) -> Result<MessageResponse>` (abstract)
   - `send_voice(...)` (abstract — `.ogg`/`.opus` per D-14)
   - `send_audio(...)` (abstract — `.mp3`/`.m4a`/`.flac`/`.wav` per D-14)
   - `send_video(...)` (abstract)
   - `send_document(...)` (abstract — fallback per D-06)
   - `send_media(&self, chat_id, &MediaRef, Option<&str>) -> Result<MessageResponse>` — **default body** matching on `media_ref.kind` and dispatching to the five per-type methods. Concrete adapters only need to implement the five per-type methods.

3. **Doc-comment block** on the trait documenting:
   - **D-17 uniform-no-caption divergence** from hermes-agent §Audio Captions (no `caption` parameter on any method, because the text body has already been rendered via `edit_message_markdown_v2` (D-01) before attachments are dispatched (D-07), so per-attachment captions would be redundant).
   - **Clone-cast-twice construction pattern** (Open Q4 / Assumption A7): trait upcasting `Arc<dyn PlatformAdapter>` → `Arc<dyn MediaSender>` is unstable on stable Rust; callers must construct `Arc<TelegramAdapter>` once and `clone()`-cast separately for each trait object. Includes a concrete code example for the runner.rs wire-up plan 06 will implement.
   - **Adopter set:** today only `TelegramAdapter` (plan 04); Discord/Slack/web do NOT implement the trait, with plan 06's handler holding `Option<Arc<dyn MediaSender>>` set to `None` on those platforms and a `warn!`+drop policy when MEDIA refs are extracted there.

`PlatformAdapter` is unmodified (plan 03 does not touch it; D-01 replacement of `edit_message_markdown` lands in plan 04).

### `crates/ironhermes-agent/src/prompt_builder.rs` (line 774 — 1-line change)

Extended the Telegram branch of `platform_hint`. The pre-edit string was:

```text
You are running as a Telegram bot. Keep responses concise. Use Telegram-compatible markdown (MarkdownV2). Avoid very long messages.
```

The post-edit string (full literal, for archival per `<output>` requirement):

```text
You are running as a Telegram bot. Keep responses concise. Use Telegram-compatible markdown (MarkdownV2). Avoid very long messages. To send a file or media attachment, emit a literal tag on its own line in your reply, in the form: <MEDIA: /absolute/path/to/file.ext> or <MEDIA: https://host.example/path/file.ext>. The gateway extracts the tag and sends it as a native Telegram attachment; supported extensions include .png .jpg .jpeg .webp .gif (photo), .ogg .opus (voice note), .mp3 .m4a .flac .wav (audio), .mp4 .mov .webm (video), and anything else as a document. Place the tag inside a fenced code block to show the literal text instead of sending an attachment.
```

The appended teaching sentence covers:
- Tag grammar (`<MEDIA: path>` and `<MEDIA: https://...>` URL form) — both D-05/D-06 forms.
- Extension dispatch table — D-13/D-14 mapping (5 categories: photo / voice / audio / video / document).
- Fenced-code-block escape — D-09 (tags inside fences pass through verbatim).

Only the `"telegram"` branch was changed; `"cli"`, `"discord"`, `"slack"` branches and the `_ => String::new()` fallback are untouched per D-18 (`MediaSender` is Telegram-only in this phase).
