## Final-text parse mode

### Q1.1 — Final-flush parse mode target

| Option | Description | Selected |
|--------|-------------|----------|
| MarkdownV2 with full escape | Match hermes-agent verbatim. Replace legacy `parse_mode: Markdown` with `parse_mode: MarkdownV2`. Smart escape preserves real markdown syntax, escapes literal reserved chars outside code/links. | ✓ |
| MarkdownV2 but escape EVERYTHING blindly | Escape all 18 reserved chars unconditionally; loses model-authored formatting. | |
| Stay on legacy `Markdown` v1 | Don't migrate; fix the prompt-builder lie to advertise v1. | |
| HTML parse_mode | Switch to `parse_mode: HTML`. Diverges from hermes-agent contract. | |

**User's choice:** MarkdownV2 with full escape (Recommended)
**Notes:** Locked as D-01.

### Q1.2 — Parse-error fallback

| Option | Description | Selected |
|--------|-------------|----------|
| Retry once as plain text | On `400 Bad Request: can't parse entities`, re-issue `editMessageText` with no `parse_mode`. Log at `warn!`. Matches hermes-agent's silent-fallback behavior. | ✓ |
| Smart-recovery: strip then retry | Run a fixup pass on the buffer, retry MarkdownV2, then fall to plain. | |
| Best-effort: pre-validate before sending | Run a markdown linter before send. | |
| Hard fail — log error and leave streamed plain text | Don't retry; let streamed plain remain. | |

**User's choice:** Retry once as plain text (Recommended)
**Notes:** Locked as D-02.

### Q1.3 — Streaming intermediate edits format

| Option | Description | Selected |
|--------|-------------|----------|
| Keep plain-text during streaming | Preserve 36.17.2 D-03 behavior verbatim. | ✓ |
| MarkdownV2 streaming too, with brace-completion | Auto-close dangling fences at each flush. High-risk. | |
| Plain during stream, but with cursor block stripped on final | Document current behavior as locked. | |

**User's choice:** Keep plain-text during streaming (Recommended)
**Notes:** Locked as D-03. Preserves 36.17.2 D-03 verbatim.

### Q1.4 — Escape function location

| Option | Description | Selected |
|--------|-------------|----------|
| `crates/ironhermes-gateway/src/markdown_v2.rs` | New module with `escape_markdown_v2` + `escape_outside_code_blocks`. Golden-tested. | ✓ |
| Inline in `telegram.rs::edit_message_markdownv2` | Less code, but not reusable for `send_message` path. | |
| In `stream_consumer.rs` only | Doesn't cover the `send_message` overflow path. | |

**User's choice:** `crates/ironhermes-gateway/src/markdown_v2.rs` (Recommended)
**Notes:** Locked as D-04.

## Media routing protocol

### Q2.1 — Wire protocol

| Option | Description | Selected |
|--------|-------------|----------|
| `<MEDIA: path\|url>` inline tags + scrubber extraction | Match hermes-agent verbatim. New `MediaTagExtractor` mirrors `StreamingContextScrubber`. | ✓ |
| Structured tool result with media payload | Every media-producing tool changes return shape. | |
| Both — tags primary, tool envelope secondary | Two parsers, two test surfaces. | |
| Markdown link with `media:` scheme | Reuses markdown parser. Diverges from hermes-agent. | |

**User's choice:** Inline tags + scrubber extraction (Recommended)
**Notes:** Locked as D-05.

### Q2.2 — Tag grammar

| Option | Description | Selected |
|--------|-------------|----------|
| `<MEDIA: <single-token>>` — path or URL, type from extension | Single regex `<MEDIA:\s*([^>]+)>`. Matches hermes-agent. | ✓ |
| `<MEDIA type="voice" src="...">` attribute form | Unambiguous type, no extension-sniffing. Bespoke. | |
| `<MEDIA: type/path>` slash-delimited | Explicit type, single token. Bespoke. | |

**User's choice:** Single-token, type from extension (Recommended)
**Notes:** Locked as D-06.

### Q2.3 — Text + media delivery order

| Option | Description | Selected |
|--------|-------------|----------|
| Text-first, attachment-second, separate messages | Final `editMessageText` first, then `send_*` per tag with no caption. | ✓ |
| Attachment-first with text as caption | Single message; 1024-char caption cap; placeholder text wasted. | |
| Attachment-only, discard accompanying text | Loses model commentary. Rejected. | |
| Configurable per-call via tag attribute | Reopens D-06 grammar. | |

**User's choice:** Text-first, attachment-second (Recommended)
**Notes:** Locked as D-07.

### Q2.4 — Extraction location

| Option | Description | Selected |
|--------|-------------|----------|
| Scrubber-style during streaming | Sibling of `StreamingContextScrubber`. Tags never visible. | ✓ |
| Post-flush pass over final buffer | Simpler code; user sees raw tags briefly. | |
| Both — scrubber + post-flush double-check | Belt-and-suspenders against partial-token bugs. | |

**User's choice:** Scrubber-style during streaming (Recommended)
**Notes:** Locked as D-08.

### Q2.5 — Fenced/inline-code tag handling

| Option | Description | Selected |
|--------|-------------|----------|
| Ignore inside fenced blocks AND inline `code` | Track both fence and inline-code state. Model can document the convention. | ✓ |
| Ignore inside fenced blocks only, NOT inline code | Simpler (single state). Inline ` `<MEDIA:...>` ` still fires. | |
| Always extract regardless of context | Simpler scrubber, can't document. Rejected. | |

**User's choice:** Ignore inside fenced AND inline code (Recommended)
**Notes:** Locked as D-09.

### Q2.6 — Missing/unreadable media handling

| Option | Description | Selected |
|--------|-------------|----------|
| Log warn + reinsert tag as visible text | `editMessageText` append of original tag. Never silent. | ✓ |
| Log error + send `⚠️ Failed to attach: <name>` reply | Extra round-trip per failure; may spam. | |
| Silent drop, log warn only | User has no signal. | |
| Fail the whole turn | Too aggressive; partial > none. | |

**User's choice:** Log warn + reinsert (Recommended)
**Notes:** Locked as D-10.

### Q2.7 — Multi-tag delivery

| Option | Description | Selected |
|--------|-------------|----------|
| Sequential separate messages in stream order | One text edit + N attachments. | ✓ |
| `sendMediaGroup` for photos+videos | Album view but bespoke routing logic. Deferred. | |
| Cap at N attachments per turn | Arbitrary cap. | |

**User's choice:** Sequential separate messages (Recommended)
**Notes:** Locked as D-11. `sendMediaGroup` deferred to follow-up phase.

### Q2.8 — URL form handling

| Option | Description | Selected |
|--------|-------------|----------|
| Pass URL directly — Telegram fetches | Zero gateway egress. Failures via D-10. | ✓ |
| Download then upload (SSRF-safe) | Egress + disk + time cost. | |
| URL for photo/video, download for voice/document | Hybrid per Telegram URL-form support quirks. | |

**User's choice:** Pass URL directly (Recommended)
**Notes:** Locked as D-12. Local paths still uploaded multipart.

## Native attachment scope

### Q3.1 — Type scope

| Option | Description | Selected |
|--------|-------------|----------|
| All four: photo, voice, video, document | Existing multipart helpers cover all four. | ✓ |
| Photo + voice only | Minimal v1 covering image-gen + TTS. | |
| All four + sticker + animation | Two new multipart helpers; scope creep. | |
| Photo only | Even smaller v1. | |

**User's choice:** All four (Recommended) — and audio added via new `send_audio` helper per Q3.2
**Notes:** Locked as D-13. Note: `sendAudio` helper is NEW (didn't exist before this phase) because of Q3.2's voice/audio split.

### Q3.2 — Voice vs audio routing

| Option | Description | Selected |
|--------|-------------|----------|
| `.ogg/.opus` → sendVoice, `.mp3` → sendAudio | Extension-driven. TTS gets round bubble; MP3 gets music player. | ✓ |
| All audio → sendVoice (force opus) | Would require ffmpeg transcode. | |
| All audio → sendAudio (music player) | Loses inline round-bubble for TTS. | |
| Default sendVoice, opt-in sendAudio via attribute | Reopens D-06 grammar. | |

**User's choice:** Extension-driven split (Recommended)
**Notes:** Locked as D-14.

### Q3.3 — File size guard

| Option | Description | Selected |
|--------|-------------|----------|
| Pre-check `metadata().len()`, log+reinsert if oversized | Saves wasted multipart attempt. | ✓ |
| Let Telegram reject — unified path via D-10 | Less code, one extra round-trip per oversize. | |
| Auto-compress photos/videos before upload | New deps, quality loss. | |
| No guard — trust upstream tool | Slightly less safe. | |

**User's choice:** Pre-check + log+reinsert (Recommended)
**Notes:** Locked as D-15.

### Q3.4 — Inbound media scope

| Option | Description | Selected |
|--------|-------------|----------|
| Outbound-only | Inbound `tg_message_to_event` flow untouched. | ✓ |
| Outbound + verify inbound voice/video paths exist | Half-step toward full multimodal inbound. | |
| Full multimodal inbound + outbound in one phase | Doubles the work. | |

**User's choice:** Outbound-only (Recommended)
**Notes:** Locked as D-16.

## Audio caption + adapter-trait surface

### Q4.1 — Audio caption policy

| Option | Description | Selected |
|--------|-------------|----------|
| Uniform D-07 — no captions for any attachment | One protocol, no carve-outs. Diverges from hermes-agent §Audio Captions. | ✓ |
| Carve-out: `sendVoice` only takes preceding/trailing text as plain-text caption | Matches hermes-agent §Audio Captions parity. | |
| All attachments take caption when text is short (<1024 chars) | Adds branch logic; inverts D-07 default. | |
| Configurable per-tag attribute | Reopens D-06 grammar. | |

**User's choice:** Uniform no-caption (Recommended)
**Notes:** Locked as D-17. Documented divergence from hermes-agent §Audio Captions in CONTEXT.md.

### Q4.2 — Adapter trait surface

| Option | Description | Selected |
|--------|-------------|----------|
| Keep media helpers Telegram-private; new `MediaSender` trait | Separate trait; `TelegramAdapter` impls both. Other adapters skip. | ✓ |
| Promote all five into `PlatformAdapter` with default `Err(Unsupported)` | Maximum forward-compat; broadest trait surface. | |
| Promote with default `Ok(())` no-op | Worst of both — silent loss on non-Telegram. | |
| Inherent methods on `TelegramAdapter` only; downcast via `Any` | Brittle; no future-platform plug point. | |

**User's choice:** New `MediaSender` trait (Recommended)
**Notes:** Locked as D-18.

### Q4.3 — Dispatch shape

| Option | Description | Selected |
|--------|-------------|----------|
| Inline in `run_agent` after final flush, sequential awaits | Simple; matches existing handler.rs flow. | ✓ |
| Spawn a detached task per attachment | Lower latency but message ordering races. | |
| Return media list from `handle_with_multimodal`, dispatch in `runner.rs` | Bigger refactor; clearer separation. | |

**User's choice:** Inline sequential (Recommended)
**Notes:** Locked as D-19.

### Q4.4 — Test plan

| Option | Description | Selected |
|--------|-------------|----------|
| Extend `RecordingPlatformAdapter` + `MediaSender` impl + golden tests + Telegram-mocked integration + live UAT | Three layers + UAT runbook per 36.17.2 D-22. | ✓ |
| Unit tests only; defer live Telegram UAT | Risk: parse_mode misbehavior won't surface. | |
| Live Telegram UAT only; skip recording layer | No CI coverage. | |

**User's choice:** Three-layer + UAT (Recommended)
**Notes:** Locked as D-20.

## Claude's Discretion

The following implementation details were intentionally left to the planner/executor's judgment (full list in CONTEXT.md §Claude's Discretion):

- Exact module location of `MediaTagExtractor` (recommended: new `crates/ironhermes-gateway/src/media_tag.rs`)
- Whether `MediaSource` / `MediaKind` / `MediaRef` live in `ironhermes-gateway` or `ironhermes-core` (recommended: gateway-only)
- `MediaSender` async-method shape (recommended: `#[async_trait]` to match `PlatformAdapter`)
- Whether `stream_consumer.rs:121-128` overflow `send_message` chunks render as MarkdownV2 or stay plain (recommended: MarkdownV2 for consistency)
- Whether the reinsert-on-failure pattern (D-10) edits the placeholder or sends a follow-up (recommended: edit placeholder)
