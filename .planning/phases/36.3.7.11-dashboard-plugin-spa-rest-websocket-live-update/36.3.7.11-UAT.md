# Phase 36.3.7.11 — Dashboard Kanban Tab Manual UAT

> Run this script end-to-end against a freshly-launched `iron_hermes_ui` dev

## Prerequisites

> All commands run from the repo root unless noted.

1. **Seed the kanban.db with two demo cards.** Required for U1/U3/U4 and the
   live-update tests. If `~/.ironhermes/kanban.db` already has cards, skip steps
   1.1 and 1.2 — note the IDs of two cards (one TRIAGE, one READY) you will
   use throughout. NOTE: `ironhermes-cli` has no `promote` verb and
   `kanban create` takes long-form flags only (no `-t`/`-a` short forms).
   The default `create` status is **READY**; the `--triage` flag overrides
   to TRIAGE. There is no CLI verb that creates directly into TODO — drag a
   READY card to TODO in the UI when a TODO card is needed (or run
   `kanban specify <id>` if Anthropic creds are configured, which promotes
   TRIAGE→TODO via the LLM specifier).

   ```bash
   # TRIAGE card — capture the id from the --json output. --idempotency-key
   # makes re-runs short-circuit to the same task instead of accumulating
   # duplicate rows with the same title (the CLI does NOT enforce title
   # uniqueness; the dashboard renders one row per task id even when titles
   # collide, so duplicates show up as separate cards across columns).
   TRIAGE_ID=$(cargo run -q -p ironhermes-cli -- kanban create --triage --assignee dev --idempotency-key uat-triage --json "UAT triage card" | jq -r .task_id)
   echo "TRIAGE_ID=$TRIAGE_ID"

   # READY card (substitute for "TODO" in U5/U6/U7 — drag-disallowed to DONE,
   # complete-via-drawer, block/unblock all behave the same from READY).
   READY_ID=$(cargo run -q -p ironhermes-cli -- kanban create --assignee dev --idempotency-key uat-ready --json "UAT ready card" | jq -r .task_id)
   echo "READY_ID=$READY_ID"
   ```

   If you already created cards without `--json` (e.g. during the earlier
   UAT-script bug pass), you can recover the IDs with `kanban list --json`
   and filter by title:

   ```bash
   TRIAGE_ID=$(cargo run -q -p ironhermes-cli -- kanban list --json --status triage | jq -r '.[] | select(.title=="UAT triage card") | .id')
   READY_ID=$(cargo run -q -p ironhermes-cli -- kanban list --json --status ready | jq -r '.[] | select(.title=="UAT ready card") | .id')
   ```

   Note: every CLI verb that mutates a task (`archive`, `block`, `unblock`,
   `complete`, `comment`, `show`, `specify`) takes the **task ID** (the
   `t_<16-hex-chars>` token), NOT the title. Passing a title produces
   `error: task not found: <title>`.

2. **Launch the dev server with the `server` feature.** The `#[server]` fns
   require it; plain `dx serve` builds the WASM client without the API
   surface and the UAT will fail with no actionable signal.

   ```bash
   cd crates/iron_hermes_ui
   dx serve --features server
   ```

   Open `http://localhost:8080` in a desktop browser. Chrome, Firefox, or
   Safari are all acceptable; DevTools-required rows (U3, U10) work in any
   of the three.

3. **Open a second shell** for cross-process CLI writes during U8 / U9.
   Keep the dev-server shell visible so you can watch tracing output for
   unexpected errors.
