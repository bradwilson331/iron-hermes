## Accomplishments

- **Risk 1 atomic fix landed:** All 6 `WheelWedge` methods (`index`, `from_index`, `label`, `sub`, `glyph`, `to_screen`) updated in one commit. `from_index` modulo changed from `rem_euclid(10)` to `rem_euclid(11)` with the new `10 => WheelWedge::Kanban` match arm. The silent-route-to-Chat bug class is eliminated.
- **DYNAMIC wheel geometry confirmed + applied:** Task 1 discovery found a single `pub const N: usize = 10` at `wheel.rs:58` drives `STEP` and all three render loops (`for i in 0..N`). Bumping `N` to 11 atomically updates wedge count, arc-angle math (`STEP = 360.0 / 11.0`), separator lines, and glyph/label text rendering.
- **Discovery-driven navigation:** `KANBAN BOARD →` button injected immediately right of `PRUNE ENDED` per D-03 / UI-SPEC §3.2. Click handler sets `active_screen` to `Screen::Kanban` via the standard `use_context::<Signal<Screen>>()` pattern.
- **Plan 04 ships before Plan 01:** Introduced `Screen::Kanban` variant + minimal `screens::kanban::ScreenKanban` placeholder + screen-router mount. Plan 01 will replace only the body of `ScreenKanban` without conflict (signature is stable).
- **Compile-time enforcement:** Adding `Screen::Kanban` forced exhaustive-match updates in `breadcrumb.rs` (`screen_short_name`) and `app_footer.rs` (`screen_label`) — both now have `Screen::Kanban => "KANBAN"`.
- **Round-trip identity test passes 17/17:** `tests/kanban_wheel_nav.rs` locks every facet of the 6-method update via `include_str!` source-grep (iron_hermes_ui is bin-only).

**1. [Rule 3 - Blocking] Test file initially used `use iron_hermes_ui::state::*` — iron_hermes_ui is bin-only**

- **Found during:** Task 2 RED build
- **Issue:** Initial draft of `tests/kanban_wheel_nav.rs` did `use iron_hermes_ui::state::{Screen, WheelWedge}` to call the methods directly. The crate has no `[lib]` target (only `src/main.rs`), so the integration test failed to compile with `E0433: failed to resolve: use of unresolved module or unlinked crate iron_hermes_ui`.
- **Fix:** Refactored the test to use `include_str!` source-grep — the same pattern as `tests/websocket_lifecycle_parity.rs` and `tests/web_queue_protocol.rs`. Every behavioral claim is now asserted via a literal-substring check on the source. The test runs in milliseconds and locks the same surface (6-method atomic update + Risk 1 modulo + agents.rs button + router placeholder mount).

**2. [Rule 3 - Blocking] Pre-existing internal unit tests in state.rs asserted modulo-10 — broke after my modulo-11 fix**

- **Issue:** `state::tests::wheel_wedge_from_index_wraps_modulo_ten` asserted `WheelWedge::from_index(10) == WheelWedge::Chat`. After my modulo-10 → modulo-11 fix, that assertion legitimately reversed: `from_index(10)` now returns `WheelWedge::Kanban`. The test name itself encoded the old modulus. Similarly `wheel_wedge_from_index_round_trips_all_indices` iterated `0..10` (missing the new index 10) and `wheel_wedge_from_index_handles_extreme_value` asserted `w.index() < 10`.
- **Fix:** Renamed `..._wraps_modulo_ten` → `..._wraps_modulo_eleven` and updated assertions: `from_index(10) == Kanban`, `from_index(11) == Chat`, `from_index(21) == Kanban`, `from_index(22) == Chat`. Bumped `0..10` to `0..11` in the round-trip loop. Changed `< 10` to `<= 10` in the extreme-value assert. Added `Kanban` arms to `wheel_wedge_to_screen_one_to_one`, `wheel_wedge_round_trips_through_json` (`0..10` → `0..11`), `wheel_wedge_labels_match_wheel_v2_js`, `wheel_wedge_subs_match_wheel_v2_js`, and `wheel_wedge_glyphs_match_wheel_v2_js`.
- **Files modified:** `crates/iron_hermes_ui/src/state.rs` (test module starting line ~810).

- **Committed in:** `ad36839a` (Task 2 GREEN commit — same atomic landing).

**3. [Rule 3 - Blocking] Wheel.rs internal tests asserted `N == 10` and `STEP == 36.0`**

- **Found during:** same test run as Deviation #2.
- **Issue:** `wheel::tests::geometry_matches_v2_constants` asserted `assert_eq!(N, 10)` and `assert_eq!(STEP, 36.0)`. `wheel::tests::step_is_thirty_six_degrees` did the same plus `(STEP * N as f64 - 360.0).abs() < 1e-9` with the message "10 wedges × STEP must exactly tile 360°". After bumping `N` to 11, both were stale.
- **Fix:** Updated `geometry_matches_v2_constants` to assert `N == 11` and `(STEP - 360.0/11.0).abs() < 1e-9`. Renamed `step_is_thirty_six_degrees` → `step_tiles_full_circle` and replaced the literal 36.0 assertion with `let expected = 360.0_f64 / 11.0; assert!((STEP - expected).abs() < 1e-9)`. Renamed `wedge_path_renders_all_ten_wedges` → `wedge_path_renders_all_wedges` (its body uses `0..N` so the logic was already correct).
- **Files modified:** `crates/iron_hermes_ui/src/components/hermes_app/wheel.rs`.
- **Verification:** wheel.rs unit tests included in the 49/49 `--bin iron_hermes_ui` test pass.
- **Committed in:** `ad36839a` (Task 2 GREEN commit).

**4. [Rule 2 - Missing Critical] Plan 04 needed to update `breadcrumb.rs` and `app_footer.rs` for exhaustive-match compliance**

- **Found during:** Task 1 discovery → Task 2 design.
- **Issue:** The PLAN file's Step A discussed coordinating with the Screen enum dispatch site in `mod.rs`. In this codebase the dispatch is `screen_router.rs` (RSX fan-out, not a match), but `breadcrumb.rs::screen_short_name` and `app_footer.rs::screen_label` both contain exhaustive `match s { Screen::Xxx => ... }` blocks. Adding `Screen::Kanban` to the enum without updating these two functions would produce two `non_exhaustive_patterns` build errors — a true blocking issue.
- **Fix:** Added `Screen::Kanban => "KANBAN"` arms to both functions in the GREEN commit. Both label strings match the wheel-wedge label per UI-SPEC §3.3.
- **Files modified:** `crates/iron_hermes_ui/src/components/hermes_app/breadcrumb.rs`, `crates/iron_hermes_ui/src/components/hermes_app/app_footer.rs`.
- **Verification:** `cargo build -p iron_hermes_ui --features server` — pass with no exhaustive-match errors.
- **Committed in:** `ad36839a` (Task 2 GREEN commit).
