## Deviations from PLAN.md

**Executor halted early.** The gsd-executor agent dispatched for Plan 05
landed Task 1 + Task 2 in commits `61696079` and `52be7cfe`, then exited
without running the workspace gate or writing SUMMARY.md (it spawned the
gates as background tasks and returned control before the notifications
arrived). The orchestrator (this session) ran the workspace gate from the
merged tree to verify all three commands pass, then wrote this SUMMARY.md
in a follow-up commit.

**UAT.md needed post-merge fixes.** The executor wrote the UAT prerequisites
using nonexistent `ironhermes-cli` verbs / flags:

| What was written | What should have been written |
|------------------|-------------------------------|
| `kanban create -t "..." -a dev` | `kanban create --triage --assignee dev "..."` (long-form flags only) |
| `kanban create -t "..." -a dev` then `kanban promote <id>` | `kanban create --assignee dev "..."` (default is READY; no `promote` verb exists) |
| `kanban promote <triage-id>` (U8) | `kanban archive <id>` (no LLM) or `kanban specify <id>` (LLM-driven TRIAGE→TODO) |
| `kanban comment <id> --body "..."` (U9) | `kanban comment <id> "..."` (body is positional) |

The orchestrator corrected all four sites in the same commit that lands
this SUMMARY.md. The actual CLI surface was confirmed via
`cargo run -p ironhermes-cli -- kanban {create,specify,comment,archive} --help`.

**TODO column has no CLI create path.** `kanban create` only writes TRIAGE
(via `--triage`) or READY (default). TODO is only reachable from TRIAGE
via `kanban specify <id>` (LLM-driven) or via a UI drag from TRIAGE →
TODO. The UAT script was revised to use READY as the substitute for TODO
in U5/U6/U7 — those rows test drag-disallowed-to-DONE, complete-via-drawer,
and block/unblock, all of which behave identically from READY.
