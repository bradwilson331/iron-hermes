# Phase 36.17.6 Plan 01: Wire voice toolset into CLI inspection path — Summary

## One-liner

Wired `register_tts_tools` into CLI inspection registry via `register_tts_for_inspection` helper, added `"voice"` to `KNOWN_TOOLSETS` and `toolset_members_map`, closing the gap that prevented `toolset list` / `toolset show voice` from surfacing TTS tools.

## What Was Built

All changes in a single file: `crates/ironhermes-cli/src/toolset_cmd.rs`.

1. **`KNOWN_TOOLSETS` updated** (8 → 9 entries): appended `"voice"` so `check_known_toolset` accepts the slug and `toolset show voice` no longer errors with "unknown toolset".

2. **`toolset_members_map()` updated**: added `m.insert("voice", &["text_to_speech", "send_audio"])` after the `"browser"` entry, following existing two-element compact inline style (same as `"agent"` entry).

3. **`register_tts_for_inspection` helper added**: private helper that constructs `SessionKey::new(Platform::Local, "inspect")` and calls `registry.register_tts_tools(session_key, None, Arc::new(ironhermes_core::Config::default()))`. Placed after `browser_chromium_unavailable()` under a new section comment. Imports are function-scoped per Pattern 8.

4. **Both inspection commands updated**: `cmd_toolset_list` and `cmd_toolset_show` each call `register_tts_for_inspection(&mut registry)` immediately after `registry.register_defaults()`.

5. **Unit tests**: `browser_in_known_set` assertion updated from `== 8` to `== 9` with updated message referencing Phase 36.17.6. New `toolset_members_map_voice_entry` test added asserting both tool names and exact length of 2.
