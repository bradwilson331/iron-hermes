<objective>
Wire the `voice` toolset into the CLI inspection path so `ironhermes toolset list`
and `ironhermes toolset show voice` both surface `text_to_speech` + `send_audio`
with correct availability state. This closes the architectural gap diagnosed in
36.17.5 Plan 04 SUMMARY: `cmd_toolset_list` / `cmd_toolset_show` build their own
`ToolRegistry::new() + register_defaults()` and never reach
`build_app_runtime_bundle`, so Plan 03's `register_tts_tools` wiring never fires
on the inspection path.

Purpose: Unblock 36.17.5 UAT Gates 4+5 by giving the CLI inspection registry the
same TTS tool registration that the agent runtime already has, without touching
`register_tts_tools`' signature or `ironhermes-tools` source.

Output: A single-file change to `crates/ironhermes-cli/src/toolset_cmd.rs` that
adds (1) `"voice"` to `KNOWN_TOOLSETS`, (2) a `"voice"` entry to
`toolset_members_map()`, (3) a private `register_tts_for_inspection` helper,
(4) helper calls from both `cmd_toolset_list` and `cmd_toolset_show`, (5) a
new `toolset_members_map_voice_entry` unit test, and (6) an updated
`browser_in_known_set` length assertion (8 → 9). All changes ship in one
commit because `KNOWN_TOOLSETS` and the length assertion are coupled at
compile/test time.
</objective>
