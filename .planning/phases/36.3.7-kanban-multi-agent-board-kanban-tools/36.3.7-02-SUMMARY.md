## Schema DDL (Final)

Full `SCHEMA_SQL` column layout — plan 04 tools reference column names from this:

```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;

CREATE TABLE IF NOT EXISTS schema_version (version INTEGER NOT NULL);

CREATE TABLE IF NOT EXISTS tasks (
    id                      TEXT PRIMARY KEY,
    title                   TEXT NOT NULL,
    body                    TEXT,
    assignee                TEXT NOT NULL,
    status                  TEXT NOT NULL DEFAULT 'ready',
    priority                INTEGER NOT NULL DEFAULT 0,
    tenant                  TEXT,
    workspace               TEXT,
    skills                  TEXT,           -- JSON array
    idempotency_key         TEXT UNIQUE,
    claim_lock              TEXT,
    claim_expires           REAL,
    current_run_id          TEXT,
    consecutive_failures    INTEGER NOT NULL DEFAULT 0,
    max_retries             INTEGER,
    max_runtime_seconds     INTEGER,
    scheduled_at            REAL,
    workflow_template_id    TEXT,
    current_step_key        TEXT,
    created_by              TEXT,
    created_at              REAL NOT NULL,
    started_at              REAL,
    ended_at                REAL
);

CREATE TABLE IF NOT EXISTS task_links (
    parent_id   TEXT NOT NULL,
    child_id    TEXT NOT NULL,
    created_at  REAL NOT NULL,
    PRIMARY KEY (parent_id, child_id),
    FOREIGN KEY (parent_id) REFERENCES tasks(id) ON DELETE CASCADE,
    FOREIGN KEY (child_id)  REFERENCES tasks(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS task_comments (
    id          TEXT PRIMARY KEY,
    task_id     TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    author      TEXT NOT NULL,
    body        TEXT NOT NULL,
    created_at  REAL NOT NULL
);

CREATE TABLE IF NOT EXISTS task_events (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id     TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    run_id      TEXT,
    kind        TEXT NOT NULL,
    payload     TEXT,
    created_at  REAL NOT NULL
);

CREATE TABLE IF NOT EXISTS task_runs (
    id          TEXT PRIMARY KEY,
    task_id     TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    claim_lock  TEXT NOT NULL,
    claim_pid   INTEGER,
    started_at  REAL NOT NULL,
    ended_at    REAL,
    outcome     TEXT,
    summary     TEXT,
    metadata    TEXT,
    error       TEXT,
    log_path    TEXT
);
```

**Indexes:** `idx_tasks_status_assignee`, `idx_tasks_idempotency` (partial, WHERE idempotency_key IS NOT NULL), `idx_task_events_task`, `idx_task_runs_task`.

## CAS `changes()` API Resolution

**RESEARCH.md Q2 ASSUMED:** "rusqlite `changes()` is available on `Connection` (not `Transaction`)" — **RESOLVED: partially incorrect.**

In rusqlite 0.32, `Transaction` implements `Deref<Target = Connection>`, so `tx.changes()` **works correctly** via deref. The RESEARCH.md fallback to `conn.changes()` was not needed. Implementation uses `tx.changes()` directly after the CAS UPDATE on the transaction — this is correct and reads more cleanly.

## Concurrency Test Results

- **Trial count:** N=20 (each trial = 2 threads racing on separate `Connection`s to same DB file)
- **Result:** All 20 trials: exactly one winner, exactly one `task_runs` row, task in `running` state
- **Flake observations:** None observed in test run. SQLite `BEGIN IMMEDIATE` serializes correctly at the OS file-lock level. The `busy_timeout(5000ms)` on each connection ensures the loser waits rather than immediately erroring with `SQLITE_BUSY`.
- **worker_write_gated test:** stale lock → `Ok(false)` + `claim_expired` event, confirmed.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] cas.rs included in Task 1 commit**
- **Found during:** Task 1 implementation
- **Issue:** `store.rs` calls `crate::cas::assert_run_id_tx()` which lives in `cas.rs`. The plan placed `cas.rs` as a Task 2 file, but the store's `complete_task` and `block_task` need it to compile.
- **Fix:** Wrote `cas.rs` alongside `store.rs` in the Task 1 commit. Task 2 focus shifted to the concurrency test + invariant un-ignoring (the behavioral verification of the CAS primitives), which is where the plan's value lies.
- **Files modified:** `crates/ironhermes-kanban/src/cas.rs` (added to Task 1 commit `e00ea9b2`).

**2. [Rule 2 - Missing] `assert_run_id_tx` variant added**
- **Found during:** Task 1 — `store.rs` `complete_task`/`block_task` hold an open `BEGIN IMMEDIATE` transaction; calling `assert_run_id(&conn, ...)` would require a re-borrow of the underlying connection through the transaction, which the borrow checker rejects.
- **Fix:** Added `assert_run_id_tx(tx: &Transaction, ...)` that takes the open transaction directly. The `assert_run_id(conn: &Connection, ...)` form is preserved for callers without an open transaction.
- **Files modified:** `crates/ironhermes-kanban/src/cas.rs`.

**3. [Rule 1 - Bug] Profile name 'default' is reserved**
- **Found during:** Task 1 smoke test RED → GREEN run.
- **Issue:** `ironhermes_core::profile::validate_profile_name("default")` returns `Err` — "default", "current", "none" are reserved names. Tests used `"default"` as the assignee.
- **Fix:** Changed all test assignees from `"default"` to `"alice"`.
- **Files modified:** `crates/ironhermes-kanban/tests/store_smoke.rs`.
