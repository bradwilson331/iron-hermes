<objective>
Bundle the two upstream Hermes Kanban skills as static assets in the IronHermes repo (`skills/kanban-{worker,orchestrator}/SKILL.md`) and wire their sync into both first-run home-dir scaffolding (D-30) and the `ironhermes skills update` flow. Per D-29 this is a byte-for-byte translation with TWO substitution rules: `hermes -p <P>` → `ironhermes --profile <P>` and `~/.hermes/` → `~/.ironhermes/`. NO semantic edits.

Purpose: Workers spawned by plan 03 receive `--skills kanban-worker` on every spawn (D-28). For that flag to do anything, the skill must exist at the profile's resolved skills root. Per `ensure_home_dirs()` precedent (Phase 21.6), `~/.ironhermes/skills/` is the global skills root that every profile reads. D-30 requires the sync to preserve user edits — the user might tweak the worker skill for their own anti-pattern list, and a re-sync should not clobber it (except via the explicit `skills reset --restore` path).

Output: Two SKILL.md files in `skills/`, a `skills_bundle.rs` module with `include_str!` constants + sync helper, two CLI integration points (ensure_home_dirs hook + skills update handler).
</objective>
