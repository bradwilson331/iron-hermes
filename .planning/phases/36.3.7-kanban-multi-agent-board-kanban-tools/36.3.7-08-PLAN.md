<objective>
Wire the dispatcher (plan 03) into the gateway runtime per D-09. This is the production hosting decision — D-09 commits to "gateway-embedded by default" so a single `ironhermes gateway start` invocation gives you both message routing AND kanban dispatching, no separate daemon needed.

The gateway's `GatewayRunner::start()` already spawns multiple long-lived tokio tasks into a `JoinSet` (verified at runner.rs:714, 808, 851, 1175, 1201 — including the existing cron tick task as "step 10"). Adding the kanban dispatcher follows the exact same shape — capture an Arc to the dispatcher state, spawn `run_dispatch_loop(ctx, cancel)` into the join_set, log a startup message. The CancellationToken-based shutdown protocol from cron tick applies as-is.
