<objective>
Build the 6 LLM tools that workers (and orchestrators) use to read/write the board. Each tool is its own `Tool` trait implementation, gated by `HERMES_KANBAN_TASK` env (worker mode) OR explicit toolset enable (orchestrator mode), per D-20. These tools NEVER shell out to `ironhermes kanban …`; they call `KanbanStore` methods directly (D-20 backend portability — workers may run in Docker/Modal/SSH where the CLI isn't installed; reference.md §"Why tools instead of shelling to hermes kanban").

Purpose: This is the LLM-facing protocol surface. The 6 tools encode the worker lifecycle in tool calls (`kanban_show` → orient, `kanban_comment`/`kanban_heartbeat`-deferred → mid-work, `kanban_complete`/`kanban_block` → terminate). Their JSON schemas + return shapes ARE the contract the worker skill teaches the model. Getting `expected_run_id` and `created_cards` rejection right at the tool layer (not just the store layer) is what makes the worker protocol survive reclaim races and LLM hallucination (D-22).

Output: 6 tool structs in `crates/ironhermes-kanban/src/tools/`, plus a registration helper that downstream consumers (CLI session, AgentLoop in the worker process) call to add them to `ToolRegistry`.
</objective>
