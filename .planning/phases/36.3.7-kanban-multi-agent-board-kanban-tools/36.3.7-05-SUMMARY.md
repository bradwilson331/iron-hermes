## Task 2 — Conditional injection at session-construction site

Two helpers in `crates/ironhermes-cli/src/main.rs`:

```rust
fn inject_kanban_guidance_if_worker(prompt_builder: &mut PromptBuilder) {
    if std::env::var("HERMES_KANBAN_TASK").is_ok() {
        prompt_builder.activate_skill("KANBAN_GUIDANCE", KANBAN_GUIDANCE);
    }
}

async fn register_kanban_tools_if_applicable(
    registry: &Arc<RwLock<ToolRegistry>>,
    toolsets: &HashSet<String>,
) -> anyhow::Result<()> {
    let worker_mode = std::env::var("HERMES_KANBAN_TASK").is_ok();
    let orchestrator_mode = toolsets.contains("kanban");
    if worker_mode || orchestrator_mode {
        let store = match KanbanStore::open_default() { Ok(s) => s, Err(_) => return Ok(()) };
        let store_arc = Arc::new(tokio::sync::Mutex::new(store));
        let explicit_enable = orchestrator_mode && !worker_mode;
        register_kanban_tools(&mut *registry.write().await, store_arc, explicit_enable);
    }
    Ok(())
}
```

### Known flake — surfaced for plan 09

The 6 plan-04 tool tests at `src/tools/{show,list,comment,complete,block,create}.rs::tests::is_available_respects_env` mutate the same `HERMES_KANBAN_TASK` env var without a shared mutex. Default parallel `cargo test` flakes ~1-in-10 runs (saw one trip during plan 05 verification; did not reproduce on retry). The deterministic serial run is green.

**Recommended fix (plan 09 polish):** add a `parking_lot::Mutex<()>` shared across all `tools::*::tests` modules, hold its guard for the lifetime of each `is_available_respects_env` body. Mirror the existing `IRONHERMES_HOME` lock pattern from `main.rs:33`.

This is NOT a plan 05 regression — the tests are plan 04 code; plan 05's main.rs diff does not run during `ironhermes-kanban` unit tests.
