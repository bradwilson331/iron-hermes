<objective>
Build the 8-step dispatcher tick loop + worker subprocess spawn pipeline. This is the runtime kernel — the thing that converts `ready` tasks into `ironhermes --profile P chat -q "..."` child processes with the correct env scrub and the 9-env-var contract.

Purpose: D-09 puts the dispatcher inside the gateway (plan 08 wires the gateway hook); this plan owns the dispatcher's actual logic so it is testable standalone. D-10 specifies an 8-step ordered loop with subtle invariants (live-PID extension BEFORE reclaim, respawn-guard BEFORE spawn, atomic-claim only after max_in_progress check). D-16/D-17/D-18 lock the spawn shape down to a contract that does not leak secrets via inherited env (Phase 22 precedent) — getting this wrong means worker processes accidentally publish OPENAI_API_KEY into a log file the next reviewer sees.

Output: A fully self-contained dispatcher module that takes a `KanbanStore` + `KanbanConfig` and ticks; plan 08 will host it inside the gateway runtime; this plan only proves it works in isolation against a tempfile DB.
</objective>

    - `run_dispatch_tick(ctx)` performs the 8-step loop in order:
      (1) detect_crashed: for each running task, load its current task_runs row → if `claim_pid.is_some()` AND `!is_pid_alive(pid)` → close run with outcome='crashed', release_claim with reason="crashed", increment consecutive_failures, append `crashed` event with `{pid, claimer}`.
      (2) live-PID extension: for each running task whose claim_expires < now AND claim_pid.is_some() AND is_pid_alive(pid) → UPDATE tasks SET claim_expires = now + DEFAULT_CLAIM_TTL_SECONDS WHERE id=?; append `claim_extended` event with `{pid, new_expires}`.
      (3) stale-claim reclaim: for each running task with claim_expires < now AND (claim_pid IS NULL OR !is_pid_alive(pid)) → release_claim with reason="ttl_expired"; UPDATE consecutive_failures += 1 (this counts as a failed attempt).
      (4) max-runtime enforcement: for each running task with task.max_runtime_seconds.is_some() AND (now - run.started_at) > max_runtime → call `kill_pid(pid, Signal::Term)`; sleep 5s; if still alive, `kill_pid(pid, Signal::Kill)`; close run with outcome='timed_out'; UPDATE consecutive_failures += 1; append `timed_out` event with `{pid, elapsed_seconds, limit_seconds, sigkill: bool}`.
      (5) ready promotion: for each task with status='todo', check via SELECT COUNT(*) FROM task_links JOIN tasks ON task_links.parent_id=tasks.id WHERE task_links.child_id=? AND tasks.status != 'done' — if zero, UPDATE status='ready'; append `promoted` event.
