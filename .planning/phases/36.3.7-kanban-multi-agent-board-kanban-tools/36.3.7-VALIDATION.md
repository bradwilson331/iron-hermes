## Critical Invariants (from RESEARCH.md `## Validation Architecture`)

Each of these MUST have a corresponding automated test:

1. **Atomic claim race** — Two workers attempting claim on same `ready` task; only one wins; loser sees `claim_lock IS NULL` precondition fail. Requires `BEGIN IMMEDIATE` (rusqlite landmine — DEFERRED transaction would allow both to win).
2. **`expected_run_id` rejection of stale writes** — Reclaimed-then-respawned worker's prior-run `kanban_complete` rejected with structured error.
3. **`created_cards` phantom-id rejection** — `kanban_complete(created_cards=[t_phantom])` rejected; `completion_rejected` event emitted permanently (never deletable).
4. **Dispatcher respawn-guard correctness** — `blocker_auth`, `recent_success`, `active_pr` blocks block respawn; emit `respawn_guarded`.
5. **Live-PID extension vs reclaim** — Alive PID at TTL expiry → `claim_extended`; dead PID at TTL expiry → `reclaimed`.
6. **Stranded-task diagnostic** — Ready task whose assignee never claims surfaces as `stranded_in_ready` at threshold; severity escalates at 2x/6x.
7. **Env scrub** — Worker subprocess receives ONLY `build_safe_env()` allowlist + 9 kanban env vars; no inherited shell secrets.
8. **Skills sync idempotency** — Second sync run is a no-op; profile-local edits preserved.
9. **`claim_lock`-gated worker writes** — `kanban_comment` from a worker whose `claim_lock` doesn't match no-ops and emits `claim_expired`.
10. **Protocol violation auto-block** — Worker exits 0 with task still `running` → emit `protocol_violation` AND auto-block (distinct from `crashed`).
