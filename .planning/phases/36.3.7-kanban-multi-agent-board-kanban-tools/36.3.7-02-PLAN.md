<objective>
Land the durable kernel: schema with 5 tables + WAL + migrations, `KanbanStore` with all CRUD helpers, and the atomic CAS claim primitive that is the load-bearing concurrency guarantee for the whole phase (D-40 + D-41). This plan owns every correctness invariant from VALIDATION.md that is testable without a live dispatcher.

Purpose: The CAS claim is the most error-prone moment in the entire kernel. `BEGIN IMMEDIATE` vs the default `DEFERRED` is the difference between a working multi-process dispatcher and silent double-claims. `expected_run_id` + `claim_lock` are defense-in-depth for the reclaim-then-respawn race. `created_cards` is a permanent audit gate against LLM hallucination. Cross-tenant link rejection (D-39) and idempotency_key dedup (D-24) live here because they are write-time invariants on the store, not runtime concerns.

Output: A `KanbanStore` that supports every kanban_* tool's read/write needs, plus the atomic claim primitive the dispatcher consumes in plan 03, plus a concurrency test that proves the CAS race is correctly resolved.
</objective>


    ```
    let tx = conn.transaction_with_behavior(TransactionBehavior::Immediate)?;
    let claim_expires = now + ttl_secs as f64;
    tx.execute(
        "UPDATE tasks SET status='running', claim_lock=?1, claim_expires=?2, \
         started_at=COALESCE(started_at, ?3), current_run_id=?4 \
         WHERE id=?5 AND status='ready' AND claim_lock IS NULL \
         AND (scheduled_at IS NULL OR scheduled_at <= ?3)",
        params![claim_lock, claim_expires, now, run_id, task_id],
    )?;
    let won = tx.changes() == 1;
    if won {
        tx.execute(
            "INSERT INTO task_runs (id, task_id, claim_lock, claim_pid, started_at) \
             VALUES (?1, ?2, ?3, ?4, ?5)",
            params![run_id, task_id, claim_lock, claim_pid, now],
        )?;
        // Append claimed event in same tx
        tx.execute(
            "INSERT INTO task_events (task_id, run_id, kind, payload, created_at) \
    ```
