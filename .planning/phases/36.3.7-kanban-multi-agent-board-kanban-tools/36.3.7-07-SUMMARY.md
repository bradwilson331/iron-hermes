## Decisions Made

### SkillsAction::Reset — was NOT present

The existing `SkillsAction` enum had no `Reset` variant. Added fresh:
```rust
Reset {
    name: String,
    #[arg(long)]
    restore: bool,
}
```

### ensure_home_dirs hook location

Hook landed at **line 601** in `crates/ironhermes-cli/src/main.rs`, immediately after the 9-subdir creation loop closes. The `skills/` subdir is guaranteed to exist at that point (it's in the loop), so `sync_bundled_kanban_skills` can write into it safely.

### Non-fatal error handling in ensure_home_dirs

The sync call is wrapped in `if let Err(e) = ... { tracing::warn!(...) }` — intentional. If the bundled skills sync fails (e.g., disk full, permission error), the operator still gets a functional CLI. The kanban worker just won't have its skill until the next opportunity (`skills update` will retry).

### cmd_update hook placement

The kanban sync is appended **after** the hub-side update loop completes (after `Ok(exit_code)` was the prior return). This means: (a) hub skills update first, (b) kanban bundled skills sync second. The `exit_code` from hub updates is preserved; kanban sync failure only emits a warning (non-fatal, does not change exit_code).
