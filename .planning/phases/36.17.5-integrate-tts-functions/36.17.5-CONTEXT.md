# Phase 36.17.5: integrate TTS functions - Context

**Gathered:** 2026-06-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Port text-to-speech from hermes-agent (Python) into IronHermes (Rust) as a faithful concept-level port of Python's `TTSProvider` ABC. This phase ships:

1. A Rust `TtsProvider` trait + `TtsRegistry` in `ironhermes-core`
2. Two compile-time-registered built-in provider impls in `ironhermes-tools`: **Edge TTS** (free default, no API key) and **ElevenLabs** (premium, `ELEVENLABS_API_KEY`)
3. A single LLM-callable tool `text_to_speech` (Path B from `tts-idea.txt`) that synthesizes to a file and returns the path
4. A companion `send_audio` LLM tool that dispatches the produced file to the current platform's voice/audio reply path (Telegram only this phase; CLI plays locally via `rodio`)
5. Telegram delivery wiring: with ffmpeg present → MP3 → Opus voice bubble; without → audio attachment fallback. ElevenLabs Opus voice-bubbles natively.

**Out of scope (will live in their own phases):**
- STT / voice-message transcription (Whisper / Groq / OpenAI etc.)
- Full Voice Mode (CLI Ctrl+B push-to-talk, Discord voice channels)
- Auto-speak hook on `ChatStreamEvent` (Path A from tts-idea.txt) — rejected for this phase; tool-only model
- Streaming TTS (sentence-by-sentence) — trait omits `stream()`
- Discord and `iron_hermes_ui` web delivery surfaces (only Telegram this phase; future phases bolt on)
- All other 8 Python providers (OpenAI / MiniMax / Mistral / Gemini / xAI / NeuTTS / KittenTTS / Piper) — trait/registry is ready for them; impls land in future phases
- Pure-Rust Opus encoding (`audiopus`) — ffmpeg is the v1 path
- Expanded `text_to_speech` arg schema (`voice`, `model`, `speed`, `output_format`) — v1 ships `text` + optional `output_path` only

</domain>

<decisions>
## Implementation Decisions

### Scope & Urgency
- **D-01:** Urgency driver is **parity-gap catch-up**, not a deadline. Port the concept faithfully; no race to ship.
- **D-02:** Phase width = **TTS output + `TtsProvider` trait + registry**. STT, push-to-talk, Discord VC = own phases. Matches the "TTS-output AND port the Provider trait/registry" option.
- **D-03:** Built-in provider lineup v1 = **Edge TTS + ElevenLabs** (free default + premium). Two providers proves the trait isn't accidentally Edge-shaped without ballooning scope.
- **D-04:** ffmpeg is **optional, opt-in via config**, detected at startup. Present → MP3↔Opus conversion for Telegram voice bubbles. Absent → Edge ships as audio attachment, ElevenLabs Opus still voice-bubbles natively. Mirrors Python's actual behavior (`tts.md` Telegram Voice Bubbles & ffmpeg section).

### Integration Model
- **D-05:** **Tool-only** (Path B from tts-idea.txt). NO auto-speak hook on `ChatStreamEvent`. LLM-callable `text_to_speech` is the sole entry point this phase.
- **D-06:** Tool I/O = **write to file + return path string**. No bytes/base64 in return value. No side-channel events. Smallest possible surface, matches existing `Tool` trait's `anyhow::Result<String>` shape.
- **D-07:** v1 tool args = `text` (required) + `output_path` (optional, defaults to `$IRONHERMES_HOME/audio_cache/<uuid>.<ext>`). Voice / model / speed / output_format come from config. **Follow-up phase** expands to full Python-parity arg surface (`voice`, `model`, `speed`, `output_format`) — DO NOT ship that expansion here.
- **D-08:** Code placement = **trait + registry in `ironhermes-core`; provider impls + tools in `ironhermes-tools`**. Matches the `SessionKey`-in-core pattern from Phase 36.17.3. No new crate this phase.

### Provider Abstraction
- **D-09:** Trait surface = **name + display_name + is_available + synthesize + voice_compatible**. `list_voices`, `list_models`, `default_voice`, `default_model`, `get_setup_schema`, `stream` are DEFERRED to future phases.
- **D-10:** **Keep the "built-ins always win" invariant**. Define a frozen set `BUILTIN_TTS_NAMES = {"edge", "elevenlabs"}`. `TtsRegistry::register()` rejects (warn-and-ignore) any registration whose `name()` is not in the frozen set this phase. This pre-positions the invariant for any future user-extension reversal.
- **D-11:** Error type = `anyhow::Result<PathBuf>` on `synthesize()`. Matches the existing `Tool` trait pattern and project-wide `anyhow` convention. Typed `TtsError` enum is DEFERRED until a real consumer (e.g., gateway-side retry/rate-limit handling) demands it.
- **D-12:** Config shape = `TtsConfig { provider: String, edge: EdgeTtsConfig, elevenlabs: ElevenLabsConfig }` — strongly-typed per-provider sub-blocks. Mirrors the existing `ModelConfig` style. Adding a new provider in a future phase = adding a new strongly-typed field; no `serde_json::Value` escape hatches.

### Delivery Surfaces
- **D-13:** Delivery wired this phase = **Telegram voice/audio attach only**. Discord and `iron_hermes_ui` web auto-delivery deferred.
- **D-14:** Detection mechanism = **dedicated `send_audio` LLM tool**, NOT a side-channel event or trajectory scan. Agent explicitly calls `text_to_speech` then `send_audio`. Two-tool sequence is explicit and controllable; matches the Python Path B pattern from `tts-idea.txt` final paragraph.
- **D-15:** `send_audio` tool shape = **`send_audio(path)`** — single platform-agnostic tool that reads the current `SessionKey` (Platform + chat_id) from per-turn context and dispatches:
  - `Platform::Local` → play locally via `rodio` (CLI path)
  - `Platform::Telegram` → `TelegramAdapter::send_voice` (if Opus) or `send_audio` (if MP3)
  - Other platforms → `anyhow::bail!("send_audio not yet wired for {platform}")` — future phases add Discord/web arms without a new tool.
- **D-16:** Audio cache = **`$IRONHERMES_HOME/audio_cache/<uuid>.<ext>`** (NOTE: `$IRONHERMES_HOME`, NOT `$HERMES_HOME` — the project uses `~/.ironhermes/`). NO cleanup logic this phase. Future phase adds size-cap or age-based eviction when disk usage becomes a real problem.

### Claude's Discretion
- Exact tool `toolset()` grouping name (suggest `"voice"` to leave room for STT in a sibling phase).
- Edge TTS Rust crate selection: `tts-idea.txt` recommends `edge-tts-rust` — verify it's still actively maintained at planning time; if not, evaluate `msedge-tts` or other actively-maintained alternatives. Crate choice is a research output, not a CONTEXT lock.
- Default voice IDs for `EdgeTtsConfig` (`"en-US-AriaNeural"`) and `ElevenLabsConfig` (`"pNInz6obpgDQGcFmaJgB"` / Adam, `"eleven_multilingual_v2"`) — mirror Python defaults unless researcher finds a stronger Rust-side choice.
- Whether `is_available()` for ElevenLabs reads the env var directly or goes through `Config` — pick whichever is consistent with `ironhermes-tools::web_search::WebSearchTool`'s API-key handling.
- UAT script shape — model on `scripts/uat/phase-36.17-web-logging.sh` (the closest recent UAT). Spin up nothing more than what's needed to prove Edge synth + file write succeed without an API key.
- Whether `send_audio`'s `Platform::Local` arm gates on a `voice_compatible` flag from the provider or always plays whatever was written. Recommend always-play; the file extension is the source of truth.

</decisions>

<specifics>
## Specific Ideas

- **Path B explicitly chosen** (D-05): the tts-idea.txt example sketch in "Tool Logic Example" is the prototype for `TextToSpeechTool::execute()`. Implementer should not invent a different shape.
- **Tool sequencing**: the agent calls `text_to_speech` → gets a path → calls `send_audio` with that path. The two-tool sequence is INTENTIONAL — explicit > implicit per D-14.
- **`$IRONHERMES_HOME` is the env var** (D-16) — the project uses `~/.ironhermes/`, NOT `~/.hermes/`. Any reference to `HERMES_HOME` in the seed docs/code from the Python project should be translated to `IRONHERMES_HOME` in Rust.
- **Default Edge voice** = `"en-US-AriaNeural"` (matches Python default in tts.md and tts-idea.txt).
- **Default ElevenLabs voice + model** = `voice_id: "pNInz6obpgDQGcFmaJgB"` (Adam) + `model_id: "eleven_multilingual_v2"` (matches Python tts.md).
- **Output format defaults**: Edge → `.mp3`. ElevenLabs → if Opus model output configured, `.opus`; else `.mp3`. UUID-based filenames to avoid collision.
- **No streaming this phase** (`stream()` deferred per D-09) — `synthesize()` is the only required call path. Buffering full text in memory before the HTTP call is acceptable for v1.

</specifics>

<deferred>
## Deferred Ideas

### Next-phase candidates (close successors)
- **Expand `text_to_speech` arg schema** to full Python parity: add `voice`, `model`, `speed`, `output_format` optional args. Explicitly noted in D-07.
- **STT (voice-message transcription)** — own phase. Mirrors the trait/registry pattern landed here. Providers: `local` (faster-whisper bindings or fallback CLI), Groq, OpenAI.
- **Auto-speak hook (Path A)** — own phase. Intercept `ChatStreamEvent::Delta` in gateway + CLI, sentence-buffer, dispatch to `TtsProvider::stream()`. Requires the `stream()` trait method this phase deferred.

### Mid-term (after the close successors)
- **More providers** behind the same trait: OpenAI TTS, MiniMax, Mistral, Gemini, xAI, NeuTTS, KittenTTS, Piper. Each is its own (small) phase; registry's `BUILTIN_TTS_NAMES` expands each time.
- **Discord delivery** — extend `SendAudioTool`'s match with a `Platform::Discord` arm; needs Discord voice-message API wiring.
- **`iron_hermes_ui` web delivery** — extend `SendAudioTool` with a web arm using the existing `ChatStreamEvent` channel to push audio chunks over WS for HTML5 `<audio>` playback.

### Long-term (likely separate milestone)
- **Full Voice Mode** — Ctrl+B push-to-talk CLI loop, Discord voice channels (PyNaCl/Opus + voice WS + SPEAKING opcode SSRC mapping), Telegram-side `/voice on` / `/voice tts` mode toggling.
- **Audio cache cleanup** — size-cap or age-based eviction when `$IRONHERMES_HOME/audio_cache/` becomes a disk-usage problem.
- **Pure-Rust Opus encoding** (`audiopus` / `opus`) — drop the optional ffmpeg dep in favor of in-process encoding. Only worth doing when ffmpeg friction shows up as a real user complaint.
- **Voice cloning support** (xAI custom voices / ElevenLabs voice library) — requires `list_voices()` trait method this phase deferred.
- **`hermes tts test` CLI subcommand** + `hermes tts setup` picker — UX work for first-time configuration; can wait until voice ecosystem has more providers to pick between.
- **Command-type providers / Python plugin providers** — REJECTED at the project level via the plugin-loader rejection. Don't re-litigate.

</deferred>
