## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] rodio 0.22 broke OutputStream/Sink API**
- **Found during:** Task 1 build verification
- **Issue:** Plan documented `rodio::OutputStream::try_default()` + `rodio::Sink::try_new()` API (from rodio 0.20 / 0.22 docs). rodio 0.22.2 ships an entirely new API: `DeviceSinkBuilder::open_default_sink()` + `Player::connect_new()`. The old types do not exist in this version.
- **Fix:** Updated SendAudioTool Local arm to use `rodio::DeviceSinkBuilder::open_default_sink()? ` + `rodio::Player::connect_new(stream_handle.mixer())` + `player.append(source)` + `player.sleep_until_end()` — verified against `~/.cargo/registry/src/*/rodio-0.22.2/examples/music_mp3.rs`.
- **Files modified:** `crates/ironhermes-tools/src/send_audio_tool.rs`
- **Commit:** 4d117f2c

**2. [Rule 1 - Bug] new_with_registry needs to be visible to integration test binaries**
- **Found during:** Task 2 test compilation
- **Issue:** Plan specified `#[cfg(test)] impl TextToSpeechTool` for `new_with_registry`, but integration tests in `tests/tts_tools.rs` compile as a separate binary — `#[cfg(test)]` on a library impl is not visible to external test binaries.
- **Fix:** Moved `new_with_registry` to a regular (always-compiled) `impl TextToSpeechTool` block with a doc comment explaining its test-friendly purpose. No behavioral impact.
- **Files modified:** `crates/ironhermes-tools/src/tts_tool.rs`
- **Commit:** fa813dfa

**3. [Rule 1 - Bug] TgSendApi::send_voice ambiguous with MediaSender::send_voice**
- **Found during:** Task 3 gateway build
- **Issue:** `self.send_voice(...)` in the new `AudioDispatcher for TelegramAdapter` impl was ambiguous: both `TgSendApi` (takes `&Path`) and `MediaSender` (takes `&MediaSource`) define `send_voice`. Rust E0034.
- **Fix:** Used `TgSendApi::send_voice(self, ...)` fully-qualified call to select the `&Path`-accepting variant.
- **Files modified:** `crates/ironhermes-gateway/src/telegram.rs`
- **Commit:** 6e188f61
